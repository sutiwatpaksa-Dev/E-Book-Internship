# Form validation

ทุกช่องที่คนพิมพ์เองต้องมีกฎ ไม่ใช่แค่ `maxLength` · บทเรียนจาก v2.1.13: ช่องเบอร์รับ 20 หลัก และ LINE/IG รับภาษาไทย เพราะกฎมีแค่ "ยาวไม่เกิน" ผู้ใช้เจอเองก่อนเรา

## กติกา 5 ข้อ

1. **กฎเดียว ใช้สองที่:** เขียนเป็นฟังก์ชัน `xxxProblem(v): string | null` ใน `src/lib/` (ไม่มี import ของ server หรือ React) แล้ว
   - server: `server/validators/*.validator.ts` เรียกใน `.superRefine()` ส่งข้อความกลับเป็น issue `custom`
   - ฟอร์ม: เรียกฟังก์ชันเดียวกัน แสดงข้อความใต้ช่องทันทีที่พิมพ์ (`role="alert"`, `aria-invalid`)
   - ตัวอย่างจริง: `src/lib/contact.ts` (เบอร์, อีเมล, LINE, IG, Facebook รวมอยู่ใน `CONTACT_RULES`), `src/lib/username.ts` (`USERNAME_PATTERN` ใช้ทั้ง `user.validator` และ `register.validator`) และ `passwordProblem` ใน `server/validators/auth.validator.ts`
   - **เหตุผล:** ฟอร์มกันได้แค่คนที่ใช้หน้าเว็บ server คือด่านจริง (ยิง API ตรงก็ต้องโดน) ถ้าเขียนกฎสองชุดจะเพี้ยนกันในไม่ช้า
2. **กฎมาจากของจริง ไม่ใช่เดา:** ใช้กติกาของระบบปลายทาง และเขียนที่มาไว้ใน comment
   | ช่อง | กฎ |
   |---|---|
   | เบอร์ไทย | ตัด `- ( ) ช่องว่าง` แล้วเหลือ `0` + 8–9 หลัก · สากล `+` + 10–15 หลัก |
   | อีเมล | `name@domain.tld` อังกฤษเท่านั้น ไม่เกิน 254 ตัว (`emailProblem`) |
   | LINE ID | `a-z 0-9 . _ -` ยาว 4–20 |
   | Instagram | `a-z 0-9 . _` ไม่เกิน 30 (`@` นำหน้าได้) |
   | Facebook | ลิงก์ `facebook.com/...` หรือ username อังกฤษ |
   | username | `USERNAME_PATTERN` ใน `src/lib/username.ts` |
   | ชื่อ/ข้อความอิสระ | ภาษาไทยได้ · trim · ความยาวสูงสุด · ช่องว่างล้วน = ไม่กรอก (`null`) |
3. **ช่องไหนห้ามภาษาไทย ต้องบอกในกฎ:** ID, username, ลิงก์, เบอร์ ใช้ allowlist ตัวอักษร (`/^[a-z0-9._-]+$/i`) ไม่ใช่ blocklist · ช่องชื่อคนต้องรับไทยได้
4. **ข้อความผิดภาษาไทย บอกวิธีแก้:** "เบอร์ไทยขึ้นต้นด้วย 0 และมี 9–10 หลัก เช่น 081-234-5678" ไม่ใช่ "invalid" หรือข้อความ default ของ Zod (`Too big: expected string...`)
5. **input ช่วยตั้งแต่แรก:** `type="tel" inputMode="tel"` · `autoCapitalize="none" spellCheck={false}` ช่อง ID · `maxLength` ตรงกับ server · placeholder เป็นตัวอย่างที่ถูก

## ทุกช่องใหม่ต้องมีเทสต์

`src/lib/<ชื่อ>.test.ts` อย่างน้อย:
- ค่าที่ถูก 3–5 แบบ (รวมรูปแบบที่คนพิมพ์จริง เช่น มีขีด มีช่องว่าง)
- ค่าที่ผิด: ยาวเกิน, สั้นไป, ภาษาไทยในช่องที่ห้าม, ตัวอักษรในช่องตัวเลข, **ค่าที่ผู้ใช้รายงานมา (ใส่ตรงตัว)**
- ว่าง = ผ่าน (ถ้าไม่บังคับ)

## ตรวจก่อนส่ง (ทำจริง)

1. `bun test src/lib/<ชื่อ>.test.ts`
2. ยิง API ตรงด้วย curl ส่งค่าผิด ต้องได้ `400` กับข้อความไทย (ด่าน server ทำงานจริง ไม่ใช่แค่ฟอร์ม)
3. แคปหน้าฟอร์มตอนพิมพ์ค่าผิด เห็นข้อความใต้ช่อง (`$S/cdp-shot.ts` รับ JS ตัวที่ 5 ใช้ setter ของ `HTMLInputElement` + `dispatchEvent("input")` เพื่อพิมพ์ใส่ช่อง React)
4. ข้อมูลเก่าใน DB ที่ผิดกฎใหม่: ฟอร์มต้องแสดงข้อความผิดให้แก้ได้ ไม่พัง

## ตรวจทั้งเว็บ (ถ้าถูกสั่ง "ไล่ validation ทั้งหมด")

```bash
grep -rn "z.string()" server/validators | grep -v "refine\|regex\|email\|enum"   # ช่องที่มีแค่ความยาว
grep -rn "<Input\|<textarea" src/components | grep -v "maxLength"                  # ช่องไม่จำกัดความยาว
```

รายงานเป็นตาราง `ไฟล์:บรรทัด | ช่อง | กฎตอนนี้ | ควรเป็น` แล้วถามก่อนแก้ ถ้ากฎใหม่ทำให้ข้อมูลเดิมกลายเป็นผิด ให้บอกจำนวนแถวที่กระทบ (SELECT อ่านอย่างเดียว)
