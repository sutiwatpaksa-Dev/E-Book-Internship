# Maintainer

คู่มือฉบับเต็มของคนดูแลอยู่ที่ `MAINTAINING.md` ให้อ่านส่วนที่เกี่ยวข้องก่อนลงมือ ไฟล์นี้สรุปเฉพาะกติกาที่พลาดบ่อย

## Branch

- ทำงานบน `dev` เท่านั้น push `dev` ได้เลย (ตั้งแต่ v2.1.18c Vercel build เฉพาะ `main` ไม่มี preview ของ dev แล้ว ทดสอบในเครื่อง)
- `main` คือเว็บที่น้องใช้จริง **push หรือ merge เข้า main เฉพาะเมื่อผู้ใช้สั่งชัดๆ** (เช่น "ขึ้น main ได้เลย") การอนุมัติครั้งก่อนใช้กับครั้งนี้ไม่ได้

## เลขเวอร์ชัน

- ทุก release เพิ่มเลขท้ายทีละ 1 เท่านั้น (2.0.6 → 2.0.7) ห้ามขยับเลข minor/major เอง
- ยกเว้น redesign ที่เสร็จครบตามเกณฑ์และขึ้น `main` แล้ว ได้เลขกลาง เช่น redesign /learn 7 ขั้น = v2.1.0 (ผู้ใช้ตกลง 25 ต.ค. 2569 รายละเอียดใน `MAINTAINING.md`) ระหว่างทางบน `dev` ยังขยับเลขท้ายตามปกติ และต้องให้ผู้ใช้สั่งเองว่าครบแล้ว
- งานที่แก้แค่หลังบ้านหรือเครื่องมือ (น้องไม่เห็นความต่าง) ให้ใช้ตัวอักษรต่อท้าย เช่น `2.0.5a` และ**ไม่ต้องลง changelog สาธารณะ**
- ขั้นตอน:
  1. เพิ่มหัวข้อบนสุดใน `content/docs/changelog.mdx` รูปแบบ `## v2.0.7 · 24 ต.ค. 2569` (ใช้ปี พ.ศ.) เขียนเป็นภาษาคนอ่าน บอกว่าได้อะไร มีลิงก์ไปหน้าที่เปลี่ยน
  2. `npm version 2.0.7 --no-git-tag-version`
  3. commit แล้ว `git tag v2.0.7` แล้ว push

## Commit

- รูปแบบ `docs: ...` / `feat: ...` / `fix: ...` / `chore: ...` ตามด้วย `; v2.0.7` ท้ายบรรทัดแรก
- ตรวจก่อน commit: `npm test && npm run typecheck && npm run build`
- `AGENTS.md` ถูกสร้างใหม่ทุกครั้งที่รัน `next dev` และถูก gitignore ไว้แล้ว ไม่ต้องแตะ

## เพิ่มบทใหม่

1. สร้าง `content/docs/<ชื่อ>.mdx` ที่มี frontmatter `title` และ `navTitle`
2. เพิ่มชื่อใน `content/docs/meta.json` และ `src/data/roadmap.ts`
3. ถ้าเป็นบทที่ต้องติ๊กผ่าน ให้ตรวจว่าลิงก์อยู่ใน `KNOWN` ของ `server/services/progress.service.ts`
4. บทเรียนสอนเป็น "กลุ่มเครื่องมือ" ไม่ใช่ "A vs B" ตารางเครื่องมือดึงจาก `src/data/tool-groups.ts` โดยข้อมูลต้องมาจากเว็บทางการ และ**เขียนสรุปด้วยคำของเราเอง**
5. ทุกบทต้องอธิบาย "ทำไม" และคำสั่งต้องมีทั้ง Windows และ Mac

## โค้ดของเว็บ

- เว็บนี้เป็นตัวอย่างของ stack ที่สอน: ฝั่ง frontend `app → components → hooks / api → client` ฝั่ง backend Hono `routes → services → repositories → db` ห้ามข้ามชั้น
- ชื่อไฟล์ตัวพิมพ์เล็กคั่นด้วย `-`
- Next.js รุ่นนี้มี breaking change ให้อ่าน `node_modules/next/dist/docs/` ก่อนเขียนโค้ด Next

## ฐานข้อมูล

- แก้ `server/db/schema.ts` แล้วรัน `npm run db:generate` และ commit ไฟล์ migration ด้วย
- **migration ใหม่ทุกตัว และการเขียนลง DB ของ preview/production ต้องขออนุมัติผู้ใช้ก่อน** ตรวจแบบอ่านอย่างเดียวได้
- ทดสอบในเครื่องใช้บัญชีชื่อขึ้นต้น `zz.` แล้วลบทิ้งหลังทดสอบ ห้ามสร้างบัญชีบนเว็บจริง

## Handoff

`Handoff.md` (gitignored) คือจุดที่ session ถัดไปเริ่มอ่าน เมื่อจบงานก้อนใหญ่ให้เพิ่มหัวข้อ "อัปเดต <วันที่>" ไว้บนสุดใต้ "0. กลับมาเริ่มตรงนี้" บอกว่าเสร็จอะไร, commit ไหน, อะไรรอผู้ใช้ตัดสิน และบทเรียนที่ได้ ถ้าไฟล์ยาวเกินไป ให้ย้ายของเก่าไปไว้ใน `Handoff.archive-<วันที่>.md`

## ห้ามเด็ดขาด

ห้ามเขียนค่าลับลงไฟล์ใดๆ (repo เปิดสาธารณะ) และห้าม force push
