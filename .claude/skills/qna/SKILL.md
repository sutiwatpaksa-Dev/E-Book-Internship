# Q&A: ตอบน้องฝึกงาน

Claude แค่**ร่าง**คำตอบให้ ผู้ใช้เป็นคนส่งเองบนเว็บ ห้าม login แทน ห้ามสร้างบัญชีบน production และห้ามเขียนลงตาราง threads เอง

## ขั้นตอน

1. **อ่านคำถามให้เข้าใจจริง** ว่าน้องติดตรงไหน ถามเรื่องเนื้อหา, ติดตั้งเครื่องมือ, OS (Windows?), หรือหาของไม่เจอ ถ้ามี `page_url` ให้เปิดบทนั้นดู
2. **หาในคู่มือก่อน:** `grep -rn "<คำสำคัญ>" content/docs` · ถ้ามีอยู่แล้วแต่น้องหาไม่เจอ แสดงว่าเป็นปัญหา UX ให้จดไว้ (ดู skill `ux-ui-design`)
3. **ร่างคำตอบ** ตามรูปแบบนี้
   - ทักแล้วตอบตรงคำถามในประโยคแรก
   - บอกขั้นตอนเป็นข้อๆ ใช้ภาษาง่าย ศัพท์น้อย บอกว่าทำแต่ละขั้นแล้วควรเห็นอะไร
   - อธิบาย "ทำไม" สั้นๆ เพราะคู่มือสอนให้เข้าใจ ไม่ใช่ให้ก๊อปวาง
   - ลิงก์ไปหัวข้อในคู่มือ (`/บท#anchor`)
   - มีคำสั่ง terminal ต้องให้ทั้ง Windows และ Mac
   - ปิดท้ายด้วยการชวนถามต่อถ้ายังติด
4. **ตัดสินว่าต้องแก้คู่มือไหม**
   - ถามซ้ำหลายคน / ไม่มีในคู่มือ / มีแต่หายาก → เสนออัปเดต บอกน้องได้ว่า "เดี๋ยวพี่เพิ่มในคู่มือ" แต่**ไม่สัญญาวันที่**
   - คำถามเฉพาะตัว → ตอบอย่างเดียว
5. **บันทึก** ไว้ที่ `Docs/Intern_Requests_<YYYY-MM-DD>/<ชื่อน้อง>-<เรื่อง>.md` (ไม่ขึ้น git) โดยมีหัวข้อ คำถาม → วิเคราะห์ → คำตอบที่ส่ง → งานต่อ
6. **บอกผู้ใช้**ว่าต้องทำอะไรต่อบนเว็บ เช่น ส่งคำตอบ, เปลี่ยนสถานะคำขอ (รับเรื่องแล้ว / กำลังทำ / ทำเสร็จแล้ว)

## ห้าม

- ใส่ PIN, ค่าลับ หรือข้อมูลของน้องคนอื่นในคำตอบ
- ตอบด้วยโค้ดทั้งก้อนให้ก๊อป ถ้าจำเป็นต้องมีโค้ด ให้ใส่คำอธิบายทีละส่วนด้วย
