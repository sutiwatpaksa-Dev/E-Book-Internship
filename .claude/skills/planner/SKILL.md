# Planner

ถ้าผู้ใช้บอกว่า "ร่างเป็นเอกสารก่อน" หรือ "ยังไม่ทำ" **ห้ามแก้ไฟล์ใน repo** ให้ทำเอกสารอย่างเดียว

## เขียนแผนที่ไหน

- แผนที่คนอื่นต้องอ่านหรือคอมเมนต์: ใช้ Claude Doc (แผนปรับโครงสร้างอยู่ที่ https://claude.ai/artifact/WtmY7SdQZxV1qAEqtyQHnk ถ้าเป็นเรื่องเดียวกันให้แก้ฉบับนี้ ไม่ต้องสร้างใหม่)
- แผนสั้นที่ใช้ในแชท: ตอบในแชทได้เลย
- บันทึกภายใน: `Docs/<หัวข้อ>_<วันที่>/` (ไม่ขึ้น git)

## โครงของแผน

1. **ปัญหาที่เจอ:** ใช้ตัวเลขและหลักฐานจริง (จำนวนบรรทัด, คำถามของน้อง, ผล audit)
2. **สาเหตุจริง:** แยกให้ออกว่าเป็นปัญหาเนื้อหา, UX หรือข้อมูล
3. **หลักการ:** ข้อสั้นๆ ที่ใช้ตัดสินเวลาลังเล และ UX-UI ต้องเป็นหนึ่งในหลักการเสมอ (ดู skill `ux-ui-design`)
4. **หน้าตาของผลลัพธ์:** ใช้แผนภาพหรือ mock-up และตัวอย่างหน้าจริง 1 หน้า
5. **ของที่ต้องสร้างหรือแก้:** ชี้ไฟล์จริง
6. **ข้อมูลที่ต้องใช้:** ระบุว่าอะไรไม่ต้องแตะ DB, อะไรแก้แค่โค้ด และอะไรต้องมี migration (ต้องขออนุมัติ)
7. **เฟส:** แต่ละเฟสต้องมีเกณฑ์ผ่าน (gate) ที่วัดได้ รวมถึงเกณฑ์ UX และทำเรื่องที่เจ็บที่สุดก่อน (เช่น คำสั่ง Windows, โค้ดที่พัง)
8. **เรื่องที่ผู้ใช้ต้องตัดสิน:** เป็น checkbox แต่ละข้อมีคำแนะนำของเราพร้อมเหตุผล

## ตรวจแผน ("เช็ค plan")

ตรวจแผนเทียบกับโค้ดจริงทุกข้อ อย่าเชื่อสิ่งที่แผนเขียนไว้ เช่น
- route, role และหน้าที่ login แล้วไปถึง: `src/lib/page-access.ts`, `src/components/login-form.tsx`
- ข้อมูลที่แผนต้องการมีคอลัมน์อยู่จริงไหม: `server/db/schema.ts`
- whitelist ของลิงก์ติ๊กผ่าน: `server/services/progress.service.ts` (`KNOWN`) และ `src/lib/admin-stats.ts` (`cardSummary` นับการ์ด 7 ขั้น)
- ชื่อเครื่องมือในแผนตรงกับในบทไหม (เช่น pgAdmin กับ Drizzle Studio)
- ลิงก์ "อ่านลึก" ชี้ไปบทที่ใช้ framework เดียวกันไหม (Express อยู่ในบท 05/08b–d, Hono อยู่ในบท 14/15)

รายงานเป็นรายการปัญหาที่มีเลขข้อ, หลักฐาน (`ไฟล์:บรรทัด`) และวิธีแก้ที่เสนอ แล้วถามผู้ใช้ว่าจะให้แก้ลงเอกสารไหม
