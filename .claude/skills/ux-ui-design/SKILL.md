# ออกแบบ UX-UI

ในเว็บนี้ UX-UI สำคัญเท่ากับเนื้อหา ตัวอย่างคือเคสของ poom: เนื้อหามีอยู่แล้ว แต่น้องหาไม่เจอ ปัญหาแบบนี้แก้ด้วย UX ไม่ใช่การเขียนเนื้อหาเพิ่ม

## ก่อนออกแบบ: อ่านของจริงก่อน

1. ดูว่าผู้ใช้เดินผ่านหน้าไหนบ้าง และตรวจในโค้ดทุกครั้ง อย่าเดา
   - หลัง login: `src/lib/home-path.ts` (ค่าคงที่ `HOME`) พาน้องไป `/today` และพาพี่เลี้ยงไป `/dev/admin` (`src/components/login-form.tsx` ใช้ค่านี้เมื่อไม่มี `?next=`)
   - กฎว่า path ไหนต้องเป็น role อะไร: `src/lib/page-access.ts`
   - หน้าบท: `src/components/doc-page.tsx` วาง `MarkDoneButton` ไว้บนสุด และ `AskQuestion` ไว้ท้ายหน้า
   - ข้อมูลที่เก็บได้: `server/db/schema.ts` (ตาราง users, threads, progress)
2. ถ้ามีแผนใหญ่อยู่แล้ว ให้อ่านก่อน: Claude Doc "แผนปรับโครงสร้างคู่มือฝึกงาน (ร่าง)" https://claude.ai/artifact/WtmY7SdQZxV1qAEqtyQHnk (อ่านด้วย Claude Docs `read` ห้ามใช้ web fetch)
3. ระบุให้ชัดว่ากำลังออกแบบให้ใคร (น้อง / พี่เลี้ยง) และงานที่เขาต้องทำให้สำเร็จคืออะไร เขียนเป็นประโยคเดียว เช่น "login แล้วกลับไปบทที่ค้างได้ใน 2 คลิก"

## วิธีทำ (วน 5 ขั้น)

1. **ดู:** ฟังหรือดูน้อง 2–3 คนใช้หน้าจริง จดว่าติดตรงไหน (หรืออ่านคำถามใน threads ที่ถามซ้ำๆ)
2. **ร่าง:** ทำ mock-up ก่อนเขียนโค้ดจริง (Claude Doc widget, Figma หรือหน้าต้นแบบบน `dev` ที่รันในเครื่อง)
3. **ทดสอบ:** ให้น้อง 3–5 คนลองทำงานจริง 5 งาน แต่ละงานต้องมีเกณฑ์ว่าผ่านคืออะไร
4. **รีวิวทุก PR** ด้วยเช็กลิสต์ด้านล่าง
5. **วัดผลหลังปล่อย:** ดูว่าคำถามแนว "หาไม่เจอ" ลดลงไหม และขั้นไหนถูกกด "ติดอยู่?" บ่อย แล้ววนกลับไปข้อ 1

## เช็กลิสต์รีวิว 6 ข้อ

| ข้อ | ถามว่า |
|---|---|
| 1. ขั้นต่อไปชัดไหม | เปิดหน้ามาแล้วรู้ภายใน 5 วินาทีไหมว่าต้องทำอะไรต่อ |
| 2. ภาษา | ใช้ไทยง่ายๆ ไหม ศัพท์เทคนิคมีคำอธิบายหรือลิงก์ไป glossary ไหม |
| 3. Windows / Mac | ทุกคำสั่งที่พิมพ์ใน terminal ใช้ได้ทั้ง Mac และ Windows (Git Bash เท่านั้น ไม่สอน PowerShell ตามกฎบท 0)ไหม (Windows คือปัญหาอันดับ 1 ใน content audit) |
| 4. ติดแล้วทำไง | ทุกขั้นมีทางออกไหม (ปุ่มถามพี่เลี้ยงที่แนบหน้านี้ไปให้, ลิงก์ "ติดอยู่?") |
| 5. มือถือ | จอกว้าง 375px ไม่ล้นจอ ตารางเลื่อนได้ ปุ่มสูงอย่างน้อย 44px |
| 6. เข้าถึงได้ | ตัวหนังสือกับพื้นหลัง contrast ไม่ต่ำกว่า 4.5:1, ใช้คีย์บอร์ดได้ครบ, รูปมี alt / svg มี `<title>` |

## กติกาหน้าตาของเว็บนี้

- ฟอนต์ IBM Plex Sans Thai, line-height 1.85 · สีและฟอนต์อยู่ที่ `src/app/global.css` และ `src/app/layout.tsx` ห้ามใส่สีลงไปตรงๆ ใน component
- component ระดับ 1 (ใช้ร่วมกันทั้งเว็บ) ได้แก่ `button`, `field`, `error-text`, `empty-state`, `status-badge`, `confirm-box`, `toaster` ให้ใช้ของที่มีอยู่ก่อนสร้างใหม่
- เว็บนี้เป็นตัวอย่างของ stack ที่คู่มือสอน: React + TS + Tailwind, component ไม่เรียก fetch เอง (เรียกผ่าน `src/api/`)
- ผลของการกดต้องเห็นได้เสมอ (toast, สถานะ, empty state) ห้ามปล่อยให้กดแล้วเงียบ
- การกระทำที่ย้อนกลับไม่ได้ต้องผ่าน `ConfirmBox`

## กฎจากจุดที่พลาดซ้ำ (ตรวจทุกครั้งก่อนส่ง)

จากรีวิวหน้า /feed 3 พ.ย. 2569 · ทุกข้อเคยหลุดขึ้น production มาแล้ว

| ข้อ | กฎ | ในเว็บนี้ |
|---|---|---|
| 1. ข้อความหลายบรรทัด | ข้อความที่คนพิมพ์เองต้องแสดงบรรทัดตามที่พิมพ์ ใช้ `MarkdownBody` (ให้ `<p>` เป็น `whitespace-pre-line` แล้ว) หรือใส่ `whitespace-pre-line` เอง ห้ามใส่ลง `<p>` เปล่าๆ | `src/components/markdown-body.tsx` |
| 2. ปุ่มหลักกับเนื้อหายาว | ปุ่ม action หลัก (รับทราบ ส่ง บันทึก) ต้องกดได้โดยไม่ต้องเลื่อนถึงท้ายเนื้อหายาว วางที่หัวการ์ด หรือพับเนื้อหาไว้ก่อน | `AckButton` ใน `post-feed.tsx` |
| 3. เนื้อหายาว | เกินราว 600 ตัวอักษรให้พับเป็นค่าเริ่มต้น เห็นหัวข้อ + ต้นเรื่อง แล้วมีปุ่ม "อ่านทั้งหมด" ที่บอกว่ายาวแค่ไหน | `LONG_BODY` ใน `post-feed.tsx` |
| 4. filter / tab | คิด empty state ทุกตัวเลือก ตัวกรองที่ได้ 0 รายการให้ซ่อน (ยกเว้น "ทั้งหมด" และตัวที่เลือกอยู่) ถ้าซ่อนไม่ได้ต้องมี empty state ที่บอกว่าทำอะไรต่อ | ตัวกรองใน `post-feed.tsx` |
| 5. ความสำคัญ | ห้ามใช้สีอย่างเดียวบอกความสำคัญ ต้องมีคำหรือไอคอนด้วย เรื่องร้ายแรงแยกเป็นกล่อง `> [!CAUTION]` (ป้าย "ต้องแก้ทันที") แต่ละข้อมีป้ายระดับ 🔴 ต้องแก้ทันที · 🟠 ควรแก้ · ⚪ เก็บกวาด | `src/lib/markdown.ts` (`ALERTS`), CSS `.md-alert` ใน `global.css` |
| 6. alt / label / ขนาดปุ่ม | รูปที่มีความหมายต้องมี alt · รูปตกแต่งข้างข้อความ (โลโก้คู่ชื่อเว็บ) ใช้ `alt=""` ถูกแล้ว · ปุ่มไอคอนต้องมี `aria-label` · เป้ากดสูงอย่างน้อย 44px (`min-h-11`) ถ้าเมนูยาวบนจอใหญ่จะแน่นเกิน ใช้ `pointer-coarse:min-h-11` | `sidebar-nav.tsx` |
| 7. ข้อความยาว | ห้ามตัดด้วย `overflow: hidden` / `truncate` โดยไม่มีทางอ่านเต็ม ให้ wrap (`break-words`) หรือมี `title` | |
| 8. ทดสอบจอ 375px | เปิดดูจริงที่ 1280 และ 375px ก่อนส่ง เช็กว่าไม่มีเลื่อนแนวนอน และกล่องสี/ป้ายออกมาตามที่ตั้งใจ (CSS ของ Fumadocs `.prose` ทับ class ของเราได้ ต้องเห็นของจริง) | ใช้ `playwright-core` + Chrome ในเครื่องแบบ headless ใน scratchpad พร้อม cookie `bt_session` ของบัญชี `zz.` ไม่ต้องย่อหน้าต่าง Chrome ของผู้ใช้ |

ผลตรวจอัตโนมัติต้องยืนยันก่อนรายงาน: element ที่ซ่อนอยู่ (เช่น เมนูที่พับไว้) ยังวัดขนาดได้ และ skip link ที่ซ่อนจนกด Tab ก็นับว่ามี

## ถ้าต้องเปลี่ยนข้อมูล

ถ้า UX ใหม่ต้องเก็บข้อมูลเพิ่ม (เช่น วันเริ่มฝึก หรือ log การกด "ติดอยู่?") ต้องเพิ่ม migration ซึ่ง**ต้องขออนุมัติผู้ใช้ก่อน** ถ้าเก็บในเบราว์เซอร์ได้ (เช่น เลือก OS) ให้เลือกทางนั้นก่อน · ลิงก์ที่ติ๊กผ่านต้องอยู่ใน `KNOWN` ของ `server/services/progress.service.ts` ไม่งั้นระบบไม่รับ
