## 📱 ใช้ได้ทุกขนาดจอ

- ลองที่ความกว้าง **375px** (มือถือ), **768px** (แท็บเล็ต), **1280px** (คอม) ต้องไม่มีอะไรล้นจนต้องเลื่อนซ้ายขวา
- ตารางในหน้าจัดการร้าน ถ้ากว้างเกินจอมือถือ ให้เลื่อนซ้ายขวาได้ **ในกรอบตาราง** ไม่ใช่ทั้งหน้า

## 🔎 ให้ Google หาเจอ และแชร์แล้วสวย

- แต่ละหน้ามี **ชื่อหน้า** (ที่ขึ้นบนแท็บเบราว์เซอร์) และ **คำอธิบายสั้น** ของตัวเอง ดึงมาจากตาราง `pages`
- แชร์ลิงก์ลง LINE/Facebook แล้วขึ้น **การ์ดมีรูป หัวข้อ คำอธิบาย** (ข้อมูลส่วนนี้เรียกว่า OG tags)
- รูปทุกรูปมีคำอธิบายรูป (`alt`) และแต่ละหน้ามีหัวข้อใหญ่สุด (`h1`) แค่ 1 อัน
- มีไฟล์ `robots.txt` (บอก Google ว่าหน้าไหนไม่ต้องเข้า) และ `sitemap.xml` (รายชื่อหน้าทั้งหมด) เขียนเองได้เลย มีแค่ 3 หน้า

> 🤓 **ข้อควรรู้:** เว็บ React แบบที่เราทำ เวลาเปิดครั้งแรกหน้าว่างก่อน แล้วโค้ดค่อยเติมเนื้อหาทีหลัง
> Google รอได้ แต่ระบบของ LINE/Facebook บางตัวไม่รอ เลยอาจไม่เห็นรูปและหัวข้อที่เราตั้งไว้
> ระดับงานนี้ยอมรับได้ แต่น้องต้อง **เขียนอธิบายใน README ได้ว่าเพราะอะไร และถ้าจะแก้ต้องทำยังไง**
> วิธีทำทั้งหมดอยู่ใน [บทที่ 13 ข้อ 6–7](../13-router-seo.md)

## 🔐 ความปลอดภัย

ทบทวนหลักการใน [บทที่ 10](../10-security.md) แล้วดูโค้ดตัวอย่างใน [บทที่ 14](../14-hono-api.md) กับ [บทที่ 15](../15-auth.md)

| ต้องทำ | แปลว่า | ดูที่ |
|---|---|---|
| hash รหัสผ่านด้วย `Bun.password.hash` (argon2) | เก็บรหัสผ่านแบบย้อนกลับไม่ได้ (ห้ามใช้การเข้ารหัสที่ถอดกลับได้) ถึงฐานข้อมูลหลุดก็ไม่มีใครเห็นรหัสจริง | [บทที่ 10 ข้อ 2](../10-security.md#_2-เก็บรหัสผ่านผู้ใช้-hash-ไม่ใช่-encrypt), [บทที่ 15 ข้อ 2](../15-auth.md) |
| บัตรผ่าน login (JWT) อยู่ใน cookie แบบ `httpOnly` และ `sameSite=lax` **ห้ามเก็บใน localStorage** | เก็บบัตรผ่านไว้ในที่ที่โค้ดแปลกปลอมอ่านไม่ได้ | [บทที่ 15 ข้อ 1](../15-auth.md) |
| ทุกที่อยู่ `/api/admin/...` ต้องผ่านด่านตรวจ login | ใครไม่ได้ login เรียกแล้วต้องได้ `401` | [บทที่ 15 ข้อ 3–4](../15-auth.md) |
| ฟอร์มติดต่อส่งได้ **5 ครั้ง ต่อ 10 นาที ต่อ 1 เครื่อง** | กันคนส่งข้อความขยะรัวๆ | [บทที่ 14 ข้อ 5](../14-hono-api.md), [บทที่ 10](../10-security.md#🔁-ลองรหัสผ่านรัวๆ-brute-force) |
| ถ้า server พัง (500) ห้ามส่งรายละเอียดข้างในโค้ดกลับไป | คนนอกจะได้ไม่รู้ว่าระบบข้างในเป็นยังไง | [บทที่ 14 ข้อ 4](../14-hono-api.md), [บทที่ 10](../10-security.md#📣-error-ที่บอกมากเกินไป) |

> ⚠️ **ทำไมห้ามเก็บบัตรผ่านใน localStorage?** ถ้าคนร้ายแอบใส่โค้ดลงหน้าเว็บเราได้แม้จุดเดียว โค้ดนั้นอ่าน localStorage ได้ทั้งหมด แต่อ่าน cookie แบบ `httpOnly` ไม่ได้

## ✅ ตรวจข้อมูลที่ส่งเข้ามา

- ข้อมูลทุกอย่างที่ส่งเข้า server ต้อง **ตรวจด้วย Zod ที่ server เสมอ** (ตรวจแค่ที่หน้าเว็บไม่นับ เพราะคนร้ายส่งตรงมาที่ server ได้)
- เบอร์โทร 9–10 หลัก, อีเมลถูกรูปแบบ, ข้อความไม่เกิน 1,000 ตัวอักษร

> 💡 เขียนกฎตรวจ (Zod) ไว้ที่ server ที่เดียว แล้วให้หน้าเว็บใช้ชนิดข้อมูลชุดเดียวกัน สองฝั่งจะไม่เพี้ยนกัน ([บทที่ 4 ข้อ 5](../04-typescript.md#_5-ข้อจํากัด-typescript-ไม่ได้ตรวจข้อมูลตอนรัน))
