## 📖 วิธีอ่านคู่มือนี้

1. **อ่านตามลำดับ** แต่ละบทต่อยอดจากบทก่อน
2. **พิมพ์คำสั่งเองทุกบรรทัด** อย่าก๊อปวาง มือจำได้ดีกว่าตา
3. **ดูผลลัพธ์ทุกครั้ง** คู่มือบอกไว้ว่า "ควรเห็นอะไร" ถ้าไม่เหมือน หยุดหาสาเหตุก่อน
4. **ลองพังมันดู** 💥 เปลี่ยนค่า ลบบรรทัด ใส่ข้อมูลผิด แล้วดูว่าเกิดอะไร คือวิธีเรียนที่เร็วที่สุด
5. **ทำ "เช็คความเข้าใจ" ท้ายบท** ตอบในใจก่อนแล้วค่อยกดดูเฉลย

**ทุกบทมีหน้าตาแบบเดียวกัน**

| ส่วน | คืออะไร |
|---|---|
| ⚡ **สรุป 30 วินาที** | อ่านก่อนเริ่ม จะได้รู้ว่ากำลังจะเจออะไร |
| 📖 **เรื่องเล่า** | สถานการณ์จริงที่ทำให้ต้องมีเครื่องมือนี้ |
| 💡 **เปรียบเทียบ** | อธิบายด้วยของในชีวิตประจำวัน |
| 🔧 **ลงมือ** | ทำตามทีละขั้น |
| ⚠️ **กับดัก** | จุดที่มือใหม่พลาดบ่อย |
| 🤓 **เกร็ด** | เรื่องสนุกที่ไม่ต้องจำ |
| 🧠 **เช็คความเข้าใจ** | คำถามสั้นๆ มีเฉลย |

## 📏 กติกาทีม (สั้นๆ)

- โค้ดทุกชิ้นเป็น **TypeScript** เปิด `"strict": true` ห้าม `any` ห้ามมีไฟล์ `.js` ใน `src/`
- ส่งแบบฝึกหัดผ่าน Git ตามรูปแบบใน [📤 การส่งแบบฝึกหัด](#📤-การส่งแบบฝึกหัด) และ Mini Project ตาม [การส่งงาน STARTER](./starter/submission.md)
- ใช้ AI หรือ Google ช่วยได้เต็มที่ แต่ **ต้องอธิบายโค้ดที่ส่งได้ทุกบรรทัด**
- ติดตรงไหนถามได้ตลอด ใช้เทมเพลตการถามใน [บทที่ 9](./09-debugging.md#_6-🙋-ถามคนอื่นยังไงให้ได้คําตอบเร็ว)
