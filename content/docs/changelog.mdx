## v2.0.0 · 21 ต.ค. 2569

- **เว็บคู่มือสร้างใหม่ด้วย React + TypeScript + Tailwind (Next.js + Fumadocs):** stack เดียวกับที่คู่มือสอน โค้ดของเว็บนี้จึงเป็นตัวอย่างระบบจริงให้เปิดดูได้ หน้าเว็บแบ่งตามหน้าที่ (components / hooks / api) และ API แบ่งเป็นชั้น routes → services → repositories ค้นหาภาษาไทยได้ดีขึ้น และหน้าที่ล็อกตรวจสิทธิ์ฝั่ง server ทุกครั้งก่อนส่งเนื้อหา
- **ระบบ login (username + PIN):** หน้า Mini Project STARTER และเอกสาร Requirement เปิดได้เฉพาะ role **Internship** และ **Dev** เนื้อหาบทเรียนทั่วไปยังอ่านได้ทุกคน การตรวจสิทธิ์อยู่ฝั่ง server ทั้งหมด (พิมพ์ URL เปิดตรงๆ ก็ต้องผ่าน) PIN เก็บแบบ hash, กรอกผิด 5 ครั้งล็อก 15 นาที, จำกัดจำนวนครั้งต่อ IP และข้อความตอน login ผิดเหมือนกันทุกกรณี
- **หน้าจัดการบัญชีสำหรับพี่เลี้ยง:** เพิ่มบัญชี ออก PIN ใหม่ ปลดล็อก ปิดบัญชี เปลี่ยน role และอัปโหลดไฟล์ Requirement ใหม่ได้เอง
- **ไฟล์ Requirement ย้ายมาอยู่หลัง login:** ลิงก์และแผง PDF ข้างคู่มือใช้ได้เหมือนเดิมหลัง login
- **หน้าแรกเป็น Roadmap Full-stack:** ตารางบทเรียนเปลี่ยนเป็นแผนที่เส้นทางแบบ roadmap.sh เรียงด่าน 1–7 จากบนลงล่าง แต่ละบทบอกว่าจบแล้วทำอะไรได้และใช้เวลาเท่าไร ติ๊กบทที่ผ่านแล้วพร้อมแถบความคืบหน้า (เก็บในเบราว์เซอร์ของตัวเอง) บทเสริมแสดงเป็นกรอบเส้นประ และบทที่ต้อง login มี 🔒
- **บทที่ 3 เขียนใหม่เป็น "Runtime & Package Manager" (บทนำร่องของโครงใหม่):** เริ่มจากปัญหาที่เครื่องมือแต่ละกลุ่มแก้ → กลุ่มนี้คืออะไร → ในกลุ่มมีใครบ้าง → เลือกยังไง แล้วค่อยลงมือกับตัวที่ทีมใช้ เครื่องมือเปลี่ยนชื่อได้ทุกปี แต่ความเข้าใจเรื่องกลุ่มยังใช้ได้ บทอื่นจะทยอยปรับตามโครงนี้
- **บทใหม่ 8b "จากแบบฐานข้อมูลสู่ Backend":** สะพานที่ขาดไประหว่างออกแบบตาราง (บท 6) ORM (บท 8) และ API (บท 5/14) สอนเป็นขั้นตอน: อ่านผังตาราง → เขียนรายการกฎและบอกว่าใครตรวจกฎข้อไหน → schema และ migration → ออกแบบ API จากสิ่งที่ผู้ใช้ทำ → แบ่งชั้น routes / services / repositories → แปลง error ของฐานข้อมูลเป็นคำตอบที่อ่านเข้าใจ → ทดสอบตามรายการกฎ ลงมือย้าย Laptop API จากบทที่ 5 มาใช้ PostgreSQL จริง ทดลองให้เห็นว่าฐานข้อมูลกันการเช่าซ้อนได้แม้คำขอมาพร้อมกัน และมีเช็คลิสต์ใช้กับงาน STARTER
- **บทที่ 3 ตรวจกับเว็บทางการ:** ตารางเครื่องมือทุกแถวลิงก์ไปหน้าเอกสารทางการที่ยืนยันข้อมูล และบอกวันที่ตรวจล่าสุด
- **โลโก้และไอคอนใหม่:** favicon, โลโก้บนแถบเมนู (มีแบบโหมดมืด), โลโก้เต็มบนหน้าแรก และภาพตัวอย่างตอนแชร์ลิงก์

## v1.6.1 · 21 ต.ค. 2569

แก้จุดที่ทำตามบทแล้วพังหรือผลไม่ตรง (ทดสอบกับเครื่องมือเวอร์ชันปัจจุบัน: TypeScript 7, PostgreSQL 17, Bun 1.4, React 19.3) ทุกจุดอธิบายเหตุผลด้วยว่าทำไมต้องแก้

- **บท 1:** `git switch <hash>` ใช้ไม่ได้ เปลี่ยนเป็น `git switch --detach` พร้อมอธิบายว่า `switch` มีไว้สลับ branch และแก้ข้อความ "no changes added to commit"
- **บท 3–4:** tsconfig เพิ่ม `"types": ["node"]` (TypeScript 7 ไม่โหลด `@types` เอง ทำให้ไม่รู้จัก `process` และบท 8 พังตาม) แก้ข้อความ error TS2739 / TS18047 ให้ตรงของจริง
- **บท 7:** ไม่สั่ง `docker compose down` ก่อนหัวข้อที่ยังใช้ container อธิบายความต่างของ `down` กับ `down -v` และเพิ่มหมายเหตุ `libpq` บน Homebrew
- **บท 8:** ย้ายขั้น seed ขึ้นมาก่อน transaction และ relation ทำตามลำดับแล้วผลตรงกับที่เขียนทุกขั้น แก้ import ที่ซ้ำ
- **บท 9:** แก้ค่า `Content-Length` และจำนวนขั้นการ debug ให้ตรงกับรูป (5 ขั้น)
- **บท 10:** least privilege เพิ่มสิทธิ์ใช้ sequence (ไม่งั้น INSERT ตาราง SERIAL พัง) เปลี่ยนชื่อ role เป็น `app_rw` ไม่ให้ชนกับบท 7 และ JWT ตัวอย่างใช้ `exp` ที่ยังไม่หมดอายุ
- **บท 11, 15, บทเสริม React:** เปลี่ยน `FormEvent` (เลิกใช้แล้วใน React 19.3) เป็น `SubmitEvent<HTMLFormElement>` และอธิบายว่า template ของ Vite ใช้ oxlint ไม่ใช่ ESLint
- **บท 13:** `<title>` เริ่มต้นของ Vite คือ `client` · **บท 14:** seed ใส่ `imageUrl` การ์ดจะไม่เป็นรูปเสีย
- **บท 21:** `alpine:3.22` (3.20 หมดอายุแล้ว) และแก้ลิงก์ไปหัวข้อ workflow ของทีมในบท 1 · **บท 23, STARTER:** LINE Notify ปิดบริการแล้ว ใช้ LINE Messaging API แทน
- **บทเสริมจัดโครงสร้างโปรเจกต์:** ตัวอย่าง Docker ที่โชว์ปัญหาตัวพิมพ์เล็ก/ใหญ่ทำให้พังได้จริงบน Mac และ path alias ต้องตั้งใน `tsconfig.app.json` กับ `vite.config.ts`
- ลิงก์ก่อนหน้า/ถัดไปของบท 16, บทเสริม และ STARTER ตรงกับลำดับใน sidebar
