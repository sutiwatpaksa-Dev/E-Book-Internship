## 1. เลือกเครื่องเช่า

ก่อนเลือก ดูว่าเราเช่าอะไรอยู่ก่อน

![เครื่องจริงในศูนย์ข้อมูลถูกแบ่งเป็นหลายห้อง VPS ด้วย hypervisor เราเช่าหนึ่งห้อง](/img/19-vps-slices.svg)
*VPS คือห้องหนึ่งที่ถูกแบ่งจากเครื่องจริงเครื่องใหญ่ แต่ละห้องแยกขาดจากกัน และเราดูแลความปลอดภัยของห้องเราเอง*


| ผู้ให้บริการ (ตัวอย่าง) | จุดเด่น |
|---|---|
| DigitalOcean, Vultr, Linode | หน้าจอใช้ง่าย คู่มือดี มีเครื่องที่สิงคโปร์ |
| AWS Lightsail | ราคาเหมาจ่ายรายเดือน อยู่ในระบบของ AWS |
| Hetzner | ราคาถูก (แต่อยู่ไกลไทยกว่า) |
| ผู้ให้บริการในไทย | ใกล้ลูกค้า ออกใบกำกับภาษีไทยได้ |

**ขนาดเครื่องสำหรับเว็บ STARTER**
| | อย่างน้อย | แนะนำ |
|---|---|---|
| หน่วยประมวลผล / หน่วยความจำ (CPU / RAM) | 1 CPU / 1 GB (ต้องเปิด swap ข้อ 3.6) | 1–2 CPU / 2 GB |
| พื้นที่เก็บข้อมูล | 25 GB | 50 GB |
| ระบบปฏิบัติการ | **Ubuntu 24.04 LTS** | (LTS = ได้อัปเดตความปลอดภัยนาน 5 ปี) |
| ที่ตั้งเครื่อง | **Singapore** | ใกล้ไทยที่สุด เว็บตอบเร็ว |

> **เคล็ดลับ:** เปิด **สำรองเครื่องอัตโนมัติ** ของผู้ให้บริการไว้ด้วย (จ่ายเพิ่มนิดหน่อย) คุ้มมากในวันที่พลาด

### ฝึกฟรี: ใช้ VM ในเครื่องตัวเองเป็น "เครื่องเช่า"

**VM (virtual machine)** = คอมพิวเตอร์จำลองที่รันอยู่ในเครื่องเรา มีระบบปฏิบัติการของตัวเอง เป็นหลักการเดียวกับที่ศูนย์ข้อมูลแบ่งเครื่องใหญ่เป็นห้อง VPS (ภาพข้างบน) แค่ย้ายมาแบ่งในโน้ตบุ๊คเรา จึงฝึกได้ครบทุกข้อของบทนี้ รวม ufw, Docker และ swap

| | ใช้อะไร | หมายเหตุ |
|---|---|---|
| ✅ แนะนำ | [**Multipass**](https://canonical.com/multipass/install) (ฟรี โดย Canonical ผู้ทำ Ubuntu) | Mac / Windows 10–11 (รวม Home) / Linux, สั่งด้วยคำสั่งเดียว ได้ Ubuntu เหมือนเครื่องเช่า |
| ทางเลือก Mac | UTM (ฟรี) | ต้องติดตั้ง Ubuntu Server เองผ่านหน้าจอ ช้ากว่าแต่เห็นทุกขั้น |
| เครื่องแรงน้อย | กล่อง Docker ที่เปิด SSH (ท้ายหัวข้อนี้) | ฝึกได้แค่ข้อ 2, 3.2, 3.3, 5 เพราะกล่อง Docker ไม่มี systemd และ firewall ของตัวเอง |

```bash
# บนเครื่องเรา (หลังติดตั้ง Multipass จากลิงก์ข้างบน)
multipass launch 24.04 --name bitcafe --cpus 2 --memory 2G --disk 20G   # สร้าง VM Ubuntu 24.04
multipass info bitcafe                       # ดูบรรทัด IPv4 เช่น 192.168.64.5 = "IP ของเครื่องเช่า" ของเรา
multipass exec bitcafe -- bash -c "echo '$(cat ~/.ssh/id_ed25519.pub)' >> ~/.ssh/authorized_keys"   # ติดแม่กุญแจ (ทำหลังข้อ 2)
ssh ubuntu@192.168.64.5                      # เข้าแบบเดียวกับเครื่องเช่าจริง
```
**ต่างจากเครื่องเช่าจริง 3 จุด**
- บัญชีเริ่มต้นชื่อ `ubuntu` (ไม่ใช่ `root`) ทุกคำสั่งในข้อ 3 ที่ไม่มี `sudo` ให้เติม `sudo` ข้างหน้า และข้อ 3.2 ใช้ `sudo rsync --archive --chown=deploy:deploy ~/.ssh /home/deploy`
- IP เป็นแบบภายใน (บทที่ 17 ข้อ 2) เข้าได้จากเครื่องเราเท่านั้น จึงไม่มีคนร้ายมาเคาะประตูแบบในเรื่องเล่า และขอใบรับรอง HTTPS จริงไม่ได้ (บทที่ 20 ข้อ 9 มีวิธีซ้อม)
- ไม่มี Cloud Firewall ของผู้ให้บริการ (ข้อ 3.4 ย่อหน้าท้าย) มีแค่ ufw ในเครื่อง

ฝึกเสร็จ `multipass stop bitcafe` (เก็บไว้ใช้บทที่ 20–23) หรือ `multipass delete bitcafe && multipass purge` (ลบทิ้ง)

<details>
<summary> เครื่องแรงน้อย: ฝึกเฉพาะเรื่อง SSH ด้วยกล่อง Docker (ทดสอบจริงตอนเขียนคู่มือ)</summary>

`sshlab/Dockerfile`
```dockerfile
FROM ubuntu:24.04
RUN apt-get update && apt-get install -y --no-install-recommends openssh-server sudo \
 && mkdir -p /run/sshd /root/.ssh && chmod 700 /root/.ssh
COPY id_ed25519.pub /root/.ssh/authorized_keys
CMD ["/usr/sbin/sshd", "-D", "-e"]
```
```bash
cd sshlab
cp ~/.ssh/id_ed25519.pub .                                  # แม่กุญแจจากข้อ 2
docker build -t fake-vps .
docker run -d --name fake-vps -p 127.0.0.1:2222:22 fake-vps
ssh -p 2222 root@127.0.0.1                                  # แทน ssh root@203.0.113.10
```
ต่างจากข้อ 3: ไม่มี `systemctl` จึงใช้ `kill -HUP 1` แทน `systemctl restart ssh` (สั่งให้ sshd ที่เป็นโปรแกรมหลักของกล่องอ่าน config ใหม่) และ `adduser`, `sshd -t`, ไฟล์ `00-hardening.conf` ใช้ได้เหมือนเดิม ผลจริงหลังทำข้อ 3.2–3.3 ในกล่องนี้:
```
$ ssh -p 2222 deploy@127.0.0.1 'whoami; id -nG'
deploy
deploy sudo users
$ ssh -p 2222 root@127.0.0.1
root@127.0.0.1: Permission denied (publickey).
```
เลิกใช้: `docker rm -f fake-vps && ssh-keygen -R "[127.0.0.1]:2222"`

## 2. กุญแจ SSH: ใช้แทนรหัสผ่าน

**SSH** = วิธีเปิดหน้าต่างพิมพ์คำสั่งของเครื่องอื่นจากเครื่องเรา โดยข้อมูลถูกเข้ารหัสระหว่างทาง
**SSH key** = กุญแจ 2 ชิ้นที่เป็นคู่กัน

```
 🔑 ลูกกุญแจ  (~/.ssh/id_ed25519)      อยู่ในเครื่องเรา ห้ามให้ใคร ห้ามขึ้น Git
 🔒 แม่กุญแจ  (~/.ssh/id_ed25519.pub)  เอาไปติดที่เครื่องเช่า ใครเห็นก็ไม่เป็นไร
```
> **นึกภาพ:** เอาแม่กุญแจไปคล้องประตูเครื่องเช่า ส่วนลูกกุญแจเราถือไว้ คนอื่นเห็นแม่กุญแจก็ไขไม่ได้

![ลำดับการเข้าเครื่องด้วย SSH key: เครื่องเช่าส่งโจทย์ เครื่องเราเซ็นด้วยลูกกุญแจ แล้วเครื่องเช่าตรวจด้วยแม่กุญแจ](/img/19-ssh-key-login.svg)
*ตอนเข้าเครื่อง เราไม่ได้ส่งรหัสผ่านหรือลูกกุญแจออกไป ส่งแค่ลายเซ็นที่พิสูจน์ว่าเราถือลูกกุญแจอยู่*

```bash
ssh-keygen -t ed25519 -C "bit@blicktech"      # กด Enter ตามค่าเริ่มต้น และตั้ง passphrase
cat ~/.ssh/id_ed25519.pub                       # ก๊อปข้อความนี้ไปใส่ตอนสร้าง VPS
```
ตอนสร้างเครื่องเช่า เลือกเข้าเครื่องด้วย **SSH key** แล้ววางข้อความแม่กุญแจลงไป → ได้ IP มา เช่น `203.0.113.10`

```bash
ssh root@203.0.113.10
```
ครั้งแรกจะถามว่า `Are you sure you want to continue connecting (yes/no)?` พิมพ์ `yes` (เครื่องเราจะจำ "ลายนิ้วมือ" ของเครื่องเช่าไว้ ถ้าวันหลังมีเครื่องปลอมมาสวมรอย จะเตือน)

## 3. ตั้งค่าเครื่องครั้งแรก

คำสั่งในข้อนี้พิมพ์ **บนเครื่องเช่า** (หลังเข้าด้วย `ssh root@...`)

![ลำดับห้าขั้นตอนตั้งค่าเครื่องเช่าครั้งแรก](/img/19-hardening-steps.svg)
*ภาพรวมของข้อ 3 ทำตามลำดับนี้ และสามขั้นที่ปรับการเข้าเครื่องต้องลองในหน้าต่างใหม่ทุกครั้ง*

> **พื้นฐาน Linux 5 บรรทัดที่ใช้ทั้งข้อนี้**
> - **`root`** = บัญชีสูงสุด ทำได้ทุกอย่างรวมถึงลบทั้งเครื่อง จึงไม่ใช้ทำงานทุกวัน
> - **user / group** = ทุกไฟล์มีเจ้าของ และสิทธิ์ให้ "กลุ่ม" ได้ เช่น คนในกลุ่ม `sudo` ขอสิทธิ์สูงสุดชั่วคราวได้ คนในกลุ่ม `docker` สั่ง Docker ได้
> - **`sudo <คำสั่ง>`** = "ขอทำคำสั่งนี้ด้วยสิทธิ์ root ครั้งเดียว" ถามรหัสผ่านของ **บัญชีเรา** (ไม่ใช่ของ root)
> - **`apt`** = ร้านแอปของ Ubuntu: `apt update` = โหลดรายการล่าสุด, `apt upgrade` = อัปเดตของที่มี, `apt install x` = ติดตั้ง
> - **สิทธิ์ไฟล์** `chmod 600` = เจ้าของอ่าน/เขียนได้คนเดียว, `chmod +x` = ให้ไฟล์นี้รันเป็นโปรแกรมได้ (บทที่ 21 จะเจอเรื่องนี้อีก)

### 3.1 อัปเดตเครื่อง + ตั้งเวลาไทย
```bash
apt update && apt upgrade -y
timedatectl set-timezone Asia/Bangkok
```

### 3.2 สร้างบัญชีของเรา (ไม่ใช้บัญชีสูงสุด root ทำงานทุกวัน)
```bash
adduser deploy                                  # ตั้งรหัสผ่าน (ใช้ตอน sudo)
usermod -aG sudo deploy                         # ให้ใช้ sudo ได้
rsync --archive --chown=deploy:deploy ~/.ssh /home/deploy   # ก๊อป public key ไปให้ deploy
```
**เปิดหน้าต่าง Terminal ใหม่ในเครื่องเรา** แล้วลองเข้า:
```bash
ssh deploy@203.0.113.10
sudo whoami                                     # ต้องได้ root
```
เข้าได้แล้วค่อยไปต่อ ยังไม่ต้องปิดหน้าต่างเดิม

### 3.3 ปิดการเข้าด้วยรหัสผ่าน และปิดบัญชี root
```bash
sudo tee /etc/ssh/sshd_config.d/00-hardening.conf > /dev/null <<'EOF'
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
EOF
sudo sshd -t && sudo systemctl restart ssh      # -t = ตรวจ config ก่อน ผิดจะไม่ restart
```
![ไฟล์ตั้งค่า SSH ถูกอ่านเรียงตามชื่อ ไฟล์ที่ขึ้นต้นด้วย 00- ชนะ](/img/19-config-order.svg)
*ค่าที่เจอก่อนชนะ ไฟล์ของเราจึงต้องขึ้นต้นด้วย 00- เพื่อให้ถูกอ่านก่อนไฟล์ของผู้ให้บริการ*

> **ทำไมชื่อไฟล์ขึ้นต้นด้วย `00-`?** โปรแกรม SSH อ่านไฟล์ตั้งค่าเรียงตามชื่อ และ **ค่าที่เจอก่อนชนะ** เครื่องเช่าบางเจ้ามีไฟล์ `50-cloud-init.conf` ที่เปิดให้เข้าด้วยรหัสผ่านไว้ ถ้าเราตั้งชื่อ `99-` ค่าของเราจะแพ้

**ลองในหน้าต่างใหม่อีกครั้ง:**
```bash
ssh deploy@203.0.113.10                         # ต้องเข้าได้
ssh root@203.0.113.10                           # ต้องถูกปฏิเสธ (Permission denied)
```

### 3.4 ยามหน้าตึก (firewall ชื่อ ufw)
```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH          # 22  ⚠️ ต้องมีบรรทัดนี้ก่อน enable ไม่งั้นหลุดทันที
sudo ufw allow 80/tcp           # HTTP
sudo ufw allow 443/tcp          # HTTPS
sudo ufw allow 443/udp          # HTTP/3
sudo ufw enable
sudo ufw status verbose
```
![ufw ปล่อยพอร์ต 22 80 443 ผ่าน และบล็อกพอร์ตอื่น เช่น 5432 และ 3000](/img/19-firewall-ports.svg)
*ยามหน้าตึก (ufw) ปิดทุกประตูไว้ก่อน แล้วเปิดเฉพาะ 22, 80, 443*

ที่หน้าเว็บของผู้ให้บริการก็มีที่ตั้ง firewall (มักชื่อ Cloud Firewall) ให้เปิดแค่ 22, 80, 443 เหมือนกัน เป็นยามชั้นที่สอง

### 3.5 ให้เครื่องอัปเดตความปลอดภัยเอง
```bash
sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure --priority=low unattended-upgrades    # เลือก Yes
```

### 3.6 Swap (จำเป็นถ้าหน่วยความจำ 1–2 GB)
ตอนสร้างกล่อง Docker บนเครื่องเช่า ใช้หน่วยความจำเยอะ ถ้าไม่พอโปรแกรมจะถูกปิดกลางทาง **swap** คือการยืมพื้นที่เก็บข้อมูลมาใช้เป็นหน่วยความจำสำรอง
```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h                                          # ต้องเห็นบรรทัด Swap: 2.0Gi
```

## 4. ติดตั้ง Docker

```bash
curl -fsSL https://get.docker.com -o get-docker.sh
less get-docker.sh              # 👀 เปิดอ่านคร่าวๆ ก่อนรัน script จากเน็ตเสมอ (กด q ออก)
sudo sh get-docker.sh
sudo usermod -aG docker deploy  # ให้ deploy ใช้ docker ได้โดยไม่ต้อง sudo
exit                            # ออกแล้ว ssh เข้าใหม่ให้สิทธิ์มีผล
```
```bash
ssh deploy@203.0.113.10
docker run --rm hello-world     # เห็น "Hello from Docker!" = พร้อม 🎉
docker compose version
```

> **กับดักใหญ่: Docker เปิดประตูข้ามยาม (ufw)** ถ้าในไฟล์ compose เขียน `ports:` ไว้ (เช่น `"5432:5432"`) ประตูนั้นจะเปิดให้คนทั้งโลก **แม้ ufw จะไม่ได้อนุญาต** เพราะ Docker แก้กฎของยามเอง
![Docker เขียนกฎเปิดพอร์ตเองข้าม ufw เมื่อมี ports: ใน compose](/img/19-docker-ufw-bypass.svg)
*ufw บอกว่าไม่อนุญาต 5432 แต่กฎที่ Docker เขียนเองมาก่อน ทำให้คนนอกต่อเข้าฐานข้อมูลได้*

> ✅ บนระบบจริง: **ห้ามเขียน `ports:` ให้ฐานข้อมูลและ server** เปิดเฉพาะ Caddy (80/443) แล้วให้กล่องอื่นคุยกันในเครือข่ายภายใน (บทที่ 20)
> ถ้าจำเป็นต้องเปิดดูชั่วคราว ให้เปิดเฉพาะในเครื่อง: `"127.0.0.1:5432:5432"` แล้วต่อผ่านอุโมงค์ SSH (ข้อ 6)

## 5. พิมพ์สั้นลง: `~/.ssh/config`

ในเครื่อง **เรา** (ไม่ใช่เครื่องเช่า) สร้างหรือแก้ไฟล์ `~/.ssh/config`
```
Host bitcafe
  HostName 203.0.113.10
  User deploy
  IdentityFile ~/.ssh/id_ed25519
```
ต่อไปพิมพ์แค่ `ssh bitcafe` ก็เข้าได้

## 6. คำสั่งที่ใช้ดูแลเครื่องเช่า

| ทำอะไร | คำสั่ง |
|---|---|
| ดูพื้นที่เหลือ | `df -h` |
| ดูหน่วยความจำ | `free -h` |
| ดูว่าโปรแกรมไหนกินเครื่อง | `htop` (ติดตั้งด้วย `sudo apt install htop`) |
| ดูขนาดโฟลเดอร์ | `du -sh *` |
| ดูบันทึกการเข้าเครื่อง | `sudo journalctl -u ssh --since "1 hour ago"` |
| ดูว่าใครพยายามเดารหัส | `sudo journalctl -u ssh \| grep -i "invalid user" \| tail` |
| ดูประตูที่เปิดอยู่ | `sudo ss -tlnp` |
| รีสตาร์ทเครื่อง | `sudo reboot` |
| ส่งไฟล์ขึ้นเครื่องเช่า | `scp ./file.txt bitcafe:~/` |
| เปิดดูฐานข้อมูลบนเครื่องเช่าจากเครื่องเรา (อุโมงค์ SSH) | `ssh -L 5433:127.0.0.1:5432 bitcafe` แล้วเปิด pgAdmin ที่ `localhost:5433` |

![pgAdmin บนเครื่องเราต่อ localhost:5433 ผ่านอุโมงค์ SSH ไปยัง 127.0.0.1:5432 บนเครื่องเช่า](/img/19-ssh-tunnel.svg)
*อุโมงค์ SSH (แถวสุดท้ายของตาราง) ให้เราดูฐานข้อมูลได้โดยไม่ต้องเปิดประตู 5432 ให้ใคร*

> **เคล็ดลับ:** อยากกันคนเดารหัสเพิ่มอีกชั้น ติดตั้ง **fail2ban** (`sudo apt install fail2ban`) จะบล็อกเครื่องที่ใส่ผิดรัวๆ แต่ถ้าปิดการเข้าด้วยรหัสผ่านแล้ว ความเสี่ยงหลักก็หมดไปแล้ว

## 7. ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| `Permission denied (publickey).` | เครื่องเช่าไม่มีแม่กุญแจของเรา, ใช้ชื่อบัญชีผิด (`root` ที่ปิดไปแล้ว / VM ใช้ `ubuntu`), หรือใช้ลูกกุญแจผิดดอก | ตรวจชื่อบัญชี, `ssh -v ...` ดูว่าลองกุญแจดอกไหน, ตรวจ `~/.ssh/authorized_keys` บนเครื่องเช่า |
| `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!` | ลายนิ้วมือของเครื่องที่ IP นี้ไม่ตรงกับที่เคยจำไว้ เกิดได้ทั้ง **สร้างเครื่องใหม่ที่ได้ IP เดิม** หรือ **มีเครื่องปลอมดักกลางทาง** | ถ้าแน่ใจว่าเราสร้างเครื่องใหม่เอง: `ssh-keygen -R 203.0.113.10` แล้วเข้าใหม่ ถ้าไม่ได้ทำอะไรกับเครื่องเลย **หยุด แล้วบอกพี่เลี้ยง** |
| `Connection timed out` | Cloud Firewall ของผู้ให้บริการไม่ได้เปิด 22, IP ผิด, หรือเครื่องปิดอยู่ | ดูหน้าตั้งค่า firewall ของผู้ให้บริการ (บทที่ 17 ข้อ 1: timed out = ยามบล็อก) |
| `Connection refused` | ถึงเครื่องแล้ว แต่ sshd ไม่ได้รอรับ (ยังบูตไม่เสร็จ / config พังแล้ว restart) | รอ 1 นาที ถ้ายังไม่ได้ เข้าทาง web console |
| ล็อกตัวเองออก (ปิดหน้าต่างเดิมไปแล้ว เข้าใหม่ไม่ได้) | config SSH หรือ ufw ผิด | เข้าทาง **Web Console / Recovery Console** ในหน้าเว็บผู้ให้บริการ (เหมือนเสียบจอกับคีย์บอร์ดเข้าเครื่องตรงๆ) แก้ไฟล์แล้ว restart ใหม่ บน Multipass ใช้ `multipass shell bitcafe` |
| ถามรหัสผ่านตอน `sudo` แล้วจำไม่ได้ | ตั้งตอน `adduser` | เข้า root ทาง web console แล้ว `passwd deploy` |

ข้อความ `REMOTE HOST IDENTIFICATION HAS CHANGED` ของจริงหน้าตาแบบนี้ (ผลจริงจากการลบกล่องฝึกแล้วสร้างใหม่ ทำให้ได้ลายนิ้วมือใหม่ที่ IP และประตูเดิม ตัดบรรทัดกลางออก และเปลี่ยนที่อยู่ไฟล์เป็นแบบทั่วไป)
```
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
@    WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!     @
@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@@
IT IS POSSIBLE THAT SOMEONE IS DOING SOMETHING NASTY!
...
Offending ED25519 key in /Users/<ชื่อเรา>/.ssh/known_hosts:1
Host key verification failed.
```
 SSH ไม่ยอมให้เข้าเลย ไม่ใช่แค่เตือน เพราะถ้ายอมให้กด "ไปต่อ" ได้ง่ายๆ ทุกคนจะกดจนชิน แล้ววันที่มีเครื่องปลอมจริงก็จะกดเหมือนเดิม

> **เคล็ดลับ:** ตั้ง passphrase ให้กุญแจแล้ว (ข้อ 2) ไม่อยากพิมพ์ทุกครั้ง ให้ใช้ **ssh-agent** จำไว้ระหว่างเปิดเครื่อง: Mac ใช้ `ssh-add --apple-use-keychain ~/.ssh/id_ed25519` / Git Bash บน Windows ใช้ `eval "$(ssh-agent -s)"` แล้ว `ssh-add` (ต้องทำใหม่ทุกครั้งที่เปิด Git Bash)

## เช็คความเข้าใจ

<details>
<summary>1. ทำไมกุญแจ SSH ปลอดภัยกว่ารหัสผ่าน?</summary>

ลูกกุญแจยาวและสุ่มมากจนเดาไม่ได้ และไม่เคยถูกส่งออกไปทางเน็ต ส่วนรหัสผ่านถูกเดาได้ด้วยการลองไปเรื่อยๆ ซึ่งโปรแกรมของคนร้ายทำอยู่ตลอดเวลา

</details>

<details>
<summary>2. ทำไมต้องลองเข้าในหน้าต่างใหม่ ก่อนปิดหน้าต่างเดิม?</summary>

ถ้าตั้งค่าผิด หน้าต่างเดิมที่ยังต่ออยู่คือทางเดียวที่จะแก้กลับได้ ถ้าปิดไปแล้วอาจต้องใช้ทางเข้าฉุกเฉินของผู้ให้บริการ หรือต้องสร้างเครื่องใหม่

</details>

<details>
<summary>3. ufw ไม่ได้อนุญาต 5432 แต่ทำไมคนนอกยังต่อฐานข้อมูลได้?</summary>

ไฟล์ compose มี `ports: "5432:5432"` และ Docker เขียนกฎเปิดประตูเองข้ามยาม แก้โดยลบ `ports:` ของฐานข้อมูลออก หรือเปิดเฉพาะ `127.0.0.1`

</details>

## แบบฝึกหัด

เช่าเครื่อง หรือใช้ VM ฟรีตามข้อ 1 ส่วน "ฝึกฟรี" (ถ้ายังไม่มีเครื่องจากพี่เลี้ยง / บริษัท) ทำข้อ 2–5 ให้ครบ แล้วส่งผลของคำสั่ง `sudo ufw status verbose`, `ssh root@<IP>` (ต้องเข้าไม่ได้) และ `docker run --rm hello-world`
