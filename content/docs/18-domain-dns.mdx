> - **Domain** = ชื่อเว็บที่เช่าเป็นรายปี / **DNS** = สมุดโทรศัพท์ที่บอกว่าชื่อเว็บนี้อยู่ที่ IP ไหน
> - บรรทัดในสมุดที่ใช้บ่อย: **A** (ชื่อ → IP), **CNAME** (ชื่อ → ชื่ออื่น), **TXT** (ข้อความยืนยันตัวตน), **MX** (อีเมล)
> - แก้สมุดแล้วไม่เห็นผลทันที เพราะเครื่องอื่น **จำค่าเก่าไว้ชั่วคราว** รอได้ตั้งแต่ไม่กี่นาทีถึงหลายชั่วโมง
> - งานลูกค้า: ชื่อเว็บ **ต้องจดในชื่อลูกค้า** ไม่ใช่ชื่อเรา

## 1. ชื่อเว็บทำงานยังไง

![ส่วนประกอบของชื่อเว็บ shop.example.com: ชื่อย่อย ชื่อที่เช่า และนามสกุล](/img/18-domain-anatomy.svg)
*ชื่อเว็บเต็มประกอบด้วย ชื่อย่อย + ชื่อที่เราเช่า + นามสกุล*

**ใครเกี่ยวข้องบ้าง**
| ใคร | ทำอะไร | 💡 นึกภาพ |
|---|---|---|
| **ร้านขายชื่อเว็บ (registrar)** | ที่เราเช่าชื่อเว็บ จ่ายรายปี | สำนักงานที่ดิน ออกโฉนด |
| **ผู้ดูแลสมุดโทรศัพท์ (DNS)** | เก็บว่าชื่อไหนไปที่ IP ไหน | สมุดโทรศัพท์ |
| **เครื่องที่รันเว็บ** | เครื่องเช่า หรือบริการอย่าง Vercel | ตัวบ้าน |

3 อย่างนี้ **อยู่คนละเจ้าได้** เช่น เช่าชื่อที่ร้าน A, ใช้สมุดโทรศัพท์ของ Cloudflare, เว็บอยู่บนเครื่องเช่าของเจ้า C

![ร้านขายชื่อเว็บ ผู้ดูแลสมุดโทรศัพท์ DNS และเครื่องที่รันเว็บ เชื่อมกันด้วย nameserver และบรรทัด A](/img/18-three-parties.svg)
*3 บทบาทอยู่คนละเจ้าได้ เชื่อมกันด้วย nameserver (NS) และบรรทัด A*

**เลือกนามสกุลชื่อเว็บ**
| นามสกุล | เหมาะกับ | ข้อควรรู้ |
|---|---|---|
| `.com` | ทั่วไป คนจำง่ายสุด | ชื่อดีๆ มักมีคนจดไปแล้ว |
| `.co.th` | บริษัทในไทย | ต้องใช้หนังสือรับรองบริษัท |
| `.in.th` / `.th` | คนหรือองค์กรในไทย | เงื่อนไขต่างกันตามประเภท ดูที่ร้านที่ขายชื่อ `.th` |
| `.shop`, `.cafe`, `.studio` | ร้านเฉพาะทาง | ปีแรกมักถูก **ปีถัดไปแพงขึ้นมาก** ดูราคาต่ออายุก่อนจด |

## 2. บรรทัดในสมุดโทรศัพท์ (DNS record) ที่ต้องรู้

| ชนิด | ชี้จาก → ไป | ตัวอย่าง | ใช้เมื่อ |
|---|---|---|---|
| **A** | ชื่อ → IP | `example.com → 203.0.113.10` | ชี้ไปที่เครื่องเช่า |
| **AAAA** | ชื่อ → IP แบบใหม่ (IPv6) | `example.com → 2001:db8::10` | เครื่องเช่ามี IPv6 |
| **CNAME** | ชื่อ → **ชื่ออื่น** | `www.example.com → example.com` | ชี้ไปบริการที่ให้ชื่อมา เช่น Vercel |
| **TXT** | ชื่อ → ข้อความ | `"google-site-verification=..."` | ยืนยันว่าเราเป็นเจ้าของชื่อเว็บ, ตั้งค่าอีเมล |
| **MX** | ชื่อ → เครื่องรับอีเมล | `example.com → mx.mailprovider.com` | อีเมล `@example.com` |
| **CAA** | บอกว่าใครออกใบรับรองให้เว็บนี้ได้ | `0 issue "letsencrypt.org"` | ความปลอดภัยเพิ่ม (ไม่บังคับ) |
| **NS** | บอกว่าใครดูแลสมุดของชื่อนี้ | `ns1.cloudflare.com` | ตั้งที่ร้านขายชื่อ ตอนย้ายสมุดไปที่อื่น |

![www ชี้ด้วย CNAME ไปที่ example.com แล้ว A ชี้ไปที่ IP ของเครื่องเช่า พร้อมบรรทัด MX TXT NS](/img/18-records-map.svg)
*บรรทัด DNS ต่อกันเป็นทอด: www → example.com → IP*

**TTL** = จำนวนวินาทีที่เครื่องอื่น **จำคำตอบไว้** ก่อนจะมาถามใหม่
- TTL 3600 = แก้แล้ว บางคนอาจยังเห็นค่าเก่าได้นานถึง 1 ชั่วโมง
- 💡 **ก่อนย้ายเครื่อง** ลด TTL เหลือ 300 ไว้ล่วงหน้า 1 วัน ย้ายเสร็จค่อยปรับกลับ

![เส้นเวลาหลังแก้บรรทัด A: คนที่จำค่าเก่าไว้ยังเห็นเว็บเก่าจนกว่า TTL หมด](/img/18-ttl-timeline.svg)
*TTL คือเวลาที่เครื่องอื่นจำคำตอบไว้ แก้แล้วจึงมีช่วงที่คนเห็นไม่ตรงกัน*

> ⚠️ **กฎของ CNAME:** ชื่อที่เป็น CNAME ห้ามมีบรรทัดชนิดอื่นอยู่ด้วย และชื่อหลักเปล่าๆ (`example.com`) ใช้ CNAME ตามมาตรฐานไม่ได้ จึงมักใช้ A ที่ชื่อหลัก และ CNAME ที่ `www`

## 3. 🔧 ลงมือ: จดชื่อเว็บ + ใช้สมุดโทรศัพท์ของ Cloudflare

**ทำไมใช้ Cloudflare:** ฟรี, แก้แล้วมีผลเร็ว, หน้าจอใช้ง่าย, เปิดใช้ตัวกันโจมตีได้ภายหลัง

![5 ขั้นตอนย้ายสมุดโทรศัพท์ไป Cloudflare](/img/18-cloudflare-setup.svg)
*ภาพรวม 5 ขั้นที่จะทำในหัวข้อนี้*

1. **จดชื่อเว็บ** ที่ร้านที่บริษัทใช้ (หรือ Cloudflare Registrar)
   - ✅ เปิด **ต่ออายุอัตโนมัติ** + ใส่อีเมลที่ **ลูกค้าหรือบริษัทเป็นเจ้าของ** (ไม่ใช่อีเมลส่วนตัวของ dev)
   - ✅ เปิด **ยืนยันตัวตน 2 ชั้น (2FA)** ที่บัญชีร้านขายชื่อ
2. **เพิ่มชื่อเว็บใน Cloudflare:** dash.cloudflare.com → Add a domain → เลือกแผน Free
3. Cloudflare จะให้ **ชื่อผู้ดูแลสมุด 2 ชื่อ** (nameserver เช่น `xxx.ns.cloudflare.com`) → เอาไปใส่ในหน้าตั้งค่าชื่อเว็บที่ร้านขายชื่อ แทนของเดิม
4. รอให้ Cloudflare ขึ้นสถานะ **Active** (ไม่กี่นาทีถึงไม่กี่ชั่วโมง บางครั้งนานถึง 1–2 วัน เพราะค่า NS ของโดเมนระดับบนมี TTL ยาว ถ้ายังไม่ Active ให้รอ ไม่ต้องแก้ซ้ำ)
5. **เพิ่มบรรทัดชี้ไปเครื่องเช่า** (IP จากบทที่ 19)

| Type | Name | Content | Proxy status | TTL |
|---|---|---|---|---|
| A | `@` (= ชื่อหลัก) | `203.0.113.10` | **DNS only** (เมฆสีเทา) | Auto |
| CNAME | `www` | `example.com` | **DNS only** | Auto |

> ⚠️ **ใช้เมฆสีเทา (DNS only)** เพื่อให้ Caddy ขอใบรับรอง HTTPS ได้ตรงๆ และเห็น IP จริงของลูกค้า ระดับฝึกงานให้คงเมฆสีเทาไว้ตลอด

**ถ้าวันหนึ่งจะเปิดเมฆสีส้ม (ซ่อน IP จริง + กันโจมตี) ต้องเข้าใจก่อนว่าอะไรเปลี่ยน**

server รู้ได้แน่นอนแค่ว่า "ใครต่อเข้ามาหาเราโดยตรง" (ด่านสุดท้าย) ส่วน header อย่าง `X-Forwarded-For` ใครจะพิมพ์อะไรมาก็ได้ จึงเชื่อได้เฉพาะเมื่อด่านสุดท้ายเป็นคนที่เราไว้ใจ
- เมฆเทา: ด่านสุดท้ายของ Caddy = เครื่องลูกค้า → Caddy รู้ IP จริง
- เมฆส้ม: ด่านสุดท้ายของ Caddy = **เครื่องของ Cloudflare** → ถ้าไม่ตั้งอะไรเลย ตัวจำกัดจำนวนครั้ง (บทที่ 14) จะเห็นลูกค้าทุกคนเป็น IP ของ Cloudflare ไม่กี่ตัว คนร้ายส่งรัวๆ แล้ว **ลูกค้าจริงส่งฟอร์มไม่ได้ และเจ้าของร้านถูกล็อก login**

ก่อนเปิดเมฆส้ม ต้องทำครบทั้ง 3 ข้อ
1. Cloudflare → SSL/TLS ตั้งเป็น **Full (strict)** (ไม่งั้นเว็บจะวนพาไปพากลับไม่จบ)
2. บอก Caddy ว่า "เชื่อ header จากเครื่องของ Cloudflare เท่านั้น" แล้วส่ง IP จริงต่อให้ API โดยเพิ่มบนสุดของ `deploy/Caddyfile` (บทที่ 20) ช่วง IP เอามาจาก [cloudflare.com/ips](https://www.cloudflare.com/ips/) (เปลี่ยนได้ ต้องคอยเช็ค)
   ```
   {
   	servers {
   		trusted_proxies static 173.245.48.0/20 103.21.244.0/22 103.22.200.0/22 103.31.4.0/22 141.101.64.0/18 108.162.192.0/18 190.93.240.0/20 188.114.96.0/20 197.234.240.0/22 198.41.128.0/17 162.158.0.0/15 104.16.0.0/13 104.24.0.0/14 172.64.0.0/13 131.0.72.0/22 2400:cb00::/32 2606:4700::/32 2803:f800::/32 2405:b500::/32 2405:8100::/32 2a06:98c0::/29 2c0f:f248::/32
   		client_ip_headers CF-Connecting-IP
   	}
   }
   ```
   และในบล็อก `handle /api/*` เปลี่ยนเป็น
   ```
   reverse_proxy server:3000 {
   	header_up X-Forwarded-For {client_ip}
   }
   ```
   `{client_ip}` = ถ้าคนที่ต่อเข้ามาเป็น Cloudflare ใช้ค่าจาก `CF-Connecting-IP` ถ้าไม่ใช่ (มีคนยิงตรงมาที่ IP เครื่อง) ใช้ IP ที่ต่อเข้ามาจริง คนนอกจึงปลอม IP ไม่ได้ทั้งสองทาง ส่วน API ยังตั้ง `TRUST_PROXY=true` เหมือนเดิม
3. **ทดสอบซ้ำ** แบบเดียวกับบทที่ 22 ข้อ 4: ส่ง 6 ครั้งโดยปลอม `X-Forwarded-For` ไม่ซ้ำกัน ครั้งที่ 6 ต้องได้ `429` และลองจาก 2 เครือข่าย (Wi-Fi กับเน็ตมือถือ) ต้องนับแยกกัน

> 💡 สิ่งที่ควรติดตัวไป: ทุกครั้งที่มี "คนกลาง" เพิ่มเข้ามาในทาง (Cloudflare, load balancer, Vercel) ให้ถามว่า **ตอนนี้ด่านสุดท้ายคือใคร และเราเชื่อ header จากใคร** เพราะความปลอดภัยของตัวจำกัดจำนวนครั้งขึ้นกับคำตอบนี้

![เปรียบเทียบเมฆสีเทา (ต่อตรงที่ IP จริง) กับเมฆสีส้ม (ผ่าน Cloudflare ก่อน)](/img/18-cloudflare-proxy.svg)
*เมฆเทา = ต่อตรง / เมฆส้ม = ผ่านด่านของ Cloudflare*

**ทำชื่อย่อยหลายชื่อ** (เช่น `demo` ไว้ให้ลูกค้าดูระหว่างทำ) เพิ่มบรรทัด A ชื่อ `demo` → IP เดียวกัน แล้วให้ Caddy แยกตามชื่อ (บทที่ 20)

## 4. 🔧 ตรวจว่าชื่อเว็บชี้ถูก

เวลาเบราว์เซอร์ถามหา IP ของชื่อเว็บ คำถามเดินทางผ่านหลายด่านตามภาพ (ผลจริงของ `dig +trace www.wikipedia.org`) และ **ทุกด่านจำคำตอบไว้ตาม TTL** นี่คือที่มาของ "ค่าเก่าค้าง"

![ลำดับการถาม DNS: เครื่องเรา resolver root TLD authoritative แล้วส่งคำตอบกลับและจำไว้](/img/18-dns-lookup.svg)
*resolver ถาม root → TLD → authoritative ตามลำดับ แล้วจำคำตอบไว้ตาม TTL*

```bash
dig +short example.com            # ควรได้ 203.0.113.10
dig +short www.example.com        # ควรได้ example.com. แล้วตามด้วย IP
dig NS example.com +short         # ควรเห็น nameserver ของ Cloudflare
dig @1.1.1.1 +short example.com   # ถาม DNS ของ Cloudflare ตรงๆ (ข้าม cache ในเครื่อง)
dig @8.8.8.8 +short example.com   # ถาม DNS ของ Google
```
ถ้าถาม `@1.1.1.1` แล้วได้ค่าใหม่ แต่เครื่องเรายังได้ค่าเก่า = เครื่องเรายังจำค่าเก่าอยู่ รอ TTL หมด หรือสั่งล้างความจำ:
```bash
sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder   # Mac
ipconfig /flushdns                                              # Windows
```

## 5. 📧 อีเมลกับชื่อเว็บ (รู้ไว้ก่อน)

ลูกค้ามักอยากได้อีเมล `contact@example.com` ใช้บริการอีเมล (Google Workspace, Zoho, Microsoft 365) แล้วเพิ่มบรรทัด **MX + TXT** ตามที่เขาบอก
ถ้าระบบเราส่งอีเมลแจ้งเตือนเอง (งานเสริมของ STARTER) ต้องตั้งบรรทัด TXT สำหรับยืนยันผู้ส่งเพิ่ม (ชื่อ SPF / DKIM / DMARC) ไม่งั้นอีเมลเข้าถังขยะ

> ⚠️ ก่อนย้ายสมุดไป Cloudflare ดูก่อนว่าชื่อเว็บเดิมมีบรรทัด **MX** ไหม ถ้ามีต้องก๊อปไปด้วย ไม่งั้นอีเมลของลูกค้าหยุดทำงานทันที (Cloudflare จะพยายามก๊อปให้ แต่ต้องตรวจเองทุกครั้ง)

<summary>1. ร้านขายชื่อเว็บ กับ ผู้ดูแลสมุดโทรศัพท์ ต่างกันยังไง?</summary>

ร้านขายชื่อ = ที่เช่าชื่อและจ่ายเงินรายปี / ผู้ดูแลสมุด = ที่เก็บว่าชื่อไหนไปที่ไหน เป็นเจ้าเดียวกันหรือคนละเจ้าก็ได้ เชื่อมกันด้วยการใส่ชื่อผู้ดูแลสมุด (nameserver) ที่ร้านขายชื่อ

</details>

<details>
<summary>2. ชี้ `example.com` ไปเครื่องเช่าใช้บรรทัดชนิดไหน? แล้ว `www` ล่ะ?</summary>

ชื่อหลักใช้ A ไปที่ IP ของเครื่องเช่า / `www` ใช้ CNAME ไปที่ `example.com` (หรือใช้ A ไป IP เดียวกันก็ได้)

</details>

<details>
<summary>3. แก้บรรทัด A แล้วเพื่อนเห็นเว็บใหม่ แต่เราเห็นเว็บเก่า เพราะอะไร?</summary>

เครื่องเราหรือเน็ตบ้านเรายังจำค่าเก่าไว้ตาม TTL ตรวจด้วย `dig @1.1.1.1` แล้วรอ หรือสั่งล้างความจำ

</details>

<details>
<summary>4. ทำไมชื่อเว็บต้องจดในชื่อลูกค้า?</summary>

ชื่อเว็บคือทรัพย์สินของร้านลูกค้า ถ้าอยู่ในบัญชี dev แล้ว dev ลาออก ติดต่อไม่ได้ หรือลืมต่ออายุ ลูกค้าเสียทั้งเว็บและอีเมล และชื่ออาจถูกคนอื่นจดไป

</details>

## ✏️ แบบฝึกหัด

ใช้ `dig` ดูบรรทัด A, AAAA, MX, NS, TXT ของเว็บบริษัทใหญ่ 2 แห่ง (เช่น `dig example.com TXT +short`) จดว่าใช้สมุดของใคร อีเมลใช้บริการอะไร แล้ววาดผังว่าโปรเจกต์ STARTER ของน้อง จะจดชื่อที่ไหน / ใช้สมุดที่ไหน / เว็บอยู่ที่ไหน

## ✅ ผ่านด่าน

- [ ] อธิบายส่วนต่างๆ ของชื่อเว็บ และหน้าที่ของร้านขายชื่อ / สมุดโทรศัพท์ / เครื่องที่รันเว็บได้
- [ ] รู้ว่าจะใช้ A, CNAME, TXT, MX เมื่อไหร่ และเข้าใจ TTL
- [ ] ย้ายสมุดไป Cloudflare และเพิ่มบรรทัดชี้ไปเครื่องเช่าได้
- [ ] ตรวจด้วย `dig` และแยกออกว่าเป็นแค่เครื่องจำค่าเก่าได้
- [ ] รู้รายการเช็คเรื่องชื่อเว็บของงานลูกค้า
