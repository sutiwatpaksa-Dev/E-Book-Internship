*Outlet คือช่องว่างในโครงหน้าร่วม หน้าที่ตรงกับลิงก์จะถูกวาดลงตรงนี้*

แก้เมนูจากบทที่ 12: เปลี่ยน `<a href>` เป็น **`NavLink`** (และโลโก้เป็น `Link`) จะได้ 2 อย่าง: เปลี่ยนหน้าโดยไม่โหลดใหม่ + รู้ว่าตอนนี้อยู่หน้าไหน (เอาไปทำให้เมนูนั้นเด่น) เขียนทับ `src/components/navbar.tsx` ทั้งไฟล์
```tsx
import { useState } from "react";
import { Link, NavLink } from "react-router";

const links = [
  { href: "/", label: "หน้าแรก" },
  { href: "/about", label: "เกี่ยวกับเรา" },
  { href: "/contact", label: "ติดต่อ" },
];

// หน้าตาของเมนู: หน้าที่อยู่ตอนนี้ (isActive) ตัวหนา สีร้าน มีขีดเส้นใต้
const linkClass = ({ isActive }: { isActive: boolean }) =>
  isActive ? "font-semibold text-brand underline underline-offset-8" : "hover:text-brand";

export default function Navbar({ shopName, logoUrl }: { shopName: string; logoUrl: string }) {
  const [open, setOpen] = useState(false);

  return (
    <header className="sticky top-0 z-40 bg-white shadow-sm">
      <nav className="mx-auto flex max-w-6xl items-center justify-between px-4 py-3">
        <Link to="/" className="flex items-center gap-2 font-bold text-brand">
          <img src={logoUrl} alt={shopName} className="h-10 w-10 rounded-full" />
          {shopName}
        </Link>

        <ul className="hidden gap-6 md:flex">
          {links.map((l) => (
            <li key={l.href}>
              <NavLink to={l.href} end={l.href === "/"} className={linkClass}>   {/* "/" ต้องตรงเป๊ะ ไม่งั้น active ทุกหน้า */}
                {l.label}
              </NavLink>
            </li>
          ))}
        </ul>

        <button className="md:hidden text-2xl" onClick={() => setOpen(!open)} aria-label="เปิดเมนู">
          {open ? "✕" : "☰"}
        </button>
      </nav>

      {open && (
        <ul className="border-t border-gray-200 px-4 pb-4 md:hidden">
          {links.map((l) => (
            <li key={l.href}>
              <NavLink to={l.href} end={l.href === "/"} className={linkClass} onClick={() => setOpen(false)}>   {/* กดแล้วปิดเมนู */}
                <span className="block py-2">{l.label}</span>
              </NavLink>
            </li>
          ))}
        </ul>
      )}
    </header>
  );
}
```
อ่านส่วนที่เปลี่ยน:
- `className` ของ `NavLink` รับ **ฟังก์ชัน** ได้ React Router เรียกฟังก์ชันนั้นพร้อมบอกว่า `isActive` (ลิงก์นี้ตรงกับหน้าปัจจุบันไหม) เราจึงคืนคลาสต่างกันได้ ประกาศไว้ครั้งเดียวใน `linkClass` แล้วใช้ทั้งเมนูจอใหญ่และมือถือ
- `end` บอกว่าต้องตรง **ทั้งลิงก์** ถ้าไม่ใส่ `/` จะนับว่าตรงกับทุกหน้า (เพราะทุกลิงก์ขึ้นต้นด้วย `/`) เมนู "หน้าแรก" จะเด่นตลอด
- เมนูมือถือมี `onClick={() => setOpen(false)}` เพิ่ม เพราะเปลี่ยนหน้าแล้วหน้าไม่โหลดใหม่ state `open` จึงไม่รีเซ็ตเอง ถ้าไม่ปิดเอง เมนูจะค้างเปิดทับหน้าใหม่
> **ระวัง:** ลิงก์ไปหน้าอื่นในเว็บเราเอง ใช้ `<Link>` / `<NavLink>` เสมอ ถ้าใช้ `<a href>` เบราว์เซอร์จะโหลดใหม่ทั้งหน้า ข้อมูลที่จำไว้หายหมด
> ลิงก์ออกไปเว็บอื่น (LINE, Facebook) ใช้ `<a href target="_blank" rel="noopener noreferrer">` ได้ตามปกติ

## 4. เลือกดูทีละหมวด โดยจำไว้ในลิงก์

หน้าเกี่ยวกับร้าน/บริการต้อง **เลือกดูทีละหมวดได้** ให้จำหมวดที่เลือกไว้ในลิงก์ (`/about?category=drinks`) ดีกว่าจำไว้ในตัวแปร เพราะ **ส่งลิงก์ให้คนอื่นแล้วเห็นหมวดเดียวกัน และกดย้อนกลับแล้วกลับไปหมวดเดิม**

![ขั้นตอนกดปุ่มหมวด ลิงก์เปลี่ยน useSearchParams อ่านค่า และ useFetch ดึงข้อมูลใหม่](/img/13-search-params.svg)
*เก็บหมวดไว้ในลิงก์ รีเฟรช ส่งต่อ และย้อนกลับได้ ต่างจากเก็บไว้ในตัวแปร*

`src/components/service-list.tsx`
```tsx
import { useSearchParams } from "react-router";
import { useFetch } from "../api/useFetch";
import ServiceCard from "./service-card";
import type { Category, Service } from "../types/service";

export default function ServiceList() {
  const [params, setParams] = useSearchParams();
  const category = params.get("category") ?? "";

  const categories = useFetch<Category[]>("/api/categories");
  const services = useFetch<Service[]>(`/api/services${category ? `?category=${encodeURIComponent(category)}` : ""}`);

  return (
    <>
      <div className="flex flex-wrap gap-2">
        <button onClick={() => setParams({})} className={!category ? "bg-brand text-white" : ""}>ทั้งหมด</button>
        {categories.data?.map((c) => (
          <button key={c.id} onClick={() => setParams({ category: c.slug })}
            className={category === c.slug ? "bg-brand text-white" : ""}>
            {c.name}
          </button>
        ))}
      </div>
      {services.loading && <p>กำลังโหลด... ⏳</p>}
      {services.error && <p>โหลดข้อมูลไม่สำเร็จ: {services.error} 😢</p>}
      <div className="mt-6 grid grid-cols-1 gap-6 md:grid-cols-2 xl:grid-cols-3">
        {services.data?.map((s) => <ServiceCard key={s.id} service={s} />)}
      </div>
    </>
  );
}
```
 ลิงก์เปลี่ยน → `useFetch` ดึงข้อมูลใหม่เอง เพราะเราบอกไว้ในบทที่ 11 ข้อ 6 ว่าให้ทำใหม่เมื่อ `url` เปลี่ยน

ใส่รายการนี้ลงในหน้าเกี่ยวกับเรา: แก้ `src/pages/about-page.tsx` เพิ่มบรรทัด import และแทนบรรทัดคอมเมนต์ด้วยตัวรายการ

> ```json
> {
>   "success": true,
>   "data": [
>     { "id": 1, "name": "เครื่องดื่ม", "slug": "drinks" },
>     { "id": 2, "name": "บริการจัดเลี้ยง", "slug": "catering" }
>   ]
> }
> ```
> แล้วเปลี่ยนชั่วคราวใน `service-list.tsx` เป็น `useFetch<Category[]>("/mock/categories.json")` และ `` useFetch<Service[]>(`/mock/services.json${category ? `?category=${encodeURIComponent(category)}` : ""}`) `` สิ่งที่ควรเห็น: กดปุ่มหมวดแล้ว **ลิงก์บนแถบที่อยู่เปลี่ยน** เป็น `/about?category=drinks` และ **ปุ่มที่กดเป็นสีร้าน** กดย้อนกลับแล้วปุ่มเด่นกลับไปที่เดิม แต่ **การ์ดยังแสดงครบทุกใบ** เพราะไฟล์ใน `public/` เป็นไฟล์นิ่ง ไม่อ่าน `?category=` (การกรองจริงเป็นงานของ server ในบทที่ 14) พอถึงบทที่ 14 ค่อยเปลี่ยนกลับเป็น `/api/...`

## 5. หน้าจัดการร้าน: หน้าซ้อนหน้า + หน้าที่ต้อง login

> **ข้อนี้อ่านอย่างเดียว ยังไม่ต้องใส่ในโค้ด** ชิ้นส่วน `LoginPage`, `RequireAuth`, `AdminLayout` และหน้าในหลังร้านยังไม่มีอยู่จริง ถ้าใส่ตอนนี้จะได้ `Cannot find name 'LoginPage'` [บทที่ 15](/15-auth) จะสร้างครบแล้วให้กลับมาเพิ่มบรรทัดเหล่านี้ใน `app.tsx` ตอนนั้น ที่ให้ดูก่อนเพราะอยากให้เห็นภาพ "หน้าซ้อนหน้า" ต่อจากโครงหน้าร่วมในข้อ 3

หน้าตาที่จะเพิ่มใน `app.tsx` (ข้างใน `<Routes>` ต่อจาก `<Route element={<PublicLayout />}>...</Route>`):
```tsx
<Route path="admin/login" element={<LoginPage />} />
<Route path="admin" element={<RequireAuth><AdminLayout /></RequireAuth>}>
  <Route index element={<DashboardPage />} />            {/* /admin */}
  <Route path="settings" element={<SettingsPage />} />   {/* /admin/settings */}
  <Route path="services" element={<ServicesPage />} />   {/* /admin/services */}
</Route>
```
`RequireAuth` จะถาม server ว่า login อยู่ไหม ถ้าไม่ → พาไป `/admin/login` (เขียนจริงใน [บทที่ 15](/15-auth))

![แผนภาพ Route หน้าจัดการร้านที่ซ้อนใน RequireAuth และ AdminLayout](/img/13-admin-routes.svg)
*หน้าลูกของ admin อยู่ใน AdminLayout ที่ครอบด้วย RequireAuth ส่วน admin/login อยู่นอกด่าน*

> **ระวัง:** การซ่อนหน้าจัดการร้านไว้ในหน้าเว็บ **ไม่ใช่ความปลอดภัย** ใครก็เปิด DevTools ข้ามได้ ตัวกันจริงคือ **server ต้องตอบ 401** ถ้ายังไม่ได้ login

## 6. ให้ Google และ LINE รู้ว่าหน้านี้คืออะไร

**SEO** = ทำให้ Google เข้าใจเนื้อหาและแสดงเว็บเราในผลค้นหา
**OG tags** = ข้อมูลที่ LINE / Facebook ใช้ทำการ์ดตอนแชร์ลิงก์ (รูป หัวข้อ คำอธิบาย)

![แท็ก title meta description และ og tags ในส่วนหัวของหน้า ไปปรากฏในผลค้นหา Google และการ์ดแชร์ใน LINE](/img/13-og-card.svg)
*Google อ่าน title กับ description · LINE/Facebook อ่านแท็ก og:* มาทำการ์ดตอนแชร์ลิงก์ (ตัวอย่างข้อความเป็นข้อมูลสมมติ)*

### ตั้งชื่อหน้าและคำอธิบายของแต่ละหน้า
React 19 ให้เขียน `<title>` และ `<meta>` ไว้ในชิ้นส่วนไหนก็ได้ แล้วจะย้ายไปไว้ส่วนหัวของหน้าให้เอง

`src/components/seo.tsx`
```tsx
interface Props {
  title: string;
  description: string;
  image?: string;
}

export default function Seo({ title, description, image }: Props) {
  return (
    <>
      <title>{title}</title>
      <meta name="description" content={description} />
      <meta property="og:title" content={title} />
      <meta property="og:description" content={description} />
      <meta property="og:type" content="website" />
      {image && <meta property="og:image" content={image} />}
    </>
  );
}
```
ใช้ในแต่ละหน้า **ตอนนี้ใส่ค่าตรงๆ ไปก่อน** แทนบรรทัด `<title>...</title>` เดิมของแต่ละหน้า เช่นใน `home-page.tsx`
```tsx
import Seo from "../components/seo";
// ...ใน return แทน <title>Bit Café | กาแฟคั่วสดใกล้บ้าน</title>
<Seo title="Bit Café | กาแฟคั่วสดใกล้บ้าน" description="ร้านกาแฟเล็กๆ คั่วสดทุกสัปดาห์ รับจัดเลี้ยงนอกสถานที่" />
```
ทำแบบเดียวกันกับ `about-page.tsx` และ `contact-page.tsx` โดยใส่คำอธิบายที่ต่างกันทุกหน้า (Google ใช้คำอธิบายเป็นข้อความใต้ลิงก์ในผลค้นหา ถ้าทุกหน้าเหมือนกัน คนอ่านแยกไม่ออกว่าหน้าไหนคืออะไร) ตรวจผล: เปิด DevTools → Elements → ดูใน `<head>` ต้องเห็น `<meta name="description">` เปลี่ยนตามหน้าที่เปิด

> **ระวัง:** `og:image` ต้องเป็น **ที่อยู่เต็ม** ที่ขึ้นต้นด้วย `https://` เช่น `https://example.com/og.jpg` ไม่ใช่ `/og.jpg` เพราะระบบของ LINE/Facebook ไม่รู้ว่า `/` หมายถึงเว็บไหน

**ต่อยอดในบทที่ 14:** เมื่อมี API `GET /api/pages/:slug` (แบบฝึกหัดบทที่ 14) ค่อยเปลี่ยนไปดึงค่าที่เจ้าของร้านตั้งเอง หน้าตาข้อมูลที่ API คืนมา:
```ts
// src/types/page.ts
export interface PageData {
  slug: string;
  seoTitle: string;
  seoDescription: string;
  ogImageUrl?: string;        // ไม่ใส่ก็ได้ (Seo จะไม่สร้างแท็ก og:image)
}
```
```tsx
const page = useFetch<PageData>("/api/pages/home");
// ...
{page.data && <Seo title={page.data.seoTitle} description={page.data.seoDescription} image={page.data.ogImageUrl} />}
```

### เขียนเนื้อหาให้ Google อ่านง่าย
- หัวข้อใหญ่สุด (`h1`) **หน้าละ 1 อัน** หัวข้อรองใช้ `h2`, `h3` ตามลำดับ
- รูปทุกรูปมีคำอธิบาย (`alt`) ช่วยทั้ง Google และคนตาบอดที่ใช้โปรแกรมอ่านจอ
- คำบนลิงก์บอกปลายทาง: "ดูเมนูทั้งหมด" ✅ ไม่ใช่ "คลิกที่นี่" ❌

### `robots.txt` และ `sitemap.xml`
วางไว้ใน `client/public/` (มีแค่ 3 หน้า เขียนเองได้เลย)

`public/robots.txt` บอกว่าหน้าไหนไม่ต้องเข้ามาดู
```
User-agent: *
Disallow: /admin
Sitemap: https://example.com/sitemap.xml
```

`public/sitemap.xml` รายชื่อหน้าทั้งหมดของเว็บ
```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url><loc>https://example.com/</loc></url>
  <url><loc>https://example.com/about</loc></url>
  <url><loc>https://example.com/contact</loc></url>
</urlset>
```
(เปลี่ยน `example.com` เป็นชื่อเว็บจริงตอนขึ้นระบบใน [บทที่ 18](/18-domain-dns))

> **ระวัง:** `Disallow: /admin` แค่ **ขอร้อง** ระบบค้นหาที่สุภาพว่าไม่ต้องเข้า ไม่ได้กันใครจริง ความปลอดภัยจริงอยู่ที่ server

## 7. ข้อจำกัดของเว็บแบบนี้ (ต้องอธิบายใน README ได้)

![Google รันโค้ดแล้วเห็นเนื้อหา LINE และ Facebook ไม่รันโค้ดจึงเห็นแค่ index.html พร้อมทางแก้ 3 ระดับ](/img/13-crawler-spa.svg)
*ระบบที่มาอ่านเว็บ React ได้หน้าเปล่ากับไฟล์โค้ด ทางแก้เรียงจากง่ายไปยาก*

**ผลคือ:** แชร์ลง LINE แล้วการ์ดอาจไม่ขึ้นรูปหรือหัวข้อที่เจ้าของร้านตั้ง เพราะ LINE ไม่เคยเห็นสิ่งที่ `<Seo>` สร้างขึ้น

**ทางแก้ (จากง่ายไปยาก)**
| วิธี | ทำยังไง | เหมาะกับ |
|---|---|---|
| ใส่ข้อมูลการ์ดค่าเริ่มต้นไว้ใน `index.html` | เขียนรูปและหัวข้อของร้านไว้ตรงๆ (และแก้ `<title>client</title>` ที่ Vite ใส่ไว้ กับ `<html lang="en">` เป็นชื่อร้านและ `lang="th"` ด้วย) | อย่างน้อยแชร์แล้วมีการ์ด (ทำได้เลยในงาน STARTER) |
| **สร้างหน้าไว้ล่วงหน้า (prerender)** | ตอนแพ็กเว็บ ให้เครื่องมือเปิดแต่ละหน้าแล้วเก็บหน้าที่มีเนื้อหาไว้ | เว็บไม่กี่หน้า เนื้อหาไม่ค่อยเปลี่ยน (งานเสริมของ STARTER) |
| **ให้ server สร้างหน้าให้ทุกครั้ง (SSR)** | server สร้างหน้าที่มีเนื้อหาครบส่งให้ทุกครั้งที่มีคนขอ | เว็บที่ต้องติด Google มาก และเนื้อหาเปลี่ยนบ่อย |

> **เคล็ดลับ:** งาน STARTER ยอมรับข้อจำกัดนี้ได้ แต่ต้อง **เขียนอธิบายใน README** ว่าเพราะอะไร และถ้าจะแก้ต้องทำยังไง

**ลองการ์ดตอนแชร์ (หลังขึ้นระบบจริง):** [Facebook Sharing Debugger](https://developers.facebook.com/tools/debug/) และส่งลิงก์ให้ตัวเองใน LINE

## ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| จอแดง `useNavigate() may be used only in the context of a <Router> component` (หรือข้อความคล้ายกันเมื่อใช้ `Link`/`NavLink`) | ใช้ของจาก React Router ในชิ้นส่วนที่ไม่ได้อยู่ใต้ `<BrowserRouter>` | ครอบ `<App />` ด้วย `<BrowserRouter>` ใน `main.tsx` ตามข้อ 2 |
| `Failed to resolve import "./pages/about-page"` | import ไฟล์ที่ยังไม่ได้สร้าง หรือชื่อไฟล์สะกดไม่ตรง (ตัวพิมพ์เล็กใหญ่ด้วย) | สร้างไฟล์ตามข้อ 2 เช็คชื่อด้วย `ls src/pages` |
| เมนูกับส่วนท้ายขึ้น แต่เนื้อหาตรงกลางว่าง | ลืม `<Outlet />` ใน `public-layout.tsx` | ใส่ `<Outlet />` ใน `<main>` ตามข้อ 3 |
| เมนู "หน้าแรก" เด่นตลอดทุกหน้า | `NavLink` ของ `/` ไม่มี `end` | ใส่ `end={l.href === "/"}` |
| กดเมนูแล้วหน้ากระพริบ โหลดใหม่ทั้งหน้า | ยังใช้ `<a href>` กับลิงก์ในเว็บเรา | เปลี่ยนเป็น `<Link to>` / `<NavLink to>` |
| หน้าเกี่ยวกับเราขึ้น `ข้อมูลที่ได้กลับมาไม่ใช่ JSON` | ยังไม่มี `/api/...` จนกว่าจะถึงบทที่ 14 | ปกติ ใช้ไฟล์ mock ตามกล่องในข้อ 4 ไปก่อน |
| ขึ้นระบบจริงแล้วกดรีเฟรชที่ `/about` ได้ 404 | server ไม่ได้ส่ง `index.html` กลับเมื่อไม่มีไฟล์ตามที่ขอ (SPA fallback ข้อ 1) | ตั้ง server ตาม [บทที่ 20](/20-deploy-vps) / [บทที่ 22](/22-deploy-managed) |

## เช็คความเข้าใจ

<details>
<summary>1. ทำไมลิงก์ในเว็บเราเองต้องใช้ `NavLink`/`Link` ไม่ใช่ `<a href>`?</summary>

`<a>` ทำให้เบราว์เซอร์โหลดใหม่ทั้งหน้า ข้อมูลที่จำไว้หายและช้ากว่า ส่วน `Link` แค่เปลี่ยนลิงก์แล้วสลับเนื้อหาในหน้าเดิม

</details>

<details>
<summary>2. บนระบบจริง พิมพ์ `/contact` เข้ามาตรงๆ แล้วได้ 404 เพราะอะไร?</summary>

server หาไฟล์ชื่อ `contact` ไม่เจอ ต้องตั้งให้ server ส่งหน้าหลัก (`index.html`) กลับไปทุกครั้งที่ไม่มีไฟล์ตามที่ขอ แล้ว React Router จะเลือกหน้าที่ถูกเอง

</details>

<details>
<summary>3. ทำไมจำหมวดที่เลือกไว้ในลิงก์ ดีกว่าจำไว้ในตัวแปร?</summary>

รีเฟรชแล้วไม่หาย, ส่งลิงก์ให้คนอื่นแล้วเห็นหมวดเดียวกัน, ปุ่มย้อนกลับของเบราว์เซอร์ทำงานถูก

</details>

<details>
<summary>4. แชร์ลิงก์ลง LINE แล้วไม่ขึ้นรูปที่เจ้าของร้านตั้ง ทั้งที่เปิดในเบราว์เซอร์แล้วเห็นปกติ เพราะอะไร?</summary>

ระบบของ LINE ไม่รันโค้ดในหน้าเว็บ จึงเห็นแค่ `index.html` เปล่าๆ แก้ได้ด้วยการใส่ข้อมูลการ์ดค่าเริ่มต้นใน `index.html`, สร้างหน้าไว้ล่วงหน้า หรือให้ server สร้างหน้าให้

</details>
