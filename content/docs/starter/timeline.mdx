> **ใช้กับทุกโจทย์** ทุกโจทย์ใช้แผน 10 วันและวันตรวจเดียวกัน ของเฉพาะโจทย์ STARTER มีป้าย "STARTER:" โจทย์อื่นใช้ส่วนที่เทียบกันได้ใน [Requirement ของรุ่นตัวเอง หัวข้อ Timeline](/api/files/requirement.pdf?sec=timeline)

> **สรุป 30 วินาที**
> - ลำดับคือ **ฐานข้อมูล → API → หน้าเว็บลูกค้า → หน้าจัดการ (หลังบ้าน)** เพราะน้องถนัดส่วนเบื้องหลังมาจากงาน Todo แล้ว ทำส่วนที่มั่นใจก่อน ฐานจะแน่น
> - ทุกวันมีหัวข้อ **"อ่านก่อนลงมือ"** พร้อมลิงก์ไปบทในคู่มือนี้
> - ทำหน้าเว็บเสร็จก่อนแล้วก็ไม่เป็นไร ไม่ต้องรื้อ ดู [เริ่ม server จากหน้าเว็บที่มีอยู่](/14-hono-api#ทำหน้าเว็บเสร็จก่อนแล้ว-เริ่ม-server-จากของที่มี) แล้วค่อยกลับมาทำวันที่ 2–4
> - **ส่งลิงก์ repo วันที่ 1 แล้ว push ขึ้น GitHub ทุกวัน** พี่เลี้ยงตามดูได้เลย และส่งตรวจในเว็บด้วย tag 3 รอบ (วันที่ 5, 9, 10) ดู[วิธีส่งงาน](/starter/submission#เก็บงานบน-github-ตั้งแต่วันแรก)
> - **ถ้าวันไหนทำไม่ทัน ห้ามเงียบแล้วข้ามไปทำวันต่อไป ต้องบอกพี่เลี้ยงภายในวันนั้น**

> **คำใหม่ในหน้านี้**
> [Schema](/glossary#schema) · [Migration](/glossary#migration) · [Seed](/glossary#seed) · [API](/glossary#api) · [Zod](/glossary#zod) · [Middleware](/glossary#middleware) · [JWT](/glossary#jwt) · [Cookie](/glossary#cookie) · [Responsive](/glossary#responsive) · [SEO](/glossary#seo)

## ภาพรวม

![แผน 10 วัน: เตรียมงาน เบื้องหลัง หน้าเว็บลูกค้า หลังบ้าน ตรวจรอบ 1 วันที่ 5 ตรวจรอบ 2 วันที่ 9 นำเสนอวันที่ 10](/img/starter-timeline.svg)
*แผน 10 วัน แยกสีตามช่วงงาน พร้อมวันตรวจของพี่เลี้ยง*

| วัน | ทำอะไร | ถือว่าเสร็จเมื่อ |
|---|---|---|
| 1 | เขียนสรุปธุรกิจ (brief), ร่างหน้าตาเว็บทุกหน้า (วาดบนกระดาษก็ได้), สร้างโปรเจกต์ | พี่เลี้ยงอนุมัติ brief |
| 2 | ออกแบบตาราง, สร้างตาราง, ใส่ข้อมูลตั้งต้น, วาดผังตาราง | รัน `bun run seed` แล้วเห็นข้อมูลใน pgAdmin |
| 3 | API กลุ่มที่ใครก็เรียกได้ + ตรวจข้อมูล + รูปแบบคำตอบ | ลองเรียกทุกตัวด้วย Postman หรือไฟล์ `.http` ผ่าน |
| 4 | ระบบ login + API หลังบ้าน | เรียก API หลังบ้านตอนยังไม่ login แล้วได้ `401` |
| 5 | โครงหน้าเว็บ, เมนูบน, ส่วนท้าย, หน้าแรก | **พี่เลี้ยงตรวจรอบที่ 1** (ตาราง + API) |
| 6 | หน้าบ้านที่เหลือ + ฟอร์มที่ลูกค้าส่งได้ (STARTER: About/Services + ฟอร์มติดต่อ) | ส่งฟอร์มแล้วข้อมูลเข้าฐานข้อมูล |
| 7 | หลังบ้าน: login, หน้าสรุป, ข้อมูลหลักของเว็บ (STARTER: ข้อมูลร้าน, ข้อความในหน้า) | แก้ในหลังบ้านแล้วหน้าเว็บลูกค้าเปลี่ยนตาม |
| 8 | หลังบ้าน: จัดการข้อมูลที่เหลือ (STARTER: สินค้า, หมวด, ข้อความลูกค้า) | เพิ่ม/ดู/แก้/ลบ ได้ครบ |
| 9 | Google หาเจอ, ใช้ได้ทุกจอ, ขึ้นข้อความตอนโหลด/พัง | **พี่เลี้ยงตรวจรอบที่ 2** (ทั้งระบบ) |
| 10 | แก้ตามที่พี่เลี้ยงบอก, เขียน README, ซ้อมนำเสนอ | นำเสนอ 15 นาที |

## วันที่ 1 · เตรียมงาน

- [ ] สร้างโปรเจกต์ใน Git แยกโฟลเดอร์ `client` กับ `server` แล้ว **สร้าง repo บน GitHub, push ครั้งแรก แล้วส่งลิงก์ repo ในเว็บ** (`.env` อยู่ใน `.gitignore` ก่อน) ([วิธีทำ](/starter/submission#ครั้งเดียววันที่-1-สร้าง-repo-แล้ว-push))

**อ่านก่อนลงมือ**
- [บทที่ 16](/16-ai-pairing#0-เลือกเรียนโดยยังไม่ใช้-ai-ก็ได้) ขั้น ①–④ ทำได้ 2 ทาง เลือกทางเดียวหรือผสมก็ได้

  - **ให้ AI ช่วย:** ใช้ prompt ขั้น ①–④ ให้ช่วยสรุปโจทย์, หาคำถามที่ต้องถามพี่เลี้ยง, ออกแบบ, แบ่งงานเป็นชิ้นเล็ก + เขียนไฟล์ `CLAUDE.md` แล้วเทียบผลกับเอกสารจริงทุกครั้ง
  - ทำไมวันแรกยังไม่เขียนโค้ด: ถ้าสรุปโจทย์ 5 บรรทัดไม่ได้ แปลว่ายังไม่พร้อมออกแบบ และคำถามที่ถามวันนี้ราคาถูกกว่าการรื้อโค้ดในวันที่ 6 มาก

## วันที่ 4 · ระบบ login + API หลังบ้าน

- [ ] login / logout และเก็บรหัสผ่านแบบ hash ด้วย `Bun.password`
- [ ] เก็บบัตรผ่าน (JWT) ไว้ใน cookie แบบ `httpOnly` และ `sameSite=lax`
- [ ] ด่านตรวจ (middleware) ที่เช็ค login ทุก `/api/admin/...`
- [ ] API หลังบ้านครบตามรายการในโจทย์ (STARTER: หน้าสรุป / ข้อมูลร้าน / ข้อความในหน้า / สินค้า / หมวด / ข้อความลูกค้า)
- [ ] เรียก API หลังบ้านตอนยังไม่ login ต้องได้ `401`

**อ่านก่อนลงมือ**
- [บทที่ 10 ข้อ 2](/10-security#2-เก็บรหัสผ่านผู้ใช้-hash-ไม่ใช่-encrypt) ทำไมต้องเก็บรหัสผ่านแบบย้อนกลับไม่ได้
- [บทที่ 10 ข้อ 3](/10-security#3-authentication-vs-authorization) "คุณเป็นใคร" กับ "คุณทำได้ไหม" ต่างกันยังไง
- [บทที่ 15](/15-auth) ตัวอย่างโค้ดทั้งหมดของวันนี้ + รายการเช็คความปลอดภัย

  - ไล่ [คุณภาพที่ต้องได้](/starter/quality) ทีละแถว + [Security Checklist บทที่ 10 ข้อ 6](/10-security#6-security-checklist-ก่อนเปิด-mr) + เช็คความปลอดภัยของระบบ login ใน[บทที่ 15 ข้อ 6](/15-auth) ข้อไหนไม่ผ่าน จดเป็น Issue แล้วแก้
  - `bun run build` ในโฟลเดอร์ `client` และ `bun run typecheck` (หรือ `bunx tsc --noEmit`) ในโฟลเดอร์ `server` ต้องไม่มี error ฝั่ง server ต้องสั่งตรวจเอง เพราะ Bun รันไฟล์ `.ts` ได้โดยไม่ตรวจ type เว็บจึงรันขึ้นได้ทั้งที่ type ผิดอยู่
  - ลอง 3 ข้อที่ **ตกทันที** ด้วยตัวเอง ([เกณฑ์](/starter/submission#เกณฑ์ประเมิน-100-คะแนน)): ① `curl -i http://localhost:3000/api/admin/<ของในโจทย์>` (STARTER: `/api/admin/services` · เปลี่ยนพอร์ตตามที่ server ของน้องใช้) โดยไม่มี cookie ต้องได้ `401` ② เปิด pgAdmin ดูช่อง `password_hash` ต้องขึ้นต้นด้วย `$argon2id$` ไม่ใช่รหัสจริง ③ ให้เพื่อน clone ไปทำตาม README บนเครื่องเพื่อนเอง ถ้าเพื่อนต้องหันมาถาม แปลว่า README ยังไม่ครบ
  - ถ้าใช้ AI: ใช้ prompt "review" และ "เช็คความปลอดภัยก่อนส่ง" ใน[บทที่ 16 ข้อ 6](/16-ai-pairing) เป็นการตรวจ **เพิ่ม** หลังตรวจเองแล้ว ไม่ใช่แทน แล้วพิสูจน์ทุกข้อที่ AI ชี้ด้วยการรันจริง
