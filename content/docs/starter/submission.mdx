## 🐙 เก็บงานบน GitHub ตั้งแต่วันแรก

โค้ดทั้งหมดอยู่บน GitHub ที่เดียว เว็บคู่มือนี้ **ไม่รับไฟล์** เราแค่บอกพี่เลี้ยงว่า "ตรวจโค้ด ณ จุดนี้"

**นึกภาพ:** GitHub คือสมุดการบ้านที่วางไว้บนโต๊ะครู ครูเปิดดูได้ทุกเมื่อ ส่วน **tag** คือที่คั่นหน้าที่เราแปะไว้ว่า "ตรวจถึงหน้านี้" เขียนต่อหน้าหลังได้ ที่คั่นก็ไม่เลื่อนตาม

```text
วันที่ 1     สร้าง repo + push ครั้งแรก
   │
วันที่ 2–4   push ทุกวัน
   │
วันที่ 5     tag review-1 ─► ส่งในเว็บ
   │
วันที่ 6–8   push ทุกวัน (แก้ตามที่พี่บอก)
   │
วันที่ 9     tag review-2 ─► ส่งในเว็บ
   │
วันที่ 10    tag final    ─► ส่งในเว็บ
```

### ครั้งเดียววันที่ 1: สร้าง repo แล้ว push

1. ใส่ `.env` และ `node_modules` ใน `.gitignore` **ก่อน commit แรก** ([บทที่ 1 ข้อ 6](/01-git#6-gitignore-ของที่ห้ามเซฟ)) ถ้า `.env` หลุดขึ้น GitHub แม้ครั้งเดียว ค่าลับนั้นถือว่ารั่วแล้ว ต้องเปลี่ยนค่าใหม่ทั้งหมด
2. บน GitHub กด **New repository** ตั้งชื่อ (เช่น `starter`) ไม่ต้องติ๊กสร้าง README
3. ต่อเครื่องเรากับ repo แล้ว push ([บทที่ 1 ข้อ 13](/01-git#13--ทำงานกับ-server-กลาง-remote)) ใช้ได้ทั้ง Terminal บน Mac และ Git Bash บน Windows:

```bash
git remote add origin https://github.com/<ชื่อผู้ใช้>/starter.git
git push -u origin main
```

4. ถ้าตั้ง repo เป็น **private** ต้องเชิญพี่เลี้ยง: Settings → Collaborators → Add people ไม่งั้นพี่เลี้ยงกดลิงก์แล้วเจอ 404

### ทุกวัน: commit แล้ว push

```bash
git add .
git status          # ดูก่อนว่าไม่มี .env หลุดเข้ามา
git commit -m "เพิ่ม API หมวดสินค้า"
git push
```

push ทุกวันแม้งานยังไม่เสร็จ เครื่องพังงานก็ไม่หาย และพี่เลี้ยงเห็นความคืบหน้าได้โดยไม่ต้องถาม

### วันที่ส่ง: ปักป้าย tag แล้วส่งในเว็บ

```bash
git tag review-1
git push origin review-1
```

แล้วกรอกลิงก์ repo + `review-1` ในกล่อง [ส่งงานของคุณ](#-ส่งงานของคุณ) ด้านล่าง พี่เลี้ยงได้แจ้งเตือนทันที ([บทที่ 1 ข้อ 12: Tag](/01-git#12--tag-ปักธงเวอร์ชัน))

**พี่เลี้ยงให้แก้?** แก้ → commit → push แล้วปักป้าย **ชื่อใหม่** เช่น `review-1-fix1` แล้วส่งอีกครั้ง ห้ามย้ายป้ายเดิมหรือใช้ `git push --force` เพราะพี่เลี้ยงจะเทียบไม่ได้ว่ารอบก่อนกับรอบนี้ต่างกันตรงไหน (และงานจริงในทีม การย้ายของที่คนอื่นดึงไปแล้วทำให้ของเขาพัง)

> 💡 ลืมปักป้าย? ใส่ **commit SHA** แทนได้ (7 ตัวแรกพอ ดูจาก `git log --oneline` หรือหน้า Commits บน GitHub)

## 📦 สิ่งที่ต้องส่ง

- [ ] งานใน GitHub repo เดียว (มีทั้ง `client` และ `server`) ส่งด้วย tag `final` ใน[กล่องส่งงาน](#-ส่งงานของคุณ)
- [ ] README บอกวิธี: ติดตั้ง, ตั้งค่าไฟล์ `.env`, สร้างตาราง + ข้อมูลตั้งต้น, เปิดเว็บ, บัญชี admin สำหรับทดสอบ
- [ ] ผังตาราง (ER Diagram)
- [ ] ไฟล์ที่รวมการเรียก API ทุกตัวไว้ (จาก Postman หรือไฟล์ `.http`)
- [ ] สรุปธุรกิจ (brief) + ภาพร่างหน้าเว็บ (wireframe)
- [ ] นำเสนอสด 15 นาที: เล่าเรื่องธุรกิจ → โชว์หน้าเว็บ → แก้ข้อมูลในหน้าจัดการให้ดูว่าหน้าเว็บเปลี่ยนจริง → ตอบคำถามเรื่องโค้ด

> 💡 ก่อนส่ง ให้เพื่อนเอางานไปรันตาม README บนเครื่องเพื่อนเอง ถ้าเพื่อนต้องหันมาถามน้องแม้แต่ข้อเดียว แปลว่า README ยังไม่ครบ

## เกณฑ์ประเมิน (100 คะแนน)

| หัวข้อ | คะแนน | ดูอะไร |
|---|---|---|
| ฐานข้อมูล | 15 | ออกแบบตารางมีเหตุผล, การเชื่อมตารางและค่าห้ามซ้ำถูก, สร้างตารางด้วย migration ได้จริง |
| API | 25 | ครบตามรายการ, ตรวจข้อมูลด้วย Zod ทุกตัว, ตัวเลขบอกผลถูก, ระบบ login ปลอดภัย |
| หน้าเว็บลูกค้า | 20 | ครบทุกหน้าตามโจทย์ (STARTER: 3 หน้า), ข้อมูลมาจาก API จริง, ใช้ได้ทุกจอ, มีข้อความตอนโหลด/พัง |
| หน้าจัดการ (หลังบ้าน) | 20 | เพิ่ม/ดู/แก้/ลบ ครบ, แก้แล้วหน้าเว็บเปลี่ยนจริง, เจ้าของธุรกิจใช้เป็น |
| Google + ความปลอดภัย | 10 | ชื่อหน้า/คำอธิบาย, การ์ดตอนแชร์, จำกัดการส่งฟอร์ม, cookie ปลอดภัย |
| โค้ด + README + นำเสนอ | 10 | อ่านง่าย, ไม่ใช้ `any` มั่ว, ตอบคำถามเรื่องโค้ดตัวเองได้ |

*สัดส่วนคะแนนแต่ละหัวข้อ และเงื่อนไขผ่าน*

> - ❌ รหัสผ่านไม่ได้ hash ด้วย bcrypt/argon2 (เช่น เก็บเป็นตัวจริง หรือเข้ารหัสแบบที่ถอดกลับได้)
> - ❌ เรียก API ของหน้าจัดการ (หลังบ้าน) ได้ โดยไม่ต้อง login
> - ❌ ทำตาม README แล้วเปิดเว็บไม่ขึ้น

## 🎁 งานเสริม (Bonus)

ทำได้เมื่องานหลักครบแล้วเท่านั้น **งานหลักยังไม่ครบแต่ไปทำงานเสริม = ไม่ได้คะแนนเพิ่ม**

- 🖼️ ปุ่มอัปโหลดรูปจริง แทนการใส่ลิงก์รูป
- 🔔 แจ้งเตือนเข้า LINE หรืออีเมล เมื่อมีลูกค้าส่งข้อมูลใหม่เข้ามา (STARTER: ข้อความจากฟอร์มติดต่อ) (LINE Notify ปิดบริการแล้ว ต้องใช้ LINE Messaging API ผ่าน LINE Official Account และเก็บ token ไว้ใน `.env` ฝั่ง server เท่านั้น)
- ⚡ ทำให้ LINE/Facebook เห็นเนื้อหาครบตอนแชร์ (prerender: [บทที่ 13 ข้อ 7](/13-router-seo))
- 🐳 เปิดทั้งระบบ (ฐานข้อมูล + server + หน้าเว็บ) ได้ด้วยคำสั่งเดียว ([บทที่ 20](/20-deploy-vps))
- 🚀 ขึ้นเว็บจริงบนอินเทอร์เน็ต พร้อมชื่อเว็บของตัวเอง ([ด่าน 7: บทที่ 17–23](/17-network))
- 🧪 เขียนโค้ดทดสอบอัตโนมัติ อย่างน้อยให้ทดสอบการตรวจข้อมูลและด่านตรวจ login ([ตัวอย่างในบทที่ 21 ข้อ 2](/21-cicd))
