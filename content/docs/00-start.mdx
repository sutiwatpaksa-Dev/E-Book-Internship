## 1. ภาพรวม: Full-Stack คืออะไร

เวลาเราเปิดเว็บสักเว็บ เช่น สั่งของออนไลน์ จริงๆ แล้วมี **3 ส่วนหลัก** ทำงานร่วมกันอยู่ คำว่า **Full-Stack** แปลว่า "รู้และทำได้ครบทุกส่วนของ stack นี้" ตั้งแต่หน้าจอที่ผู้ใช้เห็นจนถึงที่เก็บข้อมูล

![ภาพรวม Full-Stack: Browser ส่ง request ไป Server แล้ว Server คุยกับ Database](/img/00-fullstack.svg)
*ภาพรวมระบบ: ผู้ใช้เห็นแค่ Browser แต่เบื้องหลังมี Server และ Database ทำงานอยู่*

| ส่วน | ชื่อเรียกอีกแบบ | หน้าที่ | ภาษา/เครื่องมือที่เจอในคู่มือ |
|---|---|---|---|
| **Browser / แอป** | Frontend (หน้าบ้าน) | แสดงผล รับการคลิก/พิมพ์จากผู้ใช้ แล้วส่งคำขอไปถามหลังบ้าน | HTML, CSS, JavaScript/TypeScript, React |
| **Server** | Backend (หลังบ้าน), API | รับคำขอ ตรวจว่าใครมีสิทธิ์ คิดตามกฎของธุรกิจ แล้วไปอ่าน/เขียนข้อมูล | Node.js, TypeScript |
| **Database** | DB, ฐานข้อมูล | เก็บข้อมูลถาวร แม้ปิดเครื่องก็ไม่หาย และค้นหาได้เร็ว | PostgreSQL, SQL |

> 💡 **เปรียบเทียบกับร้านอาหาร**
> - Browser = **ลูกค้า + เมนู** (เห็นหน้าตา สั่งอาหาร)
> - Server = **พนักงานและครัว** (รับออเดอร์ ตรวจว่าสั่งได้ไหม ทำอาหาร)
> - Database = **ห้องเก็บวัตถุดิบ/สมุดบัญชี** (ของทุกอย่างถูกเก็บไว้ที่นี่)
> ลูกค้าไม่เดินเข้าห้องเก็บของเอง ต้องผ่านพนักงานเสมอ เว็บก็เช่นกัน: **Browser ไม่คุยกับ Database ตรงๆ**

### ทำไมไม่ให้ Browser คุยกับ Database ตรงๆ?
- **ความปลอดภัย**: โค้ดใน Browser ผู้ใช้เปิดดูได้หมด ถ้าใส่รหัส DB ไว้ ใครก็ขโมยได้
- **กฎธุรกิจ**: เช่น "ลดราคาได้ไม่เกิน 20%" ต้องตรวจที่ Server ที่เดียว ไม่ใช่เชื่อ Browser
- **เปลี่ยนง่าย**: เปลี่ยนฐานข้อมูลได้โดยหน้าเว็บไม่ต้องแก้

### เส้นทางของคำขอ 1 ครั้ง

สมมติผู้ใช้เปิดหน้า "รายการสินค้า" เกิดอะไรขึ้นบ้าง:

![ลำดับ: Browser ส่ง GET ไป Server, Server ส่ง SQL ไป Database, ข้อมูลไหลกลับเป็น JSON](/img/00-request-flow.svg)
*เส้นทางของคำขอหนึ่งครั้ง: ไปและกลับ รวมแล้วใช้เวลาไม่ถึงวินาที*

1. Browser ส่ง **request** (คำขอ) ไปที่ Server เช่น `GET /products` (ขอรายการสินค้า)
2. Server ตรวจคำขอ แล้วส่งคำสั่ง **SQL** ไปถาม Database
3. Database ส่งข้อมูลกลับมาให้ Server
4. Server แปลงข้อมูลเป็น **JSON** แล้วตอบกลับ (เรียกว่า **response**)
5. Browser เอา JSON ไปวาดเป็นหน้าตาที่สวยงาม

> 🤓 **เกร็ด:** ระหว่างขั้น 1 กับ 4 คำขอวิ่งผ่าน **อินเทอร์เน็ต** ด้วยภาษากลางที่เรียกว่า **HTTP** (ถ้าเข้ารหัสด้วยจะเป็น HTTPS ที่เห็นรูปกุญแจใน Browser) ส่วนระหว่าง Server กับ Database มักอยู่ในเครือข่ายหลังบ้านที่คนนอกเข้าไม่ถึง

### แล้ว Frontend กับ Backend ต่างกันที่ไหนในเชิงงาน?

| | Frontend | Backend |
|---|---|---|
| ทำงานที่ไหน | ในเครื่องผู้ใช้ (Browser) | บนเครื่อง server ของบริษัท/คลาวด์ |
| ผู้ใช้เห็นโค้ดไหม | เห็นได้ (ห้ามใส่ความลับ) | ไม่เห็น |
| ตัวอย่างงาน | ปุ่ม ฟอร์ม ตาราง หน้าตา | ตรวจรหัสผ่าน คิดราคา เขียน DB |
| จะเจอในบท | 11-13 (React, Tailwind) | 5, 14, 15 (API, login) และ 6-8 (ฐานข้อมูล) |

คู่มือนี้พาเรียนครบวงจรทีละชิ้น ทุกบทคือการเติมชิ้นส่วนใหม่ลงในภาพข้างบน 🧩

## 2. คำศัพท์ที่ต้องรู้

| คำ | ความหมายแบบง่าย | 💡 เปรียบเทียบ |
|---|---|---|
| **Terminal** | หน้าจอพิมพ์คำสั่งสั่งคอมพิวเตอร์ | คุยกับคอมด้วยการพิมพ์แทนการคลิก |
| **Server** | โปรแกรมที่รอรับคำขอแล้วตอบกลับ | พนักงานหน้าร้าน |
| **Client** | ฝั่งที่ส่งคำขอ เช่น browser, แอปมือถือ | ลูกค้า |
| **API** | ช่องทางที่โปรแกรมใช้คุยกัน มีรูปแบบที่ตกลงกันไว้ | เมนูอาหาร: สั่งได้เฉพาะที่มีในเมนู |
| **HTTP** | กติกากลางของการส่งคำขอ/คำตอบผ่านเว็บ | ภาษากลางที่ลูกค้ากับร้านเข้าใจตรงกัน |
| **JSON** | รูปแบบข้อมูลที่โปรแกรมส่งหากัน `{ "name": "บิต", "age": 21 }` | แบบฟอร์มที่ทุกคนอ่านออก |
| **localhost** | ชื่อเรียก "เครื่องของเราเอง" | บ้านตัวเอง |
| **Port** | หมายเลขช่องทางของโปรแกรม เช่น `3000`, `5432` | เลขห้องในตึกเดียวกัน |
| **Database (DB)** | โปรแกรมเก็บและค้นข้อมูลอย่างเป็นระบบ | ตู้เอกสารที่ค้นไวมาก |
| **Package / Library** | โค้ดสำเร็จรูปที่คนอื่นเขียนไว้ให้ใช้ | ชิ้นส่วนสำเร็จรูป ไม่ต้องสร้างล้อเอง |
| **Environment Variable** | ค่าตั้งค่าที่ส่งให้โปรแกรมจากภายนอก มักเก็บในไฟล์ `.env` | กุญแจที่ไม่ควรติดไว้กับประตู |
| **Repository (repo)** | โฟลเดอร์โปรเจกต์ที่ Git บันทึกประวัติไว้ | สมุดบันทึกทุกการเปลี่ยนแปลง |
| **Container** | กล่องที่บรรจุโปรแกรมพร้อมของที่ต้องใช้ รันได้เหมือนกันทุกเครื่อง | กล่องข้าวสำเร็จรูป เปิดกินได้ทุกที่ |
| **PATH** | รายชื่อโฟลเดอร์ที่ Terminal ไปหาโปรแกรมที่เราพิมพ์ชื่อ | สมุดโทรศัพท์ที่ Terminal เปิดหาชื่อโปรแกรม |

### localhost และ port ดูยังไง

เครื่องเราเครื่องเดียวรันโปรแกรมได้หลายตัวพร้อมกัน แต่ละตัวต้องมี "เลขห้อง" ของตัวเอง ไม่งั้นคำขอจะไม่รู้ว่าต้องไปหาใคร

![localhost เป็นตึก มี port เป็นเลขห้อง: 5173 หน้าเว็บ, 3000 API, 5432 Database](/img/00-ports.svg)
*เลข port ที่พบบ่อยในคู่มือนี้ (เลขจริงเปลี่ยนได้ตามที่ตั้งค่า)*

ตัวอย่าง URL ที่จะพิมพ์ใน Browser บ่อยๆ: `http://localhost:3000/products`
- `http://` = ใช้ภาษา HTTP
- `localhost` = เครื่องของเราเอง
- `:3000` = ห้องหมายเลข 3000
- `/products` = ขอข้อมูลเรื่อง products

## 3. 🔧 ติดตั้งเครื่องมือ

| เครื่องมือ | ใช้ทำอะไร | ดาวน์โหลด |
|---|---|---|
| **VS Code** | เขียนโค้ด | https://code.visualstudio.com |
| **Git** | บันทึกประวัติโค้ด ส่งงาน | https://git-scm.com (Mac มักมีอยู่แล้ว) |
| **Node.js (LTS)** | รันโค้ด JavaScript/TypeScript | https://nodejs.org → เลือก **LTS** |
| **Docker Desktop** | รัน container | https://www.docker.com/products/docker-desktop |

> 💡 **LTS คืออะไร?** Long-Term Support คือเวอร์ชันที่เสถียรและได้รับการดูแลนาน เหมาะกับงานจริง เลือกอันนี้เสมอ ไม่ต้องไล่เวอร์ชันล่าสุด

### 🪟 เส้นทาง Windows

1. **VS Code**: ดาวน์โหลด Installer แล้วกด Next ไปเรื่อยๆ แนะนำติ๊ก *"Add to PATH"* และ *"Add 'Open with Code' action"* ถ้ามีตัวเลือก
2. **Git**: ติดตั้ง **Git for Windows** จาก https://git-scm.com ติดตั้งเสร็จจะได้โปรแกรม **Git Bash** ติดมาด้วย ซึ่งเป็น Terminal ที่เล่มนี้ใช้บน Windows หน้าส่วนใหญ่กด Next ได้เลย แต่มี 4 หน้าที่ควรอ่านก่อนกด:

   | หน้าที่ถาม | เลือก | ทำไม |
   |---|---|---|
   | **Choosing the default editor used by Git** | **Use Visual Studio Code as Git's default editor** | เวลา Git ต้องให้เราพิมพ์ข้อความ (เช่น commit message ตอน merge) จะเปิด VS Code ให้ ไม่ใช่ Vim ที่คนใช้ครั้งแรกมักออกไม่เป็น |
   | **Adjusting your PATH environment** | **Git from the command line and also from 3rd-party software** (Recommended, เป็นค่าเริ่มต้น) | VS Code และโปรแกรมอื่นจะเรียก `git` เจอ |
   | **Configuring the line ending conversions** | **Checkout Windows-style, commit Unix-style line endings** (ค่าเริ่มต้น, ตั้ง `core.autocrlf=true`) | ไฟล์ที่ commit ขึ้นไปจะใช้ตัวขึ้นบรรทัดแบบ Linux (LF) ซึ่ง server ต้องการ (รายละเอียดในกล่องนิสัยของ Git Bash ด้านล่าง) |
   | **Configuring the terminal emulator to use with Git Bash** | **Use MinTTY** (ค่าเริ่มต้น) | ใช้ได้ ข้อเสียข้อเดียวคือคำสั่งแบบโต้ตอบบางตัวต้องเติม `winpty` (ดูกล่องด้านล่าง) |

3. **Node.js**: ติดตั้ง LTS ด้วย Installer ตัวเลือกเริ่มต้นจะเพิ่มเข้า PATH ให้อัตโนมัติ (ไม่ต้องติ๊กติดตั้ง tools เพิ่มก็ได้ในตอนนี้)
4. **Docker Desktop**: ติดตั้งแล้ว restart เครื่องตามที่ถาม โดยทั่วไป Docker Desktop บน Windows ใช้ **WSL 2** เป็นตัวรัน ถ้าติดตั้งแล้วขึ้นว่า WSL ไม่พร้อม ดูหัวข้อแก้ปัญหาด้านล่าง
5. **Terminal ที่ใช้**: **Git Bash เท่านั้น** (ไม่ใช่ PowerShell หรือ Command Prompt) แล้วตั้งให้ VS Code เปิด Git Bash เป็นค่าเริ่มต้น ทำตามหัวข้อ [🪟 Windows: ใช้ Git Bash เท่านั้น](#-windows-ใช้-git-bash-เท่านั้น) ด้านล่าง ก่อนไปต่อ

### 🍎 เส้นทาง Mac

1. **VS Code**: โหลดไฟล์ `.zip` แล้วลาก **Visual Studio Code.app** ไปใส่โฟลเดอร์ **Applications**
2. **Git**: เปิด Terminal พิมพ์ `git --version` ถ้ายังไม่มี macOS จะเด้งหน้าต่างขอติดตั้ง **Command Line Tools** ให้กด **Install** รอจนเสร็จ (หรือพิมพ์ `xcode-select --install`)
3. **Node.js**: ดาวน์โหลด Installer `.pkg` แบบ LTS แล้วกดตามขั้นตอน
4. **Docker Desktop**: ต้องเลือกไฟล์ให้ตรงกับชิป ดูได้ที่ เมนู Apple (มุมซ้ายบน) → **About This Mac** ถ้าเห็น *Apple M1/M2/...* เลือก **Apple Silicon** ถ้าเห็น *Intel* เลือก **Intel chip** แล้วลาก .app ไปไว้ใน Applications เปิดครั้งแรกอาจขอรหัสผ่านเครื่อง
5. **Terminal ที่ใช้**: กด `⌘ + Space` พิมพ์ `Terminal` (Mac ใช้ shell ชื่อ **zsh** เป็นค่าเริ่มต้น ไวยากรณ์ที่ใช้ในเล่มนี้เหมือน bash ใช้ได้เลยไม่ต้องตั้งอะไร)

> 💡 **ใช้ VS Code เปิด Terminal ได้เลย** กด ``Ctrl + ` `` (Mac ใช้ ``Ctrl + ` `` เช่นกัน) Terminal จะเปิดอยู่ในโฟลเดอร์โปรเจกต์ให้เลย (บน Windows ต้องตั้งค่าตามหัวข้อถัดไปก่อน ไม่งั้น VS Code จะเปิด PowerShell ให้)

### 🪟 Windows: ใช้ Git Bash เท่านั้น

**Terminal ไม่ใช่ภาษาเดียว** หน้าต่างดำๆ ที่เราพิมพ์คำสั่งคือโปรแกรมชื่อ **shell** ซึ่งอ่านข้อความที่เราพิมพ์แล้วตีความตามไวยากรณ์ของมันเอง Mac และ server Linux (ที่เราจะ deploy ในบท 19-21) ใช้ภาษาตระกูล **bash** ส่วน Windows มี **PowerShell** ซึ่งเป็นอีกภาษาหนึ่งเลย คำสั่งง่ายๆ อย่าง `cd`, `ls`, `mkdir` ดูเหมือนใช้ได้ทั้งคู่ เพราะ PowerShell ทำชื่อเล่น (alias) ไว้ให้ แต่พอเริ่มต่อคำสั่งด้วย `&&` หรือเขียนไฟล์ด้วย `>` ผลจะต่างกันทันที

ทุกคำสั่งในเล่มนี้เขียนเป็น bash ดังนั้นบน Windows ให้ใช้ **Git Bash** (bash ที่มากับ Git for Windows) ที่เดียว ทั้งเล่ม ข้อดีคือ ถ้าคำสั่งไม่ทำงาน เราจะรู้ว่าปัญหาอยู่ที่คำสั่งหรือโค้ดของเรา ไม่ต้องสงสัยว่าเป็นเพราะ shell อ่านคนละภาษา

**ตั้ง Git Bash เป็น Terminal เริ่มต้นของ VS Code** (ทำครั้งเดียว)

1. ติดตั้ง Git for Windows ให้เสร็จก่อน แล้ว **ปิด VS Code ทุกหน้าต่างแล้วเปิดใหม่** (VS Code หา Git Bash ตอนเปิดโปรแกรม ถ้าเปิดค้างไว้ตั้งแต่ก่อนติดตั้งจะไม่เห็นในรายการ)
2. กด `Ctrl + Shift + P` (เปิด Command Palette) พิมพ์ **Terminal: Select Default Profile** แล้วกด Enter
3. เลือก **Git Bash**
4. ปิด Terminal เก่าที่เปิดค้างอยู่ใน VS Code (ไอคอนถังขยะ 🗑 ที่แผง Terminal) แล้วกด ``Ctrl + ` `` เปิดใหม่ การตั้งค่านี้มีผลกับ Terminal ที่เปิด **หลังจาก** ตั้งเท่านั้น

ถ้าชอบแก้ไฟล์ตั้งค่าตรงๆ ผลเหมือนกัน: `Ctrl + Shift + P` → **Preferences: Open User Settings (JSON)** แล้วเพิ่มบรรทัดนี้ในวงเล็บปีกกา
```json
"terminal.integrated.defaultProfile.windows": "Git Bash"
```

นอก VS Code ก็เปิดได้: กดปุ่ม Start พิมพ์ **Git Bash**

**ตรวจว่าอยู่ใน Git Bash จริง** (ทำทุกครั้งที่ไม่แน่ใจ)
```bash
echo $SHELL
```
**ควรเห็น**
```
/usr/bin/bash
```
- ถ้าได้ **บรรทัดว่าง** แปลว่ากำลังอยู่ใน PowerShell (PowerShell ไม่มีตัวแปร `SHELL` จึงพิมพ์ค่าว่างออกมา)
- ดูจากหน้าตา prompt ได้ด้วย: Git Bash จะมีคำว่า **MINGW64** และขึ้นบรรทัดใหม่ด้วย `$` ส่วน PowerShell ขึ้นต้นด้วย `PS`
```
bit@LAPTOP-BIT MINGW64 ~
$                                  ← Git Bash ✅

PS C:\Users\bit>                   ← PowerShell ❌ (เปิด Terminal ใหม่เป็น Git Bash)
```
(บน Mac `echo $SHELL` ได้ `/bin/zsh` ซึ่งถูกต้องแล้ว)

> 🪟 **ทำไม PowerShell ถึงทำให้บทหลังๆ พัง** (Windows 10/11 มากับ **Windows PowerShell 5.1** ซึ่งเป็นตัวที่ VS Code เปิดให้ถ้าไม่ได้ตั้งค่า)
> | ในคู่มือเขียนแบบ bash | ถ้าพิมพ์ใน PowerShell 5.1 | เพราะอะไร |
> |---|---|---|
> | `mkdir demo && cd demo` | `The token '&&' is not a valid statement separator in this version.` | `&&` (ทำคำสั่งถัดไปเมื่อคำสั่งแรกสำเร็จ) เพิ่งมีใน PowerShell 7 |
> | `echo ".env" > .gitignore` | ไม่มี error แต่ Git ไม่สนใจ `.gitignore` นั้นเลย และ `git diff` บอก `Binary files differ` | `>` ใน PowerShell 5.1 เขียนไฟล์เป็น **UTF-16LE** ส่วน Git และเครื่องมือฝั่ง Linux คาดว่าเป็น UTF-8 จึงอ่านไม่ออก (เงียบแบบนี้อันตรายที่สุด) |
> | `psql -U postgres < backup.sql` | `The '<' operator is reserved for future use.` | PowerShell ไม่มีการป้อนไฟล์เข้าด้วย `<` |
> | `curl -X POST http://localhost:3000/...` | `A parameter cannot be found that matches parameter name 'X'.` หรือถาม `Uri:` | ใน PowerShell 5.1 `curl` เป็นชื่อเล่นของ `Invoke-WebRequest` ไม่ใช่โปรแกรม curl จริง |
> | คำสั่งยาวที่ต่อบรรทัดด้วย `\` ท้ายบรรทัด | บรรทัดแรกรันแบบขาดท่อน บรรทัดต่อไปกลายเป็นคำสั่งแยก | PowerShell ต่อบรรทัดด้วย `` ` `` ไม่ใช่ `\` |
> | `... > /dev/null` | `Could not find a part of the path` | `/dev/null` (ถังทิ้ง output) เป็นของ Linux PowerShell ใช้ `$null` |
> | `head`, `sed`, `grep`, `which` | `is not recognized as the name of a cmdlet` | เป็นโปรแกรมฝั่ง Linux ซึ่ง Git Bash มีให้ แต่ PowerShell ไม่มี |
>
> ใน Git Bash ทุกบรรทัดข้างบนทำงานตามที่หนังสือเขียน มีข้อยกเว้นแค่ไม่กี่คำสั่งที่ **Git Bash ก็ไม่มี** เช่น `lsof` และ `dig` บทที่ใช้คำสั่งพวกนี้จะให้คำสั่งของ Windows ไว้คู่กัน (เช่น `netstat -ano`, `nslookup` ซึ่งเรียกจาก Git Bash ได้)

> 🧩 **นิสัยของ Git Bash ที่ควรรู้ไว้ก่อน** Git Bash คือ bash ที่ทำงานบน Windows ผ่านชั้นแปลงชื่อ **MSYS2** ชั้นนี้ทำให้คำสั่งแบบ Linux ใช้ได้ แต่บางครั้งก็ "ช่วย" มากเกินไป มี 4 เรื่องที่จะเจอในเล่มนี้ ไม่ต้องจำตอนนี้ แค่จำได้ว่ามีกล่องนี้อยู่แล้วกลับมาเปิดเมื่อเจอ
>
> **1. path ที่ขึ้นต้นด้วย `/` ถูกแปลงเป็น path ของ Windows** (บท 2, 6, 7) Git Bash เข้าใจว่า `/var/lib/...` คือโฟลเดอร์ในเครื่องเรา เลยแปลงเป็น `C:/Program Files/Git/var/lib/...` ก่อนส่งให้โปรแกรม Windows อย่าง `docker` แต่จริงๆ เราหมายถึง path **ในกล่อง** อาการคือได้ error ที่มีคำว่า `C:/Program Files/Git/` โผล่มาทั้งที่เราไม่ได้พิมพ์ แก้โดยเติม `MSYS_NO_PATHCONV=1` หน้าคำสั่ง (ปิดการแปลงเฉพาะคำสั่งนั้นคำสั่งเดียว)
> ```bash
> MSYS_NO_PATHCONV=1 docker exec pg-test ls /var/lib/postgresql
> ```
> ถ้าเป็น bind mount (`-v` โฟลเดอร์ในเครื่อง:path ในกล่อง) ให้ใช้ `$(pwd -W)` ซึ่งได้ path ของเครื่องแบบ Windows เช่น `C:/Users/bit/bind-demo` ที่ Docker อ่านออกแน่นอน
> ```bash
> MSYS_NO_PATHCONV=1 docker run -d -p 8080:80 -v "$(pwd -W)/site:/usr/share/nginx/html:ro" nginx:alpine
> ```
>
> **2. `the input device is not a TTY` → เติม `winpty` ข้างหน้า** (บท 2, 6, 7) เกิดเมื่อรันคำสั่งที่ต้องโต้ตอบกับคีย์บอร์ด เช่น `docker exec -it ...` หรือ `psql` ในหน้าต่าง Git Bash ที่เปิดจาก Start menu (MinTTY) เพราะ MinTTY ไม่ใช่หน้าต่าง console ของ Windows โปรแกรม Windows จึงหาคีย์บอร์ดไม่เจอ `winpty` (มากับ Git for Windows) ทำหน้าที่เป็นสะพานเชื่อม ส่วน Terminal ใน VS Code มักไม่เจอปัญหานี้
> ```bash
> winpty docker exec -it pg-test psql -U postgres
> ```
>
> **3. ตัวขึ้นบรรทัดใหม่ CRLF กับ LF** (บท 1, 21) Windows จบบรรทัดด้วย 2 ตัวอักษร (CRLF) Linux ใช้ตัวเดียว (LF) ถ้าสคริปต์ `.sh` ที่มี CRLF ไปรันบน server หรือในกล่อง Docker จะได้ error แปลกๆ อย่าง `$'\r': command not found` หรือ `bash\r: No such file or directory` ค่า `core.autocrlf=true` ที่ installer ตั้งให้ช่วยได้ระดับหนึ่ง แต่เป็นค่าของเครื่องเราคนเดียว วิธีที่แน่นอนกว่าคือใส่ไฟล์ `.gitattributes` ไว้ใน repo เพราะไฟล์นี้ถูก commit ไปด้วย ทุกคนในทีมจึงได้กติกาเดียวกัน
> ```
> * text=auto
> *.sh text eol=lf
> ```
> (มุมขวาล่างของ VS Code บอกว่าไฟล์ที่เปิดอยู่เป็น `CRLF` หรือ `LF` คลิกเพื่อเปลี่ยนได้)
>
> **4. `chmod +x` ไม่ถูกบันทึกลง Git** (บท 21, 23) ระบบไฟล์ของ Windows ไม่มีสิทธิ์ "รันได้ (executable)" แบบ Linux Git for Windows จึงปิดการติดตามสิทธิ์นี้ไว้ (`core.filemode=false`) ถ้าแค่ `chmod +x deploy.sh` แล้ว commit พอไปถึง server จะได้ `Permission denied` ให้สั่ง Git ตรงๆ แล้ว commit
> ```bash
> git update-index --chmod=+x deploy.sh
> git ls-files -s deploy.sh
> ```
> **ควรเห็น** บรรทัดที่ขึ้นต้นด้วย `100755` (รันได้) ถ้าเป็น `100644` แปลว่ายังเป็นไฟล์ธรรมดา

> 🐧 **แล้ว WSL 2 ล่ะ?** WSL 2 คือ Linux จริงที่รันอยู่ใน Windows (Docker Desktop ใช้เป็นเครื่องยนต์เบื้องหลัง) ใช้เป็น Terminal ได้ดีและไม่มีนิสัย 4 ข้อข้างบน แต่ต้องติดตั้ง Git, Node, SSH key แยกอีกชุดฝั่ง Linux และควรเก็บโปรเจกต์ไว้ใน `~` ของ Linux ไม่ใช่ `/mnt/c/...` จะได้ไม่ช้า เล่มนี้จึง **ไม่บังคับ** ถ้าใช้ WSL อยู่แล้วก็ใช้ต่อได้ เพราะคำสั่ง bash ในเล่มใช้ได้เหมือนกัน แค่อย่าสลับไปมาระหว่าง WSL กับ Git Bash ในโปรเจกต์เดียวกัน

| อาการที่เห็น | สาเหตุ | วิธีแก้ |
|---|---|---|

| เปิด Terminal ใหม่แล้วก็ยังหาไม่เจอ (PATH ผิด) | โฟลเดอร์ที่ลงโปรแกรมไม่อยู่ใน PATH | ดูว่า PATH มีอะไร: `echo $PATH` (Mac และ Git Bash ใช้คำสั่งเดียวกัน) แล้วหาตำแหน่งโปรแกรมด้วย `which node` ถ้าไม่เจอเลยให้ติดตั้งใหม่ และตอนติดตั้งอย่าเอาตัวเลือก "Add to PATH" ออก (ถ้าเผลออยู่ใน PowerShell ให้ใช้ `where.exe node` เพราะ `where` เฉยๆ ใน PowerShell คือคำสั่งกรองข้อมูล `Where-Object` ซึ่งไม่แสดงอะไรเลย ทำให้นึกว่ายังไม่ได้ติดตั้ง) |
| `Permission denied` ตอนรันสคริปต์หรือเขียนไฟล์ (Mac) | ไม่มีสิทธิ์ในโฟลเดอร์/ไฟล์นั้น | ตรวจว่าอยู่ในโฟลเดอร์ของเราเอง (`~/Desktop/...`) ไม่ใช่โฟลเดอร์ระบบ ไฟล์สคริปต์ที่ต้องรันใช้ `chmod +x ชื่อไฟล์` |
| `EACCES: permission denied` ตอน `npm install -g` | พยายามเขียนลงโฟลเดอร์ที่ต้องใช้สิทธิ์ผู้ดูแล | **อย่าใช้ `sudo` เป็นนิสัย** แนะนำให้ติดตั้งแพ็กเกจเป็น dependency ของโปรเจกต์ (ไม่ใส่ `-g`) แล้วเรียกผ่าน `npx` หรือ `npm run` |
| `npm.ps1 cannot be loaded because running scripts is disabled on this system` (PowerShell) | กำลังพิมพ์อยู่ใน PowerShell ซึ่งปิดการรันสคริปต์ไว้ตามค่าเริ่มต้น | เปิด Terminal ใหม่เป็น **Git Bash** ตาม [หัวข้อนี้](#-windows-ใช้-git-bash-เท่านั้น) แล้วรันใหม่ (ไม่ต้องแก้ค่าใน PowerShell) |
| `The token '&&' is not a valid statement separator in this version.` | อยู่ใน PowerShell 5.1 ไม่ใช่ Git Bash | สลับไป Git Bash (ตรวจด้วย `echo $SHELL` ต้องได้ `/usr/bin/bash`) |
| `The '<' operator is reserved for future use.` | อยู่ใน PowerShell | สลับไป Git Bash |
| `curl` ถาม `Uri:` หรือขึ้น `A parameter cannot be found that matches parameter name` | ใน PowerShell 5.1 `curl` คือ `Invoke-WebRequest` | สลับไป Git Bash ซึ่งมี curl ตัวจริง |
| สร้าง `.gitignore` ด้วย `echo ... >` แล้ว Git ไม่สนใจ / `git diff` บอก `Binary files differ` | ไฟล์ถูกเขียนจาก PowerShell 5.1 เป็น UTF-16LE | ลบไฟล์นั้น แล้วสร้างใหม่ใน Git Bash (หรือสร้างใน VS Code ซึ่งบันทึกเป็น UTF-8) |
| error มี `C:/Program Files/Git/...` โผล่มาทั้งที่ไม่ได้พิมพ์ | Git Bash แปลง path ที่ขึ้นต้นด้วย `/` | เติม `MSYS_NO_PATHCONV=1` หน้าคำสั่ง (ดูกล่องนิสัยของ Git Bash ข้อ 1) |
| `the input device is not a TTY. If you are using mintty, try prefixing the command with 'winpty'` | หน้าต่าง Git Bash (MinTTY) ไม่ใช่ console ของ Windows | เติม `winpty` หน้าคำสั่ง หรือรันใน Terminal ของ VS Code แทน |
| `Cannot connect to the Docker daemon` / `error during connect` | Docker Desktop ยังไม่เปิดหรือยังเริ่มไม่เสร็จ | เปิดแอป Docker Desktop รอจนสถานะเป็นพร้อมใช้งาน (Running) แล้วลองใหม่ |
| Docker บน Windows แจ้งเรื่อง WSL 2 หรือ virtualization | WSL 2 ยังไม่ได้เปิด หรือปิด virtualization ใน BIOS | เปิด PowerShell แบบ Administrator พิมพ์ `wsl --install` แล้ว restart ถ้ายังไม่ได้ ให้เปิด Virtualization (ชื่ออาจเป็น Intel VT-x / AMD-V / SVM) ใน BIOS ตามคู่มือของเครื่อง หรือถามพี่ |
| `code: command not found` | VS Code ยังไม่ได้ติดตั้งคำสั่ง `code` ใน PATH | เปิด VS Code กด `Cmd/Ctrl + Shift + P` พิมพ์ **Shell Command: Install 'code' command in PATH** (Windows มักตั้งให้ตอนติดตั้ง) |
| ติดตั้งผ่าน VPN/พร็อกซีบริษัทแล้วโหลดไม่ได้ (`ETIMEDOUT`, `certificate`) | เครือข่ายบล็อกหรือแทรกแซงการดาวน์โหลด | ลองสลับเครือข่าย (เช่น ฮอตสปอตมือถือ) หรือถามพี่ไบต์ ซึ่งรู้ค่า proxy ของบริษัท |
| ได้ Node เวอร์ชันเก่า (เช่นขึ้นเลขต่ำกว่าที่ติดตั้ง) | มี Node เก่าติดตั้งอยู่ก่อน และอยู่ก่อนใน PATH | ดูว่าตัวไหนถูกเรียก `which -a node` (Mac และ Git Bash) แล้วถอนตัวเก่าออก หรือถามพี่ |

> 🧭 **ขั้นตอนคิดเวลาติดขัด:** (1) อ่านข้อความ error ทั้งหมด อย่าอ่านแค่บรรทัดแรก (2) ก๊อปข้อความ error ไปค้นหา (3) ปิด-เปิด Terminal/โปรแกรมใหม่ (4) ถามพี่ โดยแนบ **ข้อความ error เต็มๆ + คำสั่งที่พิมพ์ + ระบบปฏิบัติการ** การถามแบบนี้ทำให้ได้คำตอบเร็วกว่ามาก

## 4. 🔧 Terminal เบื้องต้น

> 🪟 **Windows:** ทุกคำสั่งตั้งแต่นี้ไปรันใน **Git Bash** (ตรวจด้วย `echo $SHELL` ต้องได้ `/usr/bin/bash`)

Terminal มีแนวคิดเดียว: **เราอยู่ในโฟลเดอร์หนึ่งเสมอ** และทุกคำสั่งทำงานจากโฟลเดอร์นั้น

![ต้นไม้โฟลเดอร์และคำสั่ง pwd ls cd](/img/00-folders.svg)
*ตำแหน่งปัจจุบันเปลี่ยนไปตามคำสั่ง cd*

```bash
pwd                  # ตอนนี้อยู่โฟลเดอร์ไหน
ls                   # ดูไฟล์ในโฟลเดอร์นี้
mkdir playground     # สร้างโฟลเดอร์ใหม่
cd playground        # เข้าไปในโฟลเดอร์
cd ..                # ถอยออกมา 1 ชั้น
code .               # เปิดโฟลเดอร์ปัจจุบันใน VS Code
```

**ลองทำตามทีละขั้น** (เริ่มจากเปิด Terminal ใหม่):
```bash
pwd
```
**ควรเห็น** โฟลเดอร์ home ของเรา เช่น `/Users/bit` (Mac) หรือ `/c/Users/bit` (Git Bash ซึ่งเขียน `C:\Users\bit` แบบ Linux: ไดรฟ์ `C:` กลายเป็น `/c` และใช้ `/` แทน `\`)

```bash
cd ~
mkdir playground
cd playground
pwd
```
**ควรเห็น** `/Users/bit/playground` (Mac) หรือ `/c/Users/bit/playground` (Git Bash) เป็นการยืนยันว่าเข้ามาในโฟลเดอร์ที่สร้างแล้ว

> 💡 `~` คือชื่อย่อของโฟลเดอร์ home ใช้ได้ทั้ง Mac และ Git Bash เล่มนี้เก็บงานไว้ใต้ `~` แทน Desktop เพราะบน Windows ที่เปิด OneDrive ไว้ Desktop มักถูกย้ายไปอยู่ใน `~/OneDrive/Desktop` ทำให้ `cd Desktop` หาไม่เจอ และ OneDrive ยังพยายาม sync โฟลเดอร์ `node_modules` ที่มีไฟล์เป็นหมื่นไฟล์ด้วย

```bash
echo "hello" > hello.txt
ls
```
**ควรเห็น** `hello.txt` ในรายการ

> 🪟 **Windows ต่างจาก Mac ตรงไหน** ถ้าใช้ Git Bash แทบไม่ต่างเลย คำสั่งในเล่มพิมพ์ได้ตรงตัว ตารางนี้มีไว้เผื่ออ่านคำตอบในเว็บที่เขียนสำหรับ PowerShell จะได้แปลกลับเป็นแบบที่เราใช้ได้
> | ทำอะไร | Mac / Git Bash (ที่เราใช้) | PowerShell (ที่อาจเจอในเว็บ) |
> |---|---|---|
> | ดูไฟล์ | `ls` | `ls` หรือ `dir` |
> | ดูเนื้อไฟล์ | `cat hello.txt` | `cat hello.txt` หรือ `type hello.txt` |
> | หาตำแหน่งโปรแกรม | `which node` | `where.exe node` หรือ `Get-Command node` |
> | ลบไฟล์ | `rm hello.txt` | `rm hello.txt` หรือ `del hello.txt` |
> | ตัวแบ่ง path | `/` เช่น `/c/Users/bit` | `\` เช่น `C:\Users\bit` |
> | ต่อคำสั่งยาวขึ้นบรรทัดใหม่ | `\` | `` ` `` |
>
> ถ้าคำสั่งในเล่มไม่ทำงานบน Windows ให้ตรวจ `echo $SHELL` ก่อนเป็นอย่างแรก ส่วนใหญ่เป็นเพราะเผลอเปิด PowerShell

> 💡 **ทริคประหยัดนิ้ว**
> - พิมพ์ชื่อไฟล์แค่บางส่วนแล้วกด `Tab` ระบบเติมให้
> - กด `↑` เรียกคำสั่งก่อนหน้า
> - กด `Ctrl + C` หยุดโปรแกรมที่กำลังรันค้างอยู่
> - พิมพ์ `clear` ล้างหน้าจอ

> 🤓 **เกร็ด:** ทำไมโปรแกรมเมอร์ชอบ Terminal ทั้งที่คลิกง่ายกว่า? เพราะคำสั่งที่พิมพ์ **ก๊อปส่งให้เพื่อน บันทึกลงไฟล์ และสั่งให้ทำซ้ำอัตโนมัติได้** ส่วนการคลิกทำแบบนั้นไม่ได้

### PATH คืออะไร (ทำไมถึงเจอ command not found บ่อย)

เมื่อเราพิมพ์ `node` Terminal ไม่ได้รู้จักโปรแกรมนั้นเอง แต่ไล่ดูโฟลเดอร์ทีละอันใน **PATH** จนกว่าจะเจอไฟล์ชื่อ `node`

## 5. ✅ ทดสอบทั้งระบบเบื้องต้น: รันเว็บเซิร์ฟเวอร์จิ๋ว

ขอพิสูจน์ว่าเครื่องมือทั้งหมดทำงานจริง และเห็นภาพ localhost + port ด้วยตาตัวเอง

```bash
cd ~/playground
echo "<h1>Hello Blicktech</h1>" > index.html
npx --yes serve .
```
(`npx` มากับ npm ครั้งแรกอาจถามหรือดาวน์โหลดแพ็กเกจ `serve` ให้)

**ควรเห็น** ข้อความทำนองว่า Serving! และมี URL เช่น `http://localhost:3000` (เลข port อาจต่างกัน ให้ดูที่ข้อความที่ขึ้น)

เปิด Browser ไปที่ URL นั้น จะเห็นหัวข้อ **Hello Blicktech** นั่นคือ Browser (client) ส่งคำขอไปหา server ที่เปิดอยู่ในเครื่องเราเอง (localhost) ที่ port นั้น

กด `Ctrl + C` ใน Terminal เพื่อหยุด server แล้วลองรีเฟรชหน้าเว็บ จะเปิดไม่ได้ เพราะ "พนักงานหน้าร้าน" ออกจากงานไปแล้ว

## 💥 ลองพังมันดู

พังเองในที่ปลอดภัย จะได้ไม่ตกใจตอนเจอจริง:

1. พิมพ์ `nodee --version` (สะกดผิด) → ได้ `command not found` หรือ `is not recognized` ซึ่งแปลว่า "ไม่รู้จักคำสั่งนี้" ไม่ได้แปลว่าเครื่องพัง
2. รัน `cd โฟลเดอร์ที่ไม่มีอยู่จริง` → ขึ้น `No such file or directory` / `Cannot find path`
3. รัน `npx --yes serve .` ค้างไว้ แล้วเปิด Terminal อีกหน้าต่าง รัน `npx --yes serve . -l 3000` อีกครั้ง → จะขึ้นว่า port ถูกใช้แล้ว หรือเสนอให้ไปใช้ port อื่น (ข้อความต่างกันตามเวอร์ชัน) นี่คือเหตุผลที่แต่ละโปรแกรมต้องมี port ของตัวเอง

## 🧠 เช็คความเข้าใจ

<details>
<summary>1. "API รันที่ localhost:3000" แปลว่าอะไร?</summary>

โปรแกรม API กำลังทำงานอยู่ในเครื่องของเราเอง และรอรับคำขอที่ช่องหมายเลข 3000

</details>

<details>
<summary>2. ทำไมรหัสผ่านฐานข้อมูลถึงควรอยู่ใน environment variable ไม่ใช่เขียนในโค้ด?</summary>

เพราะโค้ดถูกเก็บใน Git และแชร์ให้หลายคน ถ้าเขียนรหัสผ่านไว้ในโค้ด ใครเห็นโค้ดก็เห็นรหัสผ่าน (รายละเอียดในบทที่ 10)

</details>

<details>
<summary>3. ทำไม Browser ไม่ควรคุยกับ Database ตรงๆ?</summary>

เพราะโค้ดใน Browser ผู้ใช้เปิดดูได้ ถ้าต่อ DB ตรงก็ต้องเอารหัสไว้ในนั้น และกฎธุรกิจก็ตรวจไม่ได้อย่างน่าเชื่อถือ จึงให้ผ่าน Server (API) ที่ควบคุมได้

</details>

<details>
<summary>4. ติดตั้ง Node.js เสร็จแล้ว แต่ Terminal ที่เปิดค้างไว้ขึ้น command not found ควรทำอะไรก่อน?</summary>

ปิด Terminal แล้วเปิดใหม่ เพราะ Terminal อ่านค่า PATH ตอนเปิดเท่านั้น

</details>

<details>
<summary>5. Frontend กับ Backend ต่างกันยังไง?</summary>

Frontend ทำงานในเครื่องผู้ใช้ (Browser) เกี่ยวกับสิ่งที่เห็นและโต้ตอบ ส่วน Backend ทำงานบน server เกี่ยวกับกฎ ความปลอดภัย และการอ่าน/เขียนข้อมูล

</details>
