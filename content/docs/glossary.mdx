> เจอคำไหนในคู่มือแล้วงง เปิดหน้านี้ได้ตลอด
> ไม่ต้องท่องจำ อ่านผ่านๆ ให้คุ้นก่อน แล้วจะเข้าใจเองเมื่อได้ลงมือในบทนั้น
> คำในแต่ละกลุ่มเรียงตามลำดับที่จะเจอในคู่มือ
> หาคำเร็วๆ กด **ค้นหา** ที่แถบด้านบน หรือดูหัวข้อ "คำที่มักสับสน" ถ้าสองคำฟังคล้ายกันจนงง

## เข้าใจปัญหาก่อนทำ (/learn ขั้น 1–2)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="requirement">**Requirement**</span> | เอกสารที่ลูกค้าบอกว่าระบบต้องทำอะไรได้ มีข้อห้ามอะไร และตรวจรับยังไง ([การ์ด](/learn/cards/reading-requirements)) | สูตรอาหารที่ต้องอ่านจบก่อนเข้าครัว |
| <span id="brief">**Brief**</span> | สรุป 1 หน้าว่าธุรกิจนี้คือใคร ขายอะไร ให้ใคร สีและโลโก้แบบไหน ใช้ตัดสินเรื่องเล็กทุกเรื่องในงาน ([การ์ด](/learn/cards/business-brief)) | ใบสั่งตัดชุด |
| <span id="user-story">**User story**</span> | ความต้องการ 1 อย่าง เขียนว่า "ในฐานะ [ใคร] อยาก [ทำอะไร] เพื่อ [ได้อะไร]" ([การ์ด](/learn/cards/user-stories)) | ใบสั่งงานช่าง 1 ใบ |
| <span id="acceptance-criteria">**Acceptance criteria (เกณฑ์ว่าเสร็จ)**</span> | ข้อที่ตรวจได้ว่าผ่านหรือไม่ผ่าน ทำให้ "เสร็จ" ของคนทำตรงกับของลูกค้า และกลายเป็นเช็กลิสต์ตอนทดสอบ | "ปิดก๊อกแล้วไม่หยด 1 นาที" |
| <span id="scope-creep">**Scope creep**</span> | งานที่งอกทีละนิดจนไม่ทันกำหนด กันด้วยรายการ "ไม่ทำรอบนี้" ที่ตกลงกันตั้งแต่ต้น ([การ์ด](/learn/cards/scope-questions)) | รับทาสีห้องเดียว แล้วโดนขอเพดานกับประตูเพิ่ม |
| <span id="wireframe">**Wireframe**</span> | ภาพร่างหน้าจอด้วยกล่องสีเทา บอกว่ามีอะไร อยู่ตรงไหน อะไรสำคัญกว่า ยังไม่มีสีหรือรูปจริง ([การ์ด](/learn/cards/wireframe)) | แปลนบ้านดินสอ ก่อนเลือกกระเบื้อง |
| <span id="user-flow">**User flow**</span> | ลำดับการกดและหน้าจอที่ผู้ใช้ผ่านเพื่อทำงาน 1 อย่าง รวมทางแยกเมื่อมีอะไรผิดพลาด ([การ์ด](/learn/cards/user-flow)) | แผนผังทางหนีไฟ ที่บอกด้วยว่าประตูปิดแล้วไปทางไหน |
| <span id="er-diagram">**ER diagram**</span> | ภาพตารางทั้งหมดในระบบ และเส้นบอกว่าตารางไหนชี้ไปหาตารางไหน (1 ต่อ 1, 1 ต่อหลาย, หลายต่อหลาย) ([การ์ด](/learn/cards/er-diagram)) | ผังครอบครัว ดูแผ่นเดียวรู้ว่าใครเป็นลูกใคร |

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="test-case">**Test case**</span> | การทดสอบ 1 ข้อ บอกว่า "ทำอะไร" และ "ต้องเห็นอะไร" ตัดสินได้ว่าผ่านหรือไม่ผ่าน คนอื่นทำตามได้โดยไม่ต้องถาม ([การ์ด](/learn/cards/manual-testing)) | 1 บรรทัดในใบตรวจบ้านก่อนรับโอน |

## พื้นฐาน (บทที่ 0–5)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="terminal">**Terminal**</span> | หน้าจอที่พิมพ์คำสั่งให้คอมทำงาน | คุยกับคอมด้วยการพิมพ์ แทนการคลิก |
| <span id="shell">**Shell / PowerShell / Git Bash**</span> | โปรแกรมที่อ่านคำสั่งที่เราพิมพ์ใน Terminal แล้วสั่งคอมทำ แต่ละตัวพูดคนละสำเนียง คู่มือนี้เขียนแบบ bash (Mac/Linux และ Git Bash บน Windows) คำสั่งบางตัวใช้ใน PowerShell ไม่ได้หรือทำงานต่างกัน | Terminal = โทรศัพท์ / Shell = คนรับสายที่พูดภาษาของเขา |
| <span id="cli-gui">**CLI vs GUI**</span> | CLI = สั่งงานด้วยการพิมพ์คำสั่ง / GUI = สั่งงานด้วยการคลิกหน้าจอ CLI ทำซ้ำและเขียนเป็นสคริปต์ได้ง่ายกว่า | สั่งอาหารด้วยการพูด กับชี้รูปในเมนู |
| <span id="path-env">**PATH**</span> | รายชื่อโฟลเดอร์ที่ shell ไปหาโปรแกรมเมื่อเราพิมพ์ชื่อคำสั่ง ถ้าขึ้น `command not found` ทั้งที่ติดตั้งแล้ว มักเพราะโฟลเดอร์ของโปรแกรมไม่อยู่ใน PATH (หรือยังไม่ได้เปิด Terminal ใหม่) | รายชื่อห้องที่พนักงานจะเดินไปหาคน |
| <span id="sudo">**sudo**</span> | สั่งคำสั่งนั้นด้วยสิทธิ์ผู้ดูแลเครื่อง (root) บน Mac/Linux ใช้เท่าที่จำเป็น เพราะทำพังได้ทั้งเครื่อง | ยืมกุญแจผู้จัดการตึกมาเปิดห้องเดียว |
| <span id="lts">**LTS**</span> | รุ่นที่ผู้พัฒนารับปากว่าจะดูแลแก้บั๊ก/ช่องโหว่ให้นาน (Long-Term Support) เช่น Node รุ่นเลขคู่ เหมาะกับงานจริง | รถรุ่นที่มีอะไหล่ขายอีกหลายปี |
| <span id="kernel-daemon-vm">**Kernel / Daemon / VM**</span> | Kernel = แกนกลางของระบบปฏิบัติการที่คุมฮาร์ดแวร์ · Daemon = โปรแกรมที่รันเงียบๆ อยู่เบื้องหลัง เช่น Docker daemon · VM = คอมจำลองทั้งเครื่องพร้อม OS ของตัวเอง (บทที่ 2) | เครื่องยนต์ · พนักงานกะดึก · บ้านจำลองทั้งหลังในโกดัง |
| <span id="server">**Server**</span> | โปรแกรมหรือเครื่องที่รอรับคำขอแล้วตอบกลับ | พนักงานหน้าร้าน |
| <span id="client">**Client**</span> | ฝั่งที่ส่งคำขอ เช่น เว็บเบราว์เซอร์ แอปมือถือ | ลูกค้า |
| <span id="url">**URL**</span> | ที่อยู่เต็มของสิ่งหนึ่งบนเว็บ เช่น `https://shop.com:443/laptops?q=asus` = โปรโตคอล + ชื่อเครื่อง + port + path + query | ที่อยู่บนซองจดหมาย: ประเทศ ถนน บ้านเลขที่ ห้อง |
| <span id="html-css">**HTML / CSS**</span> | HTML = โครงและเนื้อหาของหน้าเว็บ (หัวข้อ ย่อหน้า ปุ่ม) · CSS = กฎการแต่ง (สี ขนาด ตำแหน่ง) เบราว์เซอร์อ่านทั้งสองแล้ววาดหน้าจอ | โครงบ้าน กับ สีและการตกแต่ง |
| <span id="api">**API**</span> | ช่องทางที่โปรแกรมคุยกัน มีรูปแบบตกลงกันไว้ | เมนูอาหาร สั่งได้เฉพาะที่มีในเมนู |
| <span id="json">**JSON**</span> | รูปแบบข้อมูลที่โปรแกรมส่งหากัน | แบบฟอร์มที่ทุกคนอ่านออก |
| <span id="localhost">**localhost**</span> | ชื่อเรียก "เครื่องของเราเอง" | บ้านตัวเอง |
| <span id="port">**Port**</span> | เลขช่องทางของแต่ละโปรแกรมในเครื่องเดียวกัน | เลขห้องในตึกเดียวกัน |
| <span id="database">**Database (DB)**</span> | โปรแกรมเก็บและค้นข้อมูล | ตู้เอกสารที่ค้นไวมาก |
| <span id="package">**Package**</span> | โค้ดสำเร็จรูปที่คนอื่นเขียนไว้ให้ใช้ | ชิ้นส่วนสำเร็จรูป ไม่ต้องสร้างล้อเอง |
| <span id="env">**.env / Environment variable**</span> | Environment variable (env var) = ค่าตั้งค่าที่ส่งให้โปรแกรมตอนรัน อ่านด้วย `process.env.X` · `.env` = ไฟล์ในเครื่องที่จดค่าเหล่านั้นไว้ (รวมรหัสลับ) ไม่ขึ้น Git บางเครื่องมือโหลดไฟล์นี้ให้เอง (Bun) บางตัวต้องใช้ dotenv | env var = กุญแจที่ยื่นให้ตอนเข้างาน / `.env` = พวงกุญแจที่เก็บในลิ้นชัก ไม่แขวนไว้หน้าบ้าน |
| <span id="repo">**Repo (Repository)**</span> | โฟลเดอร์โปรเจกต์ที่ Git จดประวัติไว้ | สมุดบันทึกทุกการแก้ไข |
| <span id="untracked">**Untracked / Modified**</span> | สถานะไฟล์ใน `git status` · untracked = ไฟล์ใหม่ที่ Git ยังไม่เคยจด · modified = ไฟล์ที่ Git จดแล้ว แต่ถูกแก้หลัง commit ล่าสุด | ของใหม่ที่ยังไม่ลงทะเบียน / ของในทะเบียนที่ถูกขยับ |
| <span id="commit-hash">**Commit hash (รหัส commit)**</span> | รหัสประจำ commit เช่น `a1b2c3d` (ย่อจาก 40 ตัว) คำนวณจากเนื้อหาและประวัติ จึงไม่ซ้ำกัน ใช้อ้างถึง commit นั้น เช่น `git show a1b2c3d` (คนละความหมายกับ hash รหัสผ่านในบทที่ 10 แต่ใช้หลักคณิตศาสตร์ตระกูลเดียวกัน) | เลขพัสดุ ใช้ตามหาของชิ้นนั้นได้ชิ้นเดียว |
| <span id="branch">**Branch**</span> | ทางแยกของโค้ด ลองแก้ได้โดยไม่กระทบของหลัก | ถ่ายเอกสารไปลองเขียน ต้นฉบับไม่เปื้อน |
| <span id="commit">**Commit**</span> | การบันทึกงานหนึ่งครั้งใน Git | กดเซฟเกม |
| <span id="pr">**PR / MR (Pull / Merge Request)**</span> | คำขอเอางานใน branch รวมเข้าของหลัก ให้คนอื่นตรวจก่อน | ส่งการบ้านให้ครูตรวจ |
| <span id="docker">**Docker / Container**</span> | กล่องที่ใส่โปรแกรมพร้อมของที่มันต้องใช้ ย้ายไปเครื่องไหนก็รันได้ | ข้าวกล่องพร้อมช้อน เปิดกินได้ทุกที่ |
| <span id="image">**Image**</span> | แม่แบบของกล่อง Docker | แม่พิมพ์ |
| <span id="volume">**Volume**</span> | ที่เก็บข้อมูลของกล่อง ลบกล่องแล้วข้อมูลไม่หาย | ตู้เซฟนอกกล่อง |
| <span id="runtime">**Runtime (Node, Bun)**</span> | โปรแกรมที่รันโค้ด JavaScript/TypeScript | เครื่องเล่นแผ่น |
| <span id="type">**Type**</span> | ชนิดของข้อมูล เช่น ตัวเลข ข้อความ | ป้ายบอกว่ากล่องนี้ใส่อะไร |
| <span id="zod">**Zod**</span> | ตัวช่วยตรวจข้อมูลที่ส่งเข้ามา ว่าครบและถูกรูปแบบไหม | ยามตรวจบัตรหน้าประตู |
| <span id="schema-zod">**Schema (แบบ Zod)**</span> | กฎที่เขียนเป็นโค้ดว่าข้อมูลต้องหน้าตาแบบไหน แล้ว**รันตรวจจริงตอนรัน** (ต่างจาก Schema ของฐานข้อมูลที่หมายถึงผังตาราง) ([บทที่ 4](/04-typescript)) | ใบตรวจรับสินค้า: ต้องมีอะไรบ้าง ชนิดไหน |
| <span id="tsconfig">**tsconfig.json / `strict`**</span> | ไฟล์ตั้งค่าของ TypeScript ว่าจะตรวจเข้มแค่ไหน ตรวจไฟล์ไหน build ไปที่ไหน `strict: true` = เปิดการตรวจเข้มทุกข้อ (บริษัทบังคับ) | ตั้งระดับความละเอียดของโปรแกรมตรวจคำผิด |
| <span id="any-unknown">**`any` vs `unknown`**</span> | ทั้งคู่แปลว่า "เป็นอะไรก็ได้" แต่ `any` = ปิดการตรวจ ใช้ได้ทุกอย่างโดยไม่เตือน / `unknown` = ยังไม่รู้ ต้องตรวจ (narrowing หรือ Zod) ก่อนถึงจะใช้ได้ ✅ | กล่องไม่มีป้ายที่เปิดใช้เลย / กล่องไม่มีป้ายที่ต้องตรวจก่อนเปิด |
| <span id="inference">**Type inference**</span> | TypeScript เดา type ให้เองจากค่า เช่น `const n = 5` รู้ว่าเป็น `number` ไม่ต้องเขียนทุกที่ | คนที่เห็นแก้วกาแฟแล้วรู้ว่าเป็นกาแฟ ไม่ต้องติดป้าย |
| <span id="endpoint">**Endpoint**</span> | ที่อยู่ 1 จุดใน API เช่น `GET /api/services` | 1 เมนูในร้าน |
| <span id="method">**Method (GET / POST / PUT / PATCH / DELETE)**</span> | บอกว่าจะ ดู / สร้าง / แทนที่ทั้งก้อน / แก้บางช่อง / ลบ | กริยาในประโยค |
| <span id="status-code">**Status code**</span> | ตัวเลขบอกผล เช่น 200 สำเร็จ, 404 ไม่พบ | ไฟเขียว ไฟแดง |
| <span id="handler">**Handler**</span> | ฟังก์ชันที่ทำงานเมื่อมีเหตุการณ์ที่รอไว้ เช่น มีคำขอเข้า endpoint (route handler) หรือกดปุ่ม (event handler) | พนักงานที่ได้รับมอบหมายให้รับเรื่องประเภทนี้ |
| <span id="try-catch">**try / catch**</span> | ครอบโค้ดที่อาจพังด้วย `try` ถ้าพังจะกระโดดไป `catch` ให้จัดการ (บอกผู้ใช้ / log) แทนที่โปรแกรมจะล้ม | ตาข่ายใต้นักกายกรรม |

## ข้อมูล (บทที่ 6–8)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="table">**ตาราง / แถว / คอลัมน์**</span> | ข้อมูลในฐานข้อมูลเก็บเป็นตารางแบบ Excel | สมุดบัญชี |
| <span id="primary-key">**Primary key (id)**</span> | เลขประจำตัวของแต่ละแถว ไม่ซ้ำกัน | เลขบัตรประชาชน |
| <span id="foreign-key">**Foreign key (FK)**</span> | ช่องที่อ้างถึงแถวในอีกตาราง | ใบสั่งซื้อจดเลขลูกค้าไว้ |
| <span id="unique">**Unique**</span> | ห้ามมีค่าซ้ำในคอลัมน์นี้ | อีเมลซ้ำกันไม่ได้ |
| <span id="sql">**SQL**</span> | ภาษาที่ใช้สั่งฐานข้อมูล | ภาษาที่บรรณารักษ์เข้าใจ |
| <span id="orm">**ORM (Drizzle, Prisma)**</span> | ตัวช่วยให้เขียน TypeScript แทน SQL | ล่ามแปลภาษา |
| <span id="schema">**Schema**</span> | แบบแปลนว่ามีตารางอะไร คอลัมน์อะไร | แบบแปลนบ้าน |
| <span id="migration">**Migration**</span> | ไฟล์จดการเปลี่ยนโครงสร้างตาราง ทีละขั้น | บันทึกการต่อเติมบ้าน |
| <span id="seed">**Seed**</span> | ข้อมูลตั้งต้นที่ใส่ลงฐานข้อมูลตอนเริ่ม | ของตัวอย่างวางโชว์ตอนเปิดร้าน |
| <span id="transaction">**Transaction**</span> | ทำหลายอย่างพร้อมกัน ถ้าพังสักขั้นให้ยกเลิกทั้งหมด | โอนเงิน: หักต้นทางแล้วต้องเข้าปลายทาง ไม่งั้นคืนเงิน |
| <span id="jsonb">**jsonb**</span> | ช่องในตาราง Postgres ที่เก็บข้อมูลแบบ JSON ได้ | ลิ้นชักจิปาถะในตู้เอกสาร |
| <span id="constraint">**Constraint**</span> | กฎที่ฐานข้อมูลบังคับเอง เช่น `NOT NULL`, `UNIQUE`, `CHECK`, foreign key ข้อมูลที่ผิดกฎใส่ไม่ได้ไม่ว่าโค้ดจะพลาดแค่ไหน | ประตูที่ล็อกเอง ไม่ต้องพึ่งยาม |
| <span id="explain">**EXPLAIN**</span> | สั่งให้ฐานข้อมูลบอกแผนว่าจะหาข้อมูลยังไง (ไล่ทุกแถว หรือใช้ index) ใช้หาสาเหตุ query ช้า | ถาม GPS ว่าจะไปทางไหน ก่อนออกรถ |
| <span id="session">**Session**</span> | การ "จำ" ว่าผู้ใช้คนนี้ login แล้ว server เก็บข้อมูลไว้ฝั่งตัวเอง (DB หรือ Redis) แล้วให้ browser ถือแค่รหัส session ใน cookie (ต่างจาก JWT ที่ใส่ข้อมูลไว้ในบัตรเอง) | บัตรฝากของ: ของอยู่ที่เคาน์เตอร์ เราถือแค่เลขบัตร |
| <span id="embedding">**Embedding**</span> | ชุดตัวเลขที่แทน "ความหมาย" ของข้อความ/รูป ความหมายใกล้กันตัวเลขจะใกล้กัน ใช้ค้นหาด้วยความหมายใน vector database | พิกัดบนแผนที่ความหมาย |
| <span id="eventual-consistency">**Eventual consistency**</span> | อ่านทันทีหลังเขียนอาจยังเห็นค่าเก่า แต่รอสักครู่ทุกเครื่องจะตรงกัน พบในระบบที่กระจายหลายเครื่อง | ข่าวที่ค่อยๆ ไปถึงทุกสาขา |

## ความปลอดภัย (บทที่ 10, 15)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="hash">**Hash**</span> | แปลงรหัสผ่านเป็นข้อความมั่วๆ ที่ย้อนกลับไม่ได้ | บดผลไม้เป็นน้ำปั่น คืนเป็นผลไม้ไม่ได้ |
| <span id="jwt">**JWT (Token)**</span> | บัตรผ่านที่ server ออกให้หลัง login มีลายเซ็นกันปลอม | สายรัดข้อมือเข้างานคอนเสิร์ต |
| <span id="cookie">**Cookie**</span> | ข้อมูลเล็กๆ ที่เบราว์เซอร์เก็บไว้ และแนบไปกับทุกคำขอให้เอง | บัตรจอดรถที่ติดหน้ารถ |
| <span id="httponly">**HttpOnly**</span> | ตั้งให้ cookie ถูกอ่านโดยโค้ดในหน้าเว็บไม่ได้ | ซองปิดผนึกที่เปิดได้แค่ที่ server |
| <span id="middleware">**Middleware**</span> | ด่านตรวจที่ทุกคำขอต้องผ่านก่อนถึงโค้ดจริง | รปภ. หน้าลิฟต์ |
| <span id="rate-limit">**Rate limit**</span> | จำกัดจำนวนครั้งที่ส่งได้ในช่วงเวลาหนึ่ง | กดบัตรคิวได้คนละ 5 ใบต่อ 10 นาที |
| <span id="xss">**XSS**</span> | คนร้ายแอบใส่โค้ดลงหน้าเว็บเพื่อขโมยข้อมูล | แอบสอดจดหมายปลอมในตู้ไปรษณีย์ |
| <span id="cors">**CORS**</span> | กฎของเบราว์เซอร์ว่าเว็บไหนเรียก API ของใครได้ | ป้ายหน้าตึก "เฉพาะคนในบริษัท" |
| <span id="401">**401 / 403**</span> | 401 = ยังไม่ได้ login, 403 = login แล้วแต่ไม่มีสิทธิ์ | ไม่มีบัตร / มีบัตรแต่ห้ามขึ้นชั้นนี้ |

## หน้าเว็บ (บทที่ 11–13)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="frontend">**หน้าบ้าน / หลังบ้าน (Frontend / Backend)**</span> | หน้าบ้าน = ส่วนที่ลูกค้าเห็น / หลังบ้าน = ส่วนที่ทำงานเบื้องหลังและหน้าจัดการของเจ้าของร้าน | หน้าร้าน กับ ห้องครัว |
| <span id="admin">**Admin**</span> | คนดูแลระบบ ในงานนี้คือเจ้าของร้าน | ผู้จัดการร้าน |
| <span id="react">**React**</span> | เครื่องมือสร้างหน้าเว็บจากชิ้นส่วนเล็กๆ | ตัวต่อเลโก้ |
| <span id="component">**Component**</span> | ชิ้นส่วน 1 ชิ้นของหน้าเว็บ เช่น ปุ่ม การ์ด เมนู | แม่พิมพ์ขนม |
| <span id="props">**Props**</span> | ข้อมูลที่ส่งเข้าไปในชิ้นส่วน | ไส้ที่ใส่ในแม่พิมพ์ |
| <span id="state">**State**</span> | ข้อมูลที่เปลี่ยนได้ เปลี่ยนแล้วหน้าจอเปลี่ยนตาม | คะแนนบนป้ายสกอร์ |
| <span id="vite">**Vite**</span> | เครื่องมือรันเว็บตอนพัฒนา และแพ็กเว็บตอนจะขึ้นจริง | เตาอบที่ร้อนไวมาก |
| <span id="build">**Build**</span> | แปลงโค้ดที่เราเขียนเป็นไฟล์พร้อมใช้งานจริง | อบขนมเสร็จพร้อมขาย |
| <span id="tailwind">**Tailwind**</span> | ตกแต่งหน้าเว็บด้วยคำสั้นๆ เช่น `p-4` `text-xl` | สติกเกอร์สำเร็จรูป |
| <span id="responsive">**Responsive**</span> | หน้าเว็บจัดตัวเองให้พอดีทุกขนาดจอ | น้ำที่เทลงแก้วไหนก็พอดีแก้ว |
| <span id="breakpoint">**Breakpoint**</span> | ความกว้างจอที่หน้าเว็บเปลี่ยนการจัดวาง | จุดที่เปลี่ยนจากชุดเด็กเป็นชุดผู้ใหญ่ |
| <span id="router">**Router / Route**</span> | ตัวจับคู่ว่า URL ไหน แสดงหน้าไหน | ป้ายบอกทางในห้าง |
| <span id="spa">**SPA**</span> | เว็บที่โหลดครั้งเดียว แล้วสลับหน้าเองโดยไม่โหลดใหม่ | สมุดภาพแบบพลิกหน้า |
| <span id="seo">**SEO**</span> | ทำให้ Google หาเว็บเราเจอและเข้าใจเนื้อหา | ติดป้ายร้านให้มองเห็นจากถนน |
| <span id="og">**OG tags**</span> | ข้อมูลที่ LINE/Facebook ใช้ทำการ์ดตอนแชร์ลิงก์ (รูป หัวข้อ คำอธิบาย) | ปกหนังสือ |
| <span id="loading-state">**Loading / Error state**</span> | สิ่งที่หน้าเว็บแสดงระหว่างรอข้อมูล หรือเมื่อโหลดพัง | ป้าย "กำลังเตรียมอาหาร" / "ขออภัย ของหมด" |
| <span id="proxy-dev">**Proxy (ตอนพัฒนา)**</span> | ให้ Vite ส่งคำขอ `/api` ต่อไปที่ API ของเรา | พนักงานรับออร์เดอร์ส่งต่อให้ครัว |
| <span id="jsx">**JSX**</span> | เขียนหน้าตาเว็บแบบคล้าย HTML ในไฟล์ `.tsx` แล้วเครื่องมือแปลงเป็นโค้ด JavaScript ที่สร้างหน้าจอ มีกฎไม่กี่ข้อ เช่น `className`, ห่อก้อนเดียว ([บทที่ 11](/11-react)) | เขียนหน้าตาด้วยภาษาที่คล้ายภาษาเดิม |
| <span id="hook">**Hook**</span> | ฟังก์ชันของ React ที่ชื่อขึ้นต้นด้วย `use` (`useState`, `useEffect`) ให้ component จำค่าหรือทำงานพิเศษ ต้องเรียกที่ระดับบนสุดของ component เท่านั้น | ปลั๊กเสียบเพิ่มความสามารถให้ชิ้นส่วน |
| <span id="side-effect">**Side effect / useEffect**</span> | งานที่ "ออกไปแตะโลกข้างนอก" นอกจากการวาดหน้าจอ เช่น ดึง API ตั้งเวลา ฟัง event · `useEffect` คือที่ทำงานพวกนี้หลังวาดเสร็จ | ทำอาหารเสร็จแล้วค่อยโทรสั่งของเพิ่ม |
| <span id="dependency-array">**Dependency array**</span> | วงเล็บเหลี่ยมท้าย `useEffect(fn, [a, b])` บอกว่าให้รัน effect ใหม่เมื่อค่าไหนเปลี่ยน `[]` = รันครั้งเดียวหลังวาดครั้งแรก | รายการ "ถ้าสิ่งนี้เปลี่ยน ให้ทำใหม่" |
| <span id="strict-mode">**StrictMode**</span> | โหมดตรวจของ React ตอนพัฒนา ตั้งใจรัน effect 2 รอบเพื่อให้เห็นบั๊กที่ลืมเก็บกวาด (cleanup) ตอนขึ้นจริงไม่รันซ้ำ | ครูที่ให้ทำโจทย์ซ้ำเพื่อดูว่าเข้าใจจริง |
| <span id="utility-class">**Utility class**</span> | คลาส CSS ที่ทำแค่ 1 อย่าง เช่น `p-4` (ระยะขอบใน) `text-xl` (ตัวใหญ่) เอามาต่อกันแทนการเขียน CSS เอง (บทที่ 12) | สติกเกอร์ทีละชิ้น |
| <span id="mobile-first">**Mobile-first**</span> | ออกแบบจอมือถือก่อน แล้วค่อยเพิ่มการจัดวางสำหรับจอใหญ่ (ใน Tailwind คลาสไม่มีคำนำหน้า = ทุกจอ, `md:` = จอกลางขึ้นไป) | เขียนเมนูขนาดพกก่อน แล้วค่อยขยายเป็นโปสเตอร์ |
| <span id="ssr">**SSR / Prerender**</span> | สร้างหน้า HTML ที่มีเนื้อหาครบไว้ฝั่ง server · SSR = สร้างใหม่ทุกครั้งที่มีคนขอ · prerender = สร้างไว้ล่วงหน้าตอน build ทำให้ Google/LINE อ่านเนื้อหาได้ (บทที่ 13) | ทำอาหารสดตามสั่ง / ทำเตรียมไว้ในตู้ |

## ขึ้นระบบจริง (บทที่ 17–23)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="deploy">**Deploy**</span> | เอาระบบขึ้นเครื่องจริง ให้คนทั่วไปเข้าใช้ได้ | เปิดร้านจริง |
| <span id="production">**Production**</span> | ระบบจริงที่ลูกค้าใช้อยู่ | หน้าร้านที่เปิดขายอยู่ |
| <span id="preview">**Preview**</span> | เว็บทดลองให้ดูก่อนขึ้นของจริง | ชิมก่อนเสิร์ฟ |
| <span id="ip">**IP address**</span> | ที่อยู่ของเครื่องบนอินเทอร์เน็ต เป็นตัวเลข | บ้านเลขที่ |
| <span id="domain">**Domain (โดเมน)**</span> | ชื่อเว็บที่จำง่าย เช่น `example.com` เช่ารายปี | ชื่อร้าน |
| <span id="dns">**DNS**</span> | ระบบแปลงชื่อเว็บเป็น IP | สมุดโทรศัพท์ |
| <span id="dns-record">**DNS record (A, CNAME)**</span> | บรรทัดในสมุดโทรศัพท์ A = ชื่อ → IP, CNAME = ชื่อ → ชื่ออื่น | "ร้านบิต อยู่บ้านเลขที่ 10" |
| <span id="ttl">**TTL**</span> | เวลาที่เครื่องอื่นจำคำตอบ DNS ไว้ก่อนถามใหม่ ถ้าตั้งยาว เปลี่ยน IP แล้วบางคนยังเห็นที่อยู่เก่าอยู่สักพัก | วันหมดอายุของสมุดโทรศัพท์ฉบับที่ถ่ายเก็บไว้ |
| <span id="nameserver">**Nameserver**</span> | server ที่เป็นเจ้าของคำตอบ DNS ของโดเมนเรา (ที่ที่เราไปเพิ่ม record) เช่น ของ Cloudflare หรือของที่จดโดเมน | ประชาสัมพันธ์ประจำตึกที่รู้ว่าใครอยู่ห้องไหน |
| <span id="registrar">**Registrar**</span> | บริษัทที่เราจ่ายเงินจดและต่ออายุชื่อโดเมน | สำนักงานที่ดินที่ออกโฉนด |
| <span id="https">**HTTPS / SSL / Certificate**</span> | การเข้ารหัสระหว่างเบราว์เซอร์กับเว็บ ใบรับรองยืนยันว่าเว็บเป็นของจริง | ซองปิดผนึก + บัตรประชาชนของเว็บ |
| <span id="vps">**VPS**</span> | คอมพิวเตอร์ที่เช่าในศูนย์ข้อมูล เปิด 24 ชั่วโมง | เช่าห้องในตึกที่มีไฟ มียาม |
| <span id="ssh">**SSH**</span> | วิธีเข้าไปพิมพ์คำสั่งบนเครื่องเช่าจากเครื่องเรา | รีโมตทางไกล |
| <span id="ssh-key">**SSH key**</span> | กุญแจคู่ใช้แทนรหัสผ่าน ดอกหนึ่งเก็บไว้ อีกดอกเอาไปติดที่เครื่องเช่า | ลูกกุญแจ กับ แม่กุญแจ |
| <span id="known-hosts">**known_hosts**</span> | ไฟล์ในเครื่องเราที่จำ "ลายนิ้วมือ" ของเครื่องเช่าที่เคย SSH เข้า ถ้าวันหนึ่งไม่ตรง SSH จะเตือน (อาจสร้างเครื่องใหม่ หรือมีคนปลอมตัว) | จำหน้ายามคนเดิมได้ คนใหม่มาต้องถามก่อน |
| <span id="deploy-key">**Deploy key**</span> | SSH key ที่ผูกกับ repo เดียว ให้เครื่องเช่าดึงโค้ดได้อย่างเดียว ไม่ใช่กุญแจของบัญชีเราทั้งบัญชี (บทที่ 20) | กุญแจที่ไขได้แค่ตู้เดียว |
| <span id="firewall">**Firewall (ufw)**</span> | กฎว่าประตูไหนให้คนนอกเข้าได้ | ยามหน้าตึก |
| <span id="reverse-proxy">**Reverse proxy (Caddy)**</span> | ประตูหน้าบานเดียว รับทุกคนแล้วพาไปห้องที่ถูก | พนักงานต้อนรับที่ล็อบบี้ |
| <span id="docker-compose">**Docker Compose**</span> | ไฟล์สั่งเปิดหลายกล่องพร้อมกัน | รายการเปิดร้าน: เปิดไฟ เปิดแอร์ เปิดเครื่องคิดเงิน |
| <span id="health-check">**Health check**</span> | ที่อยู่ไว้ถามว่า "ระบบยังปกติไหม" | วัดไข้ |
| <span id="rollback">**Rollback**</span> | ถอยกลับไปใช้เวอร์ชันก่อนหน้าเมื่อเวอร์ชันใหม่มีปัญหา | กด Undo |
| <span id="ci-cd">**CI / CD**</span> | CI = ตรวจโค้ดอัตโนมัติทุกครั้งที่ส่งงาน / CD = ขึ้นระบบจริงอัตโนมัติ | ครูตรวจการบ้านให้ทุกครั้ง แล้วติดบอร์ดให้เอง |
| <span id="pipeline">**Pipeline**</span> | ลำดับขั้นตอนอัตโนมัติ เช่น ตรวจ → build → ขึ้นระบบ | สายพานในโรงงาน |
| <span id="secret">**Secret**</span> | ค่าลับ เช่น รหัสผ่าน กุญแจ ที่เก็บไว้ในระบบ ไม่อยู่ในโค้ด | ของในตู้เซฟ |
| <span id="managed">**Managed service (Vercel, Render, Neon)**</span> | บริการที่ดูแลเครื่องให้ เราแค่ส่งโค้ด | เช่าครัวพร้อมพ่อครัว |
| <span id="cold-start">**Cold start**</span> | คำขอแรกหลังบริการฟรี/serverless "หลับ" ต้องรอเครื่องตื่น จึงช้ากว่าปกติหลายวินาที (บทที่ 22) | ร้านที่ปิดไฟไว้ ลูกค้าคนแรกต้องรอเปิดร้าน |
| <span id="rewrite">**Rewrite**</span> | กฎให้ Vercel ส่งคำขอบางแบบต่อไปที่อื่นแทน | พนักงานรับสายแล้วโอนสายให้แผนกที่ถูก |
| <span id="backup">**Backup / Restore**</span> | สำรองข้อมูล / กู้ข้อมูลกลับ | ถ่ายสำเนาเอกสารเก็บไว้อีกที่ |
| <span id="monitor">**Uptime monitor**</span> | บริการที่คอยเปิดเว็บเราทุก 5 นาที ถ้าล่มจะแจ้งเตือน | คนโทรเช็คร้านเป็นระยะ |
| <span id="log">**Log**</span> | บันทึกว่าระบบทำอะไร เกิด error อะไร | กล้องวงจรปิด |

## คำที่มักสับสน

| เทียบกัน | ต่างกันยังไง |
|---|---|
| **Git vs GitHub** | Git = โปรแกรมบันทึกประวัติในเครื่อง / GitHub = เว็บเก็บ repo ออนไลน์ |
| **Node vs npm** | Node = ตัวรันโค้ด / npm = ตัวติดตั้ง package ที่มากับ Node |
| **Image vs Container** | Image = แม่แบบ / Container = ของที่ถูกสร้างจากแม่แบบแล้วกำลังรัน |
| **Library vs Framework** | Library เราเรียกใช้เอง / Framework เป็นฝ่ายเรียกโค้ดของเรา |
| **Authentication vs Authorization** | พิสูจน์ว่าเป็นใคร / เช็คว่ามีสิทธิ์ทำสิ่งนี้ไหม |
| **Hash vs Encrypt** | Hash ย้อนกลับไม่ได้ (ใช้กับรหัสผ่าน) / Encrypt ถอดกลับได้ด้วยกุญแจ |
| **PUT vs PATCH** | PUT แทนที่ทั้งก้อน / PATCH แก้เฉพาะบางช่อง |
| **401 vs 403** | 401 = ยังไม่ได้ login / 403 = login แล้วแต่ไม่มีสิทธิ์ |
| **Merge vs Rebase** | Merge สร้างจุดรวมประวัติ / Rebase ย้ายประวัติให้เป็นเส้นตรง |
| **Frontend vs Backend** | หน้าที่ผู้ใช้เห็นและกด / ระบบหลังบ้านที่เก็บข้อมูลและกฎธุรกิจ |
| **SQL vs NoSQL** | ตารางมีโครงสร้างชัด / เก็บข้อมูลยืดหยุ่นแบบเอกสารหรือคีย์-ค่า |
| **Build vs Deploy** | Build = แปลงโค้ดให้พร้อมใช้ / Deploy = เอาขึ้นระบบจริง |
| **Dev vs Production** | บนเครื่องเรา ลองพังได้ / ระบบที่ลูกค้าใช้จริง ห้ามพัง |
| **Layered vs Feature-based** | จัดโฟลเดอร์ตามหน้าที่ / จัดตามฟีเจอร์ |

## พื้นฐานการเขียนโปรแกรม (บทที่ 4, 9)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="variable">**Variable (ตัวแปร)**</span> | ชื่อที่ตั้งให้ข้อมูล เพื่อเรียกใช้ซ้ำได้ เช่น `const price = 100` | กล่องมีป้ายชื่อ เปิดดูของข้างในได้ทุกเมื่อ |
| <span id="function">**Function (ฟังก์ชัน)**</span> | ชุดคำสั่งที่ตั้งชื่อไว้ เรียกใช้กี่ครั้งก็ได้ รับค่าเข้า ส่งผลออก | สูตรทำอาหาร ใส่วัตถุดิบ ได้จาน |
| <span id="array">**Array**</span> | ลิสต์ของค่าหลายตัวเรียงกัน เช่น `[1, 2, 3]` | แถวของตู้ล็อกเกอร์ มีเลขที่ตู้ |
| <span id="object">**Object**</span> | กลุ่มข้อมูลที่มีชื่อช่องกำกับ เช่น `{ model: "Asus", ramGb: 16 }` | บัตรประวัติ 1 ใบ มีหลายช่องที่ตอบได้ |
| <span id="library-framework">**Library vs Framework**</span> | Library คือชุดเครื่องมือที่เราหยิบมาใช้เอง (Zod) ส่วน Framework คือโครงที่กำหนดวิธีวางโค้ดให้เรา (Hono, React) | ซื้อเครื่องมือมาใช้เอง กับเช่าครัวที่มีผังให้เสร็จ |
| <span id="null-undefined">**null / undefined**</span> | ค่าที่แปลว่า "ไม่มีค่า" `undefined` คือยังไม่ได้ตั้ง `null` คือตั้งใจให้ว่าง ตัวต้นเหตุ error ยอดฮิต | กล่องที่ยังไม่ได้วางของ กับกล่องที่ติดป้ายว่า "ว่าง" |
| <span id="compile">**Compile**</span> | แปลงโค้ดภาษาหนึ่งเป็นอีกภาษาหนึ่ง เช่น TypeScript → JavaScript ด้วย `tsc` | ล่ามแปลภาษา |
| <span id="interface">**Interface / Type alias**</span> | การตั้งชื่อ "รูปร่างของข้อมูล" ใน TypeScript ว่ามีช่องอะไร ชนิดอะไร ([บทที่ 4](/04-typescript)) | แบบฟอร์มเปล่าที่กำหนดช่องไว้แล้ว |
| <span id="union">**Union / Literal type**</span> | ชนิดที่เป็นได้หลายแบบ เช่น `"available" \| "rented"` ใช้กันพิมพ์ผิดตั้งแต่ตอนเขียน | ตัวเลือกในแบบฟอร์ม เลือกได้เฉพาะที่ให้ไว้ |
| <span id="narrowing">**Narrowing**</span> | การเช็คให้ TypeScript รู้ว่าข้อมูลตอนนี้เป็นชนิดไหนแน่ เช่น `if (typeof x === "string")` | ตรวจบัตรก่อนเข้าห้อง |
| <span id="async">**async / await / Promise**</span> | วิธีเขียนงานที่ต้องรอ (เรียก API, อ่านไฟล์) โดยไม่ทำให้โปรแกรมค้าง Promise คือ "สัญญาว่าจะมีผลมาทีหลัง" | รับบัตรคิวที่ร้านกาแฟ แล้วไปนั่งรอได้ |
| <span id="module">**Module (import / export)**</span> | ไฟล์ที่ส่งของออก (`export`) ให้ไฟล์อื่นหยิบไปใช้ (`import`) | แผนกที่เปิดบริการให้แผนกอื่นขอใช้ |
| <span id="generic">**Generic**</span> | ตัวแทนชนิดข้อมูลที่ยังไม่รู้ เช่น `Array<string>` อ่านว่า "ลิสต์ของข้อความ" | กล่องเก็บของแบบปรับขนาดได้ตามของข้างใน |
| <span id="bug">**Bug / Debug**</span> | Bug คือจุดที่โค้ดทำงานผิดจากที่ตั้งใจ Debug คือการไล่หาและแก้ ([บทที่ 9](/09-debugging)) | นักสืบไล่หาต้นเหตุ ไม่ใช่เดาสุ่ม |
| <span id="stack-trace">**Stack trace**</span> | รายการที่ error บอกว่าโค้ดวิ่งผ่านไฟล์ไหน บรรทัดไหน ก่อนพัง ให้อ่านจากบรรทัดที่เป็นไฟล์ของเราก่อน | รอยเท้าที่บอกเส้นทางก่อนล้ม |
| <span id="breakpoint-debug">**Breakpoint**</span> | จุดที่เราสั่งให้โปรแกรมหยุดชั่วคราว เพื่อดูค่าตัวแปรทีละขั้น | กดหยุดวิดีโอเพื่อดูเฟรมนั้นชัดๆ |
| <span id="devtools">**DevTools**</span> | เครื่องมือในเบราว์เซอร์ (กด F12) ดู Console, Network, Elements | ฝาเปิดเครื่องยนต์ของหน้าเว็บ |
| <span id="repro">**Reproduce / Minimal reproduction**</span> | ทำให้บั๊กเกิดซ้ำได้ตามต้องการ และลดโค้ดให้เล็กที่สุดที่ยังพังอยู่ | บอกหมอว่าเจ็บตอนไหน ไม่ใช่แค่ "ไม่สบาย" |
| <span id="callback">**Callback**</span> | ฟังก์ชันที่เราส่งเข้าไปให้ฟังก์ชันอื่นเรียกทีหลัง เช่น `laptops.map((l) => l.brand)` ส่ง `(l) => l.brand` ให้ `map` เรียกทีละตัว | ฝากเบอร์ไว้ ให้เขาโทรกลับเมื่อถึงคิว |
| <span id="arrow-function">**Arrow function (`=>`)**</span> | วิธีเขียนฟังก์ชันแบบสั้น `(a, b) => a + b` ถ้ามีบรรทัดเดียวไม่ต้องเขียน `return` ([JavaScript พื้นฐาน](/js-basics)) | ทางลัดของการเขียนสูตร |
| <span id="template-literal">**Template literal**</span> | ข้อความในเครื่องหมาย `` ` `` ที่แทรกค่าได้ด้วย `${...}` เช่น `` `ราคา ${price} บาท` `` | แบบฟอร์มที่เว้นช่องไว้เติม |
| <span id="destructuring">**Destructuring**</span> | แกะค่าออกจาก object/array มาเป็นตัวแปร `const { brand } = laptop` หรือ `const [a, b] = list` ([react-language ข้อ 1.4](/react-language#14-destructuring-แกะของออกจากกล่อง)) | แกะของออกจากกล่องพัสดุวางบนโต๊ะ |
| <span id="spread">**Spread (`...`)**</span> | กางของใน array/object ออกมาวางในอันใหม่ `[...items, x]`, `{ ...form, name: "บิต" }` ใช้สร้างค่าใหม่โดยไม่แก้ของเดิม | ถ่ายเอกสารแล้วเขียนเพิ่มในสำเนา |
| <span id="source-map">**Source map**</span> | ไฟล์ที่จับคู่โค้ดที่ถูกแปลง/บีบอัดแล้ว กลับไปหาบรรทัดในไฟล์ต้นฉบับ ทำให้ stack trace และ DevTools ชี้ไฟล์ `.ts` ของเราได้ | ดัชนีที่บอกว่าหน้า 3 ของฉบับย่อ มาจากหน้าไหนของฉบับเต็ม |
| <span id="unhandled-rejection">**Unhandled rejection**</span> | Promise ที่พัง (reject) แต่ไม่มี `try/catch` หรือ `.catch` รับ Node จะพิมพ์ error และหยุดโปรแกรม (บทที่ 9 ข้อ 9) | จดหมายตีกลับที่ไม่มีใครเปิดอ่าน |
| <span id="official-docs">**เอกสารทางการ (Official docs)**</span> | เอกสารที่ผู้สร้างเครื่องมือเขียนเอง ตรงกับเวอร์ชันจริงที่สุด แบ่งเป็น **Guide** (สอนเป็นเรื่อง) กับ **API Reference** (รายการทุกฟังก์ชัน) ([เรียนรู้ด้วยตัวเอง](/self-learning)) | คู่มือที่มากับเครื่อง ไม่ใช่คำบอกเล่าต่อๆ กัน |
| <span id="changelog">**Changelog / Release notes**</span> | บันทึกว่าแต่ละเวอร์ชันเปลี่ยนอะไร โดยเฉพาะ **breaking changes** ที่ทำให้โค้ดเดิมพัง เปิดดูก่อนอัปเกรด หรือเมื่อโค้ดจากเน็ตใช้ไม่ได้ | ใบแจ้ง "สินค้าเปลี่ยนสูตร" |
| <span id="rubber-duck">**Rubber duck debugging**</span> | อธิบายโค้ดทีละบรรทัดให้เป็ดยาง (หรือใครก็ได้) ฟัง แล้วมักเจอบั๊กเองระหว่างพูด ([บทที่ 9](/09-debugging)) | สอนเพื่อนแล้วตัวเองเข้าใจขึ้น |
| <span id="time-box">**Time-box**</span> | กำหนดเวลาให้แต่ละขั้นของการหาคำตอบ เช่น 15 นาที ถ้าไม่คืบให้ขึ้นขั้นถัดไป (รวมถึงการถาม) แทนที่จะติดอยู่ทั้งวัน | นาฬิกาจับเวลาตอนทำข้อสอบ |

## Git และ GitHub เพิ่มเติม (บทที่ 1)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="github">**GitHub / GitLab**</span> | เว็บที่เก็บ repo ออนไลน์ ให้ทีมแชร์และรีวิวโค้ด Git คือโปรแกรมในเครื่อง ส่วนสองเว็บนี้คือที่เก็บบนเน็ต ([บทที่ 1](/01-git)) | Git = กล้องถ่ายรูป / GitHub = อัลบั้มออนไลน์ |
| <span id="clone">**Clone**</span> | ดึง repo จากเว็บมาไว้ในเครื่องเรา พร้อมประวัติทั้งหมด | ถ่ายเอกสารทั้งแฟ้มมาไว้ที่โต๊ะ |
| <span id="remote">**Remote / origin**</span> | ที่อยู่ของ repo บนเว็บ โดยปกติตั้งชื่อว่า `origin` | ที่อยู่ของคลังกลาง |
| <span id="push-pull">**Push / Pull**</span> | Push = ส่ง commit ของเราขึ้นเว็บ / Pull = ดึงของคนอื่นลงมา | ส่งของขึ้นรถ / ขนของลงรถ |
| <span id="staging">**Staging (`git add`)**</span> | ที่พักไฟล์ที่เลือกไว้ว่าจะรวมใน commit ถัดไป | เรียกคนมายืนหน้ากล้องก่อนกดชัตเตอร์ |
| <span id="conflict">**Merge conflict**</span> | สองคนแก้บรรทัดเดียวกัน Git ตัดสินเองไม่ได้ ต้องให้คนเลือก | สองคนแก้ประโยคเดียวกันในเอกสารร่วม |
| <span id="gitignore">**.gitignore**</span> | ไฟล์บอก Git ว่าไฟล์ไหนห้ามเก็บ เช่น `.env`, `node_modules` | รายชื่อของต้องห้ามขึ้นเครื่อง |
| <span id="fork">**Fork**</span> | ก๊อปปี้ repo ของคนอื่นมาเป็นของเราบน GitHub เพื่อแก้แล้วเสนอกลับ | ถ่ายสำเนาหนังสือไปเขียนเพิ่ม แล้วเสนอให้เจ้าของ |
| <span id="issue">**Issue**</span> | บัตรบันทึกงานหรือปัญหาบน GitHub/GitLab | ใบแจ้งซ่อม |
| <span id="stash">**Stash**</span> | เก็บงานที่ยังทำไม่เสร็จไว้ชั่วคราว เพื่อสลับไปทำอย่างอื่น | ใส่งานค้างไว้ในลิ้นชัก |
| <span id="rebase">**Rebase**</span> | ย้าย commit ของเราไปต่อท้ายของล่าสุด ให้ประวัติเป็นเส้นตรง (ต่างจาก merge ที่สร้างจุดรวม) | ย้ายแผ่นที่เขียนไว้ไปต่อท้ายเล่มล่าสุด |
| <span id="tag">**Tag**</span> | ป้ายชื่อติดที่ commit สำคัญ เช่น `v1.2.0` | สติ๊กเกอร์ติดที่หน้าสมุดบอกว่า "ฉบับพิมพ์ครั้งที่ 2" |
| <span id="head">**HEAD**</span> | ชี้ว่าตอนนี้เราอยู่ที่ commit ไหน (ปกติคือปลายของ branch) | หัวลูกศร "คุณอยู่ที่นี่" |
| <span id="reflog">**reflog**</span> | บันทึกทุกที่ที่ HEAD เคยไป ใช้กู้งานที่เผลอลบ | กล้องวงจรปิดของ Git |
| <span id="detached-head">**Detached HEAD**</span> | HEAD ชี้ไปที่ commit ตรงๆ ไม่ได้ชี้ที่ branch (เช่น หลัง `git checkout a1b2c3d`) commit ใหม่ตอนนี้จะไม่อยู่ใน branch ไหน ให้สร้าง branch ก่อนทำงานต่อ (`git switch -c ชื่อ`) | ยืนอยู่บนสถานีที่ไม่มีรถสายไหนผ่าน |
| <span id="force-push">**Force push**</span> | `git push --force` เขียนทับประวัติบนเว็บด้วยของในเครื่องเรา งานที่คนอื่น push ไว้หายได้ ถ้าจำเป็นใช้ `--force-with-lease` และห้ามทำกับ `main` | ฉีกหน้าสมุดกลางของทีมแล้วแปะของเราแทน |
| <span id="pat">**Personal Access Token (PAT)**</span> | รหัสยาวที่ GitHub ออกให้ใช้แทนรหัสผ่านตอนสั่ง Git ผ่าน https ตั้งสิทธิ์และวันหมดอายุได้ ถือเป็นความลับเท่ารหัสผ่าน | บัตรผ่านเฉพาะงาน มีวันหมดอายุ |

## Docker, Node และ Package เพิ่มเติม (บทที่ 2–3)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="dockerfile">**Dockerfile**</span> | ไฟล์สูตรบอก Docker ว่าจะสร้าง image ยังไง ทีละบรรทัด | สูตรทำข้าวกล่อง |
| <span id="registry">**Registry / Docker Hub**</span> | คลังเก็บ image ให้ดึงลงมาใช้ เช่น Docker Hub | ร้านขายแม่พิมพ์สำเร็จรูป |
| <span id="layer">**Layer / Cache**</span> | image ประกอบจากชั้นซ้อนกัน ชั้นที่ไม่เปลี่ยนจะใช้ของเดิม build จึงเร็ว | ชั้นเค้ก ชั้นที่ทำไว้แล้วไม่ต้องอบใหม่ |
| <span id="bind-mount">**Bind mount**</span> | ผูกโฟลเดอร์ในเครื่องเรากับในกล่อง แก้ไฟล์ปุ๊บ กล่องเห็นปั๊บ | หน้าต่างที่มองทะลุจากกล่องมาที่โต๊ะเรา |
| <span id="port-mapping">**Port mapping (`-p 5433:5432`)**</span> | ต่อช่องของเครื่องเราเข้ากับช่องในกล่อง เลขซ้ายคือของเรา เลขขวาคือในกล่อง | ต่อสายจากเบอร์ตึกเข้าห้องในกล่อง |
| <span id="docker-desktop">**Docker Desktop / WSL 2**</span> | โปรแกรม Docker บน Mac/Windows (Windows ใช้ WSL 2 เป็นฐาน) | ตัวเปิดเครื่องของ Docker |
| <span id="npm">**npm / Yarn / Bun**</span> | ตัวจัดการ package สำหรับติดตั้งและอัปเดตโค้ดสำเร็จรูป (Bun เป็นทั้ง runtime และ package manager) | แอปสโตร์ของโค้ด |
| <span id="package-json">**package.json**</span> | ไฟล์ประจำโปรเจกต์ บอกชื่อ สคริปต์ และ package ที่ใช้ | ใบรายการของที่ต้องซื้อ |
| <span id="lockfile">**Lock file**</span> | ไฟล์ล็อกเวอร์ชัน package ที่ติดตั้งจริง ให้ทุกเครื่องได้เหมือนกัน ต้อง commit ขึ้น Git | ใบเสร็จที่ระบุยี่ห้อและรุ่นเป๊ะๆ |
| <span id="node-modules">**node_modules**</span> | โฟลเดอร์ที่ package ถูกติดตั้งลงไป ใหญ่มาก ห้ามขึ้น Git สร้างใหม่ได้ด้วย `install` | ลังวัตถุดิบ ซื้อใหม่ได้ ไม่ต้องเก็บใน repo |
| <span id="dependency">**Dependency / devDependency**</span> | package ที่โปรเจกต์ต้องใช้ตอนรัน / ใช้เฉพาะตอนพัฒนา (เช่นตัวตรวจ type) | วัตถุดิบหลัก / อุปกรณ์ช่วยทำครัว |
| <span id="semver">**Semver (`^1.2.3`)**</span> | เลขเวอร์ชัน มาจาก major.minor.patch เครื่องหมาย `^` แปลว่ารับอัปเดตเล็กได้ | เลขรุ่นสินค้า 1.2.3 = รุ่นใหญ่.รุ่นย่อย.แก้บั๊ก |
| <span id="npx">**npx / bunx**</span> | รันเครื่องมือจาก package โดยไม่ต้องติดตั้งถาวร | ยืมเครื่องมือมาใช้ครั้งเดียว |
| <span id="esm">**ESM / CommonJS**</span> | สองแบบเขียน import/export ของ JavaScript ปัจจุบันใช้ ESM (`import`) เป็นหลัก | ภาษาถิ่นเก่ากับภาษากลางใหม่ |

## HTTP และ API เพิ่มเติม (บทที่ 5)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="http">**HTTP**</span> | กติกาที่เบราว์เซอร์กับเซิร์ฟเวอร์ใช้คุยกัน เป็นคำขอ (request) แล้วตอบกลับ (response) | การสั่งอาหาร: ลูกค้าสั่ง ครัวส่งอาหาร |
| <span id="request-response">**Request / Response**</span> | คำขอที่ client ส่ง / คำตอบที่ server ส่งกลับ ประกอบด้วย header และ body | ใบสั่ง / อาหารที่ได้ |
| <span id="header">**Header**</span> | ข้อมูลกำกับคำขอหรือคำตอบ เช่น `Content-Type`, `Authorization` | ป้ายบนหน้ากล่องพัสดุ |
| <span id="body">**Body**</span> | เนื้อหาหลักที่ส่ง เช่น JSON ที่เป็นข้อมูลฟอร์ม | ของที่อยู่ในกล่องพัสดุ |
| <span id="query-param">**Query / Path parameter**</span> | ค่าที่ต่อท้ายลิงก์: `?q=asus` (query) หรือ `/laptops/3` (path) | ระบุเงื่อนไขค้นหา / ระบุเลขที่ที่ต้องการ |
| <span id="rest">**REST / CRUD**</span> | แนวตั้งชื่อ endpoint ตามสิ่งของ (`/laptops`) และใช้ method บอกการกระทำ CRUD = Create, Read, Update, Delete | ชื่อตู้เอกสาร + กริยาที่ทำกับตู้ |
| <span id="idempotent">**Idempotent / Safe**</span> | ทำซ้ำกี่ครั้งผลเหมือนเดิม (PUT, DELETE) / ไม่เปลี่ยนข้อมูล (GET) เลยห้ามให้ GET แก้ข้อมูล | กดปุ่มปิดไฟซ้ำ ไฟก็ยังปิดเหมือนเดิม |
| <span id="pagination">**Pagination**</span> | แบ่งข้อมูลจำนวนมากเป็นหน้าๆ (`?page=2&limit=20`) | สมุดโทรศัพท์แบ่งเป็นเล่ม |
| <span id="curl">**curl / `.http` file**</span> | เครื่องมือยิงคำขอจาก Terminal / ไฟล์ใน VS Code สำหรับทดสอบ API | เครื่องกดกริ่งทดสอบ API |
| <span id="preflight">**Preflight (OPTIONS)**</span> | คำขอถามล่วงหน้าที่เบราว์เซอร์ส่งก่อน เพื่อถามเซิร์ฟเวอร์ว่ายอมรับ CORS ไหม | โทรถามก่อนว่าร้านเปิดไหม ก่อนเดินไปจริง |
| <span id="graphql">**GraphQL**</span> | รูปแบบ API ที่ client เขียนคำถามระบุเองว่าอยากได้ช่องไหน ผ่าน endpoint เดียว (บทที่ 5) | บุฟเฟต์ ตักเฉพาะที่อยากกิน |
| <span id="websocket">**WebSocket**</span> | สายที่เปิดค้างไว้ให้ server กับ browser ส่งข้อมูลหากันได้ทั้งสองทางตลอดเวลา เช่น แชท | โทรศัพท์ที่ไม่วางสาย |
| <span id="sse">**SSE (Server-Sent Events)**</span> | server ส่งข้อมูลมาหา browser ทางเดียวต่อเนื่องผ่าน HTTP ธรรมดา เช่น แจ้งสถานะ ข้อความที่ AI พิมพ์ทีละคำ | วิทยุ: ฟังได้ ตอบกลับทางเดียวกันไม่ได้ |
| <span id="webhook">**Webhook**</span> | ระบบอื่นยิงคำขอมาที่ URL ของเราเองเมื่อมีเหตุการณ์ เช่น payment สำเร็จ แทนที่เราจะต้องคอยถาม | ให้เบอร์ไว้ "เสร็จแล้วโทรบอก" |

## ฐานข้อมูลเพิ่มเติม (บทที่ 6–8)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="query">**Query**</span> | คำสั่งถามหรือแก้ข้อมูลในฐานข้อมูล | ถามบรรณารักษ์ว่ามีหนังสือเล่มนี้ไหม |
| <span id="join">**JOIN**</span> | เชื่อมข้อมูลสองตารางด้วยค่าที่ตรงกัน เช่น ลูกค้ากับรายการเช่า | จับคู่รายชื่อกับใบเสร็จด้วยเลขลูกค้า |
| <span id="index">**Index**</span> | ตัวช่วยให้ค้นเร็ว ไม่ต้องไล่อ่านทุกแถว แต่เขียนข้อมูลช้าลงเล็กน้อย | สารบัญท้ายเล่ม |
| <span id="relation">**Relation (1:1, 1:N, N:M)**</span> | ความสัมพันธ์ระหว่างตาราง เช่น ลูกค้า 1 คนเช่าได้หลายครั้ง (1:N) | พ่อแม่ 1 คน มีลูกได้หลายคน |
| <span id="normalization">**Normalization**</span> | จัดตารางไม่ให้เก็บข้อมูลเดียวกันซ้ำหลายที่ เพื่อกันข้อมูลขัดแย้งกัน | เก็บที่อยู่ลูกค้าที่เดียว ไม่แปะซ้ำทุกใบเสร็จ |
| <span id="acid">**ACID**</span> | คุณสมบัติที่ทำให้ transaction ไว้ใจได้: ทำครบหรือไม่ทำเลย, ข้อมูลไม่ขัดกัน, ไม่ปนกัน, ไม่หาย | การโอนเงินที่ไม่มีวันหักแล้วเงินหาย |
| <span id="nosql">**NoSQL**</span> | ฐานข้อมูลที่ไม่ใช้ตารางแบบ SQL เช่น document, key-value เหมาะกับข้อมูลหน้าตาไม่คงที่ | กองโน้ตอิสระ แทนตารางเรียบร้อย |
| <span id="connection-string">**Connection string**</span> | ข้อความเดียวที่บอกที่อยู่ ชื่อผู้ใช้ รหัสผ่าน และชื่อฐานข้อมูล เช่น `postgres://user:pass@host:5432/db` | ที่อยู่ + รหัสผ่านเข้าตึก ในบรรทัดเดียว |
| <span id="pool">**Connection pool**</span> | กลุ่มการเชื่อมต่อฐานข้อมูลที่เปิดค้างไว้แชร์กัน ไม่ต้องเปิดใหม่ทุกคำขอ | แท็กซี่จอดรอ ไม่ต้องเรียกใหม่ทุกครั้ง |
| <span id="n-plus-one">**N+1 problem**</span> | โค้ดวนถามฐานข้อมูลทีละแถว (1 ครั้งดึงรายการ แล้วอีก N ครั้งดึงรายละเอียด) แทนที่จะถามรอบเดียว | เดินไปตู้เอกสาร 100 รอบ แทนหยิบทีเดียว |
| <span id="drift">**Migration drift**</span> | โครงฐานข้อมูลจริงไม่ตรงกับที่ migration บันทึกไว้ มักเกิดจากแก้ตรงๆ แล้วไม่สร้าง migration | แผนผังตึกไม่ตรงกับตึกจริง |
| <span id="superuser">**Superuser**</span> | user ของฐานข้อมูลที่ทำได้ทุกอย่าง (เช่น `postgres`) ใช้ดูแลระบบเท่านั้น แอปควรใช้ user ที่สิทธิ์น้อยกว่า (least privilege) | กุญแจผี เปิดได้ทุกห้อง |
| <span id="pooler">**Pooler**</span> | ตัวกลางที่รวมการเชื่อมต่อจากแอปจำนวนมากให้เหลือไม่กี่สายไปที่ฐานข้อมูล เพราะฐานข้อมูลรับสายพร้อมกันได้จำกัด (เช่น host `-pooler` ของ Neon) | พนักงานรับสายกลางที่ต่อสายให้ทีละคน |
| <span id="collation">**Collation**</span> | กติกาเทียบและเรียงข้อความ เช่น ตัวพิมพ์เล็กใหญ่ถือว่าเท่ากันไหม เรียงภาษาไทยยังไง | กฎเรียงชื่อในสมุดรายชื่อ |
| <span id="cron">**cron**</span> | ตัวตั้งเวลาให้รันคำสั่งอัตโนมัติตามรอบ เช่น backup ทุกตีสอง (`0 2 * * *`) | นาฬิกาปลุกของเครื่อง |
| <span id="utc">**UTC**</span> | เวลามาตรฐานกลางของโลก ไม่มีเขตเวลา ควรเก็บเวลาในฐานข้อมูลเป็น UTC (ไทย = UTC+7) แล้วแปลงตอนแสดงผล | นาฬิกากลางที่ทุกประเทศเทียบ |
| <span id="driver">**Driver**</span> | library ที่รู้วิธีคุยกับฐานข้อมูลยี่ห้อนั้นจริงๆ (เช่น `pg`, `postgres`) ORM/query builder ทำงานอยู่บนมันอีกชั้น (บทที่ 8) | สายไฟและปลั๊กที่ต่อเข้ากับเครื่อง |
| <span id="query-builder">**Query Builder**</span> | ตัวช่วยเขียน SQL ด้วยฟังก์ชันใน TypeScript ทีละท่อน (`select().from().where()`) ใกล้ SQL กว่า ORM | ต่อประโยค SQL ด้วยตัวต่อที่ตรวจสะกดให้ |
| <span id="dotenv">**dotenv**</span> | library ที่อ่านไฟล์ `.env` แล้วใส่ค่าให้ `process.env` (Bun ทำให้เองไม่ต้องใช้ · Node รุ่นใหม่มี `--env-file`) | คนอ่านโน้ตในลิ้นชักแล้วยื่นกุญแจให้ |
| <span id="serverless">**Serverless**</span> | รันโค้ดบนบริการที่เปิดเครื่องให้เฉพาะตอนมีคำขอ เราไม่ต้องดูแลเครื่องเอง (แต่มีเครื่องจริงอยู่ข้างหลัง) และอาจมี cold start | แท็กซี่ เรียกเมื่อจะใช้ ไม่ต้องมีรถเอง |
| <span id="cascade-restrict">**cascade / restrict**</span> | ตั้งว่าเมื่อลบแถวแม่ แถวลูกที่อ้างถึงจะเป็นยังไง · cascade = ลบตามไปด้วย · restrict = ห้ามลบแม่ถ้ายังมีลูก (บทที่ 8b) | ปิดบัญชีแล้วลบประวัติทิ้งด้วย / ปิดไม่ได้จนกว่าจะเคลียร์หนี้ |
| <span id="partial-unique-index">**Partial unique index**</span> | ห้ามซ้ำ **เฉพาะแถวที่ตรงเงื่อนไข** เช่น "rental ที่ยังไม่คืน ห้ามมี laptop ซ้ำ" แถวที่คืนแล้วไม่นับ (บทที่ 8b) | ห้ามจองห้องซ้ำ เฉพาะการจองที่ยังไม่หมดเวลา |
| <span id="sql-injection">**SQL injection**</span> | ช่องโหว่ที่คนร้ายพิมพ์คำสั่ง SQL แทรกมาในช่องกรอก กันด้วย parameterized query ([บทที่ 10](/10-security)) | พิมพ์คำสั่งปลอมใส่ในใบสั่งงาน |
| <span id="object-storage">**Object storage**</span> | บริการเก็บไฟล์จำนวนมาก สั่งงานผ่าน HTTP เช่น Amazon S3, Cloudflare R2, RustFS ฐานข้อมูลจดแค่ชื่อไฟล์ ([บทที่ 8c](/08c-image-storage)) | โกดังรับฝากของ เราจดแค่เลขช่อง |
| <span id="bucket">**Bucket / Object / Key**</span> | bucket = ถังใส่ไฟล์ · object = ไฟล์ 1 ไฟล์ · key = ชื่อเต็มของไฟล์ในถัง เช่น `laptops/2/abc-400.webp` | โกดัง · กล่อง · ป้ายชื่อบนกล่อง |
| <span id="s3-compatible">**S3 API / S3-compatible**</span> | วิธีสั่งงาน object storage ที่ Amazon S3 ทำไว้ เจ้าอื่นทำตามจนเป็นภาษากลาง โค้ดเดียวย้ายเจ้าได้ด้วยการเปลี่ยน `.env` (แต่ไม่ได้เหมือนกันทุกคำสั่ง) | ปลั๊กไฟมาตรฐานเดียวกัน เสียบได้หลายยี่ห้อ |
| <span id="presigned-url">**Presigned URL**</span> | ลิงก์ชั่วคราวที่ server เซ็นด้วยกุญแจลับ ให้ทำได้ 1 อย่างกับ 1 ไฟล์ภายในเวลาที่กำหนด เช่น อัปโหลดภายใน 5 นาที | บัตรผ่านรายวันที่ประทับเวลาหมดอายุ |
| <span id="magic-bytes">**Magic bytes**</span> | ไบต์ชุดแรกของไฟล์ที่บอกชนิดจริง เช่น JPEG ขึ้นต้นด้วย `FF D8 FF` ใช้ตรวจไฟล์แทนการเชื่อนามสกุล | ลายนิ้วมือ ปลอมชื่อได้ แต่ปลอมลายนิ้วมือไม่ได้ |
| <span id="orphan-file">**ไฟล์กำพร้า (Orphan file)**</span> | ไฟล์ใน storage ที่ไม่มีแถวไหนในฐานข้อมูลอ้างถึงแล้ว ผู้ใช้ไม่เห็น เสียแค่พื้นที่ ลบด้วยงานเก็บกวาดเป็นรอบ | ของในโกดังที่ไม่มีใครจดเลขช่องไว้ |
| <span id="exif">**EXIF**</span> | ข้อมูลที่กล้อง/มือถือแนบในไฟล์รูป เช่น รุ่นกล้อง ทิศการหมุน และมักมีพิกัด GPS ต้องลบก่อนเผยแพร่ | ป้ายหลังรูปที่เขียนว่าถ่ายที่ไหน |
| <span id="multipart">**multipart/form-data**</span> | รูปแบบ body ที่ browser ใช้ส่งไฟล์พร้อมช่องข้อมูลอื่นในคำขอเดียว | ซองพัสดุที่แบ่งช่อง ใส่ทั้งจดหมายและของ |
| <span id="cdn">**CDN**</span> | เครือข่าย server ทั่วโลกที่เก็บสำเนาไฟล์ไว้ใกล้ผู้ใช้ ผู้ใช้โหลดจากจุดที่ใกล้ที่สุด | ร้านสาขาใกล้บ้าน ไม่ต้องไปถึงโรงงาน |
| <span id="cache-control">**Cache-Control**</span> | header ที่บอก browser/CDN ว่าเก็บไฟล์ไว้ใช้ซ้ำได้นานแค่ไหน `immutable` = ไฟล์นี้ไม่เปลี่ยนแน่นอน ไม่ต้องถามซ้ำ | ป้าย "หมดอายุวันที่..." บนกล่องนม |
| <span id="toast">**TOAST**</span> | กลไกของ Postgres ที่บีบอัดค่าที่ใหญ่เกินราว 2 KB และย้ายไปเก็บในตารางลับคู่กัน แถวหลักเก็บแค่ตัวชี้ ไม่ได้ทำให้ไฟล์ที่บีบมาแล้ว (เช่น WebP) เล็กลง | ห้องเก็บของหลังร้าน ของชิ้นใหญ่ไม่วางบนชั้นหน้าร้าน แต่ยังนับเป็นพื้นที่ของร้าน |
| <span id="etag">**ETag / 304 Not Modified**</span> | ลายนิ้วมือของเนื้อไฟล์ที่ server ส่งมา browser ถามกลับด้วย `If-None-Match` ถ้าไม่เปลี่ยน server ตอบ `304` ไม่ส่งเนื้อไฟล์ซ้ำ | ถามร้านว่า "เมนูยังเหมือนเดิมไหม" แทนการขอเมนูเล่มใหม่ทุกครั้ง |
| <span id="soft-delete">**Soft delete (ลบแบบกู้คืนได้)**</span> | ลบโดยจดเวลาลงคอลัมน์ `deleted_at` แทนการลบแถวจริง กู้คืนได้ภายในเวลาที่กำหนด แล้วงานล้างถังขยะค่อยลบจริง | ถังขยะบนเดสก์ท็อป |
| <span id="image-cdn">**Image CDN**</span> | บริการที่เก็บรูปต้นฉบับแล้วย่อ/แปลงรูปตามที่ระบุใน URL ตอนมีคนขอ แล้ว cache ผลไว้ เช่น Cloudinary, Cloudflare Images, imgix | ร้านถ่ายเอกสารที่ย่อ/ขยายให้ตามสั่ง แล้วเก็บสำเนาไว้ให้คนถัดไป |
| <span id="placeholder">**Placeholder / LQIP**</span> | ตัวแทนรูประหว่างรอโหลด เช่น สีหลักหรือรูปจิ๋วเบลอ (Low-Quality Image Placeholder) ส่งมากับ JSON ได้ทันที | ภาพร่างดินสอก่อนลงสีจริง |
| <span id="content-hash">**Content hash**</span> | ค่า hash (เช่น sha256) ที่คำนวณจากเนื้อไฟล์ ไฟล์เหมือนกันทุกไบต์ได้ค่าเดียวกัน ใช้หาไฟล์ซ้ำ | ลายนิ้วมือของไฟล์ |
| <span id="path-traversal">**Path traversal**</span> | การโจมตีที่ใส่ `../` ในชื่อไฟล์ให้โปรแกรมอ่าน/เขียนไฟล์นอกโฟลเดอร์ที่ตั้งใจ เช่น ทับ `.env` | เดินออกจากห้องที่อนุญาตไปห้องข้างๆ ด้วยประตูหลัง |

## ความปลอดภัยเพิ่มเติม (บทที่ 10)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="authn">**Authentication vs Authorization**</span> | Authentication = พิสูจน์ว่าคุณคือใคร (login) / Authorization = เช็คว่าคุณทำสิ่งนี้ได้ไหม (สิทธิ์) | ตรวจบัตรประชาชนที่ประตู / เช็คว่าบัตรผ่านเข้าห้องนี้ได้ไหม |
| <span id="encrypt">**Encrypt vs Hash**</span> | Encrypt = เข้ารหัสแล้วถอดกลับได้ถ้ามีกุญแจ / Hash = แปลงทางเดียวย้อนไม่ได้ ใช้กับรหัสผ่าน | ใส่กุญแจแล้วไขได้ / บดจนย้อนกลับเป็นของเดิมไม่ได้ |
| <span id="salt">**Salt**</span> | ค่าสุ่มที่ผสมกับรหัสผ่านก่อน hash ทำให้รหัสเหมือนกันได้ hash ต่างกัน | ใส่เครื่องปรุงลับที่ต่างกันทุกจาน |
| <span id="argon2">**bcrypt / argon2**</span> | วิธี hash รหัสผ่านที่ตั้งใจให้ช้า คนร้ายเดาทีละล้านรหัสไม่ไหว (`Bun.password` ใช้ argon2id) | ล็อกที่เปิดยากโดยตั้งใจ |
| <span id="brute-force">**Brute force**</span> | ลองรหัสผ่านรัวๆ ทีละตัวจนเจอ กันด้วย rate limit และรหัสยาว | ลองกุญแจทุกดอกจนไขได้ |
| <span id="csrf">**CSRF**</span> | หลอกให้เบราว์เซอร์ที่ login ค้างอยู่ส่งคำขอโดยที่เจ้าตัวไม่รู้ cookie `SameSite=Lax` กันได้ส่วนใหญ่แต่ไม่ครบ (เช่น เว็บอื่นที่อยู่ใต้โดเมนหลักเดียวกันยังนับเป็น "site เดียวกัน") จึงต้องมี **ด่านตรวจ Origin** ที่ server เพิ่ม เช่น `hono/csrf` ([บทที่ 15](/15-auth)) | ปลอมลายเซ็นโดยใช้บัตรที่เจ้าตัวถือค้างไว้ ยามจึงต้องดูด้วยว่าใบสั่งมาจากโต๊ะไหน |
| <span id="idor">**IDOR (Broken access control)**</span> | เปลี่ยนเลขในลิงก์ (`/orders/5` → `/orders/6`) แล้วเห็นของคนอื่น เพราะไม่เช็คสิทธิ์ | ไขตู้เลขที่ 6 ได้ด้วยกุญแจตู้ 5 |
| <span id="tls">**TLS / SSL**</span> | ระบบเข้ารหัสการสื่อสารที่อยู่เบื้องหลัง HTTPS ให้คนกลางอ่านไม่ได้ | ซองจดหมายปิดผนึก |
| <span id="least-privilege">**Least privilege**</span> | ให้สิทธิ์น้อยที่สุดเท่าที่งานต้องใช้ เช่น user ของ DB ที่ใช้ในแอปไม่ควรลบตารางได้ | ให้กุญแจเฉพาะห้องที่ต้องเข้า |
| <span id="rotate">**Rotate (secret)**</span> | เปลี่ยนรหัสลับใหม่ทันทีที่สงสัยว่ารั่ว แล้วเลิกใช้ตัวเก่า | เปลี่ยนกุญแจทันทีเมื่อทำหาย |
| <span id="owasp">**OWASP**</span> | องค์กรที่รวบรวมรายการช่องโหว่เว็บที่พบบ่อย เป็นแนวอ้างอิงมาตรฐาน | สมุดบันทึกอาชญากรรมที่เจอบ่อย |
| <span id="csp">**CSP (Content-Security-Policy)**</span> | header ที่บอก browser ว่าหน้านี้โหลดสคริปต์/รูปจากที่ไหนได้บ้าง ถ้ามีคนแอบฝังสคริปต์ (XSS) browser จะไม่ยอมรัน | รายชื่อแขกที่อนุญาตให้เข้างาน |
| <span id="hsts">**HSTS**</span> | header ที่สั่ง browser ว่า "เว็บนี้ต้องเปิดด้วย https เท่านั้น" ครั้งต่อไปพิมพ์ http ก็จะเปลี่ยนเป็น https ให้เอง | ป้าย "ทางเข้าด้านหน้าเท่านั้น" ที่ลูกค้าจำได้ |
| <span id="pdpa">**PDPA**</span> | พ.ร.บ.คุ้มครองข้อมูลส่วนบุคคลของไทย เก็บข้อมูลลูกค้าเท่าที่จำเป็น บอกเหตุผล ดูแลไม่ให้รั่ว และลบเมื่อขอ | กฎหมายว่าด้วยการเก็บสมุดรายชื่อลูกค้า |
| <span id="mass-assignment">**Mass assignment**</span> | เอาข้อมูลที่ผู้ใช้ส่งมาทั้งก้อนไปบันทึกตรงๆ คนร้ายจึงแอบเติมช่องอย่าง `isAdmin: true` ได้ กันด้วยการ parse ด้วย Zod แล้วใช้เฉพาะช่องที่ประกาศ ([บทที่ 10](/10-security)) | ลูกค้ากรอกช่อง "ส่วนลด 100%" เองในใบสั่ง |

## โครงสร้างโปรเจกต์ (บทเสริม)

| คำ | ความหมายแบบง่าย | นึกภาพแบบนี้ |
|---|---|---|
| <span id="layered">**Layered architecture**</span> | แบ่งโค้ดเป็นชั้น (routes → services → repositories) แต่ละชั้นเรียกได้เฉพาะชั้นถัดลงไป ([บทเสริม](/project-structure)) | สายพานในโรงงาน แต่ละสถานีทำหน้าที่เดียว |
| <span id="mvc">**MVC**</span> | Model / View / Controller แนวแบ่งหน้าที่แบบเก่า ใน API: Controller = routes, Model = services + repositories, View = JSON ที่ตอบ | ครัว / จานอาหาร / พนักงานเสิร์ฟ |
| <span id="service-repo">**Service / Repository**</span> | Service = กฎธุรกิจ (ไม่รู้จัก HTTP) / Repository = ชั้นคุยกับฐานข้อมูล | ผู้จัดการตัดสินใจ / พนักงานคลังหยิบของ |
| <span id="feature-based">**Feature-based (Module)**</span> | จัดโฟลเดอร์ตามฟีเจอร์ ทุกอย่างของฟีเจอร์เดียวอยู่ด้วยกัน | ครัวแบบสถานี แต่ละสถานีมีของครบ |
| <span id="shared">**Shared**</span> | ของที่หลายฟีเจอร์ใช้ร่วมกันและไม่ผูกกับธุรกิจ เช่น `button`, middleware | ห้องอุปกรณ์กลาง |
| <span id="barrel">**`index.ts` ของโมดูล**</span> | ไฟล์ประตูหน้าบ้านที่บอกว่าโมดูลเปิดอะไรให้คนนอกใช้ | เคาน์เตอร์ประชาสัมพันธ์ของแผนก |
| <span id="circular">**Circular dependency**</span> | สองโมดูล import กันเป็นวงกลม มักทำให้ค่าเป็น `undefined` ตอนรัน | สองคนรอให้อีกฝ่ายเปิดประตูก่อน |
| <span id="two-level">**Component 2 ระดับ**</span> | ระดับ 1 = shared ไม่รู้จักธุรกิจ ใช้ได้ทุกที่ / ระดับ 2 = ของฟีเจอร์เดียว รู้จักธุรกิจ | เลโก้ชิ้นพื้นฐาน กับชุดที่ประกอบเสร็จเฉพาะธีม |
| <span id="kebab">**kebab-case**</span> | แบบตั้งชื่อตัวพิมพ์เล็กคั่นด้วย `-` เช่น `rent-form.tsx` | ชื่อที่เรียงเหมือนเสียบไม้เคบับ |
| <span id="alias">**Path alias (`@/`)**</span> | ทางลัดการ import เช่น `@/components/button` แทน `../../../components/button` | ทางลัดใน GPS |
