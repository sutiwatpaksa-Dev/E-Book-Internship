## 1. ภาพรวม

![เส้นทางคำขอ /api จากเบราว์เซอร์ผ่าน Vite, Hono, Drizzle ไปถึง PostgreSQL แล้วตอบกลับทางเดิม](/img/14-request-path.svg)

> 🧩 วิธีคิดจากผังตาราง → รายการกฎ → API → แบ่งชั้น อยู่ใน [บทที่ 8b](/08b-db-to-backend) บทนี้ทำซ้ำแบบเดียวกันด้วย Hono สำหรับงาน STARTER

> 📚 บทนี้จัดโฟลเดอร์ `routes / db / validators / middleware` แบบแบ่งตามหน้าที่ ถ้าอยากรู้ว่าเมื่อไหร่ควรจัดแบบโมดูล/ฟีเจอร์ ดู [บทเสริม: จัดโครงสร้างโปรเจกต์](/project-structure)

**Hono เทียบกับ Express (บทที่ 5)** เขียนต่างกันนิดเดียว
| ทำอะไร | Express | Hono |
|---|---|---|
| ประกาศที่อยู่ API | `app.get("/x", (req, res) => res.json(...))` | `app.get("/x", (c) => c.json(...))` |
| อ่านข้อมูลที่ส่งมา | `req.body` (ต้องมี `express.json()`) | `await c.req.json()` |
| อ่านค่าในลิงก์ | `req.query.q` / `req.params.id` | `c.req.query("q")` / `c.req.param("id")` |
| ตอบพร้อมตัวเลขบอกผล | `res.status(201).json(x)` | `c.json(x, 201)` |
| รันบน | Node | Bun, Node และอื่นๆ อีกหลายที่ |

## 3. 🔧 ฐานข้อมูลด้วย Drizzle

`src/db/schema.ts` แบบแปลนตาราง (หยิบมา 3 จาก [6 ตารางของงาน STARTER](/starter/database-api#1-ตารางที่ต้องมี))
```ts
import { pgTable, serial, text, integer, boolean, timestamp } from "drizzle-orm/pg-core";

// ทุกตารางต้องมี created_at / updated_at เขียนครั้งเดียวแล้วกระจายใส่
const timestamps = {
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
  updatedAt: timestamp("updated_at", { withTimezone: true })
    .defaultNow()
    .notNull()
    .$onUpdate(() => new Date()),
};

export const categories = pgTable("categories", {
  id: serial("id").primaryKey(),
  name: text("name").notNull(),
  slug: text("slug").notNull().unique(),
  sortOrder: integer("sort_order").notNull().default(0),
  ...timestamps,
});

export const services = pgTable("services", {
  id: serial("id").primaryKey(),
  categoryId: integer("category_id")
    .notNull()
    .references(() => categories.id, { onDelete: "restrict" }),   // ห้ามลบหมวดที่ยังมีบริการ
  name: text("name").notNull(),
  description: text("description").notNull().default(""),
  price: integer("price"),                                          // null = ไม่แสดงราคา
  imageUrl: text("image_url").notNull().default(""),
  isFeatured: boolean("is_featured").notNull().default(false),
  isActive: boolean("is_active").notNull().default(true),
  sortOrder: integer("sort_order").notNull().default(0),
  ...timestamps,
});

export const contactMessages = pgTable("contact_messages", {
  id: serial("id").primaryKey(),
  name: text("name").notNull(),
  phone: text("phone").notNull(),
  email: text("email"),
  subject: text("subject"),
  message: text("message").notNull(),
  isRead: boolean("is_read").notNull().default(false),
  ...timestamps,
});
```

![บรรทัดใน schema.ts เทียบกับคอลัมน์ของตารางใน PostgreSQL](/img/14-schema-table.svg)
*แต่ละบรรทัดใน pgTable คือหนึ่งคอลัมน์ ชื่อ sortOrder ในโค้ดคือ sort_order ในฐานข้อมูล*

`drizzle.config.ts` บอก Drizzle ว่าแบบแปลนอยู่ไหน และจะเก็บไฟล์อัปเดตตารางไว้ไหน (วางที่ `server/` นอก `src/`)
```ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/db/schema.ts",
  out: "./drizzle",
  dbCredentials: { url: process.env.DATABASE_URL! },
});
```

`src/db/index.ts` ต่อฐานข้อมูล
```ts
import { drizzle } from "drizzle-orm/node-postgres";
import { env } from "../env";
import * as schema from "./schema";

export const db = drizzle(env.DATABASE_URL, { schema });
```

`src/db/migrate.ts` สั่งอัปเดตตารางจากโค้ด (ตอนขึ้นระบบจริงใช้ไฟล์นี้)
```ts
import { migrate } from "drizzle-orm/node-postgres/migrator";
import { db } from "./index";

await migrate(db, { migrationsFolder: "./drizzle" });
console.log("✅ migrate เสร็จ");
process.exit(0);
```

`src/db/seed.ts` ใส่ข้อมูลตั้งต้น **รันซ้ำกี่ครั้งก็ไม่สร้างข้อมูลซ้ำ** (สำคัญ เพราะจะใช้กับระบบจริงด้วย)
```ts
import { db } from "./index";
import { categories, services } from "./schema";

await db
  .insert(categories)
  .values([
    { name: "เครื่องดื่ม", slug: "drinks", sortOrder: 1 },
    { name: "จัดเลี้ยง", slug: "catering", sortOrder: 2 },
  ])
  .onConflictDoNothing({ target: categories.slug });       // มี slug นี้แล้ว = ข้าม

const existing = await db.$count(services);
if (existing === 0) {
  const all = await db.select().from(categories);
  const id = (slug: string) => all.find((c) => c.slug === slug)!.id;
  await db.insert(services).values([
    { categoryId: id("drinks"), name: "ลาเต้", description: "นมสดหอมมัน", price: 65, isFeatured: true, imageUrl: "https://picsum.photos/seed/latte/400/300" },
    { categoryId: id("drinks"), name: "มอคค่า", description: "ช็อกโกแลตเข้มข้น", price: 70, isFeatured: true, imageUrl: "https://picsum.photos/seed/mocha/400/300" },
    { categoryId: id("catering"), name: "Coffee Break 50 ที่", description: "สอบถามราคา", price: null, isFeatured: true, imageUrl: "https://picsum.photos/seed/event/400/300" },
  ]);
}

console.log("🌱 seed เสร็จ");
process.exit(0);
```
> 💡 ใส่ `imageUrl` ด้วย เพราะการ์ดในบทที่ 11 แสดง `<img src={service.imageUrl}>` ถ้า seed ไม่ใส่ คอลัมน์จะได้ค่า default `""` แล้วพอหน้าเว็บเปลี่ยนจากไฟล์จำลองมาเรียก API จริง การ์ดทุกใบจะเป็นรูปเสีย ข้อมูลตั้งต้นจึงต้องมีครบทุกช่องที่หน้าเว็บใช้ ถ้าเคยรัน seed ไปแล้ว (มีบริการอยู่แล้วจึงถูกข้าม) ให้ลบแถวในตาราง `services` ก่อนแล้วรันใหม่

```bash
bun run db:generate     # อ่าน schema → สร้างไฟล์ SQL ใน drizzle/
bun run db:migrate      # สร้างตารางใน DB จริง
bun run seed            # ใส่ข้อมูลตัวอย่าง
```

## 4. 🔧 รูปแบบคำตอบ และการจัดการ error ที่เดียว

`src/http/response.ts` ตัวช่วยสร้างคำตอบ + ตัวช่วยตรวจข้อมูล
```ts
import type { Context } from "hono";
import type { ContentfulStatusCode } from "hono/utils/http-status";
import { z } from "zod";

export function ok<T>(c: Context, data: T, status: ContentfulStatusCode = 200) {
  return c.json({ success: true, data }, status);
}

export function okList<T>(c: Context, data: T[], meta: { page: number; limit: number; total: number }) {
  return c.json({ success: true, data, meta });
}

// error ที่ "ตั้งใจ" ส่งกลับ client (400, 401, 404, 409, 429)
export class AppError extends Error {
  status: ContentfulStatusCode;
  code: string;
  details: unknown;

  constructor(status: ContentfulStatusCode, code: string, message: string, details: unknown = {}) {
    super(message);
    this.status = status;
    this.code = code;
    this.details = details;
  }
}

// ตรวจข้อมูลด้วย Zod ไม่ผ่าน → 400 พร้อมบอกว่าช่องไหนผิด
export function parse<T extends z.ZodType>(schema: T, input: unknown): z.infer<T> {
  const result = schema.safeParse(input);
  if (!result.success) {
    throw new AppError(400, "VALIDATION_ERROR", "ข้อมูลไม่ถูกต้อง", z.flattenError(result.error).fieldErrors);
  }
  return result.data;
}
```

![เปรียบเทียบรูปแบบคำตอบ JSON เมื่อสำเร็จกับเมื่อผิดพลาด](/img/14-envelope.svg)
*ทุก API ตอบ success เป็น true พร้อม data หรือ false พร้อม error ฝั่งหน้าเว็บเช็คแค่ success*

`src/index.ts` ไฟล์เริ่มต้น
```ts
import { Hono } from "hono";
import { logger } from "hono/logger";
import { env } from "./env";
import { AppError } from "./http/response";
import { publicRoutes } from "./routes/public";

const app = new Hono();
app.use(logger());                                          // log ทุก request ใน terminal

app.get("/api/health", (c) => c.json({ status: "ok" }));
app.route("/api", publicRoutes);

app.notFound((c) =>
  c.json({ success: false, error: { code: "NOT_FOUND", message: "ไม่พบ endpoint นี้", details: {} } }, 404),
);

app.onError((err, c) => {
  if (err instanceof AppError) {
    return c.json({ success: false, error: { code: err.code, message: err.message, details: err.details } }, err.status);
  }
  console.error(err);                                       // stack trace อยู่ใน log ของเราเท่านั้น
  return c.json(
    { success: false, error: { code: "INTERNAL_ERROR", message: "เกิดข้อผิดพลาดในระบบ", details: {} } },
    500,
  );
});

export default { port: env.PORT, fetch: app.fetch };
```
> 🔐 `onError` คือ **ตาข่ายรองรับสุดท้าย** error ไหนที่เราไม่ได้ตั้งใจ จะถูกเปลี่ยนเป็นข้อความกลางๆ ก่อนส่งกลับ รายละเอียดจริงอยู่ในหน้าจอ server ของเราเท่านั้น ไม่ต้องเขียนดักทุกที่เอง

![error จากหลายที่ไหลมารวมที่ app.onError แล้วตอบ JSON หรือ 500 ข้อความกลางๆ](/img/14-error-funnel.svg)
*AppError ที่ตั้งใจจะตอบตามที่ใส่ไว้ error ที่ไม่ได้ตั้งใจจะตอบ 500 ข้อความกลางๆ และเก็บรายละเอียดไว้ใน log ของ server*

`src/middleware/rate-limit.ts` ด่านจำกัดจำนวนครั้ง (กันส่งฟอร์มรัวๆ)
```ts
import type { Context } from "hono";
import { createMiddleware } from "hono/factory";
import { getConnInfo } from "hono/bun";
import { env } from "../env";
import { AppError } from "../http/response";

// IP ของคนที่ส่งมา
// - ไม่มี proxy (ตอนพัฒนา): ใช้ IP ของคนที่ต่อเข้ามาตรงๆ header ใดๆ ที่ client ส่งมาเองห้ามเชื่อ
// - มี proxy ที่ไว้ใจอยู่ข้างหน้า (TRUST_PROXY=true): ใช้ค่า "ท้ายสุด" ของ X-Forwarded-For
//   เพราะเป็นค่าที่ proxy ของเราเติมเอง ค่าก่อนหน้านั้น client พิมพ์ปลอมมาได้
function clientIp(c: Context): string {
  if (env.TRUST_PROXY) {
    const last = c.req.header("x-forwarded-for")?.split(",").at(-1)?.trim();
    if (last) return last;
  }
  return getConnInfo(c).remote.address ?? "unknown";
}

// จำ IP ไว้ใน memory: พอสำหรับ server ตัวเดียว (restart แล้วนับใหม่)
export function rateLimit({ limit, windowMs }: { limit: number; windowMs: number }) {
  const hits = new Map<string, number[]>();

  return createMiddleware(async (c, next) => {
    const ip = clientIp(c);
    const now = Date.now();
    const recent = (hits.get(ip) ?? []).filter((t) => now - t < windowMs);

    if (recent.length >= limit) {
      throw new AppError(429, "RATE_LIMITED", "ส่งบ่อยเกินไป กรุณารอสักครู่");
    }
    recent.push(now);
    hits.set(ip, recent);
    await next();
  });
}
```

![เปรียบเทียบการหา IP ของผู้ส่งเมื่อ TRUST_PROXY เป็น false กับ true](/img/14-client-ip.svg)

`src/routes/public.ts`
```ts
import { Hono } from "hono";
import { and, asc, eq } from "drizzle-orm";
import { db } from "../db";
import { categories, contactMessages, services } from "../db/schema";
import { ok, parse } from "../http/response";
import { rateLimit } from "../middleware/rate-limit";
import { ContactInput, ServiceQuery } from "../validators/public";

export const publicRoutes = new Hono();

publicRoutes.get("/categories", async (c) => {
  const rows = await db.select().from(categories).orderBy(asc(categories.sortOrder));
  return ok(c, rows);
});

publicRoutes.get("/services", async (c) => {
  const q = parse(ServiceQuery, c.req.query());
  const rows = await db
    .select({
      id: services.id,
      name: services.name,
      description: services.description,
      price: services.price,
      imageUrl: services.imageUrl,
      category: categories.slug,
    })
    .from(services)
    .innerJoin(categories, eq(services.categoryId, categories.id))
    .where(
      and(
        eq(services.isActive, true),                                   // แสดงเฉพาะที่เปิดอยู่
        q.category ? eq(categories.slug, q.category) : undefined,     // undefined = ไม่กรอง
        q.featured === "true" ? eq(services.isFeatured, true) : undefined,
      ),
    )
    .orderBy(asc(services.sortOrder));
  return ok(c, rows);
});

publicRoutes.post("/contact", rateLimit({ limit: 5, windowMs: 10 * 60 * 1000 }), async (c) => {
  const body = parse(ContactInput, await c.req.json().catch(() => null));   // JSON พัง = 400 ไม่ใช่ 500
  const [row] = await db
    .insert(contactMessages)
    .values({ ...body, email: body.email || null })
    .returning({ id: contactMessages.id });
  return ok(c, row, 201);
});
```

### ตัวกลางเรียก API อยู่ที่เดียว
`client/src/api/client.ts`
```ts
type ApiBody<T> =
  | { success: true; data: T }
  | { success: false; error: { code: string; message: string; details?: Record<string, string[]> } };

export class ApiError extends Error {
  status: number;
  code: string;
  details: Record<string, string[]>;

  constructor(status: number, code: string, message: string, details: Record<string, string[]> = {}) {
    super(message);
    this.status = status;
    this.code = code;
    this.details = details;
  }
}

export async function api<T>(path: string, init: RequestInit = {}): Promise<T> {
  let res: Response;
  try {
    res = await fetch(path, {
      ...init,
      headers: { "Content-Type": "application/json", ...init.headers },
    });
  } catch {
    throw new ApiError(0, "NETWORK_ERROR", "เชื่อมต่อ server ไม่ได้");
  }

  const body = (await res.json().catch(() => null)) as ApiBody<T> | null;
  if (!body) throw new ApiError(res.status, "BAD_RESPONSE", "server ตอบกลับไม่ถูกต้อง");
  if (!body.success) throw new ApiError(res.status, body.error.code, body.error.message, body.error.details);
  return body.data;
}
```

แก้ `useFetch` ในบทที่ 11 ให้เรียก `api<T>(url, { signal: controller.signal })` แทน `fetch` และเปลี่ยนที่อยู่จาก `/mock/services.json` เป็น `/api/services`

ส่งฟอร์มติดต่อของจริง (แทน `setTimeout` ในบทที่ 11) เพิ่ม state ไว้เก็บ error จาก server ในฟอร์มก่อน:
```tsx
const [serverError, setServerError] = useState<string | null>(null);
// ...แล้วแสดงไว้เหนือปุ่มส่ง
{serverError && <p className="error">{serverError}</p>}
```
จากนั้นแทนที่ส่วน `try` ใน `onSubmit`:
```ts
import { api, ApiError } from "../api/client";

try {
  await api("/api/contact", { method: "POST", body: JSON.stringify(form) });
  setDone(true);
  setForm(empty);
} catch (err) {
  if (err instanceof ApiError && err.code === "VALIDATION_ERROR") {
    // server ส่ง details มาว่าช่องไหนผิด แสดงใต้ช่องนั้นได้เลย
    setErrors(Object.fromEntries(Object.entries(err.details).map(([k, v]) => [k, v[0]])));
  } else {
    setServerError(err instanceof Error ? err.message : "ส่งไม่สำเร็จ");
  }
}
```

## 7. ⚠️ ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| ขึ้น `ZodError ... DATABASE_URL` ตอนเปิด | ไม่มีไฟล์ `.env` หรือสั่งนอกโฟลเดอร์ `server/` | `cd server` แล้วสั่ง `bun run dev` |
| ขึ้น `ECONNREFUSED 127.0.0.1:5432` | ฐานข้อมูลยังไม่เปิด | `docker compose up -d` แล้วดู `docker compose ps` |
| ขึ้น `relation "services" does not exist` | ยังไม่ได้สร้างตาราง | `bun run db:generate` แล้ว `bun run db:migrate` |
| หน้าเว็บได้หน้า HTML แทนข้อมูล | ไม่ได้ตั้งการส่งต่อใน Vite หรือ server ไม่ได้เปิด | ตรวจ `vite.config.ts` แล้วปิด-เปิด `bun run dev` ฝั่งหน้าเว็บใหม่ |
| ส่งข้อมูลผิดแล้วได้ 500 แทน 400 | เรียก `.parse()` ของ Zod ตรงๆ | ใช้ตัวช่วย `parse(schema, input)` ที่เราเขียนไว้ |
| แก้แบบแปลนแล้วตารางไม่เปลี่ยน | ลืมสร้างไฟล์อัปเดตตารางใหม่ | `db:generate` → `db:migrate` ทุกครั้งที่แก้แบบแปลน |

## 🧠 เช็คความเข้าใจ

<details>
<summary>1. ทำไมคำสั่งใส่ข้อมูลตั้งต้น (seed) ต้องรันซ้ำได้โดยข้อมูลไม่ซ้ำ?</summary>

เพราะจะใช้กับระบบจริงตอนขึ้นเว็บด้วย ถ้ารันซ้ำแล้วข้อมูลซ้ำหรือถูกลบ ลูกค้าจะเสียข้อมูลจริง จึงใช้ `onConflictDoNothing` และเช็คก่อนใส่

</details>

<details>
<summary>2. ทำไมใช้ `app.onError` ดีกว่าเขียนดัก error ทุกที่?</summary>

มั่นใจได้ว่า error ทุกตัวที่ไม่ได้ตั้งใจ จะกลายเป็นข้อความกลางๆ แบบเดียวกันหมด ลืมดักสักที่ก็ไม่หลุดรายละเอียดออกไป และโค้ดแต่ละ API สั้นลง

</details>

<details>
<summary>3. ตัวจำกัดจำนวนครั้งที่จำไว้ในหน่วยความจำ มีข้อจำกัดอะไร?</summary>

ปิด-เปิด server แล้วตัวนับหาย และถ้ามี server หลายเครื่อง แต่ละเครื่องนับแยกกัน ระบบใหญ่จึงเก็บตัวนับไว้ที่อื่น (เช่น Redis) แต่งาน STARTER มี server เครื่องเดียวถือว่าพอ

</details>

<details>
<summary>4. `onDelete: "restrict"` กับ `"cascade"` ต่างกันยังไง?</summary>

restrict = ห้ามลบหมวดถ้ายังมีสินค้าอยู่ในหมวด / cascade = ลบหมวดแล้วสินค้าในหมวดหายไปด้วย งาน STARTER ต้องการแบบแรก และ API ควรเช็คก่อนแล้วตอบ `409`

</details>
