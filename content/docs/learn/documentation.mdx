## ขั้นนี้คืออะไร

เขียนสิ่งที่คนอื่น (และตัวเราในอีก 3 เดือน) ต้องรู้เพื่อ **รัน ใช้ และแก้ระบบต่อได้โดยไม่ต้องถามเรา** เอกสารไม่ได้เขียนครั้งเดียวตอนท้าย จดไปตลอดทุกขั้น ขั้นนี้คือจุดที่รวมให้ครบและอ่านรู้เรื่อง

**ทำไมมาก่อน Deploy:** ก่อนขึ้นระบบจริงต้องรู้แล้วว่าต้องตั้งค่า env อะไร รันคำสั่งไหน ซึ่งก็คือ README นั่นเอง

## ถ้าข้ามขั้นนี้จะเกิดอะไร

พี่ไบต์ลาพักร้อน ลูกค้าแจ้งว่าเว็บล่ม บิตเปิด repo ไม่เจอว่าต้องตั้ง env อะไร ฐานข้อมูลอยู่ไหน ต้องรอพี่ไบต์กลับมา **ความรู้ที่อยู่ในหัวคนเดียว หายไปพร้อมคนนั้น**

## ความรู้ที่ใช้ในขั้นนี้

<StepCards step="documentation" />

เริ่มจาก [README ที่คนอื่นรันตามได้](/learn/cards/readme) ซึ่งเป็นของส่งที่ Requirement ตรวจหนักที่สุด (รันตาม README ไม่ขึ้น = ไม่ผ่านทันที) ส่วนเอกสาร API คือ Postman collection จากการ์ด [ยิงทดสอบ API](/learn/cards/api-testing) และตัวอย่าง changelog ที่ใช้จริงคือหน้า [มีอะไรใหม่](/changelog) ของเว็บนี้

## ลงมือกับโปรเจกต์ของเรา

<Task>

เขียน README ของ STARTER แล้วให้เพื่อน clone repo ไปรันในเครื่องตัวเองโดยดูแค่ README ห้ามถามเรา จดทุกจุดที่เพื่อนติด แล้วแก้ README ตรงนั้น

<Hint level={1}>เขียนตามลำดับที่คนใหม่ต้องทำ: ติดตั้งอะไร → clone → ตั้งค่า → รัน → เปิดดูที่ไหน</Hint>

<Hint level={2}>ค่าลับห้ามอยู่ใน README ใส่แค่ชื่อตัวแปรใน `.env.example` แล้วบอกว่าเอาค่ามาจากไหน</Hint>

<Hint level={3}>คำสั่งที่ Windows กับ Mac พิมพ์ต่างกัน ต้องมีให้ครบทั้งสองแบบ</Hint>

</Task>

## จบขั้นแล้วต้องมี

- [ ] `README.md`: ระบบนี้คืออะไร, ติดตั้ง, ตั้งค่า `.env`, migration/seed, รัน, บัญชี admin ทดสอบ และตาราง "ติดปัญหา" (ใช้ Git Bash บน Windows ได้ทุกคำสั่ง)
- [ ] เพื่อนที่ไม่เคยเห็นโปรเจกต์ clone แล้วรันขึ้นตาม README โดยไม่ถามเรา
- [ ] `.env.example`: ชื่อตัวแปรทุกตัวพร้อมคำอธิบาย **ไม่มีค่าจริง**
- [ ] รายการ API ที่ตรงกับโค้ดปัจจุบัน
- [ ] บันทึกการเปลี่ยนแปลง (changelog) และเลขเวอร์ชัน

## คำถามที่ต้องตอบได้

1. คนที่ไม่เคยเห็นโปรเจกต์นี้ ทำตาม README แล้วรันได้ภายใน 30 นาทีไหม
2. ค่าลับทุกตัวอยู่นอก repo แล้วหรือยัง
3. ถ้าพรุ่งนี้มีคนมาแทน เขาต้องถามอะไรเราบ้าง (คำตอบเหล่านั้นควรอยู่ในเอกสาร)
