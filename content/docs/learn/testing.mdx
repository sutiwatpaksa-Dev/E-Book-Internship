## ขั้นนี้คืออะไร

พิสูจน์ว่าระบบทำได้ตามเกณฑ์ใน user story และ **แก้ตรงหนึ่งแล้วตรงอื่นไม่พัง** มีสองแบบที่ใช้คู่กัน: ทดสอบด้วยมือตามเช็กลิสต์ กับเทสต์ที่เขียนเป็นโค้ดให้เครื่องรันซ้ำได้ทุกครั้ง

## ถ้าข้ามขั้นนี้จะเกิดอะไร

บิตแก้ให้ราคาแสดงทศนิยม 2 ตำแหน่ง ส่งงานไปแล้วลูกค้าแจ้งว่ายอดรวมตะกร้าผิด เพราะฟังก์ชันคิดยอดรวมใช้ค่าที่ถูกปัดไปแล้ว **ไม่มีเทสต์ = รู้ว่าพังตอนผู้ใช้เจอ**

## จบขั้นแล้วต้องมี

- [ ] เช็กลิสต์ทดสอบด้วยมือ: 1 ข้อต่อเกณฑ์ใน user story ทั้งกรณีปกติและกรณีผิด (ข้อมูลว่าง, ไม่ได้ login, ไม่มีสิทธิ์)
- [ ] ไฟล์ `.http` หรือรายการคำสั่ง `curl` ที่ยิง API หลักได้ครบ
- [ ] เทสต์โค้ดของกฎสำคัญใน Backend (เช่น คิดราคา ตรวจสิทธิ์) รันด้วยคำสั่งเดียว
- [ ] รันเทสต์ผ่านทั้งหมดก่อนส่งงานทุกครั้ง

## คำถามที่ต้องตอบได้

1. กฎข้อไหนถ้าพังแล้วเสียหายที่สุด ข้อนั้นมีเทสต์หรือยัง
2. ผู้ใช้ทำอะไรผิดได้บ้าง ระบบตอบกลับยังไง
3. เทสต์ที่พังบอกเราได้ไหมว่าพังตรงไหน

## ลงมือกับโปรเจกต์ของเรา

เขียนเช็กลิสต์ทดสอบจาก user story ของ STARTER ทุกข้อที่ "ต้องมี" แล้วให้เพื่อนอีกคนทำตามเช็กลิสต์ของเรา (คนเขียนมักมองไม่เห็นจุดพังของตัวเอง)
