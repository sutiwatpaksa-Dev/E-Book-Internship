## ขั้นนี้คืออะไร

พิสูจน์ว่าระบบทำได้ตามเกณฑ์ใน user story และ **แก้ตรงหนึ่งแล้วตรงอื่นไม่พัง** มีสองแบบที่ใช้คู่กัน: ทดสอบด้วยมือตามเช็กลิสต์ กับเทสต์ที่เขียนเป็นโค้ดให้เครื่องรันซ้ำได้ทุกครั้ง

## ถ้าข้ามขั้นนี้จะเกิดอะไร

บิตแก้ให้วันครบกำหนดคืนแสดงเป็นวันที่ไทย ส่งงานไปแล้วบรรณารักษ์แจ้งว่ารายการเกินกำหนดคืน (story 7) มีชื่อสมาชิกที่เพิ่งยืมเมื่อวาน เพราะโค้ดที่เทียบวันไปใช้ข้อความวันที่ที่แปลงแล้ว แทนวันที่จริง **ไม่มีเทสต์ = รู้ว่าพังตอนผู้ใช้เจอ**

## ความรู้ที่ใช้ในขั้นนี้

<StepCards step="testing" />

เริ่มจาก [ทดสอบด้วยมือแบบมีแผน](/learn/cards/manual-testing) ได้ `TESTING.md` ที่คนอื่นทำตามได้ แล้ว [เทสต์อัตโนมัติด้วย bun test](/learn/cards/unit-test) ย้ายข้อที่ต้องตรวจซ้ำทุกรอบไปให้เครื่องทำ

## ลงมือกับโปรเจกต์ของเรา

<Task>

เขียน `TESTING.md` จาก user story ของ STARTER ทุกข้อที่ "ต้องมี" แล้วให้เพื่อนอีกคนทำตามเช็กลิสต์ของเรา (คนเขียนมักมองไม่เห็นจุดพังของตัวเอง)

<Hint level={1}>1 story ที่ "ต้องมี" = อย่างน้อย 1 ข้อในเช็กลิสต์ เขียนเป็น "ทำ [อะไร] แล้วต้องเห็น [อะไร]"</Hint>

<Hint level={2}>อย่าลืมทางพัง: ช่องว่าง, กรอกผิดรูปแบบ, กดซ้ำสองครั้ง, ยังไม่ login</Hint>

<Hint level={3}>ให้เพื่อนทำโดยเราไม่ช่วยพูด จดเฉพาะสิ่งที่เพื่อนเห็นจริง ไม่ใช่สิ่งที่เราคิดว่าควรเห็น</Hint>

</Task>

## จบขั้นแล้วต้องมี

- [ ] `TESTING.md`: test case อย่างน้อย 1 ข้อต่อเกณฑ์ใน user story ทั้งกรณีปกติและกรณีผิด (ข้อมูลว่าง, ไม่ได้ login, ไม่มีสิทธิ์), 4 สถานะของทุกหน้า และ 3 ขนาดจอ
- [ ] ข้อไม่ผ่านทันทีของ Requirement หน้า 12 อยู่บนสุดของ `TESTING.md` และผ่านครบ
- [ ] ไฟล์ `.http` หรือรายการคำสั่ง `curl` ที่ยิง API หลักได้ครบ
- [ ] เทสต์โค้ดของกฎสำคัญใน Backend (เช่น validator ของฟอร์มหลักทุกตัว ตรวจสิทธิ์) รันด้วย `bun test` คำสั่งเดียว
- [ ] รันเทสต์ผ่านทั้งหมดก่อนส่งงานทุกครั้ง

## คำถามที่ต้องตอบได้

1. กฎข้อไหนถ้าพังแล้วเสียหายที่สุด ข้อนั้นมีเทสต์หรือยัง
2. ผู้ใช้ทำอะไรผิดได้บ้าง ระบบตอบกลับยังไง
3. เทสต์ที่พังบอกเราได้ไหมว่าพังตรงไหน
