## ขั้นนี้คืออะไร

ย้ายระบบจากเครื่องเราไปไว้บนเครื่องที่เปิดตลอดเวลา แล้วให้คนอื่นเปิดได้จาก URL จริง มีสองทางหลัก: **บริการสำเร็จรูป** (เช่น Vercel + Neon ดูแลเครื่องให้) กับ **เช่าเครื่องเอง** (VPS ดูแลเองทั้งหมด)

## ถ้าทำไม่ครบจะเกิดอะไร

บิตขึ้นเว็บสำเร็จ แต่ลืมรัน migration กับฐานข้อมูลจริง เปิดหน้าแรกได้ login หลังบ้านแล้ว error เพราะไม่มีตาราง **deploy ไม่ได้จบที่ "เว็บเปิดได้" แต่จบที่ "งานหลักใช้ได้จริง"**

## ลงมือกับโปรเจกต์ของเรา

<Task>

เริ่มจากการ์ด build ให้ server ตัวเดียวเสิร์ฟทั้งเว็บ แล้วเลือกขึ้นจริง**ทางเดียว**: รวมเป็น Docker Compose แล้วขึ้น VPS พร้อมโดเมนย่อย (ดูแลเครื่องเอง) หรือขึ้นด้วย Vercel + Neon (ไม่ต้องดูแลเครื่อง แต่ต้องคิดเรื่องโค้ดที่รันเป็น function) คุยกับพี่เลี้ยงก่อนว่าจะใช้ทางไหน เพราะ VPS และ DNS เป็นของบริษัท ส่วนแผนฟรีของ Vercel ห้ามใช้เชิงพาณิชย์ จากนั้นไล่เช็กลิสต์จากขั้น 4 บนเว็บจริงทุกข้อ จดข้อที่ผลต่างจากในเครื่องพร้อมสาเหตุ

<Hint level={1}>สิ่งที่ในเครื่องมีแต่บนเว็บจริงไม่มี มักเป็นค่าใน `.env` ไล่ดูทุกตัวว่าใส่ในบริการแล้วหรือยัง</Hint>

<Hint level={2}>ฐานข้อมูลบนเว็บจริงเป็นคนละฐานกับในเครื่อง ตารางต้องถูกสร้างด้วย migration แบบเดียวกัน</Hint>

<Hint level={3}>บนเว็บจริงพังแต่ในเครื่องผ่าน ให้เปิด log ก่อนแก้โค้ด (`docker compose logs app` หรือหน้า log ของบริการ) บรรทัดแรกของ error มักบอกต้นเหตุ</Hint>

</Task>

## จบขั้นแล้วต้องมี

- [ ] เว็บเปิดได้จาก URL จริงผ่าน https
- [ ] ค่า env ตั้งบน server ครบ ไม่มีค่าลับใน repo
- [ ] ฐานข้อมูลจริงรัน migration แล้ว
- [ ] ลองทำงานหลักทุกข้อบนเว็บจริงตามเช็กลิสต์จากขั้น 4
- [ ] รู้ว่าถ้าต้องถอยกลับเวอร์ชันก่อน ทำยังไง

## คำถามที่ต้องตอบได้

1. ทำไมเลือกบริการสำเร็จรูปหรือเช่าเครื่อง แลกกับอะไร
2. ค่า env บนเครื่องจริงต่างจากในเครื่องเราตรงไหน
3. ถ้า deploy แล้วพัง จะดู error ได้ที่ไหน
