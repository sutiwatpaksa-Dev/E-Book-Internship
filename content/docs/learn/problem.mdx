## ขั้นนี้คืออะไร

หาให้ชัดว่า **ใครเจอปัญหาอะไร และระบบต้องทำอะไรได้บ้าง** ก่อนเปิดโปรแกรมเขียนโค้ด ผลของขั้นนี้คือรายการสั้นๆ ที่ทุกคน (เรา ลูกค้า พี่เลี้ยง) อ่านแล้วเข้าใจตรงกัน

## ถ้าข้ามขั้นนี้จะเกิดอะไร

บิตได้โจทย์ "ทำระบบยืมหนังสือของห้องสมุด" แล้วรีบเขียนทันที 3 วันต่อมาบรรณารักษ์ถามว่า "แล้วต่ออายุการยืมตรงไหน" บิตต้องรื้อตารางใหม่ เพราะไม่ได้ถามตั้งแต่ต้นว่ายืมต่อได้ไหม **คำถามที่ไม่ได้ถามวันแรก กลายเป็นงานแก้ในวันท้ายๆ**

<Task>

<Hint level={1}>ลองเขียนแต่ละข้อในรูป "ในฐานะ [ใคร] อยาก [ทำอะไร] เพื่อ [ได้อะไร]" ถ้าเติมช่อง "เพื่อ" ไม่ได้ ข้อนั้นอาจยังไม่ใช่ความต้องการจริง</Hint>

<Hint level={2}>ไล่ผู้ใช้ทุกแบบที่ Requirement พูดถึง แต่ละแบบน่าจะมีอย่างน้อย 2 story</Hint>

## จบขั้นแล้วต้องมี

- [ ] brief 1 หน้า (ชื่อ ลูกค้าหลัก สี โลโก้ สินค้า/บริการ 6 อย่าง) **ผ่านพี่เลี้ยงแล้ว**
- [ ] รายการ user story รูปแบบ "ในฐานะ **ใคร** อยากจะ **ทำอะไร** เพื่อ **ได้อะไร**"
- [ ] แต่ละ story มีเกณฑ์ว่าแบบไหนถือว่าเสร็จ (เช่น "สมาชิกที่ยืมค้าง 3 เล่ม บันทึกการยืมเพิ่มไม่ได้")
- [ ] จัดลำดับแล้วว่าข้อไหน **ต้องมี** / **ควรมี** / **ไว้ทีหลัง**
- [ ] ไฟล์ `NOTES.md` มีรายการสิ่งที่ **ไม่ทำ** ในรอบนี้ (ขอบเขต), ข้อสมมติ และคำถามที่ยังไม่มีคำตอบ

## คำถามที่ต้องตอบได้

1. ผู้ใช้ระบบนี้มีกี่แบบ แต่ละแบบต้องทำอะไรได้บ้าง
2. ถ้าทำได้แค่ 3 อย่าง ต้องเป็น 3 อย่างไหน เพราะอะไร
3. มีอะไรที่ลูกค้าพูดถึงแต่เราตกลงว่ายังไม่ทำ
