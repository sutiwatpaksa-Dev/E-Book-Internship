## ขั้นนี้คืออะไร

หาให้ชัดว่า **ใครเจอปัญหาอะไร และระบบต้องทำอะไรได้บ้าง** ก่อนเปิดโปรแกรมเขียนโค้ด ผลของขั้นนี้คือรายการสั้นๆ ที่ทุกคน (เรา ลูกค้า พี่เลี้ยง) อ่านแล้วเข้าใจตรงกัน

## ถ้าข้ามขั้นนี้จะเกิดอะไร

บิตได้โจทย์ "ทำหน้าจองคิว" แล้วรีบเขียนทันที 3 วันต่อมาลูกค้าถามว่า "แล้วยกเลิกคิวตรงไหน" บิตต้องรื้อตารางใหม่ เพราะไม่ได้ถามตั้งแต่ต้นว่ายกเลิกได้ไหม **คำถามที่ไม่ได้ถามวันแรก กลายเป็นงานแก้ในวันท้ายๆ**

## ความรู้ที่ใช้ในขั้นนี้

<StepCards step="problem" />

> การ์ดของขั้นนี้ (อ่าน requirement, เขียน user story, ถามลูกค้าให้ได้คำตอบ) กำลังเขียน ระหว่างนี้ใช้ Requirement STARTER ฝึกได้เลย

## ลงมือกับโปรเจกต์ของเรา

<Task>

อ่าน Requirement ของงาน STARTER (ต้อง login) แล้วเขียน user story ของตัวเอง **อย่างน้อย 8 ข้อ** จัดลำดับ ต้องมี / ควรมี / ไว้ทีหลัง และจดคำถามที่อ่านแล้วยังไม่แน่ใจไว้ถามพี่เลี้ยง ยังไม่ต้องคิดเรื่องโค้ดหรือตาราง

<Hint level={1}>ลองเขียนแต่ละข้อในรูป "ในฐานะ [ใคร] อยาก [ทำอะไร] เพื่อ [ได้อะไร]" ถ้าเติมช่อง "เพื่อ" ไม่ได้ ข้อนั้นอาจยังไม่ใช่ความต้องการจริง</Hint>

<Hint level={2}>ไล่ผู้ใช้ทุกแบบที่ Requirement พูดถึง แต่ละแบบน่าจะมีอย่างน้อย 2 story</Hint>

<Hint level={3}>ตัดสินว่า "ต้องมี" ด้วยคำถามเดียว: ถ้าไม่มีข้อนี้ ยังส่งมอบระบบได้ไหม ถ้าไม่ได้ แปลว่าต้องมี</Hint>

</Task>

## จบขั้นแล้วต้องมี

- [ ] รายการ user story รูปแบบ "ในฐานะ **ใคร** อยากจะ **ทำอะไร** เพื่อ **ได้อะไร**"
- [ ] แต่ละ story มีเกณฑ์ว่าแบบไหนถือว่าเสร็จ (เช่น "ยกเลิกได้ก่อนเวลานัด 1 ชั่วโมง")
- [ ] จัดลำดับแล้วว่าข้อไหน **ต้องมี** / **ควรมี** / **ไว้ทีหลัง**
- [ ] รายการสิ่งที่ **ไม่ทำ** ในรอบนี้ (ขอบเขต)
- [ ] รายการคำถามที่ยังไม่มีคำตอบ พร้อมว่าจะถามใคร

## คำถามที่ต้องตอบได้

1. ผู้ใช้ระบบนี้มีกี่แบบ แต่ละแบบต้องทำอะไรได้บ้าง
2. ถ้าทำได้แค่ 3 อย่าง ต้องเป็น 3 อย่างไหน เพราะอะไร
3. มีอะไรที่ลูกค้าพูดถึงแต่เราตกลงว่ายังไม่ทำ
