## ขั้นนี้คืออะไร

เปลี่ยน user story จากขั้น 1 เป็น **แบบ** 3 ชิ้นที่ต่อกัน: หน้าจอที่ผู้ใช้เห็น → ข้อมูลที่ต้องเก็บ → API ที่เชื่อมสองฝั่ง แล้วแบ่งงานเป็นชิ้นเล็กๆ ที่ทำเสร็จได้ทีละชิ้น

## ถ้าข้ามขั้นนี้จะเกิดอะไร

บิตทำหน้าเว็บเสร็จสวยงาม พอเริ่มทำ server ถึงรู้ว่าหน้า "ประวัติการยืมของสมาชิก" ต้องใช้วันที่คืนจริง ซึ่งไม่ได้เก็บไว้เลย ต้องกลับไปแก้ทั้งตาราง API และหน้าเว็บ **แบบที่วาดบนกระดาษแก้ใน 5 นาที แบบที่เขียนเป็นโค้ดแล้วแก้เป็นวัน**

## ลงมือกับโปรเจกต์ของเรา

<Task>

จาก user story ของ STARTER วาดหน้าจอหลักทุกหน้า แล้ว **ไล่ทีละช่องบนหน้าจอ** ว่าต้องเก็บข้อมูลอะไร จดเป็นตาราง จากนั้นเขียนรายการ API ส่งทั้ง 3 อย่างให้พี่เลี้ยงดูก่อนเริ่มเขียนโค้ด

<Hint level={1}>เริ่มจากหน้าที่ใช้บ่อยที่สุด วาดเป็นกล่องบนกระดาษก็พอ ยังไม่ต้องสวย</Hint>

<Hint level={2}>ทุกช่องบนหน้าจอต้องตอบได้ว่ามาจากตารางไหน คอลัมน์ไหน ช่องที่ตอบไม่ได้แปลว่าตารางยังขาด</Hint>

<Hint level={3}>รายการ API: 1 ปุ่มหรือ 1 การโหลดหน้า ประมาณ 1 API เขียนบรรทัดละตัว `METHOD /path` แล้วตามด้วยสิ่งที่ได้กลับ</Hint>

</Task>

## จบขั้นแล้วต้องมี

- [ ] ภาพร่างหน้าจอ (Draft UX-UI) ทุกหน้าใน story ที่ "ต้องมี" วาดมือหรือใช้ Figma / Penpot ก็ได้ ไม่ต้องสวย
- [ ] ลำดับการกด (user flow) ของงานหลัก เช่น เปิดเว็บ → เลือกเวลา → ยืนยัน → เห็นคิว
- [ ] แบบตาราง: มีตารางอะไร คอลัมน์อะไร ตารางไหนโยงกับตารางไหน
- [ ] รายการ API: method + path + ใครเรียกได้ + ส่งอะไรไป ได้อะไรกลับ
- [ ] รายการงานย่อย แต่ละชิ้นทำเสร็จได้ใน 1 วัน

## คำถามที่ต้องตอบได้

1. ทุกช่องบนภาพร่างหน้าจอ มาจากคอลัมน์ไหนของตารางไหน
2. ทุกปุ่มบนหน้าจอ เรียก API ตัวไหน
3. ถ้าลบข้อมูลแถวหนึ่ง ข้อมูลในตารางอื่นที่โยงอยู่จะเป็นยังไง
