## ความหมาย

`README.md` คือไฟล์แรกที่ GitHub แสดงเมื่อเปิด repo บอกว่าโปรเจกต์นี้คืออะไร และ **คนที่ไม่เคยเห็นมันมาก่อนต้องทำอะไรบ้าง ทีละคำสั่ง จนเปิดเว็บขึ้นมาได้** README ที่ดีวัดผลง่ายมาก: ให้เพื่อนทำตามบนเครื่องของเขาโดยไม่ถามเราสักคำ ถ้ารันขึ้นคือผ่าน

**นึกภาพ:** คู่มือประกอบตู้ IKEA ทุกขั้นมีรูป มีรายการน็อตที่ต้องใช้ตั้งแต่หน้าแรก คนซื้อประกอบเองที่บ้านได้โดยไม่ต้องโทรหาร้าน ถ้าคู่มือลืมบอกขั้นเดียว ตู้ทั้งหลังก็ประกอบไม่เสร็จ

## ที่มา

ตอนเราเขียนโค้ด เครื่องเรามีของที่ทำไว้เมื่อหลายวันก่อนครบ: กล่อง Postgres ใน Docker, ไฟล์ `.env`, ตารางที่ migrate แล้ว, บัญชีบรรณารักษ์ที่ seed แล้ว เราจึงลืมว่าเคยทำ แต่คนที่ clone repo ไปได้แค่ไฟล์ที่ commit **ไม่ได้ `.env`** (เราตั้งใจไม่ commit) **ไม่ได้ `node_modules`** และ **ไม่ได้ฐานข้อมูล** ลองแล้ว: clone มาแล้วรัน migrate ทันที ได้แค่

```text
Error  Please provide required params for Postgres driver:
    [x] url: undefined
```

ข้อความนี้ไม่บอกเลยว่าต้องสร้าง `server/.env` คนที่ไม่รู้จะติดอยู่ตรงนี้ README มีไว้ปิดช่องว่างระหว่าง "เครื่องเรา" กับ "เครื่องคนอื่น"

## การใช้งาน

**1. ลองเป็นคนใหม่ก่อนเขียน** clone repo ของตัวเองลงโฟลเดอร์ใหม่ (Mac และ Windows Git Bash พิมพ์เหมือนกัน)

```bash
cd ~/Desktop
git clone https://github.com/<ชื่อบัญชี>/<ชื่อ-repo>.git test-readme
cd test-readme
```

แล้วพยายามรันให้ขึ้น จดทุกคำสั่งที่ต้องพิมพ์และทุกครั้งที่ติด รายการนี้คือโครงของ README ส่วนโฟลเดอร์เดิมที่ทำงานอยู่ไม่ต้องแตะ

**2. เขียน `README.md` ที่ root ของ repo** (ข้าง `client/` และ `server/`) ตามลำดับที่คนใหม่ต้องทำ ตัวอย่างของห้องสมุดบิต ใช้คำสั่งจากการ์ดช่วง Coding ทั้งหมด

````markdown
# ห้องสมุดบิต

เว็บค้นหนังสือของห้องสมุดบิต คนทั่วไปค้นและดูว่าเล่มไหนว่าง บรรณารักษ์ login เข้าหลังบ้านเพื่อเพิ่ม แก้ ลบหนังสือ

## ต้องมีในเครื่องก่อน

- [Bun](https://bun.sh) (เช็กด้วย `bun --version`)
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) เปิดไว้ก่อนเริ่ม
- Git · **Windows ใช้ Git Bash** พิมพ์ทุกคำสั่งในไฟล์นี้ (ไม่ใช่ PowerShell)

## ติดตั้งครั้งแรก

**1. เปิดฐานข้อมูล** (ทำครั้งเดียว ครั้งต่อไปใช้ `docker start pg`)

```bash
MSYS_NO_PATHCONV=1 docker run -d --name pg -e POSTGRES_PASSWORD=secret -p 5432:5432 -v pgdata:/var/lib/postgresql/data postgres:17-alpine
```

**2. ตั้งค่า server**

```bash
cd server
bun install
cp .env.example .env
```

เปิด `server/.env` แล้วใส่ค่าทุกตัว

| ตัวแปร | ใส่อะไร |
|---|---|
| `DATABASE_URL` | `postgres://postgres:secret@localhost:5432/postgres` (ตรงกับข้อ 1) |
| `JWT_SECRET` | สุ่มด้วย `bun -e "console.log(require('crypto').randomBytes(48).toString('base64'))"` |
| `LIBRARIAN_EMAIL`, `LIBRARIAN_PASSWORD` | บัญชีบรรณารักษ์ที่ seed จะสร้างให้ ตั้งเองได้ |

**3. สร้างตารางและข้อมูลตัวอย่าง** (ยังอยู่ใน `server/`)

```bash
bunx drizzle-kit migrate
bun run seed
```

**4. ติดตั้งหน้าเว็บ**

```bash
cd ../client
bun install
```

## รัน

เปิด Terminal 2 หน้าต่าง แต่ละหน้าต่างเริ่มที่ root ของ repo (โฟลเดอร์ที่มี README นี้)

| หน้าต่าง | คำสั่ง | เปิดดูที่ |
|---|---|---|
| 1 | `cd server && bun run dev` | http://localhost:3000/api/books |
| 2 | `cd client && bun run dev` | http://localhost:5173 |

หลังบ้าน: http://localhost:5173/admin/login ใช้อีเมลและรหัสที่ตั้งใน `LIBRARIAN_EMAIL` / `LIBRARIAN_PASSWORD`

## ติดปัญหา

| เห็น | แปลว่า / แก้ |
|---|---|
| `url: undefined` ตอน migrate | ยังไม่มี `server/.env` หรือยังไม่ใส่ `DATABASE_URL` (ข้อ 2) |
| migrate ค้างที่ `applying migrations...` ไม่จบ | ฐานข้อมูลยังไม่เปิด `docker ps` ต้องเห็น `pg` ถ้าไม่เห็น `docker start pg` |
| `JWT_SECRET ใน .env ต้องยาวอย่างน้อย 32 ตัวอักษร` | ยังไม่ได้สุ่ม `JWT_SECRET` (ข้อ 2) แก้แล้วหยุด server แล้วรันใหม่ |
| `port is already allocated` | มี Postgres ตัวอื่นใช้ port 5432 อยู่ ปิดตัวนั้น หรือเปลี่ยนเลขหน้าใน `-p` และใน `DATABASE_URL` ให้ตรงกัน |

## เอกสารอื่น

- รายการ API และตัวอย่างคำขอ: `docs/library.postman_collection.json` (Import เข้า Postman)
- แบบตาราง: `docs/er-diagram.png`
````

ตาราง "ติดปัญหา" มาจากการลองจริงตอน clone ในข้อ 1 ของการ์ดนี้ทุกบรรทัด ไม่ได้เดา บรรทัดที่ 2 เจอตอนลืมเปิด Docker: migrate ค้างโดยไม่มี error สักบรรทัด ถ้าไม่เขียนไว้ คนใหม่จะรอไปเรื่อยๆ

**3. ตรวจ `server/.env.example` ว่าครบทุกตัว** ไฟล์นี้ทำมาตั้งแต่การ์ด Drizzle แล้วเติมทีละตัวในการ์ด Login README บอกว่า "ใส่อะไร" ไฟล์นี้บอกว่า "มีตัวไหนบ้าง" มีแค่ชื่อ **ไม่มีค่าจริง** เพราะไฟล์นี้ถูก commit ขึ้น GitHub

```bash
DATABASE_URL=
JWT_SECRET=
LIBRARIAN_EMAIL=
LIBRARIAN_PASSWORD=
```

**4. รวมของส่งไว้ใน `docs/`** สร้างโฟลเดอร์ `docs/` ที่ root แล้วย้ายไฟล์ที่ทำไว้เข้าไป ตั้งชื่อให้ตรงกับที่ README อ้าง: ไฟล์ `.json` ที่ Export จาก Postman ในการ์ด [ยิงทดสอบ API](/learn/cards/api-testing) เป็น `docs/library.postman_collection.json` และรูป `.png` จากการ์ด [ER diagram](/learn/cards/er-diagram) เป็น `docs/er-diagram.png` แล้ว commit

**5. ทดสอบ README ด้วยการลบแล้วทำใหม่** ลบโฟลเดอร์ `test-readme` แล้วทำตาม README ของตัวเองทีละบรรทัดตั้งแต่ clone ห้ามใช้ความจำ ถ้าต้องพิมพ์อะไรที่ README ไม่ได้เขียน แปลว่า README ขาดบรรทัดนั้น

> เครื่องเรามีกล่อง `pg` อยู่แล้ว `docker run` ใน README ข้อ 1 จะขึ้นว่าชื่อซ้ำ **อย่าลบกล่องเดิม** (ข้อมูลที่ทำมาจะหาย) และอย่าให้ `test-readme` ใช้ฐานเดิม เพราะ `bun run seed` จะใส่สมาชิกและหนังสือซ้ำลงฐานที่ทำงานอยู่ ให้สร้างฐานใหม่ในกล่องเดิมแทน
>
> ```bash
> docker exec pg createdb -U postgres readme_test
> ```
>
> แล้วใน `test-readme/server/.env` ใช้ `DATABASE_URL` ที่ลงท้าย `/readme_test` แทน `/postgres` ทำต่อตั้งแต่ README ข้อ 2 ได้เลย (ลองแล้ว migrate และ seed ผ่าน) ส่วนการทดสอบเต็มรูปแบบจากเครื่องเปล่าคือให้เพื่อนทำในโจทย์ลองเอง

**ควรได้:** `README.md` ที่ root และ `server/.env.example` ครบทุกตัวแปร ทำตามจากโฟลเดอร์ว่างแล้วเปิด http://localhost:5173 ได้ และ login หลังบ้านได้

## ทริคที่แนะนำ

1. **ทุกคำสั่งบอกว่าพิมพ์ในโฟลเดอร์ไหน:** monorepo มี `client/` กับ `server/` คำสั่งเดียวกันพิมพ์ผิดโฟลเดอร์ได้ผลต่างกัน (`bun install` ที่ root ไม่ติดตั้งอะไรให้ทั้งสองฝั่ง) จึงขึ้นทุกก้อนด้วย `cd` หรือเขียนว่า "(ยังอยู่ใน `server/`)"
2. **ค่าลับใส่แค่วิธีหามา ไม่ใส่ค่า:** README ถูก commit เหมือน `.env.example` ห้ามมีรหัสผ่านจริงหรือ `JWT_SECRET` จริง ใส่คำสั่งสุ่ม หรือบอกว่าขอจากใคร ส่วนรหัส `secret` ของ Postgres ในเครื่องเป็นค่าสำหรับฝึก ใช้ได้แค่บนเครื่องตัวเอง
3. **เขียนตอนเพิ่งติดตั้งเสร็จ แล้วแก้ทุกครั้งที่ขั้นตอนเปลี่ยน:** เพิ่มตัวแปรใน `.env` เมื่อไหร่ ให้เพิ่มใน `.env.example` และตาราง README ใน commit เดียวกัน README ที่เก่ากว่าโค้ด แย่กว่าไม่มี เพราะคนอ่านเชื่อมัน

## ปรับไปใช้จริง

**ในงาน STARTER:** [Requirement หน้า 12](/api/files/requirement.pdf#page=12) (ต้อง login) กำหนดว่า README ต้องมี **วิธีติดตั้ง, ตั้งค่า .env, รัน migration/seed, รันโปรเจกต์ และบัญชี admin ทดสอบ** ครบทั้ง 5 อย่างแบบตัวอย่างข้างบน และ **"โปรเจกต์รันตาม README ไม่ขึ้น" คือ 1 ใน 3 ข้อที่ไม่ผ่านทันที** แม้คะแนนส่วนอื่นจะเต็ม วันที่ 10 คือวันเขียน README และเตรียม demo (หน้า 11) แต่ให้เริ่มไฟล์ตั้งแต่วันที่ 2 ที่ทำ migration เสร็จ แล้วเติมทุกวัน วันที่ 10 จะเหลือแค่ให้เพื่อนทดสอบ ส่วนของส่งอื่นในหน้า 12 (ER Diagram, Postman collection, brief, wireframe) เก็บในโฟลเดอร์ `docs/` แล้วลิงก์จาก README

**เว็บคู่มือนี้:** [README.md บน GitHub](https://github.com/sutiwatpaksa-Dev/E-Book-Internship/blob/main/README.md) สั้นมาก แค่บอกว่าเว็บนี้คืออะไร อ่านที่ไหน แล้วชี้ต่อไปที่ [MAINTAINING.md](https://github.com/sutiwatpaksa-Dev/E-Book-Internship/blob/main/MAINTAINING.md) ซึ่งมีคำสั่งติดตั้ง, `cp .env.example .env`, การเปิด Postgres ในเครื่อง และเรื่องออกเวอร์ชันกับ deploy เพราะคนอ่านเว็บนี้ส่วนใหญ่มาอ่านเนื้อหา ไม่ได้มารันเอง ข้อเสียคือคนที่อยากรันต้องเปิด 2 ไฟล์ และคำสั่งติดตั้งอยู่ใต้หัวข้อ "แก้เนื้อหา" ซึ่งหาไม่ง่าย งาน STARTER มีคนต้องรันจริง (พี่เลี้ยงที่ตรวจงาน) จึงควรใส่ขั้นติดตั้งครบใน README ไฟล์เดียว

ลองคิด: ถ้าพี่เลี้ยงใช้ Windows ส่วนเราใช้ Mac คำสั่งไหนใน README ของเราที่เสี่ยงพังบนเครื่องพี่เลี้ยงมากที่สุด
