## ความหมาย

**[State](/glossary#state)** คือข้อมูลในชิ้นส่วนที่ **เปลี่ยนได้แล้วหน้าจอเปลี่ยนตาม** สร้างด้วย `useState` เปลี่ยนค่าด้วยฟังก์ชันที่ได้คู่กัน ห้ามแก้ตัวแปรตรงๆ

**useEffect** ([hook](/glossary#hook) ตัวหนึ่ง) คือช่องสำหรับงานที่อยู่ **นอกการวาดหน้าจอ** ([side effect](/glossary#side-effect)) เช่น ดึงข้อมูล ตั้ง timer ฟังเหตุการณ์ของหน้าต่าง React รันให้หลังวาดเสร็จ

**นึกภาพ:** ป้ายคะแนนในสนามกีฬา state คือคะแนน ถ้าแอบเขียนตัวเลขในสมุด ป้ายไม่เปลี่ยน ต้องบอกคนคุมป้าย (`setCount`) ป้ายถึงจะขึ้นเลขใหม่ ส่วน useEffect คือ "ทุกครั้งที่คะแนนเปลี่ยน ให้ประกาศผ่านลำโพงด้วย" เป็นงานนอกป้าย

## ที่มา

ถ้าเขียน `count = count + 1` ตรงๆ ค่าเปลี่ยนแต่ React ไม่รู้ หน้าจอไม่ขยับ `setCount` เป็นการ **บอก React** ว่าข้อมูลเปลี่ยน ให้วาดชิ้นส่วนนี้ใหม่ ส่วนงานอย่างดึงข้อมูล ถ้าทำระหว่างวาด จะยิงซ้ำทุกครั้งที่วาดใหม่ React จึงแยกช่อง `useEffect` ไว้ให้ พร้อมบอกได้ว่าจะรันใหม่เมื่อไร

## การใช้งาน

```tsx
import { useEffect, useState } from "react";

export function BorrowButton({ title }: { title: string }) {
  const [count, setCount] = useState(0);

  useEffect(() => {
    document.title = `${title} (${count})`;     // งานนอกหน้าจอ
  }, [title, count]);                           // รันใหม่เมื่อ 2 ค่านี้เปลี่ยน

  return <button onClick={() => setCount((c) => c + 1)}>ยืมแล้ว {count} ครั้ง</button>;
}
```

ลองวาง `<BorrowButton title="เจ้าชายน้อย" />` ใน `App.tsx` กดปุ่มแล้วดูตัวเลขบนปุ่มกับชื่อแท็บ browser เปลี่ยนพร้อมกัน

ท้าย `useEffect` คือ **รายการค่าที่ต้องเฝ้าดู** ([dependency array](/glossary#dependency-array))

| เขียนแบบ | รันเมื่อ |
|---|---|
| `[]` | ครั้งเดียวตอนชิ้นส่วนขึ้นจอ |
| `[x]` | ครั้งแรก และทุกครั้งที่ `x` เปลี่ยน |
| ไม่ใส่ | ทุกครั้งที่วาดใหม่ (แทบไม่ได้ใช้ ระวังวนไม่หยุด) |

ถ้า effect ตั้งอะไรไว้ (timer, listener, คำขอ) ให้ `return` ฟังก์ชันเก็บกวาด React จะเรียกก่อนรันรอบใหม่และตอนชิ้นส่วนหายไป

## ทริคที่แนะนำ

1. **ค่าที่คำนวณได้ ไม่ต้องเป็น state:** "จำนวนเล่มที่ยังไม่คืน" คำนวณจากรายการการยืมได้ทุกครั้ง ถ้าเก็บเป็น state แยก สักวันสองค่าจะไม่ตรงกัน
2. **งานที่เกิดเพราะผู้ใช้กด ทำใน `onClick` ไม่ใช่ใน effect** effect มีไว้ "ซิงก์กับโลกข้างนอก" ไม่ใช่ตอบสนองการกด
3. **ตอน dev เห็น effect รัน 2 รอบเป็นเรื่องปกติ** [`<StrictMode>`](/glossary#strict-mode) (มีใน `main.tsx` ที่ Vite สร้างให้) จงใจรัน effect → เก็บกวาด → effect ใหม่ เพื่อจับ effect ที่เก็บกวาดไม่ครบ ห้ามลบ `StrictMode` ทิ้งเพื่อให้หายซ้ำ

## ปรับไปใช้จริง

**ในงาน STARTER:** ทุกหน้าที่ดึงข้อมูล (วันที่ 6) ใช้ state เก็บผลและ useEffect สั่งดึง (การ์ดถัดไป) ส่วนหลังบ้าน (วันที่ 8) ใช้ state คุมป๊อปอัปยืนยันลบ และสวิตช์ "เปิด/ปิด" ของบริการ

**เว็บคู่มือนี้:** ปุ่ม "เข้าใจการ์ดนี้แล้ว" ใช้ state ที่หลายชิ้นส่วนแชร์กัน ([src/hooks/use-progress.ts](https://github.com/sutiwatpaksa-Dev/E-Book-Internship/blob/main/src/hooks/use-progress.ts)) กดที่ท้ายการ์ด แล้ววงกลมใน sidebar กับตัวเลขบนหน้าวันนี้เปลี่ยนพร้อมกัน เพราะทุกชิ้นอ่านจากที่เดียว ส่วนคำใบ้ ([hint.tsx](https://github.com/sutiwatpaksa-Dev/E-Book-Internship/blob/main/src/components/hint.tsx)) จำว่าเปิดถึงระดับไหนแล้วด้วยวิธีเดียวกัน

ลองคิด: ถ้าแต่ละชิ้นส่วนเก็บ "เข้าใจแล้วกี่ใบ" เป็น `useState` ของตัวเอง จะเกิดอะไรตอนกดปุ่ม

## ตัวเลือกอื่นที่คล้ายกัน

| ที่เก็บ state | ใช้เมื่อ |
|---|---|
| **`useState` (ทีมใช้)** | ข้อมูลของชิ้นส่วนเดียว เช่น ช่องกรอก เปิด/ปิดเมนู |
| ยกขึ้นไปไว้ที่แม่ + ส่ง props | ลูกหลายตัวต้องเห็นค่าเดียวกัน |
| Context ของ React | ค่าที่ทั้งแอปใช้ เช่น ผู้ใช้ที่ login, ธีม |
| store ภายนอก (`useSyncExternalStore`, Zustand ฯลฯ) | ค่าที่อัปเดตจากหลายที่ หรือมาจากนอก React เช่น localStorage |
| URL (`?q=...`) | ค่าที่อยากให้แชร์ลิงก์แล้วได้หน้าเดียวกัน เช่น ตัวกรอง |

## ลองเอง

**โจทย์:** ใช้รายการหนังสือแบบเขียนตายตัวจากการ์ด Component ทำช่องค้นหาที่กรองรายการทันทีที่พิมพ์ แสดงจำนวนที่เจอ และตั้งชื่อแท็บเบราว์เซอร์เป็น `ค้นหา: คำที่พิมพ์`

<Hint level={1}>มีข้อมูลที่ "เปลี่ยนเพราะผู้ใช้" อยู่ตัวเดียว คือคำที่พิมพ์ ที่เหลือคำนวณจากมันได้หมด</Hint>
<Hint level={2}>รายการที่กรองแล้วกับจำนวนที่เจอ ไม่ต้องเป็น state คำนวณตรงๆ ในชิ้นส่วนก่อน `return`</Hint>
<Hint level={3}>ชื่อแท็บเป็นของนอกหน้าจอ ต้องอยู่ใน `useEffect` และต้องรันใหม่เมื่อคำค้นเปลี่ยน</Hint>
