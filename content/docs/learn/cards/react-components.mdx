## ความหมาย

พูดง่ายๆ คือ แบ่งหน้าเว็บเป็นชิ้นเล็กที่ใช้ซ้ำได้ เช่น การ์ดหนังสือ 1 ใบ เขียนครั้งเดียว แล้วใช้กับหนังสือทุกเล่มในรายการ

[React](/glossary#react) สร้างหน้าเว็บจาก **ชิ้นส่วน ([component](/glossary#component))** ชิ้นส่วนคือฟังก์ชันที่ **รับข้อมูลเข้า ([props](/glossary#props)) แล้วคืนหน้าตา** เขียนหน้าตาด้วย **[JSX](/glossary#jsx)** ซึ่งหน้าตาเหมือน HTML แต่อยู่ในไฟล์ TypeScript (`.tsx`) และแทรกค่าด้วย `{ }`

**นึกภาพ:** แม่พิมพ์ขนม แม่พิมพ์ (component) มีอันเดียว เทแป้งคนละสี (props) ก็ได้ขนมหน้าตาเดียวกันแต่ไส้ต่างกัน

จับคู่: แม่พิมพ์ = component (`BookCard`) · แป้งกับไส้ที่เทลงไป = props (`book`) · ขนมที่ได้ = หน้าตาที่ component คืนออกมา (JSX)

ชิ้นส่วนในการ์ดนี้ซ้อนกันแบบนี้ (ข้อมูลไหลจากบนลงล่างผ่าน props):

```text
App
└─ BooksPage
   props: books (หนังสือทุกเล่ม)
   │
   ├─ BookCard  props: book เล่มที่ 1
   ├─ BookCard  props: book เล่มที่ 2
   └─ BookCard  ...ครบทุกเล่ม
```

จุดที่ไม่ตรง: แม่พิมพ์ขนมกดครั้งเดียวได้ขนมแล้วจบ แต่ component ถูกเรียกซ้ำทุกครั้งที่ข้อมูลเปลี่ยน React วาดหน้าตาใหม่ให้เอง (เรื่องนี้อยู่ในการ์ด [State](/learn/cards/react-state))

## ที่มา

เขียน HTML ล้วน ถ้ามีหนังสือ 20 เล่มต้องก๊อปกล่อง 20 ก้อน พอแก้หน้าตากล่องต้องตามแก้ 20 ที่ และข้อมูลที่มาจาก API ก็ต้องเขียน JavaScript ไปสร้างกล่องเองทีละชิ้น React (Meta เปิดเป็น open source ปี 2013) ให้เราเขียนกล่องครั้งเดียวเป็นชิ้นส่วน แล้ว **บอกว่าข้อมูลแบบนี้ควรหน้าตาแบบไหน** ส่วนการสร้างและอัปเดตหน้าจอจริงเป็นงานของ React

## การใช้งาน

### ตั้งค่าครั้งแรก (โฟลเดอร์ `client/` ตามโครงใน Requirement)

ที่โฟลเดอร์บนสุดของโปรเจกต์ (ข้างๆ `server/`) พิมพ์ (เหมือนกันทั้ง Windows และ Mac)

```bash
bun create vite client --template react-ts
cd client
bun install
bun run dev
```

**ควรเห็น:** `Local: http://localhost:5173/` เปิดแล้วเจอหน้าตัวอย่างของ [Vite](/glossary#vite) ต่อจากนี้แก้ไฟล์ใน `client/src/` แล้วหน้าเว็บเปลี่ยนเองทันที

### 1. ชิ้นส่วนกล่องหนังสือ

```tsx
// src/types/book.ts · type ใช้ร่วมกันหลายไฟล์ เก็บไว้ที่เดียว
export type Book = { id: number; title: string; available: boolean };
```

```tsx
// src/components/book-card.tsx
import type { Book } from "../types/book";

export function BookCard({ book }: { book: Book }) {
  return (
    <article className="rounded-xl border p-4">
      <h3>{book.title}</h3>
      {book.available ? <p>ยืมได้</p> : <p>ถูกยืมอยู่</p>}
    </article>
  );
}
```

### 2. หน้าที่ใช้กล่องซ้ำหลายครั้ง

```tsx
// src/pages/books-page.tsx
import { BookCard } from "../components/book-card";
import type { Book } from "../types/book";

export function BooksPage({ books }: { books: Book[] }) {
  if (books.length === 0) return <p>ยังไม่มีหนังสือ</p>;
  return (
    <section>
      {books.map((b) => (
        <BookCard key={b.id} book={b} />
      ))}
    </section>
  );
}
```

### 3. ลองแสดงผล

ยังไม่ต่อ API ใช้ข้อมูลเขียนตายตัวไปก่อน แก้ `src/App.tsx` ทั้งไฟล์เป็น

```tsx
import { BooksPage } from "./pages/books-page";

const books = [
  { id: 1, title: "เจ้าชายน้อย", available: true },
  { id: 2, title: "ฮอบบิท", available: false },
];

export default function App() {
  return <BooksPage books={books} />;
}
```

**ควรเห็น:** กล่องหนังสือ 2 กล่อง เล่มที่ 2 ขึ้น "ถูกยืมอยู่" (ยังไม่สวย การ์ด [Tailwind](/learn/cards/tailwind) จะตกแต่ง)

ต่างจาก HTML 3 จุดที่เจอบ่อย: ใช้ `className` แทน `class`, ทุกแท็กต้องปิด (`<img />`), และคืนได้ก้อนเดียว (หลายก้อนให้ห่อด้วย `<>...</>`)

## ทริคที่แนะนำ

1. **ทุกรายการที่ `.map` ต้องมี `key` ที่ไม่ซ้ำและไม่เปลี่ยน** ใช้ id จากฐานข้อมูล อย่าใช้ลำดับ (index) เพราะพอลบหรือเรียงใหม่ React จะจับคู่ชิ้นผิด ช่องกรอกในรายการจะสลับค่ากัน
2. **props ไหลทางเดียว จากแม่ลงลูก** ลูกห้ามแก้ props ตัวเอง อยากให้ลูกบอกแม่ ให้ส่งฟังก์ชันลงไป เช่น `onBorrow={() => ...}`
3. **แยกชิ้นเมื่อมีเหตุผล:** ใช้ซ้ำหลายที่ หรือไฟล์ยาวจนอ่านไม่จบในหน้าจอเดียว ไม่ต้องแยกทุก `<div>`

## ปรับไปใช้จริง

**ในโจทย์ฝึกงาน** (ตัวอย่างจาก STARTER)**:** Requirement ให้แยก `client/src/` เป็น `pages/` (หน้า) กับ `components/` (ชิ้นส่วนใช้ซ้ำ) ตรงกับตัวอย่างข้างบน ลองนับว่าหน้าแรก (`/`), เกี่ยวกับร้าน (`/about`) และติดต่อ (`/contact`) ใช้ชิ้นส่วนอะไรซ้ำกันบ้าง (เช่น กล่องบริการ, ปุ่ม) ก่อนลงมือเขียน

**เว็บคู่มือนี้:** สร้างด้วย React ทั้งหมด เปิด [src/components/step-cards.tsx บน GitHub](https://github.com/sutiwatpaksa-Dev/E-Book-Internship/blob/main/src/components/step-cards.tsx) จะเห็นการ์ดในหน้าขั้นเป็นชิ้นส่วนที่รับ `step` เข้ามาแล้ว `.map` เป็นรายการ โดยใช้ `slug` ของการ์ดเป็น `key` ส่วนหน้าตาที่เปลี่ยนตามข้อมูล (วงกลมติ๊กถูกเมื่อเข้าใจแล้ว) ใช้ `isDone ? ... : ...` แบบเดียวกับตัวอย่างข้างบน

ลองคิด: หน้า "คลังการ์ด" มีกล่องการ์ดหน้าตาเดียวกับหน้าขั้น ควรเป็นชิ้นส่วนเดียวกันไหม ถ้าวันหนึ่งสองหน้าต้องหน้าตาต่างกัน จะทำยังไง

## ตัวเลือกอื่นที่คล้ายกัน

| ตัว | เขียนหน้าตาด้วย | ระดับ |
|---|---|---|
| **React (ทีมใช้)** | JSX ในไฟล์ `.tsx` | ใช้ทุกงาน คนใช้และตัวอย่างมากที่สุด |
| Vue | template ในไฟล์ `.vue` | ควรรู้จัก เจอในงานลูกค้าหลายเจ้า |
| Svelte | template ที่ถูกแปลงเป็น JavaScript ตอน build | รู้ว่ามี |
| Angular | template + TypeScript มีโครงใหญ่ครบในตัว | รู้ว่ามี เจอในองค์กรใหญ่ |

แนวคิดชิ้นส่วน + ข้อมูลเข้า + หน้าตาเปลี่ยนตามข้อมูล เหมือนกันทุกตัว ย้ายค่ายได้ไม่ต้องเริ่มใหม่

## ลองเอง

**โจทย์:** ใช้ข้อมูลเขียนตายตัวแบบตัวอย่าง (สมาชิก 3 คน ยืมอยู่ 0, 2, 3 เล่ม) ทำหน้ารายชื่อสมาชิกห้องสมุดที่แสดงชื่อ จำนวนเล่มที่ยืมอยู่ และป้าย "ยืมครบแล้ว" สีแดงเมื่อยืมครบ 3 เล่ม ถ้าไม่มีสมาชิกเลยต้องขึ้นข้อความแทนรายการว่าง

<Hint level={1}>เริ่มจากกล่องของสมาชิก 1 คน ให้ใช้ได้ก่อน แล้วค่อยทำรายการ</Hint>
<Hint level={2}>ป้ายที่ขึ้นบ้างไม่ขึ้นบ้าง ใช้ `{เงื่อนไข && <span>...</span>}`</Hint>
<Hint level={3}>ลองลบสมาชิกคนแรกออกจาก array แล้วดูว่า DevTools Console มีเตือนเรื่อง `key` ไหม ถ้ามีแปลว่ายังไม่ได้ใส่หรือใส่ซ้ำ</Hint>
