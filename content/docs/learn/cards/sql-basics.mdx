## ความหมาย

[SQL](/glossary#sql) คือ **ภาษาที่ใช้สั่งงานฐานข้อมูลแบบตาราง** เราบอกว่า "อยากได้อะไร" แล้วฐานข้อมูลไปหาวิธีเอง

**นึกภาพ:** บอกบรรณารักษ์ว่า "ขอรายชื่อหนังสือที่ยังไม่มีคนคืน" โดยไม่ต้องบอกว่าเดินไปชั้นไหน

ข้อมูลอยู่เป็น [ตาราง](/glossary#table) แต่ละแถวมี **[primary key](/glossary#primary-key)** (เลขประจำแถวที่ไม่ซ้ำ ปกติชื่อ `id`) และตารางโยงกันด้วย **[foreign key](/glossary#foreign-key)** (คอลัมน์ที่เก็บ `id` ของอีกตาราง)

## ที่มา

ก่อนมี SQL แต่ละโปรแกรมเก็บข้อมูลแบบของตัวเอง จะหาข้อมูลทีต้องเขียนโปรแกรมไล่อ่านไฟล์เอง ทศวรรษ 1970 นักวิจัยของ IBM ออกแบบภาษาที่ "บอกสิ่งที่อยากได้" บนแนวคิดตารางที่โยงกันได้ ต่อมาเป็นมาตรฐาน ฐานข้อมูลแบบตารางเกือบทุกตัวจึงพูดภาษาเดียวกัน ต่างกันแค่สำเนียงเล็กน้อย

## การใช้งาน

เปิด Query Tool ใน pgAdmin (ดูการ์ด [Postgres](/learn/cards/postgres)) ที่ฐาน `postgres` แล้วลองทีละก้อน กดปุ่ม ▶ (หรือ F5) เพื่อรัน

**1. สร้างตาราง** ห้องสมุดมีสมาชิก หนังสือ และการยืม การยืม 1 ครั้งโยงไปหา 1 สมาชิกกับ 1 เล่ม

```sql
CREATE TABLE members (
  id   serial PRIMARY KEY,          -- เลขเพิ่มเองทีละ 1
  name text NOT NULL                -- ห้ามว่าง
);
CREATE TABLE books (
  id    serial PRIMARY KEY,
  title text NOT NULL
);
CREATE TABLE loans (
  id          serial PRIMARY KEY,
  member_id   integer NOT NULL REFERENCES members(id),   -- foreign key
  book_id     integer NOT NULL REFERENCES books(id),
  due_at      timestamptz NOT NULL,                       -- วันที่ต้องคืน
  returned_at timestamptz                                 -- ว่าง = ยังไม่คืน
);
```

**2. เพิ่มข้อมูล**

```sql
INSERT INTO members (name) VALUES ('มานี'), ('ปิติ');
INSERT INTO books (title) VALUES ('เจ้าชายน้อย'), ('ฮอบบิท');
INSERT INTO loans (member_id, book_id, due_at) VALUES (1, 1, now() - interval '3 days');
```

**3. ดึงข้อมูล** ใครยืมอะไรอยู่บ้าง

```sql
SELECT members.name, books.title
FROM loans
JOIN members ON members.id = loans.member_id
JOIN books   ON books.id   = loans.book_id
WHERE loans.returned_at IS NULL;
```

**ควรเห็น:** ตารางผล 1 แถว: `มานี | เจ้าชายน้อย`

อ่านจากล่างขึ้นบนจะเข้าใจง่าย: เอาการยืมที่ยังไม่คืน → ต่อ ([JOIN](/glossary#join)) กับสมาชิกและหนังสือ → เลือกแค่ชื่อกับชื่อเรื่อง ส่วน `UPDATE` (แก้) กับ `DELETE` (ลบ) ใช้ `WHERE` แบบเดียวกัน

## ทริคที่แนะนำ

1. **ก่อน `UPDATE` หรือ `DELETE` ให้ `SELECT` ด้วย `WHERE` เดียวกันก่อน** ดูว่าโดนกี่แถว ลืม `WHERE` = แก้หรือลบทั้งตาราง
2. **ลองแบบย้อนได้:** พิมพ์ `BEGIN;` ก่อน ลองคำสั่ง ถ้าผลไม่ใช่พิมพ์ `ROLLBACK;` ข้อมูลกลับเหมือนเดิม (เรียกว่า [transaction](/glossary#transaction))
3. **ลองลบสมาชิกที่ยังมีการยืมอยู่** (`DELETE FROM members WHERE id = 1;`) จะเจอ error เพราะ foreign key ไม่ยอมให้การยืมชี้ไปหาคนที่ไม่มีอยู่ นี่คือฐานข้อมูลช่วยกันข้อมูลพังให้เรา

## ปรับไปใช้จริง

**ในงาน STARTER:** ตาราง `services` มี `category_id` ที่เป็น foreign key ไปหา `categories` และ Requirement บอกว่า "ห้ามลบ category ทิ้งถ้ายังมี service" นั่นคือพฤติกรรมเดียวกับทริคข้อ 3 ส่วนในโปรเจกต์จริง เราจะไม่พิมพ์ `CREATE TABLE` เอง แต่ให้ Drizzle สร้างผ่าน migration (การ์ดถัดๆ ไป) ถึงอย่างนั้นยังต้องอ่าน SQL ออก เพราะไฟล์ migration เป็น SQL ล้วน

ลองคิด: หน้าไหนของงาน STARTER ต้องใช้ข้อมูลจากมากกว่า 1 ตาราง (หน้านั้นจะต้องมี `JOIN`)

## ลองเอง

**โจทย์:** ใช้ตารางที่สร้างไว้ หาสมาชิกที่ยืมหนังสือ **เกินกำหนด** (ถึงวันคืนแล้วยังไม่คืน) พร้อมชื่อหนังสือ เรียงจากเกินนานที่สุด

<Hint level={1}>"เกินกำหนด" มี 2 เงื่อนไขพร้อมกัน: ยังไม่คืน และวันที่ต้องคืนผ่านมาแล้ว</Hint>
<Hint level={2}>Postgres มี `now()` ให้เวลาปัจจุบัน ต่อ 2 เงื่อนไขด้วย `AND` และเรียงผลด้วย `ORDER BY`</Hint>
<Hint level={3}>"เกินนานที่สุด" คือวันที่ต้องคืนเก่าที่สุด ลองคิดว่าต้องเรียงจากน้อยไปมาก (`ASC`) หรือมากไปน้อย (`DESC`) แล้วตรวจกับข้อมูลที่ใส่ไว้</Hint>
