## ความหมาย

**HTTP** คือภาษาที่หน้าเว็บกับ server ใช้คุยกัน ทุกครั้งเป็นคู่ **คำขอ (request) → คำตอบ (response)** คำขอบอกว่า "อยากทำอะไร กับอะไร" คำตอบบอกว่า "ผลเป็นยังไง พร้อมข้อมูล"

**REST** คือวิธีตั้งชื่อ API ให้เดาได้: ให้ URL เป็น **สิ่งของ** (คำนาม) แล้วใช้ method ของ HTTP เป็น **คำกริยา**

| อยากทำ | method + URL | ตอบกลับเมื่อสำเร็จ |
|---|---|---|
| ดูหนังสือทั้งหมด | `GET /api/books` | `200` + รายการ |
| ดูเล่มเดียว | `GET /api/books/7` | `200` + หนังสือ |
| เพิ่มหนังสือ | `POST /api/books` | `201` + หนังสือที่สร้าง |
| แก้บางช่อง | `PATCH /api/books/7` | `200` |
| ลบ | `DELETE /api/books/7` | `204` (ไม่มีเนื้อหา) |

## ที่มา

ถ้าไม่มีแบบแผน ทุกคนตั้งชื่อเอง: `/getBook`, `/book_list`, `/deleteBookById?id=7` คนเรียกต้องเปิดเอกสารทุกครั้ง REST มาจากวิทยานิพนธ์ของ Roy Fielding (ปี 2000) ที่อธิบายว่าเว็บใหญ่โตได้เพราะทุกอย่างมี "ที่อยู่" และใช้คำกริยาชุดเดียวกัน พอทุกทีมทำตามแบบเดียวกัน เห็น `POST /api/loans` ก็เดาได้ทันทีว่าคือ "สร้างการยืม"

## การใช้งาน

คำขอหนึ่งอันมี 4 ส่วน:

```http
POST /api/books?draft=1 HTTP/1.1      ← method + path + query
Content-Type: application/json         ← header: ข้อมูลประกอบ
Cookie: bt_session=...

{"title": "เจ้าชายน้อย"}                ← body: ข้อมูลที่ส่งไป
```

คำตอบบอกผลด้วย **status code** ตัวเลขหลักแรกบอกว่าเป็นความผิดของใคร:

| กลุ่ม | ความหมาย | ที่เจอบ่อย |
|---|---|---|
| `2xx` | สำเร็จ | `200` ได้แล้ว, `201` สร้างแล้ว, `204` สำเร็จแต่ไม่มีอะไรส่งกลับ |
| `4xx` | **คนขอ**ส่งมาผิด | `400` ข้อมูลผิด, `401` ยังไม่ login, `403` login แล้วแต่ไม่มีสิทธิ์, `404` ไม่มี, `409` ขัดกับของที่มีอยู่ (เช่นยืมซ้ำ) |
| `5xx` | **server** พังเอง | `500` โค้ดเราพัง, `503` ต่อฐานข้อมูลไม่ได้ |

## ทริคที่แนะนำ

1. **URL เป็นคำนามพหูพจน์ ไม่มีคำกริยา:** `POST /api/loans` ไม่ใช่ `POST /api/createLoan`
2. **เลือก status ให้ถูกกลุ่ม:** ข้อมูลผิดแล้วตอบ `500` ทำให้คนเรียกคิดว่า server พัง และไปแก้ผิดที่ ตอบ `200` พร้อม `{ "error": ... }` ก็ผิด เพราะโค้ดฝั่งหน้าเว็บที่เช็ก `res.ok` จะคิดว่าสำเร็จ
3. **`GET` ห้ามเปลี่ยนข้อมูล:** browser, proxy และ AI crawler ยิง `GET` เองได้ ถ้า `GET /api/books/7/delete` ลบหนังสือได้ สักวันจะมีอะไรไปกดมัน

## ปรับไปใช้จริง

เว็บคู่มือนี้ใช้ REST + JSON ทั้งหมด ดูได้ใน DevTools แท็บ Network ตอนกด "เข้าใจการ์ดนี้แล้ว" จะเห็น `PUT /api/progress` ได้ `204` ตอนยังไม่ login เปิด `/api/progress` ตรงๆ จะได้ `401` (ต้อง login ก่อน)

ลองคิด: "คืนหนังสือ" ควรเป็น `DELETE /api/loans/7` หรือ `PATCH /api/loans/7` ที่ใส่วันคืน ประวัติการยืมยังต้องใช้ไหม

## ลองเอง

**โจทย์:** เขียนรายการ API ของระบบจองห้องประชุม (ดูห้องว่าง, จอง, ยกเลิก, ดูการจองของฉัน) เป็น `METHOD /path` พร้อม status ตอนสำเร็จ และ status ตอน "ห้องถูกจองไปแล้ว"

<Hint level={1}>เริ่มจากหาคำนาม: ระบบนี้มี "ของ" กี่อย่าง แต่ละอย่างคือ URL หนึ่งกลุ่ม</Hint>
<Hint level={2}>"การจอง" เป็นของสิ่งหนึ่ง จองคือสร้างมัน ยกเลิกคือลบหรือเปลี่ยนสถานะมัน ส่วน "ของฉัน" ไม่ต้องมี id ในURL เพราะ server รู้จาก cookie อยู่แล้ว</Hint>
<Hint level={3}>ห้องถูกจองแล้วไม่ใช่ความผิดของ server และไม่ใช่ข้อมูลผิดรูปแบบ แต่ "ขัดกับสิ่งที่มีอยู่" ไล่ดูตาราง 4xx อีกที</Hint>
