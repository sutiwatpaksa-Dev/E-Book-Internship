## ความหมาย

Postgres (ชื่อเต็ม PostgreSQL) คือ **โปรแกรม[ฐานข้อมูล](/glossary#database)** ที่เก็บข้อมูลเป็นตาราง และรับคำสั่งภาษา [SQL](/glossary#sql)

**นึกภาพ:** ห้องเก็บเอกสาร มี 3 อย่างที่ต้องแยกให้ออก

| ส่วน | เปรียบเหมือน | ในงานจริง |
|---|---|---|
| Engine (ตัวฐานข้อมูล) | ตู้เอกสารและระบบจัดเก็บ | Postgres, MySQL |
| ที่ที่รัน | ห้องที่วางตู้ | [Docker](/glossary#docker) ในเครื่องเรา, Neon บนคลาวด์ |
| Client (ตัวเปิดดู) | คนที่เดินเข้าไปหยิบเอกสาร | pgAdmin (งาน STARTER ใช้ตัวนี้), `psql` |

## ที่มา

Postgres เริ่มจากโปรเจกต์วิจัยที่ UC Berkeley กลางทศวรรษ 1980 และเปลี่ยนชื่อเป็น PostgreSQL ในปี 1996 เป็น open source ที่ไม่มีบริษัทเดียวเป็นเจ้าของ จึงมีผู้ให้บริการหลายเจ้า ย้ายค่ายได้ง่าย เราแยก "engine" กับ "ที่ที่รัน" ออกจากกัน เพราะโค้ดชุดเดียวกันต่อได้ทั้งฐานในเครื่องและฐานบนคลาวด์ ต่างกันแค่ "ที่อยู่" ที่ใส่ให้

## การใช้งาน

### 1. เปิด Postgres ในเครื่องด้วย Docker

ต้องเปิดโปรแกรม Docker Desktop ไว้ก่อน แล้วพิมพ์ใน Terminal (เหมือนกันทั้ง Mac และ Windows ที่ใช้ [Git Bash](/00-start#-windows-ใช้-git-bash-เท่านั้น))

```bash
docker run -d --name pg -e POSTGRES_PASSWORD=secret -p 5432:5432 -v pgdata:/var/lib/postgresql/data postgres:17-alpine
```

| ส่วนของคำสั่ง | แปลว่า |
|---|---|
| `--name pg` | ตั้งชื่อกล่องว่า `pg` ไว้เรียกทีหลัง |
| `-e POSTGRES_PASSWORD=secret` | รหัสผ่านของผู้ใช้ `postgres` |
| `-p 5432:5432` | เปิด[ประตูเลข](/glossary#port) 5432 ของเครื่องเรา ต่อเข้า 5432 ในกล่อง |
| `-v pgdata:...` | เก็บข้อมูลไว้นอกกล่อง ([volume](/glossary#volume)) ลบกล่องแล้วข้อมูลไม่หาย |

**ควรเห็น:** ตัวอักษรยาวๆ 1 บรรทัด (รหัสกล่อง) แล้วพิมพ์ `docker ps` ต้องเห็นกล่องชื่อ `pg` สถานะ `Up`

### 2. ต่อด้วย pgAdmin

เปิด pgAdmin → คลิกขวา **Servers** → **Register** → **Server...**

- แท็บ General: Name ตั้งอะไรก็ได้ เช่น `local`
- แท็บ Connection: Host `localhost` · Port `5432` · Username `postgres` · Password `secret`

กด Save แล้วเปิด `local` → Databases → `postgres` → คลิกขวา **Query Tool** ไว้พิมพ์ SQL (ใช้ในการ์ดถัดไป)

### 3. ที่อยู่ของฐานข้อมูล (connection string)

โค้ดของเราต่อเข้าฐานด้วยข้อความบรรทัดเดียว เรียกว่า [connection string](/glossary#connection-string)

```
postgres://postgres:secret@localhost:5432/postgres
           ผู้ใช้  :รหัส  @เครื่อง  :port/ชื่อฐาน
```

## ทริคที่แนะนำ

1. **ขึ้น `port is already allocated`** แปลว่ามีโปรแกรมอื่นใช้ 5432 อยู่ (มักเป็น Postgres ที่ติดตั้งไว้ในเครื่อง) เปลี่ยนเป็น `-p 5433:5432` แล้วใน pgAdmin กับ connection string ใช้ port `5433`
2. **connection string มีรหัสผ่าน** เก็บในไฟล์ `.env` เสมอ และห้าม commit ไฟล์ `.env` (Requirement บังคับ ให้มี `.env.example` ที่บอกชื่อตัวแปรแทน)
3. **ปิดเครื่องแล้วเปิดใหม่ กล่องไม่ขึ้นเอง** สั่ง `docker start pg` ไม่ต้อง `docker run` ใหม่

## ปรับไปใช้จริง

**ในงาน STARTER:** Requirement กำหนด PostgreSQL + pgAdmin ทำขั้น 1–2 ของการ์ดนี้ในวันที่ 1 (setup repo) ให้เรียบร้อย พอวันที่ 2 ต้องเปิด pgAdmin ดูข้อมูลที่ seed ได้ทันที

**เว็บคู่มือนี้:** ในเครื่องใช้ Docker แบบเดียวกับการ์ดนี้ ส่วนเว็บจริงใช้ Neon บนคลาวด์ โค้ดเหมือนกันทุกบรรทัด ต่างกันแค่ค่า `DATABASE_URL`

ลองคิด: ถ้าวันส่งงาน พี่เลี้ยง clone โปรเจกต์ไปรันในเครื่องตัวเอง เขาต้องรู้อะไรบ้างถึงจะต่อฐานได้ และเราจะบอกเขาไว้ที่ไหน

## ลองเอง

**โจทย์:** พิสูจน์ว่าข้อมูลรอดจริงหลังลบกล่อง: สร้างฐานชื่อ `library` ใน pgAdmin → `docker rm -f pg` → เปิดกล่องใหม่ด้วยคำสั่งเดิม → ฐาน `library` ต้องยังอยู่

<Hint level={1}>ฐานใหม่สร้างใน pgAdmin ได้: คลิกขวา Databases → Create → Database...</Hint>
<Hint level={2}>ถ้าฐานหายหลังเปิดกล่องใหม่ ดูว่าคำสั่ง `docker run` มีส่วน `-v` ไหม</Hint>
<Hint level={3}>ลองอีกครั้งโดยตัด `-v` ออก แล้วเทียบผล จะเห็นชัดว่า volume ทำหน้าที่อะไร (ลบ volume ทิ้งได้ด้วย `docker volume rm pgdata`)</Hint>
