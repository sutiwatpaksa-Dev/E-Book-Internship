## ความหมาย

ฟอร์มที่ดีมี 4 จังหวะ: **เก็บค่าที่พิมพ์ → ตรวจก่อนส่ง → ส่งโดยกันกดซ้ำ → บอกผล** ทุกจังหวะต้องเห็นบนหน้าจอ ผู้ใช้ไม่ต้องเดาว่าเกิดอะไรขึ้น

## ที่มา

ฟอร์มคือที่ที่ผู้ใช้เจอปัญหาบ่อยที่สุด: กดส่งแล้วเงียบ ไม่รู้ว่าส่งไปหรือยังเลยกดซ้ำ ได้ข้อมูลซ้ำ 3 แถว หรือกรอกผิดแล้วไม่บอกว่าผิดช่องไหน ต้องกรอกใหม่หมด ส่วนการตรวจฝั่งหน้าเว็บมีไว้ **ช่วยผู้ใช้** ให้รู้เร็ว ไม่ใช่กันคนไม่หวังดี เพราะคนยิง API ตรงได้เสมอ (ด่านจริงอยู่ที่ API ดูการ์ด Zod)

## การใช้งาน

```tsx
import { useState, type SubmitEvent } from "react";

const empty = { title: "", isbn: "" };

export function NewBookForm({ onSaved }: { onSaved: () => void }) {
  const [form, setForm] = useState(empty);
  const [errors, setErrors] = useState<Partial<typeof empty>>({});
  const [sending, setSending] = useState(false);
  const [serverError, setServerError] = useState("");

  async function onSubmit(e: SubmitEvent<HTMLFormElement>) {
    e.preventDefault();                                   // ไม่ให้ browser โหลดหน้าใหม่
    const found: Partial<typeof empty> = {};
    if (!form.title.trim()) found.title = "กรอกชื่อหนังสือ";
    if (!/^\d{13}$/.test(form.isbn)) found.isbn = "ISBN เป็นตัวเลข 13 หลัก";
    setErrors(found);
    if (Object.keys(found).length > 0) return;

    setSending(true);
    setServerError("");
    try {
      await booksApi.create(form);
      setForm(empty);
      onSaved();
    } catch (err) {
      setServerError((err as Error).message);              // เช่น "มีหนังสือ ISBN นี้แล้ว" จาก API
    } finally {
      setSending(false);
    }
  }

  return (
    <form onSubmit={onSubmit} noValidate>
      <label>
        ชื่อหนังสือ
        <input value={form.title} onChange={(e) => setForm({ ...form, title: e.target.value })} />
      </label>
      {errors.title && <p role="alert">{errors.title}</p>}
      {/* ช่อง ISBN เขียนแบบเดียวกัน */}
      {serverError && <p role="alert">{serverError}</p>}
      <button type="submit" disabled={sending}>{sending ? "กำลังบันทึก..." : "บันทึก"}</button>
    </form>
  );
}
```

## ทริคที่แนะนำ

1. **ข้อความผิดอยู่ใต้ช่องที่ผิด** และบอกวิธีแก้ ("ISBN เป็นตัวเลข 13 หลัก") ไม่ใช่แค่ "ข้อมูลไม่ถูกต้อง" รวมไว้บนสุด
2. **ทุกช่องมี `<label>`** คลิกที่ชื่อแล้วเคอร์เซอร์ไปที่ช่อง และโปรแกรมอ่านหน้าจอบอกได้ว่าช่องนี้คืออะไร placeholder ไม่ใช่ label เพราะหายไปตอนเริ่มพิมพ์
3. **ส่งไม่สำเร็จห้ามล้างฟอร์ม** ผู้ใช้ต้องแก้แค่ช่องที่ผิดแล้วส่งใหม่ ล้างฟอร์มเฉพาะตอนสำเร็จ

## ปรับไปใช้จริง

ฟอร์มถามพี่เลี้ยงท้ายหน้าของเว็บนี้ (`src/components/new-thread-form.tsx` ที่ `ask-question.tsx` เรียกใช้) ทำครบ 4 จังหวะ: ปุ่มกดซ้ำไม่ได้ระหว่างส่ง, ข้อความ error จาก API ขึ้นในกล่อง, สำเร็จแล้วขึ้น toast "ส่งถึงพี่เลี้ยงแล้ว" พร้อมปุ่มเปิดแชท ส่วนช่องกรอกทุกฟอร์มในเว็บนี้ (login, หลังบ้าน, แชท) ใช้ชิ้นส่วนกลาง `Field` จาก `field.tsx` ตัวเดียวกัน label จึงหน้าตาและทำงานเหมือนกันทุกที่

ลองคิด: ถ้าตรวจรูปแบบทั้งฝั่งหน้าเว็บและ API ข้อความ error ควรเหมือนกันไหม และจะทำยังไงให้ไม่ต้องเขียนกฎซ้ำสองที่

## ตัวเลือกอื่นที่คล้ายกัน

| วิธี | เหมาะกับ | ระดับ |
|---|---|---|
| **`useState` ต่อช่อง + ตรวจเอง (ทีมใช้)** | ฟอร์มไม่เกินราว 5 ช่อง เห็นทุกขั้น | ใช้ทุกงาน |
| React Hook Form | ฟอร์มยาว หลายหน้า ช่องเยอะ ใช้ schema ของ Zod ตรวจได้ | ควรรู้จัก |
| `<form action>` + FormData (React 19) | ฟอร์มสั้นๆ ไม่ต้องเก็บค่าใน state ทีละตัวอักษร | รู้ว่ามี |
| TanStack Form | ฟอร์มซับซ้อนที่ต้องคุม type ทุกช่อง | รู้ว่ามี |

## ลองเอง

**โจทย์:** ทำฟอร์มสมัครสมาชิกห้องสมุด (ชื่อ, อีเมล, เบอร์โทร) ที่ตรวจทุกช่องก่อนส่ง ปุ่มกดซ้ำไม่ได้ระหว่างส่ง ถ้า API ตอบว่าอีเมลซ้ำ ต้องขึ้นข้อความโดยค่าที่กรอกไว้ยังอยู่ครบ

<Hint level={1}>นับ state ที่ต้องมีก่อนเขียน: ค่าที่กรอก, ข้อความผิดแต่ละช่อง, กำลังส่ง, error จาก server</Hint>
<Hint level={2}>ลองทดสอบกดส่งรัวๆ ใน DevTools แท็บ Network ต้องเห็นคำขอแค่ 1 ตัว</Hint>
<Hint level={3}>ถ้าค่าหายตอน API ตอบ error ให้ดูว่าบรรทัดล้างฟอร์มอยู่ก่อนหรือหลังบรรทัดที่อาจโยน error</Hint>
