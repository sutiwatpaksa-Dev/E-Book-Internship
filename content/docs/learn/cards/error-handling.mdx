## ความหมาย

พูดง่ายๆ คือ เจอปัญหาตรงไหน ให้แจ้งออกมาเฉยๆ แล้วให้จุดเดียวเป็นคนตัดสินว่าจะบอกผู้ใช้ว่าอะไร

ในภาษาโค้ด: ให้โค้ดทุกชั้น **โยน error ออกมาเฉยๆ** แล้วมี **ตัวจับกลางตัวเดียว** แปลง error เป็นคำตอบที่ถูกต้อง: เรื่องที่รู้จัก (เช่น ยืมเกินโควตา) ตอบ status ที่ตรงพร้อมข้อความภาษาไทย ส่วนเรื่องที่ไม่รู้จัก ตอบ `500` แบบสุภาพ และเก็บรายละเอียดไว้ดูเองใน log

**นึกภาพ:** ร้านอาหารเดียวกับการ์ด [แบ่งชั้น](/learn/cards/layers) เวลาเชฟหรือคนดูแลห้องเก็บของเจอปัญหา ไม่ต้องเดินออกไปอธิบายกับลูกค้าเอง แค่ส่งเรื่องให้ผู้จัดการร้านคนเดียว ผู้จัดการรู้ว่าเรื่องไหนบอกลูกค้าว่าอะไร เช่น "เมนูนี้วัตถุดิบหมด" ส่วนเรื่องภายในที่ลูกค้าไม่ควรรู้ (เครื่องล้างจานพัง) ก็จดลงสมุดของร้าน แล้วบอกลูกค้าแค่ขออภัย

จับคู่: เชฟ คนดูแลห้องเก็บของ พนักงานหน้าร้าน = services, repositories, routes · ส่งเรื่องให้ผู้จัดการ = `throw` · ผู้จัดการร้าน = `app.onError` · คำตอบถึงลูกค้า = status + ข้อความไทย · สมุดของร้าน = log ฝั่ง server (`console.error`)

```text
service: ยืมเล่มที่ 4
   │ throw new Error("LOAN_LIMIT")
   ▼
ตัวจับกลาง app.onError
   │
   ├──► รหัสที่รู้จัก
   │    409 + "ยืมได้ไม่เกิน 3 เล่ม..."
   │
   └──► เรื่องที่ไม่รู้จัก
        500 + ข้อความสุภาพ
        รายละเอียดจดลง log
```

จุดที่ไม่ตรง: ผู้จัดการร้านเจอเรื่องแปลกๆ ยังเดินไปถามเชฟได้ แต่ตัวจับกลางถามกลับไม่ได้ เรื่องไหนไม่อยู่ในรายการรหัสที่รู้จัก จะกลายเป็น `500` ทันที เวลาเพิ่มรหัสใหม่ที่ service จึงต้องเพิ่มในรายการของตัวจับกลางด้วย

## ที่มา

ถ้าทุก route เขียน [try-catch](/glossary#try-catch) เอง ไม่นานจะมี route ที่ลืม และแต่ละ route ตอบ error คนละหน้าตา หน้าเว็บต้องเขียนโค้ดเดาหลายแบบ ร้ายกว่านั้น ถ้าปล่อยให้ error หลุดออกไปทั้งก้อน คนนอกจะเห็น **stack trace** (รายชื่อไฟล์และบรรทัดที่พัง) บางครั้งมีชื่อตารางหรือ SQL ติดไปด้วย ซึ่งเป็นข้อมูลให้คนไม่หวังดีเดาโครงระบบ framework อย่าง Hono จึงมีช่องให้ใส่ตัวจับกลางไว้ตัวเดียว

## การใช้งาน

ต่อจากการ์ด [แบ่งชั้น](/learn/cards/layers) ที่ service โยน `new Error("LOAN_LIMIT")` และ `new Error("BOOK_NOT_FOUND")` แล้วได้ `500` ทั้งคู่

**1. ตัวจับกลาง** `server/src/middleware/error-handler.ts`

```ts
import type { Context } from "hono";
import type { ContentfulStatusCode } from "hono/utils/http-status";
import { fail } from "../lib/response";

// รหัสที่เรารู้จัก → [status, ข้อความที่ผู้ใช้เห็น]
const KNOWN: Record<string, [ContentfulStatusCode, string]> = {
  BOOK_NOT_FOUND: [404, "ไม่พบหนังสือ"],
  LOAN_LIMIT: [409, "ยืมได้ไม่เกิน 3 เล่ม คืนเล่มเก่าก่อน"],
};

export function errorHandler(err: Error, c: Context) {
  const known = KNOWN[err.message];
  if (known) return fail(c, known[0], err.message, known[1]);
  console.error(err);                                    // รายละเอียดจริงอยู่ใน log ฝั่ง server เท่านั้น
  return fail(c, 500, "INTERNAL_ERROR", "ระบบขัดข้อง");   // คนนอกเห็นแค่นี้
}
```

**2. ติดตั้ง** ใน `server/src/index.ts` เพิ่ม 2 บรรทัด: import ไว้บนสุด และ `app.onError(...)` ไว้หลัง `app.notFound(...)` ก่อน `export default app`

```ts
import { errorHandler } from "./middleware/error-handler";

app.onError(errorHandler);
```

**ควรเห็น:** ยืมเล่มที่ 4 ได้ `409` แทน `500` สมาชิก 1 ยืมค้างอยู่ 3 รายการตั้งแต่การ์ดแบ่งชั้นแล้ว จึงยิงครั้งเดียวก็เห็นผลนี้ (ถ้าทำโจทย์ 1 ของการ์ดแบ่งชั้นแล้ว ให้ส่ง `bookId: 2` เพราะเล่ม 1 จะโดนกฎยืมซ้ำก่อน)

```json
{"success":false,"error":{"code":"LOAN_LIMIT","message":"ยืมได้ไม่เกิน 3 เล่ม คืนเล่มเก่าก่อน"}}
```

ส่ง `bookId: 99` ได้ `404`

```json
{"success":false,"error":{"code":"BOOK_NOT_FOUND","message":"ไม่พบหนังสือ"}}
```

ลองทำให้พังจริง: ปิด Postgres (`docker stop pg`) แล้วยิงอีกครั้ง คำตอบได้แค่ `ระบบขัดข้อง` ส่วน Terminal ที่รัน server มีรายละเอียดเต็ม (เสร็จแล้ว `docker start pg`)

## ทริคที่แนะนำ

1. **โยนเป็น "รหัส" ไม่ใช่ข้อความภาษาคน:** service โยน `LOAN_LIMIT` แล้วตัวจับกลางแปลเป็นข้อความ วันหลังจะเปลี่ยนคำพูดหรือทำสองภาษา แก้ที่เดียว
2. **ห้ามส่ง `err.message` ของเรื่องที่ไม่รู้จักออกไป:** error จาก Drizzle ขึ้นต้นด้วย `Failed query: insert into "books" ...` คือ SQL ทั้งคำสั่งพร้อมค่าที่คนอื่นกรอกไว้
3. **error ที่ "เดาได้" ไม่ต้องรอถึงตัวจับกลาง:** ข้อมูลผิดรูปแบบตอบ `400` ใน route ได้เลย (การ์ด Zod) ตัวจับกลางไว้สำหรับกฎใน service และของที่พังแบบไม่คาดคิด

## ปรับไปใช้จริง

**ในงาน STARTER:** Requirement ให้มีรหัส error เป็นคำภาษาอังกฤษตัวใหญ่ (เช่น `VALIDATION_ERROR`) และหัวข้อ Security บอกว่า "error 500 ห้ามส่ง stack trace กลับไป" ซึ่งตรวจในวันที่ 9 วิธีข้างบนผ่านทั้งสองข้อ ส่วนโฟลเดอร์ `middleware/` มีอยู่แล้วในโครงที่ Requirement กำหนด

**เว็บคู่มือนี้:** ใช้หลักเดียวกัน ดู `app.onError` ใน [server/app.ts บน GitHub](https://github.com/sutiwatpaksa-Dev/E-Book-Internship/blob/main/server/app.ts) (เว็บนี้ตอบ error แบบสั้น `{ error: "..." }` เพราะทำก่อนมี Requirement หลักการเหมือนกัน)

ลองคิด: ถ้าสองคนกดยืมเล่มสุดท้ายพร้อมกันพอดี ทั้งคู่ผ่านการนับโควตาแล้วฐานข้อมูลปฏิเสธคนหนึ่งด้วย unique constraint error นั้นจะออกมาเป็น status อะไร และควรเป็นอะไร

## ตัวเลือกอื่นที่คล้ายกัน

| วิธี | หน้าตา | ข้อดี / ข้อเสีย |
|---|---|---|
| **โยนรหัส + ตัวจับกลาง (การ์ดนี้)** | `throw new Error("LOAN_LIMIT")` | สั้น อ่านง่าย / ต้องจำว่ารหัสไหนมีในตาราง |
| class error ของตัวเอง | `throw new AppError(409, "LOAN_LIMIT")` | status อยู่ติดกับที่โยน / service เริ่มรู้จัก HTTP |
| `HTTPException` ของ Hono | `throw new HTTPException(409, { message })` | มีให้ใช้เลย / service ต้อง import Hono ผิดหลักแบ่งชั้น |
| คืนค่าแทนโยน (Result) | `return { ok: false, code: "LOAN_LIMIT" }` | ลืมจัดการแล้ว TypeScript เตือน / โค้ดยาวกว่า |

## ลองเอง

**โจทย์:** เพิ่มคอลัมน์ `isbn` (ห้ามซ้ำ) ให้ตาราง `books` แล้วทำให้การเพิ่มหนังสือที่ isbn ซ้ำได้ `409` พร้อมข้อความ "มีหนังสือ isbn นี้แล้ว" แทน `500`

<Hint level={1}>เริ่มจาก schema: Drizzle มี `.unique()` แล้วทำตามการ์ด [Migration](/learn/cards/migration) (หนังสือที่ seed ไว้ไม่มี isbn ได้ ค่าว่างหลายแถวไม่นับว่าซ้ำ) จากนั้นให้ `newBookSchema` และ `bookRepository.create` จากการ์ดแบ่งชั้นรับ `isbn` ด้วย</Hint>
<Hint level={2}>ยิงซ้ำแล้วดู `console.error` ใน Terminal: Drizzle ห่อ error ของ Postgres ไว้ข้างใน รหัสอยู่ที่ `err.cause.code` (ไม่ใช่ `err.code`) และรหัสของ "ซ้ำ" คือ `23505`</Hint>
<Hint level={3}>มีสองที่ให้เลือก: เช็กก่อนบันทึกใน service ("มี isbn นี้หรือยัง") หรือจับรหัส `23505` ในตัวจับกลาง ลองคิดว่าทางไหนรอดกรณีสองคนกดพร้อมกัน</Hint>
