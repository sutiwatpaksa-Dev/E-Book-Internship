---
title: "จัดการ error ที่จุดเดียว"
---

## ความหมาย

แทนที่จะเขียน `try/catch` ทุก route ให้ทุกชั้น **โยน error ขึ้นมา** แล้วมี **ตัวจัดการกลาง** ตัวเดียวแปลงเป็นคำตอบ: error ที่รู้จักได้ status กับข้อความที่ผู้ใช้อ่านรู้เรื่อง error ที่ไม่รู้จักได้ `500` และจดรายละเอียดลง log ฝั่ง server

## ที่มา

ถ้าแต่ละ route จับ error เอง ข้อความจะไม่เหมือนกัน (`"not found"`, `"ไม่พบ"`, `"Error: ..."`) บาง route ลืมจับ คำตอบกลายเป็นหน้า error ของ framework ที่ **โชว์ชื่อตารางหรือ path ในเครื่อง server** ให้คนนอกเห็น ซึ่งเป็นข้อมูลที่คนโจมตีอยากได้ จุดเดียวทำให้รูปแบบคำตอบเหมือนกันทุกตัว และกันข้อมูลข้างในรั่วได้ที่เดียว

## การใช้งาน

```ts
// middleware/error-handler.ts
import type { Context } from "hono";

// รหัสที่ service โยนได้ → status + ข้อความที่ผู้ใช้อ่าน
const KNOWN: Record<string, [400 | 404 | 409, string]> = {
  BOOK_NOT_FOUND: [404, "ไม่พบหนังสือ"],
  LOAN_LIMIT: [409, "ยืมได้ไม่เกิน 3 เล่ม คืนเล่มเก่าก่อน"],
};

export function errorHandler(err: Error, c: Context) {
  const known = KNOWN[err.message];
  if (known) return c.json({ error: known[1] }, known[0]);
  console.error(err);                                   // รายละเอียดเต็มอยู่ใน log เท่านั้น
  return c.json({ error: "ระบบขัดข้อง" }, 500);          // คนนอกเห็นแค่นี้
}
```

```ts
// app.ts
app.onError(errorHandler);
```

ตอนนี้ service แค่ `throw new Error("LOAN_LIMIT")` ทุก route ที่เรียก service นั้นตอบ `409` เหมือนกันหมดโดยไม่ต้องเขียนอะไรเพิ่ม

## ทริคที่แนะนำ

1. **คำตอบ error มีหน้าตาเดียวทั้งระบบ** เช่น `{ "error": "ข้อความ" }` หน้าเว็บเขียนโค้ดแสดง error ชุดเดียวใช้ได้ทุกที่
2. **แปลง error ของฐานข้อมูลเป็นรหัสของเรา:** ใส่ข้อมูลซ้ำ Postgres ตอบรหัส `23505` ถ้าปล่อยหลุดจะได้ `500` ทั้งที่จริงควรเป็น `409` ให้ repository หรือ service จับรหัสนี้แล้วโยนรหัสของเราแทน
3. **ข้อความถึงผู้ใช้บอกว่าต้องทำอะไรต่อ:** "ยืมได้ไม่เกิน 3 เล่ม คืนเล่มเก่าก่อน" ดีกว่า "เกินจำนวน"

## ปรับไปใช้จริง

`server/middleware/error-handler.ts` ของเว็บนี้มีรหัส 12 ตัว เช่น `TOO_MANY_ATTEMPTS` → `429` "ลองผิดหลายครั้งเกินไป รอ 15 นาที" และ `UNKNOWN_CHAPTER` → `400` ส่วนบรรทัดแรกจับ `HTTPException` ของ Hono (เช่นจากด่านกัน CSRF ที่ตอบ `403` โดยไม่มีข้อความ) แล้วเติมข้อความให้อ่านรู้เรื่อง

ลองคิด: ถ้าลืมเพิ่มรหัสใหม่ใน `KNOWN` ผู้ใช้จะเห็นอะไร และเราจะรู้ตัวจากที่ไหน

## ตัวเลือกอื่นที่คล้ายกัน

| วิธี | หน้าตา | ข้อดี / ข้อควรระวัง |
|---|---|---|
| **รหัสใน `Error` + ตารางแปลง (ทีมใช้)** | `throw new Error("LOAN_LIMIT")` | ง่าย service ไม่รู้จัก HTTP · ต้องจำเพิ่มรหัสในตาราง |
| คลาส error ของตัวเอง | `class AppError { code; status }` | เช็กด้วย `instanceof` ได้ ใส่ข้อมูลเพิ่มได้ · service เริ่มรู้จัก status |
| `HTTPException` ของ Hono | `throw new HTTPException(404, ...)` | มีให้ในตัว · ใช้ใน route/middleware ได้ ไม่ควรโยนจาก service |
| คืนค่าแทนโยน (Result) | `return { ok: false, error: "LOAN_LIMIT" }` | ผู้เรียกลืมเช็กไม่ได้ (type บังคับ) · โค้ดยาวขึ้นทุกจุดที่เรียก |

## ลองเอง

**โจทย์:** ทำให้การเพิ่มหนังสือที่มี ISBN ซ้ำตอบ `409` "มีหนังสือ ISBN นี้แล้ว" แทน `500` โดยใช้ unique constraint ของฐานข้อมูล ไม่ใช่ query เช็กก่อนเพิ่ม

<Hint level={1}>ฐานข้อมูลกันซ้ำให้อยู่แล้วถ้าคอลัมน์เป็น unique ปัญหาคือ error ที่ได้ยังเป็นภาษาของฐานข้อมูล</Hint>
<Hint level={2}>error จาก Drizzle ห่อ error ของ Postgres ไว้ใน `cause` ลอง `console.log` ดูว่ารหัสอยู่ช่องไหน</Hint>
<Hint level={3}>จับเฉพาะรหัส `23505` แล้วโยนรหัสของเรา รหัสอื่นโยนต่อไปตามเดิม และอย่าลืมเพิ่มในตารางแปลง</Hint>
