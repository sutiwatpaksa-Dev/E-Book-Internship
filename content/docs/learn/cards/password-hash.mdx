## ความหมาย

ระบบไม่เก็บรหัสผ่านตัวจริงเลย เก็บแค่ **[hash](/glossary#hash)** ซึ่งเป็นผลจากการแปลงรหัสผ่านทางเดียว ย้อนกลับเป็นรหัสเดิมไม่ได้ ตอน login ก็เอารหัสที่กรอกมาแปลงด้วยวิธีเดียวกัน แล้วเทียบว่าตรงกับที่เก็บไว้ไหม

**นึกภาพ:** ปั่นผลไม้เป็นน้ำปั่น ปั่นสูตรเดิมได้รสเดิม เลยรู้ว่าใช้ผลไม้ชุดเดียวกัน แต่จะเอาน้ำปั่นคืนกลับเป็นผลไม้ไม่ได้

จับคู่: ผลไม้ = รหัสผ่าน · น้ำปั่น = hash ที่เก็บในคอลัมน์ `password_hash` · สูตรปั่น = วิธีแปลง (การ์ดนี้ใช้ argon2id ผ่าน `Bun.password`)

```text
ตอนสร้างบัญชี (seed)
รหัสผ่าน
   │ Bun.password.hash
   ▼
$argon2id$v=19$...
เก็บลงตาราง librarians

ตอน login
รหัสที่กรอก + hash จากตาราง
   │ Bun.password.verify
   ▼
true = ให้เข้า
false = ไม่ให้เข้า
```

จุดที่ไม่ตรง: ปั่นผลไม้ชุดเดิมได้รสเดิมทุกครั้ง แต่ `Bun.password.hash` ผสม **ค่าสุ่ม (salt)** ลงไปทุกครั้ง รหัสเดียวกัน hash 2 รอบจึงได้ข้อความไม่เหมือนกัน (เห็นจริงในข้อ 1 ด้านล่าง) ตอนตรวจจึงห้ามเอา hash มาเทียบกันตรงๆ ต้องใช้ `Bun.password.verify` ซึ่งอ่านค่าสุ่มจาก hash เดิมแล้วปั่นรหัสที่กรอกด้วยค่าสุ่มเดียวกัน

## ที่มา

ฐานข้อมูลหลุดได้เสมอ เช่น ไฟล์ backup ถูกแชร์ผิดที่ หรือมีคนได้สิทธิ์อ่านตารางที่ไม่ควรได้ ถ้าเก็บรหัสผ่านตรงๆ คนที่ได้ไฟล์ไปจะ login ได้ทันที และคนส่วนใหญ่ใช้รหัสเดียวกันหลายเว็บ ความเสียหายจึงลามไปถึงอีเมลและบัญชีธนาคารของเขาด้วย พอเก็บแค่ hash คนที่ได้ไฟล์ไปต้องเดารหัสทีละตัวแล้วแปลงมาเทียบ วิธี hash สำหรับรหัสผ่านจึง **ตั้งใจให้ช้า** เพื่อให้การเดาแบบนี้ใช้เวลานานจนไม่คุ้ม

## การใช้งาน

Bun มี `Bun.password` มาในตัว ไม่ต้องติดตั้งอะไร ค่าเริ่มต้นคือ [argon2id](/glossary#argon2) ([เอกสาร Bun](https://bun.com/docs/runtime/hashing))

### 1. ลองเล่นก่อน `server/try-hash.ts`

```ts
const a = await Bun.password.hash("1234");
const b = await Bun.password.hash("1234");
console.log(a);
console.log(b);
console.log("เหมือนกันไหม:", a === b);
console.log("รหัสถูก:", await Bun.password.verify("1234", a));
console.log("รหัสผิด:", await Bun.password.verify("12345", a));
```

```bash
cd server
bun try-hash.ts
```

**ควรเห็น:** (ค่าที่ได้ไม่เหมือนตัวอย่าง เพราะมีค่าสุ่มผสมอยู่)

```text
$argon2id$v=19$m=65536,t=2,p=1$eBRJyKMP3rP9qTaL0vegLVT1YDBJCH6A8xP1FB8cKAY$BFoTjlzA...
$argon2id$v=19$m=65536,t=2,p=1$5Oe3wU/AqhYskZox13vUscPML137Gvy7jo111r02IEI$i704CS7u...
เหมือนกันไหม: false
รหัสถูก: true
รหัสผิด: false
```

รหัสเดียวกันได้ hash ไม่เหมือนกัน เพราะทุกครั้งมี **[salt](/glossary#salt)** (ค่าสุ่ม) ผสมเข้าไป ข้อความที่ได้แบ่งเป็นท่อนด้วย `$`

| ท่อน | ตัวอย่าง | คืออะไร |
|---|---|---|
| 1 | `argon2id` | วิธี hash |
| 2 | `v=19` | รุ่นของวิธีนั้น |
| 3 | `m=65536,t=2,p=1` | ค่าตั้งความช้า: ใช้หน่วยความจำ 64 MB, วน 2 รอบ |
| 4 | `eBRJyKMP3rP9...` | salt |
| 5 | `BFoTjlzA...` | ผล hash จริง |

salt ถูกเก็บไว้ในข้อความเดียวกัน `verify` จึงอ่าน salt ตัวเดิมออกมาแปลงรหัสที่กรอกซ้ำได้

### 2. ตารางบรรณารักษ์ (คนที่ login เข้าหลังบ้านได้)

เพิ่มใน `server/src/db/schema.ts` แล้วสร้าง migration ตามการ์ด [Migration](/learn/cards/migration)

```ts
export const librarians = pgTable("librarians", {
  id: serial("id").primaryKey(),
  email: text("email").notNull().unique(),
  passwordHash: text("password_hash").notNull(),   // ไม่มีคอลัมน์ password เด็ดขาด
  name: text("name").notNull(),
  createdAt: timestamp("created_at", { withTimezone: true }).notNull().defaultNow(),
});
```

```bash
bunx drizzle-kit generate
bunx drizzle-kit migrate
```

### 3. seed บัญชีแรก

อีเมลกับรหัสผ่านของบัญชีแรกอยู่ใน `server/.env` (ห้าม commit) และใส่แค่ชื่อตัวแปรใน `.env.example`

```text
LIBRARIAN_EMAIL=librarian@library.local
LIBRARIAN_PASSWORD=correct-horse-battery
```

เพิ่มใน `server/src/db/seed.ts` ก่อนบรรทัด `process.exit` (และเพิ่ม `librarians` ใน import บนสุด)

```ts
const email = process.env.LIBRARIAN_EMAIL;
const password = process.env.LIBRARIAN_PASSWORD;
if (email && password) {
  await db
    .insert(librarians)
    .values({ email: email.toLowerCase(), passwordHash: await Bun.password.hash(password), name: "บรรณารักษ์" })
    .onConflictDoNothing({ target: librarians.email });       // รันซ้ำได้ ไม่ซ้ำบัญชี
  console.log(`บรรณารักษ์: ${email}`);
}
```

```bash
bun run seed
docker exec pg psql -U postgres -c "SELECT email, left(password_hash, 30) AS hash FROM librarians;"
```

**ควรเห็น:** (คำสั่งที่สองใช้ได้ทั้ง Mac และ Windows ใน Git Bash ไม่ใส่ `-it` เพราะ `-c` สั่งคำสั่งเดียวแล้วจบ ไม่ต้องพิมพ์โต้ตอบ ถ้าใส่ บน Git Bash อาจขึ้น `the input device is not a TTY` ถ้าตั้งชื่อ container อื่น ให้เปลี่ยน `pg` เป็นชื่อนั้น หรือเปิดดูใน pgAdmin ก็ได้)

```text
          email          |              hash
-------------------------+--------------------------------
 librarian@library.local | $argon2id$v=19$m=65536,t=2,p=1
(1 row)
```

รัน `bun run seed` ซ้ำ ตาราง `librarians` ยังมีแถวเดียว เพราะ `onConflictDoNothing` ข้ามอีเมลที่มีอยู่แล้ว แต่สมาชิกและหนังสือจาก seed ของการ์ด Migration จะเพิ่มซ้ำทุกรอบ **รวมรอบแรกในการ์ดนี้ด้วย** (การ์ด Migration รันไปแล้ว 1 รอบ จึงได้ id 3, 4 เพิ่ม) เพราะส่วนนั้นยังไม่ได้กันไว้ ไม่เป็นไร ข้อมูลตัวอย่างซ้ำไม่ทำให้อะไรพัง

## ทริคที่แนะนำ

1. **ใช้ `Bun.password` อย่าใช้ sha256 หรือ md5:** วัดในเครื่องที่เขียนการ์ดนี้ `Bun.password.hash` 1 ครั้งใช้ราว 95 ms แต่ sha256 แสนครั้งใช้แค่ 23 ms คนเดารหัสด้วย sha256 จึงลองได้เร็วกว่าเป็นแสนเท่า ความช้าคือสิ่งที่เราต้องการ
2. **ทำอีเมลเป็นตัวพิมพ์เล็กก่อนเก็บและก่อนค้น:** `Mani@x.com` กับ `mani@x.com` คือคนเดียวกัน ถ้าไม่ทำ จะได้ 2 บัญชี หรือ login ไม่ติดเพราะพิมพ์ตัวใหญ่
3. **เลือกคอลัมน์ทุกครั้งที่ดึงข้อมูลบัญชีไปตอบ:** ถ้า `select()` ทั้งแถวแล้วส่งออก API `password_hash` จะหลุดออกไปด้วย hash ก็ไม่ควรให้ใครเห็น เพราะเอาไปเดาในเครื่องตัวเองได้เรื่อยๆ

## ปรับไปใช้จริง

**ในโจทย์ฝึกงาน** (ตัวอย่างจาก STARTER)**:** ตาราง `admins` (email unique, password_hash, name) ทำวันที่ 2 พร้อม seed "admin 1 คน" และวันที่ 4 ใช้ `Bun.password` ตอน login Requirement ระบุว่า **รหัสผ่านที่เก็บแบบไม่ hash = ไม่ผ่านทันที** ไม่ว่าคะแนนส่วนอื่นจะดีแค่ไหน และ README ต้องบอกบัญชี admin สำหรับทดสอบ (บอกในเอกสาร ไม่ใช่ใส่รหัสจริงใน `seed.ts`)

**เว็บคู่มือนี้:** พี่เลี้ยงออก PIN 6 หลักให้ใช้ login ครั้งแรก แล้วระบบบังคับให้ตั้งรหัสผ่านของตัวเอง (10 ตัวขึ้นไป) ทั้ง PIN และรหัสผ่านเก็บแบบเดียวกัน คือ `Bun.password.hash` บรรทัดเดียวใน [server/lib/pin.ts บน GitHub](https://github.com/sutiwatpaksa-Dev/E-Book-Internship/blob/main/server/lib/pin.ts) ตาราง `users` จึงมีแค่คอลัมน์ `secret_hash` (กับ `secret_kind` บอกว่าเป็น PIN หรือรหัสผ่าน) ไม่มีตัวจริงสักตัว

ลองคิด: ถ้าลูกค้าโทรมาบอกว่า "ลืมรหัสผ่าน ช่วยบอกรหัสเดิมหน่อย" เราบอกได้ไหม แล้วระบบควรมีอะไรแทน

## ตัวเลือกอื่นที่คล้ายกัน

| วิธี | ใช้กับรหัสผ่านได้ไหม | หมายเหตุ |
|---|---|---|
| **argon2id (`Bun.password` ค่าเริ่มต้น)** | ได้ ทีมใช้ | ตั้งความช้าได้ทั้งเวลาและหน่วยความจำ |
| bcrypt | ได้ | ใช้กันมานาน `Bun.password` เลือกได้ด้วย `{ algorithm: "bcrypt" }` รับรหัสยาวไม่เกิน 72 byte |
| sha256, md5 | ไม่ได้ | เร็วเกินไป ใช้ตรวจว่าไฟล์เหมือนกันไหม ไม่ใช่เก็บรหัสผ่าน |
| [เข้ารหัส](/glossary#encrypt) (encrypt) | ไม่ได้ | ถอดกลับได้ถ้ามีกุญแจ กุญแจหลุดคือรหัสทุกคนหลุด |

## ลองเอง

**โจทย์:** เขียนสคริปต์ `server/src/db/reset-password.ts` ที่รับอีเมลกับรหัสใหม่จาก Terminal (`bun run src/db/reset-password.ts librarian@library.local รหัสใหม่`) แล้วเปลี่ยนรหัสของบัญชีนั้น ถ้าไม่พบอีเมลต้องบอกว่าไม่พบ และถ้ารหัสใหม่สั้นกว่า 12 ตัวต้องไม่ยอมเปลี่ยน

<Hint level={1}>ค่าที่พิมพ์ตามหลังคำสั่งอยู่ใน `process.argv` ลอง `console.log(process.argv)` ดูก่อนว่าค่าที่ต้องการอยู่ช่องที่เท่าไร</Hint>
<Hint level={2}>การเปลี่ยนแถวใน Drizzle คือ `db.update(...).set(...).where(...)` ถ้าต่อด้วย `.returning()` แล้วได้ array ว่าง แปลว่าไม่มีแถวไหนตรงเงื่อนไข</Hint>
<Hint level={3}>ตรวจผล: hash ในตารางต้องเปลี่ยน และ `Bun.password.verify` กับรหัสใหม่ต้องได้ `true` กับรหัสเก่าต้องได้ `false` (ลองใน `try-hash.ts` โดยเอา hash จากตารางมาแปะ)</Hint>

## อ่านเพิ่ม

hash กับการเข้ารหัสต่างกันยังไง และลองเดารหัสที่เก็บด้วย sha256 ให้เห็นกับตา อยู่ในบทเดิม [Security พื้นฐาน](/10-security#2-เก็บรหัสผ่านผู้ใช้-hash-ไม่ใช่-encrypt)
