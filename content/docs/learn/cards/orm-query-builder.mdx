## ความหมาย

เครื่องมือที่ให้โค้ดของเราคุยกับฐานข้อมูล มี 3 ระดับ ยิ่งสูงยิ่งเขียนน้อย แต่ยิ่งมองไม่เห็นว่าข้างล่างเกิดอะไร

| ระดับ | เขียนแบบไหน | เปรียบเทียบ |
|---|---|---|
| Driver | พิมพ์ SQL เป็นข้อความเอง | เขียนจดหมายภาษาต่างประเทศเองทุกคำ |
| Query Builder | เรียกฟังก์ชันที่หน้าตาคล้าย SQL แล้วมันประกอบ SQL ให้ | กรอกแบบฟอร์มที่มีช่องให้เติม |
| ORM | มองตารางเป็น object มีความสัมพันธ์ให้เรียกต่อกันได้ | บอกเลขาว่าอยากได้อะไร เลขาไปจัดการเอง |

## ที่มา

การพิมพ์ SQL เป็นข้อความในโค้ดมีปัญหา 3 อย่าง: พิมพ์ชื่อคอลัมน์ผิดก็รู้ตอนรัน, editor ช่วยเติมคำไม่ได้, และถ้าต่อข้อความจากผู้ใช้ผิดวิธีจะโดน SQL Injection จึงเกิด ORM ขึ้นมาตั้งแต่ต้นทศวรรษ 2000 และในยุค TypeScript เครื่องมือรุ่นใหม่เน้นให้ **type ของโค้ดตรงกับตารางจริง** พิมพ์ผิดก็เห็นตั้งแต่ตอนเขียน

## การใช้งาน

งานเดียวกัน "หาหนังสือเล่มที่ id = 5" เขียนได้ 3 แบบ:

```ts
// Driver (pg): SQL เป็นข้อความ ส่งค่าแยกด้วย $1
await pool.query("SELECT * FROM books WHERE id = $1", [5]);
// Query Builder (Drizzle): หน้าตาเหมือน SQL แต่เป็นฟังก์ชันที่มี type
await db.select().from(books).where(eq(books.id, 5));
// ORM (Prisma): บอกสิ่งที่อยากได้เป็น object
await prisma.book.findUnique({ where: { id: 5 } });
```

ทั้งสามแบบสุดท้ายแล้วส่ง SQL ชุดเดียวกันไปที่ฐานข้อมูล

## ทริคที่แนะนำ

1. **เข้าใจ SQL ก่อนใช้เครื่องมือ** เครื่องมือแค่ช่วยเขียน เวลาช้าหรือผิดต้องกลับไปดู SQL ที่มันสร้าง
2. **เปิด log ดู SQL ที่ส่งจริงตอนพัฒนา** จะเห็นว่าคำสั่งสั้นๆ ของเราอาจกลายเป็น SQL หลายคำสั่ง
3. **ระวังปัญหา N+1:** ดึงรายการ 100 แถว แล้ววนดึงข้อมูลที่โยงกันทีละแถว = ยิงฐานข้อมูล 101 ครั้ง ให้ดึงพร้อมกันด้วย `JOIN` แทน

## ปรับไปใช้จริง

ทีมเราใช้ **Drizzle** ซึ่งอยู่กลางๆ: เขียนแบบ Query Builder ที่หน้าตาใกล้ SQL และมีโหมดดึงข้อมูลที่โยงกันแบบ ORM ให้ด้วย เหตุผลคือคนที่รู้ SQL อ่านโค้ดออกทันที และ type ตรงกับตารางจริง ดูการ์ด [Drizzle ORM](/learn/cards/drizzle-orm)

ลองคิด: ถ้าทีมหนึ่งใช้ Prisma อีกทีมใช้ Drizzle คนที่ "รู้ SQL" ย้ายไปอีกทีมได้ง่ายกว่าคนที่ "รู้แค่เครื่องมือ" เพราะอะไร

## ลองเอง

**โจทย์:** เขียน "รายการหนังสือที่ยังไม่มีคนคืน" ทั้งแบบ Driver และแบบ Drizzle แล้วเทียบว่าแบบไหนรู้ตัวก่อนถ้าพิมพ์ชื่อคอลัมน์ผิด

<Hint level={1}>เริ่มจาก SQL ล้วนก่อน (ดูการ์ด SQL ที่ใช้บ่อย) แล้วค่อยแปลงเป็นแบบ Drizzle</Hint>
<Hint level={2}>แบบ Drizzle ใช้ `isNull()` จาก `drizzle-orm` กับคอลัมน์วันที่คืน</Hint>
<Hint level={3}>ลองพิมพ์ชื่อคอลัมน์ผิดในทั้งสองแบบ: แบบหนึ่ง editor ขีดแดงทันที อีกแบบรู้ตอนรัน จดว่าแบบไหนเป็นแบบไหน</Hint>
