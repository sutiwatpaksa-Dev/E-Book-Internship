## ความหมาย

หน้าเว็บขอข้อมูลจาก API ด้วย `fetch` ระหว่างรอและเมื่อได้ผล หน้าจอต้องมี **3 สถานะเสมอ: กำลังโหลด / โหลดพัง / สำเร็จ** และโค้ดเรียก API อยู่ใน **ไฟล์กลางที่เดียว** ไม่กระจายอยู่ในทุกชิ้นส่วน

## ที่มา

บนเครื่องเรา API ตอบใน 5 มิลลิวินาที เลยลืมทำหน้า "กำลังโหลด" พอขึ้นเว็บจริงและผู้ใช้อยู่บนเน็ตมือถือ หน้าจอว่างเปล่า 3 วินาที คนคิดว่าเว็บพัง หรือ API ตอบ error แล้วหน้าเว็บขาวทั้งหน้า ส่วนการเขียน `fetch` ทุกชิ้นส่วน พอวันหนึ่งต้องเพิ่ม header หรือเปลี่ยนที่อยู่ API ต้องตามแก้ทุกไฟล์

## การใช้งาน

**ชั้นเรียก API** อยู่ไฟล์เดียว รู้จัก URL รูปแบบ error และ cookie

```ts
// src/api/client.ts
export async function request<T>(path: string, init: RequestInit = {}): Promise<T> {
  const res = await fetch(`/api${path}`, init);
  const body = res.status === 204 ? null : await res.json().catch(() => null);
  if (!res.ok) throw new Error(body?.error ?? `ผิดพลาด (${res.status})`);   // ข้อความภาษาไทยจาก API
  return body as T;
}

// src/api/books.api.ts
export const booksApi = {
  list: () => request<Book[]>("/books"),
};
```

**ชิ้นส่วน** สนใจแค่ 3 สถานะ

```tsx
export function BookList() {
  const [books, setBooks] = useState<Book[] | null>(null);
  const [error, setError] = useState("");

  useEffect(() => {
    let ignore = false;                       // ออกจากหน้าก่อนโหลดเสร็จ → ไม่ต้องอัปเดตแล้ว
    booksApi.list()
      .then((list) => !ignore && setBooks(list))
      .catch((e: Error) => !ignore && setError(e.message));
    return () => { ignore = true; };
  }, []);

  if (error) return <p role="alert">โหลดไม่สำเร็จ: {error}</p>;
  if (!books) return <p>กำลังโหลด...</p>;
  if (books.length === 0) return <p>ยังไม่มีหนังสือ</p>;
  return <ul>{books.map((b) => <li key={b.id}>{b.title}</li>)}</ul>;
}
```

## ทริคที่แนะนำ

1. **ลองช้าและลองพังทุกครั้ง:** DevTools → Network → เลือก **Slow 4G** แล้วรีเฟรช ต้องเห็น "กำลังโหลด" ลองปิด API แล้วรีเฟรช ต้องเห็นข้อความ error ไม่ใช่หน้าขาว
2. **"ว่าง" เป็นสถานะที่ 4 ที่ลืมบ่อย** รายการว่างควรบอกว่าทำอะไรต่อได้ ("ยังไม่มีหนังสือ เพิ่มเล่มแรก") ไม่ใช่พื้นที่ว่างเปล่า
3. **ใช้ข้อความ error จาก API ตรงๆ** API ที่ทำตามการ์ดจัดการ error ส่งภาษาไทยที่บอกว่าต้องทำอะไรมาแล้ว ไม่ต้องเขียนข้อความใหม่ฝั่งหน้าเว็บ

## ปรับไปใช้จริง

เว็บคู่มือนี้มีกติกาว่า **component ไม่เรียก `fetch` เอง** ทุกคำขอผ่าน `src/api/` (`client.ts` อันเดียว + ไฟล์แยกตามเรื่อง เช่น `progress.api.ts`, `threads.api.ts`) ตอนเพิ่มการส่ง cookie ทุกคำขอ แก้แค่ `client.ts` บรรทัดเดียว

ลองคิด: ปุ่มที่กดแล้วส่งคำขอ (เช่น "ยืม") ต้องมีสถานะอะไรบ้างระหว่างรอ และถ้าผู้ใช้กดรัวๆ จะเกิดอะไร

## ตัวเลือกอื่นที่คล้ายกัน

| วิธี | ช่วยอะไรเพิ่ม | ระดับ |
|---|---|---|
| **`fetch` + `useEffect` + ชั้น `src/api/` (ทีมใช้)** | ไม่ต้องติดตั้งเพิ่ม เห็นทุกขั้น | ใช้ทุกงาน |
| TanStack Query | เก็บผลไว้ใช้ซ้ำ ดึงใหม่เอง ลองใหม่เมื่อพัง | ควรรู้จัก เมื่อหน้าเว็บดึงข้อมูลหลายจุด |
| SWR | แนวเดียวกับ TanStack Query ตัวเล็กกว่า | รู้ว่ามี |
| ดึงฝั่ง server (Next.js Server Component, loader ของ React Router) | ข้อมูลมาพร้อมหน้าแรก ไม่ต้องมีหน้า "กำลังโหลด" ตอนเปิด | รู้ว่ามี |

## ลองเอง

**โจทย์:** ทำหน้า "การยืมของฉัน" ที่ดึงจาก `GET /api/loans/me` มีครบทั้ง 4 สถานะ (โหลด, พัง, ว่าง, มีข้อมูล) และปุ่ม "คืน" ที่กดซ้ำไม่ได้ระหว่างส่ง แล้วรายการอัปเดตหลังคืนสำเร็จ

<Hint level={1}>เพิ่มฟังก์ชันใน `loans.api.ts` ก่อน ลองเรียกใน Console ของ browser ให้ได้ผลก่อนไปทำหน้าจอ</Hint>
<Hint level={2}>ปุ่มต้องรู้ว่า "กำลังส่ง" อยู่ไหม นั่นคือ state อีกตัว ใช้คู่กับ `disabled`</Hint>
<Hint level={3}>หลังคืนสำเร็จมี 2 ทาง: ดึงรายการใหม่ทั้งหมด หรือลบเล่มนั้นออกจาก state เอง ลองคิดว่าทางไหนพลาดยากกว่า</Hint>
