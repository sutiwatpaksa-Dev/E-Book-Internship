## ความหมาย

Hono คือ **framework ฝั่ง server** ช่วยรับคำขอ HTTP แล้วส่งให้ฟังก์ชันที่ถูกตัว (เรียกว่า routing) พร้อมตัวช่วยอ่านค่าและตอบ JSON

**นึกภาพ:** พนักงานต้อนรับของร้าน ลูกค้าเข้ามาถามเรื่องอะไร ก็พาไปหาพนักงานที่รับผิดชอบเรื่องนั้น (ฟังก์ชันที่รับผิดชอบเรียกว่า [handler](/glossary#handler))

## ที่มา

เขียน server ด้วยมือเปล่าได้ แต่ต้องแยก URL เอง อ่าน body เอง ตั้ง header เอง ทุก route ซ้ำเดิม framework รวบงานซ้ำๆ ไว้ให้ Express ทำแบบนี้มาตั้งแต่ปี 2010 แต่ผูกกับ Node.js ส่วน Hono เกิดปี 2021 บนมาตรฐานของเว็บ โค้ดชุดเดียวจึงรันได้ทั้ง Bun, Node และอื่นๆ ไม่มี dependency และมี type ของ TypeScript มาในตัว

## การใช้งาน

### ตั้งค่าครั้งแรก

```bash
cd server
bun add hono
```

เพิ่มบรรทัด `dev` ใน `scripts` ของ `server/package.json` (คง `seed` จากการ์ด Migration ไว้ คั่นด้วย `,`) แล้วรัน `bun run dev` (`--hot` = แก้ไฟล์แล้ว server โหลดใหม่เอง)

```json
"scripts": {
  "seed": "bun run src/db/seed.ts",
  "dev": "bun run --hot src/index.ts"
}
```

### 1. ตัวช่วยรูปแบบคำตอบ `server/src/lib/response.ts`

Requirement บังคับรูปแบบคำตอบเดียวทุก endpoint (ดูการ์ด [HTTP และ REST](/learn/cards/http-rest)) เขียนครั้งเดียวไว้ตรงนี้ ทุก route เรียกใช้

```ts
import type { Context } from "hono";
import type { ContentfulStatusCode } from "hono/utils/http-status";

export const ok = (c: Context, data: unknown, status: ContentfulStatusCode = 200) =>
  c.json({ success: true, data }, status);

export const fail = (c: Context, status: ContentfulStatusCode, code: string, message: string, details?: unknown) =>
  c.json({ success: false, error: { code, message, details } }, status);
```

### 2. route ของหนังสือ `server/src/routes/books.routes.ts`

การ์ดนี้ยังไม่ต่อฐานข้อมูล ใช้ array ไปก่อน จะได้เห็นเฉพาะเรื่อง HTTP (การ์ด [แบ่งชั้น](/learn/cards/layers) จะเปลี่ยนเป็นฐานข้อมูลจริง)

```ts
import { Hono } from "hono";
import { fail, ok } from "../lib/response";

const books = [
  { id: 1, title: "เจ้าชายน้อย", available: true },
  { id: 2, title: "ฮอบบิท", available: false },
];

export const bookRoutes = new Hono();

bookRoutes.get("/", (c) => {
  const q = c.req.query("q") ?? "";                       // /api/books?q=เจ้า
  return ok(c, books.filter((b) => b.title.includes(q)));
});

bookRoutes.get("/:id", (c) => {
  const book = books.find((b) => b.id === Number(c.req.param("id")));   // /api/books/1 → "1"
  if (!book) return fail(c, 404, "NOT_FOUND", "ไม่พบหนังสือ");
  return ok(c, book);
});
```

### 3. ประกอบร่าง `server/src/index.ts`

```ts
import { Hono } from "hono";
import { fail } from "./lib/response";
import { bookRoutes } from "./routes/books.routes";

const app = new Hono().basePath("/api");
app.route("/books", bookRoutes);                 // ทุก route ของหนังสืออยู่ใต้ /api/books
app.notFound((c) => fail(c, 404, "NOT_FOUND", "ไม่พบ"));

export default app;                              // Bun เห็น export default แล้วเปิด server ที่ port 3000 ให้
```

**ควรเห็น:** รัน `bun run dev` ขึ้น `Started development server: http://localhost:3000` แล้วเปิด `http://localhost:3000/api/books/1` ใน browser

```json
{"success":true,"data":{"id":1,"title":"เจ้าชายน้อย","available":true}}
```

ตัว `c` ในทุก handler คือ **[context](/glossary#context)** = ทุกอย่างของคำขอนี้: `c.req` ไว้อ่าน (`query`, `param`, `json()`), `c.json()` ไว้ตอบ

## ทริคที่แนะนำ

1. **route เฉพาะต้องมาก่อน `/:id`:** ถ้าเขียน `get("/:id")` ก่อน `get("/popular")` คำขอ `/popular` จะเข้า `/:id` ด้วย id = `"popular"` ได้ "ไม่พบหนังสือ" แบบงงๆ (ลองแล้วเจอจริง)
2. **ทดสอบโดยไม่ต้องเปิด server:** `const res = await app.request("/api/books/1")` ได้คำตอบกลับมาเลย ใช้เขียนเทสต์ได้ทันที
3. **แยกไฟล์ route ตามของ** (`books.routes.ts`, `loans.routes.ts`) แล้วรวมด้วย `app.route()` ตามโครง `routes/` ใน Requirement เห็นภาพ API ทั้งหมดในไฟล์ `index.ts` ไฟล์เดียว

## ปรับไปใช้จริง

**ในงาน STARTER:** วันที่ 3 ทำ Public API 5 ตัว (หน้า 7 ของ Requirement) ทุกตัวขึ้นต้นด้วย `/api` เหมือน `basePath("/api")` ข้างบน และ `GET /api/services?category=&featured=` ใช้ `c.req.query()` แบบเดียวกับ `?q=` ในตัวอย่าง

**เว็บคู่มือนี้:** ใช้โครงเดียวกัน ดู [server/app.ts บน GitHub](https://github.com/sutiwatpaksa-Dev/E-Book-Internship/blob/main/server/app.ts) มี `basePath("/api")`, `app.route()` 5 กลุ่ม และ `notFound`

ลองคิด: route ของ admin ทุกตัวต้อง login ก่อน ควรเช็กในทุก handler หรือมีที่ที่เขียนครั้งเดียวแล้วครอบทั้งกลุ่มได้ (คำค้น: Hono [middleware](/glossary#middleware))

## ลองเอง

**โจทย์:** ต่อจากโค้ดข้างบน เพิ่ม `GET /api/books/available` ที่ตอบเฉพาะเล่มที่ยืมได้ และ `DELETE /api/books/:id` ที่ตอบ `200` พร้อม `{ success: true, data: { id } }` เมื่อลบได้ และ `404` เมื่อไม่มีเล่มนั้น

<Hint level={1}>เขียนเสร็จแล้วลองเปิด `/api/books/available` ถ้าได้ "ไม่พบหนังสือ" แปลว่ามี route อื่นแย่งไปก่อน</Hint>
<Hint level={2}>ลบออกจาก array ต้องรู้ตำแหน่งก่อน ลองหาใน JavaScript ว่า `findIndex` กับ `splice` ทำอะไร</Hint>
<Hint level={3}>ตรวจด้วย `await app.request("/api/books/99", { method: "DELETE" })` แล้วดู `.status` ต้องได้ 404 ก่อน แล้วค่อยลองลบเล่มที่มีอยู่</Hint>
