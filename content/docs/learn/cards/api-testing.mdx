## ความหมาย

ยิงทดสอบ API คือ **ส่งคำขอไปที่ server โดยไม่ผ่านหน้าเว็บ** แล้วดู status กับข้อมูลที่ตอบกลับ ว่าตรงกับที่ออกแบบไว้ไหม

**นึกภาพ:** ช่างไฟฟ้าเอามิเตอร์จิ้มที่ปลั๊กโดยตรง แทนที่จะเสียบหลอดไฟแล้วเดาว่าไม่ติดเพราะหลอดเสียหรือไฟไม่มา

จับคู่: มิเตอร์ = Postman หรือ curl · ปลั๊ก = API · หลอดไฟ = หน้าเว็บ · "หลอดเสียหรือไฟไม่มา" = ปัญหาอยู่ฝั่งหน้าเว็บหรือฝั่ง server

```text
ทางปกติ
หน้าเว็บ ──► API ──► ฐานข้อมูล

ยิงทดสอบ (ตัดหน้าเว็บออก)
Postman / curl ──► API ──► ฐานข้อมูล
```

ยิงตรงแล้วได้ผลถูก แต่บนหน้าเว็บผิด แปลว่าปัญหาอยู่ฝั่งหน้าเว็บ ไม่ต้องไปไล่หาในโค้ด server

จุดที่ไม่ตรง: มิเตอร์จิ้มครั้งเดียวก็รู้ว่าไฟมาไหม แต่ API ต้องลองหลายแบบ ทั้งส่งถูก ส่งผิด ไม่ได้ login และของที่ไม่มีอยู่ จนครบทุกแถวในสัญญาของการ์ด [ออกแบบรายการ API](/learn/cards/api-design)

## ที่มา

ถ้าทดสอบผ่านหน้าเว็บอย่างเดียว พอกดแล้วไม่มีอะไรเกิดขึ้น เราไม่รู้ว่าพังที่หน้าเว็บหรือที่ API การยิง API ตรงๆ ตัดหน้าเว็บออกจากสมการ และยังลองสิ่งที่หน้าเว็บไม่ยอมให้ทำได้ด้วย เช่น ส่งข้อมูลผิดรูปแบบ หรือเรียก API หลังบ้านโดยไม่ login ซึ่งเป็นสิ่งที่คนไม่หวังดีทำจริง

## การใช้งาน

เปิด server ไว้ก่อน (`bun run dev` ในโฟลเดอร์ `server/` จากการ์ด [Hono](/learn/cards/hono))

### ทางที่ 1: Postman (โจทย์ฝึกงานต้องส่งไฟล์นี้)

1. ติดตั้ง Postman จาก [postman.com/downloads](https://www.postman.com/downloads/) แล้วกด **New → Collection** ตั้งชื่อ `Library API`
2. ที่ collection แท็บ **Variables** เพิ่ม `base` = `http://localhost:3000/api`
3. **Add request** ตั้งชื่อเป็นผลที่ควรได้ เช่น `เพิ่มหนังสือ ชื่อว่าง (ควรได้ 400)`
   - method `POST` · URL `{{base}}/books`
   - แท็บ **Body** → **raw** → เลือก **JSON** แล้วใส่ `{ "title": "" }`
4. กด **Send** ดู status มุมขวา (`400 Bad Request`) และ body ด้านล่าง

**ควรเห็น:**
```json
{ "success": false, "error": { "code": "VALIDATION_ERROR", "message": "ข้อมูลไม่ถูกต้อง", "details": { "title": ["ต้องมีชื่อหนังสือ"] } } }
```

ส่งงาน: คลิก `...` ที่ collection → **Export** ได้ไฟล์ `.json` เก็บไว้ในโปรเจกต์

### ทางที่ 2: ไฟล์ `.http` ใน VS Code (extension REST Client)

เขียนเก็บในโปรเจกต์ ใช้ซ้ำได้ทั้งทีม กด **Send Request** ที่ขึ้นเหนือแต่ละคำขอ

```http
@base = http://localhost:3000/api

### ดูหนังสือทั้งหมด (ควรได้ 200)
GET {{base}}/books

### เพิ่มหนังสือ (ควรได้ 201)
POST {{base}}/books
Content-Type: application/json

{ "title": "เจ้าชายน้อย" }
```

### ทางที่ 3: `curl` ใน Terminal

เก็บ body ไว้ในไฟล์ `server/book.json` (มีแค่ `{ "title": "ฮอบบิท" }`) แล้วพิมพ์ curl จากโฟลเดอร์ `server/` เพราะ `@book.json` หาไฟล์จากโฟลเดอร์ที่ Terminal อยู่ จะได้ไม่ต้องสู้กับเครื่องหมายคำพูดที่แต่ละ Terminal ไม่เหมือนกัน

```bash
# Mac และ Windows (Git Bash) พิมพ์เหมือนกัน
curl -i http://localhost:3000/api/books/1
curl -i --json @book.json http://localhost:3000/api/books
```

`-i` ให้โชว์ status กับ header ด้วย ส่วน `--json @book.json` ส่งเนื้อไฟล์เป็น body และใส่ header JSON ให้เอง

## ทริคที่แนะนำ

1. **ตั้งชื่อคำขอเป็น "ผลที่ควรได้"** เช่น `ยืมเล่มที่ 4 (ควรได้ 409)` collection จะกลายเป็นเช็กลิสต์ทดสอบที่ใครเปิดก็รู้ว่าผ่านหรือไม่ผ่าน
2. **ยิงทางพังให้ครบทุกตัว:** ข้อมูลผิด, ไม่มีของ, ซ้ำ, ยังไม่ login ทางสำเร็จมักใช้ได้ตั้งแต่แรก ทางพังคือที่ซ่อนบั๊ก
3. **บน Windows ใช้ [Git Bash](/00-start#windows-ใช้-git-bash-เท่านั้น) ไม่ใช่ PowerShell:** ใน PowerShell 5.1 คำว่า `curl` คือคำสั่งอื่น (`Invoke-WebRequest`) ที่ไม่รู้จัก `-i` หรือ `--json` และเครื่องหมายคำพูดใน JSON ถูกตัดทิ้ง ส่วน Git Bash มี curl ตัวจริงมาให้ พิมพ์เหมือน Mac ทุกตัวอักษร

## ปรับไปใช้จริง

**ในโจทย์ฝึกงาน** (ตัวอย่างจาก STARTER)**:** "Postman collection ที่ test ได้ทุก endpoint" อยู่ในรายการส่งมอบ และวันที่ 3 ตรวจผ่านเมื่อ "ยิง Postman ได้ครบ" ทำ collection ไปพร้อมกับเขียน API ทีละตัว อย่ารอทำวันสุดท้าย ส่วนวันที่ 4 ให้เพิ่มคำขอ "เรียก API หลังบ้านโดยไม่ login (ควรได้ 401)" ถ้าได้ `200` คือเกณฑ์ไม่ผ่านทันที

**ตอนเจอบั๊กบนเว็บ:** เปิด DevTools แท็บ Network คลิกขวาที่คำขอที่พัง เลือก **Copy as cURL** จะได้คำสั่งที่ส่งคำขอเดิมทุกตัวอักษร (ระวัง: คำสั่งที่ copy มามี cookie ของเราติดมาด้วย ห้ามแปะลงแชทหรือส่งให้ AI)

ลองคิด: ถ้าเปิด DevTools แล้วเห็นคำขอได้ `200` แต่หน้าเว็บยังไม่เปลี่ยน ปัญหาอยู่ฝั่งไหน

## ลองเอง

**โจทย์:** ทำ Postman collection ของ API หนังสือและการยืมที่สร้างมาในการ์ดก่อนๆ ทุก endpoint ต้องมีอย่างน้อย 1 ทางสำเร็จและ 1 ทางพัง ชื่อทุกคำขอบอก status ที่ควรได้ แล้ว Export ให้เพื่อน Import ไปรันบนเครื่องเขา ถ้าทุกคำขอได้ตามชื่อ ถือว่าผ่าน

<Hint level={1}>ไล่ endpoint ทีละตัว ถามว่า "ตัวนี้พังได้กี่แบบ" (ข้อมูลผิด, ไม่มีของ, ขัดกฎ)</Hint>
<Hint level={2}>ใช้ตัวแปร `{{base}}` ทุกคำขอ เพื่อนที่รัน server คนละ port แก้ตัวแปรเดียวพอ</Hint>
<Hint level={3}>เพื่อนรันแล้วไม่ตรง ให้ดูก่อนว่าฐานข้อมูลเขามีข้อมูลเหมือนเราไหม (seed ชุดเดียวกันหรือเปล่า) คำขอที่ต้องพึ่งข้อมูลเฉพาะ เช่น id ที่ 1 จะพังถ้าข้อมูลต่างกัน</Hint>
