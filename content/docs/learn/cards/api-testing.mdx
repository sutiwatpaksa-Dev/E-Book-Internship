## ความหมาย

ยิงทดสอบ API คือ **ส่งคำขอไปที่ server โดยไม่ผ่านหน้าเว็บ** แล้วดู status กับข้อมูลที่ตอบกลับ ว่าตรงกับที่ออกแบบไว้ในขั้น 2 ไหม

## ที่มา

ถ้าทดสอบผ่านหน้าเว็บอย่างเดียว พอกดแล้วไม่มีอะไรเกิดขึ้น เราไม่รู้ว่าพังที่หน้าเว็บหรือที่ API การยิง API ตรงๆ ตัดหน้าเว็บออกจากสมการ และยังลองสิ่งที่หน้าเว็บไม่ยอมให้ทำได้ด้วย เช่น ส่งข้อมูลผิดรูปแบบ หรือเรียกโดยไม่ login ซึ่งเป็นสิ่งที่คนไม่หวังดีทำจริง

## การใช้งาน

**ทางที่ 1: ไฟล์ `.http`** (ติดตั้ง extension REST Client ใน VS Code) เขียนเก็บไว้ในโปรเจกต์ ใช้ซ้ำได้ทั้งทีม ใช้ได้เหมือนกันทั้ง Windows และ Mac

```http
@base = http://localhost:3000/api

### ดูหนังสือทั้งหมด (ควรได้ 200)
GET {{base}}/books

### เพิ่มหนังสือ (ควรได้ 201)
POST {{base}}/books
Content-Type: application/json

{ "title": "เจ้าชายน้อย" }

### ชื่อว่าง (ควรได้ 400 พร้อมบอกช่องที่ผิด)
POST {{base}}/books
Content-Type: application/json

{ "title": "" }
```

กด **Send Request** ที่ขึ้นเหนือแต่ละคำขอ ผลขึ้นในแท็บข้างๆ

**ทางที่ 2: `curl`** ใน terminal เก็บ body ไว้ในไฟล์ เพื่อไม่ต้องสู้กับเครื่องหมายคำพูดที่แต่ละ terminal ไม่เหมือนกัน

```bash
# Mac / Linux
curl -i http://localhost:3000/api/books/1
curl -i --json @book.json http://localhost:3000/api/books
```

```powershell
# Windows (PowerShell) พิมพ์ curl.exe ไม่ใช่ curl
curl.exe -i http://localhost:3000/api/books/1
curl.exe -i --json "@book.json" http://localhost:3000/api/books
```

`-i` ให้โชว์ status กับ header ด้วย `--json @book.json` ส่งเนื้อไฟล์เป็น body และใส่ header JSON ให้เอง (ไฟล์ `book.json` มีแค่ `{ "title": "ฮอบบิท" }`)

## ทริคที่แนะนำ

1. **บน Windows พิมพ์ `curl.exe`:** ใน Windows PowerShell 5.1 คำว่า `curl` เฉยๆ คือคำสั่งอื่น (`Invoke-WebRequest`) ที่ไม่รู้จัก `-i` หรือ `--json`
2. **เขียนชื่อคำขอเป็น "ผลที่ควรได้"** เช่น `### ยืมซ้ำ (ควรได้ 409)` ไฟล์ `.http` จะกลายเป็นเช็กลิสต์ทดสอบที่ใช้ในขั้น 4 ได้ทันที
3. **ยิงทางพังให้ครบทุกตัว:** ข้อมูลผิด, ไม่มีของ, ยังไม่ login, ไม่มีสิทธิ์ ทางสำเร็จมักใช้ได้ตั้งแต่แรก ทางพังคือที่ซ่อนบั๊ก

## ปรับไปใช้จริง

ตอนเจอบั๊กบนเว็บจริง เปิด DevTools แท็บ Network คลิกขวาที่คำขอที่พัง เลือก **Copy as cURL** จะได้คำสั่งที่ส่งคำขอเดิมทุกตัวอักษร เอาไปยิงซ้ำใน terminal ได้ (ระวัง: คำสั่งที่ copy มามี cookie ของเราติดมาด้วย ห้ามแปะลงแชทหรือส่งให้ AI)

ลองคิด: ถ้าเปิด DevTools แล้วเห็นคำขอได้ `200` แต่หน้าเว็บยังไม่เปลี่ยน ปัญหาอยู่ฝั่งไหน

## ลองเอง

**โจทย์:** เขียนไฟล์ `books.http` ที่ทดสอบ API หนังสือครบทุกตัว อย่างน้อยตัวละ 1 ทางสำเร็จและ 1 ทางพัง ชื่อทุกคำขอบอก status ที่ควรได้ แล้วส่งให้เพื่อนรัน ถ้าทุกคำขอได้ตามชื่อ ถือว่าผ่าน

<Hint level={1}>ไล่จากรายการ API ในขั้น 2 ทีละบรรทัด ถามว่า "ตัวนี้พังได้กี่แบบ"</Hint>
<Hint level={2}>ใช้ตัวแปร `@base` ไว้บนสุดไฟล์ วันที่ย้ายไปทดสอบบน preview แก้บรรทัดเดียว</Hint>
<Hint level={3}>ถ้าต้อง login ก่อน ให้ส่งคำขอ login ในไฟล์เดียวกันก่อน REST Client จำ cookie ให้คำขอถัดๆ ไปเอง</Hint>
